## 0. 开篇：这一章的"核心反转"

### 0.1 一句话概括

> **复杂腿式机器人（人形/四足）的控制，主导思想不是"把几十个关节一起算"，而是"先把机器人看成一个大块头（质心），用简单模型规划这个块头怎么动、脚踩在哪，最后再让关节去实现"。**

### 0.2 作者开场白的三层意思（逐句翻译）

**第一层：第4章 vs 第5章，是两套"方言"。**
> 第4章的被动行走器/跳跃器抓住了腿式运动的**根本动力学**——非线性 + 撞地那一下的脉冲。但你去读**人形机器人**或**多腿机器人**的论文，会发现**另一套思想站到了舞台中央**：比如"零力矩点（ZMP）"和"脚步规划（footstep planning）"。本章就是要**穿透**这个世界。

**类比**：第4章像"研究鸟为什么会飞"（空气动力学本质）；第5章像"研究民航怎么排航班"（工程调度）。两者都对，但关注点完全不同。

**第二层（全章最反直觉的一句）：复杂机器人反而用简单模型。**
> 关于复杂（高自由度）腿式机器人，**最令人惊讶的事**是：它们在**估计、规划、控制**中**主导性地使用简单模型**。当你有**足够多的自由度**，能让"脚怎么动"和"身体怎么动"**近似解耦**（脚可以相对独立地摆放）时，这些抽象就值钱了。

**类比**：你开一辆** articulated（带铰接）的超长卡车**，车头和车厢能相对转动。你规划路线时，**不会去算每个轮胎的形变**，而是把车头当"一个点"、车厢当"另一个点"，先规划这两个点怎么走，再让转向机构去实现。**自由度越多，"把局部当点"的近似就越成立**——因为你有足够的关节去"吸收"误差。这就是为什么"简单模型"在人形机器人上反而好使。

**第三层：记号要升级。**
> 机器人变复杂了，记号得加强。Drake 用 **monogram 记号**和**空间代数（spatial algebra）**。

> **记号速查（基础薄弱者必读，否则后面全是天书）**：monogram 记号就是用**上标/下标**标明"这个东西是在哪个坐标系看、属于哪个物体/哪个点"。
> - 上标 = **参考坐标系**：`W` 表示世界坐标系（地面），`B` 表示机器人身体坐标系，`C` 表示接触坐标系。
> - 下标 = **物体或点**：`Bcm` 表示"物体 B 的质心"，`Bi` 表示"第 i 个推力器/接触点"。
> - 例：`ᵂp_Bcm` = "在世界坐标系 W 里看，物体 B 质心的**位置**（position）"；`ᵂV_Bcm` = "B 质心相对 W 的**空间速度**"；`F_Bcm` = "施加在 B 质心的**空间力**"。
> - **空间（spatial）= 把"旋转"和"平移"打包成一个 6 维向量**。比如空间速度 = [角速度 ω ; 线速度 v]，空间力 = [力矩 τ ; 力 f]，空间动量 = [角动量 ; 线动量]。**记住"空间 = 旋转+平移的合体"，后面所有"空间 X"都秒懂。**

## 1. 思想实验：把行走机器人看成"带可移动推力器的航天器"（全章主线，务必吃透）

作者明说：**这个看起来和腿式机器人"八竿子打不着"的航天器模型，恰恰是理解行走问题的钥匙。** 我们慢慢加约束，每加一条，它就离"行走"更近一步。

### 1.1 第一版：带固定推力器的航天器（"这题其实不难"）

**场景**：一个飞行器，**单个刚体**，在重力场里，身上装了若干个**推力器（thruster）**，像小火箭喷口。

- 用**世界坐标系**描述它的位姿：位置 $(x,z)$ + 朝向 $\theta$，质心放在身体坐标系原点。
- 第 $i$ 个推力器到质心的向量是 $p_i$。
- 运动方程（图5.1，和平面四旋翼几乎一样，只是力用世界坐标写）：

$$m\ddot x = \sum_i f_{i,x},\qquad m\ddot z = \sum_i f_{i,z} - mg,\qquad I\ddot\theta = \sum_i [\,p_i \times f_i\,]_y$$

**人话**：
- 水平加速度 = 所有推力的水平分量之和 ÷ 质量。
- 垂直加速度 = 所有推力的垂直分量之和 ÷ 质量，**再减掉重力 g**。
- 角加速度 = 每个推力"绕质心拧的劲儿"（叉积的 y 分量，即力矩）之和 ÷ 转动惯量。

**这题难吗？作者说：不算难。** 因为：
- 如果你把**推力 $f_i$ 当输入**，那么**平移方程是"仿射"的**（= 线性 + 一个常数项 $-mg$，常数项很好对付）。
- 旋转方程虽然非线性（推力器位置 $p_i$ 会跟着航天器一起转），但**小角度**下，线性化 + 换个坐标 + LQR 就能稳住；想跟踪轨迹就用时变 LQR。
- 再加些**线性约束**（比如 $f_{\min}\le f_i \le f_{\max}$），还能用**线性 MPC**。
- 就算考虑完整非线性，用非线性优化也"还算可控"。

**类比**：这就像**无人机悬停**——四个螺旋桨的推力你能随便调，想往哪飘往哪飘，是个"听话"的系统。

### 1.2 第二版：推力器又少、又挑剔、还能"搬家"（"这题突然变难"）

现在加三条"恶心人"的设定：

1. **推力器很少**（比如就 2 个），每个还有**严重的输入限制**。
2. **推力器可以移动**！所以移动速度 $v_i = \frac{d}{dt}p_i$ 也成了**额外的控制输入**。
3. 但移动有**两条死规矩**：
   - **搬家时必须熄火**：$f_i=0$ 或 $v_i=0$（二者至少一个为 0，即"要么喷、要么挪，不能边喷边挪"）。
   - **挪得不能太快**：$\|v_i\|\le v_{\max}$。

**为什么突然变难？** 因为"$f_i=0$ **或** $v_i=0$"这种"**或**"字约束是**非凸**的！

> **什么是"非凸"，为什么可怕？** 凸 = 一碗光滑的粥，勺子（优化算法）随便搅都能滑到最低点。非凸 = 一碗粥里**竖了几堵墙**，把碗隔成几个坑，勺子会**卡在一个坑里出不来**，找不到全局最低点。"或"字就是那堵墙——它把可行域劈成两半。

**作者的核心洞察（请画重点）**：
> 这个思想练习很有用：控制器必须做一个**实质上的"离散决策"**——**决定"关掉某个推力器、把它挪走"**。最优控制框架**本该**支持这种事——你**牺牲短期的控制权威**（挪的时候不能喷，等于暂时"缴械"），**换取长期的好处**（推力器挪到了更需要它的位置）。**但我们还没开发出能很好处理"离散决策 + 连续决策"混合的工具。** 这正是本章要碰的硬骨头。

**类比**：像**下棋 + 开车**的混合。开车是连续的（方向盘转多少度）；下棋是离散的（这步"弃车保帅"是个 0/1 的决断）。行走机器人难，就难在它**一边在连续地平衡身体，一边在做"下一步脚踩哪、要不要抬脚"这种离散决断**。

### 1.3 第三版：推力器只能在"指定地点"开启（"现在它真的像腿了"）

还不够。再加一条：**推力器只能在世界坐标系的某些区域开启**（图5.2，地上画了几个圈，推力器只有飘进圈里才能喷）。

- 即使**每个圈本身是凸的**（圆的、方的），这些圈的**并集**也未必是凸集（几个分散的圈，中间是空的——又是"墙"！）。
- 更要命：这些"能喷的区域"通常用**世界坐标**写，而不是机器人坐标：$A\,p_i \le b$（脚能踩哪，是**地面**说了算，不是你身体说了算）。

**类比**：这就像**跳房子**——你只能在画好的格子里落脚，格子之间的空地踩不得。而格子画在**地上**（世界坐标），不画在你脚上。

### 1.4 终极映射：脚 = 可移动的、挑剔的推力器（5.1.2）

> **作者的观点：上面这个"带推力器的航天器"，就是行走问题的核心组件。** 如果把行走机器人看成**单个刚体 B + 无质量的腿**，那么**脚就完全等同于"可移动的推力器"**。

脚和推力器一样，**高度受限**：
- **只有踩到地才能出力**（悬空时 $f=0$）。
- **通常只能朝某些方向出力**——用**摩擦锥（friction cone）** 描述：
  - **能推地、不能拉地**：$f_{i,z}\ge 0$（法向力只能往上顶，地面没有"吸盘"）。
  - **库仑摩擦**：切向力必须小于法向力 × 摩擦系数，$|f_{i,x}| < \mu\, f_{i,z}$（斜着推太狠会打滑）。这里 $C$ 是接触坐标系。

**类比（摩擦锥，必懂）**：你**推一个放在地上的箱子**。垂直往下压，箱子纹丝不动；斜着推，只要不太斜，箱子也不滑（摩擦够）；**斜到一定程度，箱子"嗖"地滑出去**——那个"临界斜度"就是摩擦锥的边界。**摩擦系数 μ 越大，锥越"胖"，你越能斜着使劲而不打滑。** 机器人脚底也一样：它给地面的力，必须落在这个"锥"里，否则脚会滑。

**两个"难约束" vs 一个"简单本体"**：
- **脚能放哪** → 取决于**腿的运动学**（腿够不够长、关节会不会卡）。
- **脚能挪多快** → 取决于**腿的完整动力学**（腿有质量、有惯性，甩不快）。
- 这俩都是**难处理的约束**。
- **但是！** 刚体 B（身体）**本身的动力学，仍然只是航天器动力学，仍然简单！**

> **这就是全章的"题眼"**：**难的全在"脚怎么接触地面"，而"身体怎么动"反而是简单的航天器方程。** 所以工程师的策略自然是——**先用简单模型把"身体"规划好，再去头疼"脚"的约束。** 简单模型之所以在复杂机器人上好使，根子就在这里。

## 2. 压力中心（CoP）与零力矩点（ZMP）—— 人形机器人的"两大黑话"

### 2.1 平地特例：把一堆脚底压力，浓缩成"一个点"（5.2.1）

机器人走平地（或近平地）**极其常见**。即使它**同时好几个点着地**（比如两脚跟 + 两脚尖），我们也能**高效地**概括出质心受到的约束。看图5.4。

**结论一：不能拉地 ⇒ 质心不能"比自由落体还快地"砸向地面。**

平地上 $f_{i,z}$ 是第 $i$ 个接触点的**法向力**（垂直顶地的力）。"只能推不能拉"意味着每个 $f_{i,z}\ge 0$，于是总和也 $\ge 0$，代回垂直方程：

$$\forall i,\ f_{i,z}\ge 0 \ \Rightarrow\ \sum_i f_{i,z}\ge 0 \ \Rightarrow\ \ddot z \ge -g$$

**人话**：你**没法把地面往上拽**，所以你的质心**朝下加速的极限就是 g**（自由落体）。想"砸"得比自由落体还快？没门——这就是第4章作者说的"欠驱动的天花板"，这里用数学写出来了。

**结论二：摩擦 ⇒ 水平加速度有上限。**

用库仑摩擦，每个点 $|f_{i,x}|\le \mu f_{i,z}$，求和后代入水平方程：

$$| \ddot x | \le \mu(\ddot z + g)$$

**特例**：若你**保持质心高度匀速**（$\ddot z=0$），则 $|\ddot x|\le \mu g$。

**人话**：在冰面（μ 小）上你**没法急加速**，在粗糙地面（μ 大）上你才能猛冲。**这个不等式就是"摩擦决定了你能多快地改变水平速度"的硬上限。** 作者说：这是个很好的提醒——**想在世界上移动，摩擦有多重要**。

**结论三（核心）：定义"压力中心 CoP"。**

把地面上所有接触点的压力，按"力的大小"做**加权平均**，得到**一个点**，叫**压力中心（Center of Pressure, CoP）**：

$$\begin{bmatrix} x_{cp}\\ z_{cp}\end{bmatrix} \equiv \frac{\sum_i\, p_i\, f_{i,z}}{\sum_i f_{i,z}}$$

**人话（CoP 的生活直觉，务必建立）**：你**双脚并拢站在体重秤上**，秤显示的是总压力。现在想象地面是一块**布满压力传感器的智能垫**，它能告诉你"压力集中在哪"。你**站得正**，压力中心就在两脚中间；你**身体往前倾**，压力中心就**往前脚掌挪**；你**抬起脚跟、只用脚尖站着**，压力中心就**跑到脚尖**。**CoP 就是"你所有脚底压力的合力作用点"——一个把"一堆脚"浓缩成"一个点"的魔法。** 平地上所有接触点高度相同，所以 $z_{cp}$ 就是地面高度。

**CoP 与质心加速度的"杠杆关系"（方程4）**：对 CoP 做力矩平衡，能推出一个**极其重要**的关系：

$$(m\ddot z + mg)(x_{cp}-x) = (z_{cp}-z)\,m\ddot x - I\ddot\theta \qquad (4)$$

**结论四（最著名的 ZMP 方程，方程5）**：如果你用"$\ddot z=0$ 且 $\ddot\theta=0$"的策略（质心高度不变、身体不转——**这正是人形机器人最常用的简化**），上式化简成：

$$\ddot x = g\,\frac{x - x_{cp}}{z - z_{cp}} \qquad (5)$$

> **这个方程是整章的"灵魂公式"，请盯着它看 10 秒。** 它说的是：**质心的水平加速度，完全由"质心相对 CoP 偏了多少"决定**（反过来也成立：你想要某个加速度，就把 CoP 放到对应位置）。

**类比（倒立摆！这是理解 ZMP 方程的钥匙）**：方程(5) **本质上就是把整个机器人看成一个"脚踩在 CoP 的倒立摆"**！回忆第3章倒立摆：摆往哪边偏，就往哪边加速倒下。这里**质心 = 摆锤，CoP = 摆的支点，$(z-z_{cp})$ = 摆长**。
- 质心在 CoP **正上方**（$x=x_{cp}$）→ $\ddot x=0$ → **平衡**（像摆竖直立着）。
- 质心**偏右**（$x>x_{cp}$）→ $\ddot x>0$ → **向右加速**（像摆往右倒）。
- 想让它**别倒/往回拉**？把 CoP（支点）**挪到质心右边**，加速度就反过来了。

**所以"控制机器人走路"在质心层面，等价于"不断把脚下的支点 CoP 挪到合适位置，让身体这个倒立摆按你想要的方式倒/停"。** 这就是为什么 ZMP 这么重要。

**附带红利**：当 $z-z_{cp}$ 是**常数**（质心保持恒定高度）或**按计划变化**时，方程(5)里 $\ddot x$ 和 $x_{cp}$ 是**仿射关系**（线性+常数）——**仿射 = 优化算法的"亲儿子"**，特别好算！这是后面 ZMP 规划能"实时算出来"的数学原因。

**CoP 必须待在"脚底"里**：从定义容易验证，**CoP 一定落在所有地面接触点的凸包内**（即"脚踩出的那块区域"里）。

**类比**：你**双脚分开站**，CoP 只能在两脚之间那块区域里跑；你**单脚站**，CoP 只能在那只脚的脚掌里跑。**一旦 CoP 跑出脚底，你就摔了**——这就是"ZMP 在支撑多边形内 = 不摔"的几何含义。

**因此**：若采用 $\ddot z=\ddot\theta=0$ 策略，方程(5) + "CoP 在脚底内" ⇒ **给定脚踩在哪，质心能有的加速度就被严格框死了**（一个范围）。这就是 ZMP 规划的根本约束。

### 2.2 旁白：ZMP 到底怎么定义的？（5.2.2，把"黑话"正本清源）

ZMP 在论文里**出场率极高**，但**也极容易被混淆**——好多人定义略有出入（[1] 做了总结）。所以作者给一个干净推导。

**第一步：一堆外力 = 一个"等效力 + 等效力矩"。**
> 对刚体系统，**任意多个外力**总能**等效**成"作用在某点 A 的一个力 + 一个力矩"。为什么可以？因为外力**线性地**进入运动方程（力是相加的，所以能合并）。

把运动方程改写在任意点 A：

$$m\ddot x = f_{net,x},\quad m\ddot z = f_{net,z}-mg,\quad I\ddot\theta = [\,p_A\times f_{net}\,]_y + \tau_{net}$$

其中 $f_{net}=\sum_i f_i$，而 $\tau_{net}$ **取决于你选哪个点 A**。

**第二步：选一个让力矩 = 0 的点 = ZMP。**
对**某些** A 的选择，能让 $\tau_{net}=0$。这些点就叫 **ZMP**，满足：

$$[\,p_{ZMP}\times f_{net}\,]_y = p_{ZMP,z}\,f_{net,x} - p_{ZMP,x}\,f_{net,z} = \sum_i [\,p_i\times f_i\,]_y \qquad (6)$$

**人话**：ZMP 就是地面上那个**"把所有外力看作一个纯力、不带任何拧劲儿"** 的点。

**定义 5.1（ZMP）**：外力对机器人的总贡献，总能概括成"施加在任意点 P 的一个空间力"。若在 P 处，这个空间力的**旋转分量（力矩）为零**，则称 P 为**零力矩点**。平地行走时，**约定俗成**把"the ZMP"指**地面上唯一的那个零力矩点**。

**第三步：解是一条线，但和地面只有一个交点。**
只要 $f_{net,z}\ne 0$（地面在顶你），方程(6)的解是**一整条线** $p_{ZMP,x}=a\,p_{ZMP,z}+b$——其中**和地面相交的那一点**，就是行走机器人说的 ZMP。

**类比**：想象你**推一堵墙**，手施加的力可以"等效平移"到墙上任何高度，但同时会附带一个力矩；只有平移到**某一个特定高度**时，附带的力矩才为零。把这个"特定高度的点"投影到地面，就是 ZMP。

**第四步：ZMP = CoP（平地上它俩是同一个东西！）**
把运动方程代回(6)，可得 $p_{ZMP,z}\,m\ddot x - p_{ZMP,x}(m\ddot z+mg)=I\ddot\theta$ ——**这正是方程(4)**。再利用平地上 $\sum_i p_{i,z}f_{i,x}=p_{ZMP,z}\sum_i f_{i,x}$，可解出：

$$p_{ZMP,x} = \frac{\sum_i p_{i,x}\,f_{i,z}}{\sum_i f_{i,z}}$$

**这和 CoP 的定义一模一样！** 所以**在平地上，ZMP 和 CoP 是同一个点**（这就是为什么文献里两个词常混着用）。

**三维推广**：在 3D 里，解地面上 $\tau_{ZMP,y}=0$ 的点（但允许绕垂直轴 $\tau_{ZMP,z}\ne 0$，因为脚可以"拧"地面），同理得到 y 方向（侧向）的方程：

$$p_{ZMP,z}\,m\ddot y - p_{ZMP,y}(m\ddot z+mg) = I\ddot\theta$$

**人话**：前后方向一个 ZMP 方程，左右方向一个 ZMP 方程，**两套杠杆关系管住质心的水平运动**。

### 2.3 关于"撞地那一下"的注记（5.2.3）—— 为什么人形论文敢"忽略碰撞"？

第4章我们很重视**碰撞动力学**（混合系统里 guard 重置速度，用"瞬时无穷大、做有限功"的脉冲力解释速度的突变）。这套故事也能用到质心上。

**但对关节式机器人，腿有好几种"接法"，会改变质心在撞地时的表现**：
- **硬腿撞地**（像轮辐轮）→ 绕撞点**角动量守恒**，但**撞进地面的动量全丢**（漏气）。
- **弹簧腿 + 无质量脚**（像 SLIP）→ **可以不丢能量**。
- **高自由度机器人的常用策略**：**保持质心垂直速度恒定**（$\dot z=c \Rightarrow \ddot z=0$），并**最小化绕质心的角动量**（$I\dot\theta=0 \Rightarrow I\ddot\theta=0$）。

**妙处**：用这个策略，**只要摆动脚大致落在质心正下方**，那么**即使是硬腿，撞地也不耗散能量**——动量全守恒！

> **这就是大部分人形论文在"推理质心动力学"时，敢直接忽略碰撞动力学的理由/常见做法。** 不是碰撞不存在，而是**他们用"质心匀速 + 脚落在身下"的姿势，把碰撞的破坏性"消音"了**。

**类比**：像**走猫步**——你刻意让落脚点在身体正下方、并保持身体高度平稳，于是每一步的"顿挫感"被压到最小，质心几乎感觉不到撞地的冲击。**人形机器人学的就是这种"猫步"。**

## 3. 基于 ZMP 的规划：把"难问题"切成"三段简单问题"（5.3）

理解了 CoP/CoM 的关系，就拿到了一组规划工具。作者描述**最常见的流水线**，把问题**切成三步**：

1. **先规划脚踩哪**（脚步/接触位置规划）。
2. **再规划质心怎么走**（CoM 轨迹规划）。
3. **最后算每个关节怎么动**，去实现上面两条（全身运动学/动力学求解）。

这流水线**起源于著名的 ZMP 行走器**（如 **Honda 的 ASIMO**），最初针对平地，但许多概念能自然推广到 3D 和更一般的运动。

**为什么敢这么切？切的代价是什么？（作者特意点明，很重要）**
- **好处**：把一个"几十维、带离散接触、带摩擦锥"的**地狱级**优化，切成**三个各自好解**的小问题——**戏剧性地简化**。
- **代价**：
  - **脚步规划**倾向**保守 + 纯运动学**，因为它**不直接推理动力学**（它只管"脚够不够得着"，不管"这么踩身体会不会失衡"）。
  - **质心规划**没法精确考虑**关节级约束**（关节角度限、电机力矩限）。
- **本质**：用"近似"换"可解"。这正是开篇"复杂机器人用简单模型"的具体落地。

**类比（旅行规划，贯穿本节）**：你要去 5 个城市玩 10 天。
- **第1步（脚步规划）**= 先定**去哪些城市、按什么顺序**（只管"能不能到"，比如没有直飞就保守点选有直飞的）。
- **第2步（CoM 规划）**= 再定**每天大致行程**（上午去哪下午去哪）。
- **第3步（全身规划）**= 最后**订票、订车、订酒店**，把行程落地成具体动作。
- **代价**= 分步做可能错过"联程票+酒店套餐"的**全局最优**；但**不分步你根本算不出来**。

## 4. 质心动力学（Centroidal Dynamics）：简单模型"不是近似，是精确的"（5.4）

> **本节有一个反直觉的重磅结论，请一定记住：下面这些"简单方程"，对完整人形机器人是精确成立的，不是近似！**

作者说：思想实验和 ZMP 推导里用的那些方程，**不限于"单刚体 + 无质量腿"**。完整人形的运动方程确实复杂，**但只要你写的是"质心的运动方程"，它就和上面推导的单刚体情形本质相同。**

### 4.1 空间动量（5.4.1）—— 给单刚体换个"高级记号"

在简单模型里我们用 $q=[\theta,x,z]$，其中 $x,z$ 取的是**质心位置** $p_{Bcm}$。注意：**这个特定的速度选择，恰好对应一个重要的物理量——空间速度**（角速度 + 平移速度 拼起来）：

$$^WV^{Bcm} = \begin{bmatrix} \omega \\ \dot p_{Bcm}\end{bmatrix}$$

类似地定义**空间力** $F$（力矩 + 力 拼起来），和**绕质心的空间惯量**：

$$M^{B/Bcm} = \begin{bmatrix} I & 0 \\ 0 & m\,\mathbf{1}_{3\times3}\end{bmatrix}$$

**人话**：这个 6×6 矩阵，**左上角 $I$ 管"转起来多费劲"，右下角 $m$ 管"推起来多沉"**，互不干扰（块对角）。

于是**空间动量**（角动量 + 线动量 拼起来）为：

$$^WL^{B/Bcm}(\dot q) = M^{B/Bcm}\,^WV^{Bcm} = \begin{bmatrix} I\dot\theta \\ m\dot x \\ m\dot z\end{bmatrix}$$

**关键观察**：方程(1)–(3)的**左边**，正好可以**简洁地**写成"**空间动量的变化率 = 施加在质心的空间力之和**"。

**人话**：这其实就是**牛顿第二定律 + 角动量定理**的"打包版"——力 = 动量变化率，力矩 = 角动量变化率，只不过用空间代数**一行写完**。

### 4.2 推广到多体（5.4.2）—— 整个机器人也 obey 同一套方程

**整个机器人的质心** = 各连杆质心的**质量加权和**：

$$^Wp^{Rcm}(q) = \frac{\sum_i\, ^Wp^{B_i,cm}\, m_i}{\sum_i m_i} = \frac{\sum_i\, ^WX^{B_i}\,^{B_i}p^{B_i,cm}\, m_i}{\sum_i m_i}$$

**整个机器人绕该点的空间动量**，现在**配置依赖**，但形式**特别简单**：

$$^WL^{R/Rcm}(q,\dot q) = A(q)\,\dot q$$

> 在 Drake 里，用 `MultibodyPlant` 的 **`CalcSpatialMomentumInWorldAboutPoint()`** 就能算它。矩阵 $A(q)$ 有个专门的名字——**质心动量矩阵（centroidal momentum matrix）** [5]。

**全身空间动量的变化率**，仍然等于**外力之和**（正确施加空间变换后）：

$$\dot{\,^WL^{R/Rcm}}(q,\dot q,\ddot q) = A(q)\ddot q + \dot A(q,\dot q)\dot q = \sum_i F^{Bcm} \qquad (8)$$

**作者猜你直觉上早就懂**：
> 想象你是**宇航员**，处于（近似）**零重力**。如果你**不施加外力**，那么你的**质心加速度 = 0**（质心匀速/静止），且**总角动量守恒**。方程(8) **只是把这个直觉推广到"还有外力作用"的情形**。

**类比（猫翻身 / 宇航员转身，必懂）**：宇航员在空中**没有任何东西可抓**，但他**挥动手臂、蜷缩身体**，就能让自己**转个身**——这就是**角动量守恒**在起作用（手臂往一个方向甩，身体往反方向转，总角动量不变）。**方程(8) 描述的就是这件事的"带外力"版本**：如果宇航员**抓住舱壁推一下**（外力），他的质心就会加速、角动量也会变。**机器人走路 = 不断"推地面"（外力），从而控制自己质心和角动量的变化。**

### 4.3 重磅结论：这不是近似！（作者反复强调）

> **让我把一点说得非常清楚：这不是近似。这些方程精确地描述了质心的运动（和绕质心的角动量）。** 这里的"简化"**不是因为我们对动力学做了近似**，而是因为**我们还没把"肢体能产生的力"所受的全部约束**（运动学约束 + 执行器约束，如力矩限）**写进去**。

**人话（这句话值千金）**：
- 方程(8) **本身是 100% 精确的**——它就是你把整个机器人所有关节方程"加总、化简"后，**关于质心**的那部分，**一点信息都没丢**。
- 它"看起来简单"，是因为它**故意只盯着质心**，而把"几十个关节内部怎么折腾"**藏进了 $A(q)$ 和那些还没写明的约束里**。
- **真正的难点**不在方程(8)，而在"**你的手脚到底能使出多大的力、能伸到多远**"——这些**约束**才是把简单方程"绑住"的绳子。

**类比**：方程(8) 像**家庭账本的"总收入 = 总支出 + 储蓄"**——这条等式**永远精确**。但它没告诉你"每笔钱具体怎么花、能不能花"（那些是约束）。**账本简单，不代表理财简单**；**质心方程简单，不代表走路简单**。简单模型之所以能用，是因为**质心层面的物理是精确的**，难的全在约束里——而约束可以**分步、近似地**处理（回到第3节的流水线）。

## 6. 习题详解（本章实践核心，逐题讲透）

### 习题 5.1：用混合整数优化（MIQP）做脚步规划

实现文献 [2] 的脚步规划简化版。在 notebook 里，你要编码**混合整数程序（MIP）** 核心的四个组件：

**先建立直觉（跳房子模型）**：地上有一排**踏脚石（stepping stones）**，机器人要**从左跳到右**，每步选一块石头落。**"选哪块石头"是 0/1 的离散决策**（整数变量），**"脚落在石头内的哪个点"是连续决策**（连续变量）——**离散 + 连续 = 混合整数**，这就是 MIQP（目标还是二次的）。

- **(a) 最大步长约束**：相邻两脚落点距离 $\le$ 腿能迈的极限。
  $$\|p_{foot}[k+1] - p_{foot}[k]\| \le L_{\max}$$
  **人话**：你腿就这么长，一步跨不了 3 米。
- **(b) 一只脚不能同时在两块石头上**：用**互斥的 0/1 变量**保证每步每只脚**至多**被分配给一块石头。
  **人话**：你不能一只脚同时踩两块石头（劈叉也不行，这里指"同一时刻一脚一石"）。
- **(c) 每步把每只脚分配给一块石头**：用**指派约束**（assignment），每步每只脚**恰好**对应一块石头（一组 0/1 变量求和 = 1）。
  **人话**：每一步，左脚必须踩某块、右脚必须踩某块，不能"悬空不选"。
- **(d) 目标函数 = 最小化步长平方和**：$\min \sum_k \|p_{foot}[k+1]-p_{foot}[k]\|^2$。
  **人话**：在"能跳过去"的前提下，**步子越均匀、越省力越好**（平方和惩罚"忽大忽小"的步子）。

> **"大 M 法"提醒**：把"脚落在被选中的石头内"这种**"如果选了石头 j，则脚必须在石头 j 的框里"** 的逻辑，写成约束时常用**大 M 技巧**：$p \le b_j + M(1-z_j)$，其中 $z_j\in\{0,1\}$ 是"选没选石头 j"。$z_j=1$ 时约束生效，$z_j=0$ 时 $+M$ 把约束"撑开"使其失效。**这是 MIP 建模的标配手法，notebook 会让你练。**

### 习题 5.2：理解零力矩点（一道把 ZMP 讲透的神题）

图5.8：一个**抽象腿式机器人**站在平地。**脚**（被 H、T、P 三点围成，H=heel 脚跟，T=toe 脚尖，P=踝）和**长 $l$ 的腿**都**无质量**；腿末端一个**点质量 $m$** 代表身体；脚和腿在 **P 处用销关节**连接。脚高 $h$，踝到脚跟水平距 $L_1$、踝到脚尖水平距 $L_2$。

**这道题的价值**：它把"ZMP 跑出脚底 = 摔倒"这件事，**用最简单的几何让你亲手算一遍**。下面给**物理直觉 + 答案思路**（具体代数 notebook 会让你填）：

- **(a) 画三个自由体图**：bob 受重力 $mg$ + 腿的拉力；腿是**二力杆**（无质量、两端销，力沿腿方向）；脚受腿的力 + 地面在 H 和 T 的两个**垂直反力** $N_H, N_T$（题设地面力只在脚跟脚尖，且无踝力矩时脚本身无力矩源）。
  **人话**：把"身体—腿—脚"拆成三块，每块单独画"谁在推/拉它"。
- **(b) $\theta=\pi/2+10^{-3}$ 稳定吗？** $\theta=\pi/2$ 是腿**竖直**，bob 在 P 正上方。稍微偏一点点（$10^{-3}$），**没有踝力矩、没有恢复机制**，bob 会**继续倒**——**不稳定**（就像倒立摆竖直朝上的那个不稳定平衡点，和第3章一模一样）。
- **(c) 算 ZMP 关于 $\theta$ 的函数**：ZMP 是地面反力的"加权中心"。利用"绕 ZMP 力矩 = 0"或"$N_H,N_T$ 的力矩平衡"，可把 ZMP 的水平位置 $x_{ZMP}$ 写成 $\theta$ 和 $m,g,h,l,L_1,L_2$ 的函数。**直觉**：bob 越往一边偏，ZMP 越往那一边滑。
- **(d.i) ZMP 何时到脚尖？** 令 $x_{ZMP}=L_2$（踝到脚尖的距离），解出 $\theta$。**人话**：身体前倾到"压力全压到脚尖"的临界角。
- **(d.ii) 脚跟何时抬起？** 当 $N_H=0$（脚跟不再受力）——**这正好和"ZMP 到脚尖"是同一时刻**！（ZMP 跑到脚尖 = 脚跟没压力 = 脚跟要抬。）**这是一个漂亮的等价关系，务必体会。**
- **(e) 现在踝有力矩，控制器让 $\ddot\theta=0$（腿角加速度=0），机器人快摔了，说 $N_H,N_T$**：快摔 = 即将绕某点翻倒 = **一个反力趋于 0**。若往前摔，$N_H\to 0$，全部重量压到脚尖 $N_T$；反之亦然。**人话**：要摔的那一刻，你"踮脚"或"翘脚尖"，一只脚底压力归零。
- **(f) 不摔倒的 $\theta$ 范围**：要求 **ZMP 始终在 $[-L_1,\, L_2]$ 内**（脚跟到脚尖之间），即 $N_H\ge0$ 且 $N_T\ge0$。解出 $\theta$ 的上下界，用 $m,h,l,L_1,L_2$ 表示。**人话**：身体能前倾/后仰的"安全角度窗口"。
- **(g) 设计脚，最大化"不摔的姿态范围"（踝力矩无限）**：
  - **(g.i) 更高还是更平的脚（$h$ 大/小）？** **更平（$h$ 小）更好**。因为 $h$ 越大，bob 偏一点产生的"翻倒力矩"越大（力臂大），ZMP 跑得越快，安全窗口越窄。**人话**：穿**厚底高跟**比穿**平底鞋**更容易崴/摔——踝越高越不稳。
  - **(g.ii) 更长还是更短的脚（$L_1+L_2$ 大/小）？** **更长更好**。脚越长，ZMP 能跑的"跑道"越长，安全窗口越宽。**人话**：**大脚板**比**小脚板**站得稳（这就是为什么雪鞋做得那么大）。
  - **(g.iii) 踝放哪？** **放中间**（$L_1=L_2$），让前后安全余量对称，最大化"双向"姿态范围。**人话**：踝关节装在脚掌**正中间**，前后能倾的幅度才均衡。
- **(h) 设计"只向前走"的脚，希望脚跟**更容易抬起**（踝力矩无限）**：向前走需要**脚跟能轻松离地**（蹬地迈步）。
  - **(h.i) 更高还是更平？** 这里和 (g) **相反**——**更高（$h$ 大）** 让同样的踝力矩产生更大的"撬脚跟"力矩，**脚跟更容易抬**，利于迈步。**人话**：想"踮脚起步"省力，踝高一点反而好撬。
  - **(h.ii)/(h.iii) 更长/更短 + 踝的位置**：要让**脚跟短、脚尖长**（$L_1$ 小、$L_2$ 大），并把踝**靠后**放——这样重心/力矩更容易把脚跟撬起，向前迈步更顺。（注：PDF 此处 (h.ii)(h.iii) 文字重复，疑为排版遗漏，我按"步长/脚长"与"踝位置"两个维度补全其物理意图，**以 notebook 标准答案为准**。）

> **本题的"啊哈时刻"**：(d) 让你亲眼看到 **"ZMP 到脚尖 ⟺ 脚跟抬起 ⟺ 即将摔倒"** 三者是**同一件事的三种说法**。理解了它，你就真正懂了"ZMP 在支撑多边形内 = 不摔"。

### 习题 5.3：用凸集图（GCS）做脚步规划

实现文献 [9] 的简化版：把脚步规划**表述成 GCS 上的最短路问题（SPP）**。相比 5.1 的 MIQP，**GCS 的凸松弛归约为线性规划（LP）**——**快得多、扩展性好得多**。

**先建立直觉**：5.1 的 MIP 慢，是因为"选石头"的 0/1 把问题搞成非凸。**GCS 的妙处**：把**每块石头看成一个"凸集节点"**，把**"从石头 i 迈到石头 j"看成一条"边"**，**边上的连续变量 = 在 i 的落点 + 在 j 的落点**，**边的约束 = 这一步的运动学可行（够得着、不超步长）**，**边的代价 = 1（每迈一步计 1）**。于是"最少步数跳过去" = **图上最短路**，而每个节点/边内部是**凸的**，松弛后是 **LP**。

- **(a) 构造顶点**：每块踏脚石 = 一个 GCS 顶点，顶点携带的凸集 = 石头的几何区域（脚能落的范围）。
- **(b) 构造有效边**：若从石头 i **一步能迈到**石头 j（距离在腿的可达范围内），就连一条边 i→j。
- **(c) 边约束**：在该边上加**运动学约束**——i 的落点和 j 的落点之间距离 $\le L_{\max}$、落在各自凸集内等。
- **(d) 边代价**：每条边代价 = 1，目标 = **最小化总步数**（最短路 = 最少步）。

**类比**：5.1 像"在迷宫里**逐个试**每条路通不通"（MIP 暴力但慢）；5.3 像"先把迷宫**画成地铁图**（站=石头，线=能直达），再用**最短路算法**（Dijkstra/ LP）一秒算出最少换乘"——**GCS 把'几何可行性'藏进了'图的边'里，把组合爆炸变成了图搜索**。这正是 [9]（Marcucci 等，"Shortest Paths in Graphs of Convex Sets"）的核心贡献。

## 增补一：把"还不够通俗"的 4 个概念，各加一个类比

1. **仿射（affine）= 线性 + 常数**：$y=Ax+b$。为什么优化爱它？因为**它的图像是一条直线/平面**，没有弯，勺子（优化器）不会卡。**方程(5) 在 $z-z_{cp}$ 固定时对 $x_{cp}$ 是仿射的** → 所以 ZMP 规划能"实时算"。
   **类比**：线性 = 平路；仿射 = 平路但起点不在原点（有个坡底偏移 $b$）；非线性 = 山路十八弯。优化器走平路最快。

2. **凸包 / 支撑多边形**：所有接触点围成的"最小凸区域"。
   **类比**：把几根钉子钉在木板上，**用橡皮筋把它们全圈起来**，橡皮筋围成的形状就是凸包。**CoP 必须在这根橡皮筋里面**——你双脚站立，橡皮筋就是两脚外缘连成的四边形。

3. **质心动量矩阵 $A(q)$**：它把"关节速度 $\dot q$"映射成"全身空间动量"。
   **类比**：它像一张**"关节→全身动量"的汇率表**——你动哪个关节、动多快，按这张表换算成"整个身体的动量怎么变"。表的内容**随姿势 $q$ 变**（蹲着和站着，挥手臂对全身的影响不同）。

4. **capturability（可捕获性，[7]）**：从当前状态，**最少迈几步、踩到哪，能停下不摔**。
   **类比**：你**骑自行车冲下坡**，前面是悬崖。"可捕获性"回答的是：**"以我现在这个速度，最少还要多少米/拐几个弯，才能刹停而不掉下去？"** 把这个"安全刹车区"算出来，机器人就知道"现在推我这一下，我还救不救得回来"。

### 实验 1：ZMP 方程的数值验证 —— 纯 NumPy（可跑，最有教学价值）

这段**亲手验证方程(5)**：给定一条质心轨迹，算出"对应的 CoP 在哪"，并检查"CoP 是否在脚底内"。

```python
import numpy as np
import matplotlib.pyplot as plt

g = 9.81
z_com = 1.0          # 质心高度（恒定，z-z_cp = 1.0，假设地面 z_cp=0）
foot_x = 0.0         # 脚中心
foot_half = 0.12     # 脚掌半长（CoP 必须落在 [foot_x-0.12, foot_x+0.12]）

# 模拟"质心像倒立摆一样往前倒"：x(t) 缓慢偏离脚中心
t = np.linspace(0, 1.5, 300)
x_com = 0.02 * np.sinh(t)          # 质心水平位置（越来越偏）
# 数值二阶导得 ẍ
xdd = np.gradient(np.gradient(x_com, t), t)

# 由 ZMP 方程(5) 反解 CoP：  ẍ = g*(x - x_cp)/(z - z_cp)  =>  x_cp = x - ẍ*(z-z_cp)/g
x_cp = x_com - xdd * (z_com - 0.0) / g

plt.figure(figsize=(8,4))
plt.plot(t, x_com, label='质心 x')
plt.plot(t, x_cp,  label='CoP / ZMP (由方程5反解)')
plt.axhline( foot_x+foot_half, color='r', ls='--', label='脚尖边界')
plt.axhline( foot_x-foot_half, color='r', ls='--', label='脚跟边界')
plt.axhline( foot_x, color='k', ls=':',  label='脚中心')
plt.xlabel('时间'); plt.ylabel('水平位置 (m)'); plt.legend(); plt.grid(alpha=.3)
plt.title('ZMP方程验证：质心越偏/加速越猛，CoP越往脚边跑 → 跑出=摔'); plt.show()

# 观察：当 x_cp 触碰红线，就是"即将抬脚跟/摔倒"的临界 —— 对应习题5.2的(d)/(e)！
```

**你会看到**：质心一开始在脚中心上方，CoP 也在中心；随着质心加速前倾，**CoP 一路滑向脚尖红线**——**这正是"身体前倾→压力前移→脚跟要抬"的全过程**，和习题5.2 完全对上。**方程(5) 不再是纸上的符号，而是你眼前"压力在脚底滑动"的动画。**

### 实验 4：习题5.1 的 MIQP 脚步规划骨架（对应 a–d）

```python
# 用 Drake 的 MathematicalProgram 表达"跳房子"。变量/约束与习题一一对应。
from pydrake.solvers import MathematicalProgram, SolverOptions
import numpy as np

prog = MathematicalProgram()
N_step, N_stone = 4, 6
stones = np.array([[0.3,0.6,0.9,1.2,1.5,1.8],   # 每块石头的 x 中心
                   [0.0]*6]).T                    # y 略
half   = 0.10                                     # 石头半宽
Lmax   = 0.5                                      # (a) 最大步长

# 连续变量：每步脚落点 p[k] (这里简化为标量 x)
p = prog.NewContinuousVariables(N_step, "p")
# 整数变量：z[k,j] = 第 k 步是否选第 j 块石头  -> 对应 (b)(c)
z = prog.NewBinaryVariables(N_step, N_stone, "z")

for k in range(N_step):
    prog.AddConstraint(sum(z[k,j] for j in range(N_stone)) == 1)   # (c) 每步恰好选一块
    for j in range(N_stone):
        # 大M：若选石头 j，则 p[k] 落在石头 j 的框内  -> (b) 一脚一石的落地体现
        M = 10.0
        prog.AddConstraint(p[k] <= stones[j,0]+half + M*(1-z[k,j]))
        prog.AddConstraint(p[k] >= stones[j,0]-half - M*(1-z[k,j]))

for k in range(N_step-1):
    prog.AddConstraint(p[k+1] - p[k] <= Lmax)                       # (a) 步长上限
    prog.AddConstraint(p[k] - p[k+1] <= Lmax)

prog.AddQuadraticCost(np.eye(N_step-1), 0.0,                        # (d) 最小化步长平方和
                      p[1:]-p[:-1])   # 实际写法用 AddQuadraticErrorCost 等，此处示意

# 求解：MIP 求解器（如 Gurobi/CPLEX/SCS-branch）会同时决定"选哪块石头(z)"和"落在哪(p)"
```

**人话**：`z` 管"跳哪块石头"（离散），`p` 管"落在石头内哪"（连续），**大 M** 把"选了才生效"的逻辑接起来，**(a)–(d)** 四条正好对应习题四问。**跑通它，你就懂了"为什么脚步规划是混合整数问题"。**

### 实验 5：习题5.3 的 GCS 脚步规划骨架（对应 a–d，对比实验4 看"快在哪"）

```python
from pydrake.geometry.optimization import GraphOfConvexSets, HPolyhedron
import numpy as np

gcs = GraphOfConvexSets()
half, Lmax = 0.10, 0.5
stones_x = [0.3,0.6,0.9,1.2,1.5,1.8]

# (a) 顶点 = 石头（凸集 = 石头区域）
verts = []
for sx in stones_x:
    A = np.array([[1],[-1]]); b = np.array([sx+half, -(sx-half)])   # |x-sx|<=half
    verts.append(gcs.AddVertex(HPolyhedron(A, b), name=f"stone@{sx}"))

# (b) 边 = "一步能迈到"；(c) 边约束 = 步长可行；(d) 边代价 = 1（最少步）
for i, u in enumerate(verts):
    for j, v in enumerate(verts):
        if i == j: continue
        if abs(stones_x[j]-stones_x[i]) <= Lmax:                    # 够得着才连边
            e = gcs.AddEdge(u, v)
            xu = e.AddVariable("xu"); xv = e.AddVariable("xv")      # 边上的连续落点
            e.AddConstraint(xv - xu <= Lmax)                        # (c) 运动学
            e.AddConstraint(xu - xv <= Lmax)
            e.AddCost(1.0)                                          # (d) 每步计1 -> 最短路=最少步

result = gcs.SolveShortestPath(source=verts[0], target=verts[-1])   # 凸松弛 -> LP，飞快
```

**对比实验4**：同样"跳过去"，**MIQP 要分支定界（慢）**，**GCS 把组合藏进图、松弛成 LP（快）**。**这就是 [9] 的意义，也是作者把它单列一题的原因。**

### 实验 6：习题5.2 的 ZMP 解析 + 数值验证（可跑，把"啊哈时刻"做实）

```python
import numpy as np
import matplotlib.pyplot as plt
m,g,l,h,L1,L2 = 1.0,9.81,1.0,0.08,0.10,0.12   # 腿长l, 脚高h, 踝到跟L1, 踝到尖L2

# 简化模型：bob 在 P 上方 l 处，腿与竖直成角 phi=θ-π/2（θ≈π/2 时 phi≈0）
# 绕 P 取矩：地面反力 N_H(跟),N_T(尖) 满足  N_H+N_T=mg，且对 P 力矩平衡
# 设 bob 水平偏移 = l*sin(phi)；脚底对 P 的力臂：跟=-L1, 尖=+L2；脚高 h 产生水平力偶（无踝矩时由N_H,N_T差提供）
def reactions(phi):
    dx = l*np.sin(phi)                 # bob 相对 P 的水平偏移
    # 对 P 取矩（忽略腿/脚质量）：N_T*L2 - N_H*L1 - mg*dx = 0  且 N_H+N_T=mg
    # 解：
    N_T = (mg*dx + mg*L1)/(L1+L2)
    N_H = mg - N_T
    return N_H, N_T

def zmp_x(phi):
    N_H,N_T = reactions(phi)
    if N_H+N_T <= 0: return np.nan
    # ZMP = 反力加权中心（以踝P为原点，跟=-L1，尖=+L2）
    return (N_T*L2 + N_H*(-L1))/(N_H+N_T)

phis = np.linspace(-0.3, 0.3, 400)
zx   = np.array([zmp_x(p) for p in phis])
plt.figure(); plt.plot(np.degrees(phis+np.pi/2), zx)
plt.axhline( L2, color='r', ls='--', label='脚尖 (ZMP到此=跟抬)')
plt.axhline(-L1, color='g', ls='--', label='脚跟 (ZMP到此=尖抬)')
plt.xlabel('θ (deg)'); plt.ylabel('ZMP 水平位置 (m)'); plt.legend(); plt.grid(alpha=.3)
plt.title('习题5.2：ZMP 随 θ 滑动；碰红线=临界摔倒（d/e 的可视化）'); plt.show()

# 验证 (d.i)/(d.ii) 等价：找 ZMP=L2 的 phi -> 此时 N_H 应≈0
phi_crit = phis[np.argmin(np.abs(zx-L2))]
N_H,N_T  = reactions(phi_crit)
print("ZMP到脚尖时 θ≈%.2f°, 此时 N_H=%.4f (应≈0 => 脚跟抬起，二者等价!)" % (np.degrees(phi_crit+np.pi/2), N_H))
```

**你会看到**：ZMP 曲线**单调**地从脚跟滑向脚尖；**当它碰到脚尖红线的瞬间，$N_H$ 打印出来≈0**——**亲手验证了"ZMP 到脚尖 ⟺ 脚跟抬起 ⟺ 临界摔倒"**。再调 `h`（脚高）和 `L1+L2`（脚长），看安全窗口怎么变，**习题5.2 的 (g) 设计直觉就长进肌肉里了**。

1. **脚 = 可移动但挑剔的推力器**：行走的难，**全在"脚怎么接触地面"**（只能踩地、只能推不能拉、只能落在摩擦锥和指定区域里，还带"抬不抬脚"的离散决策）；而**身体本身的动力学，简单得像个航天器/倒立摆**——这就是为什么"简单模型"在复杂机器人上好使。
