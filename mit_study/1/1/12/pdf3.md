# 线性二次型调节器（LQR）：机器人的“完美”肌肉记忆
## 1. 引言：为什么 LQR 如此重要？
在上一章我们讲过“动态规划”，那是一个通用的、但计算起来非常困难的框架。但在一个特殊的“甜点区”里，问题变得既简单又完美。这个甜点区就是：
1.  **系统是线性的**（比如小角度摆动的单摆，或者工作点附近的任何机器人）。
2.  **代价是二次的**（误差越大，惩罚呈平方级增长；用力越猛，惩罚也呈平方级增长）。
在这个假设下，我们得到了**LQR（Linear Quadratic Regulator）**。它是控制领域最著名、应用最广泛的结果。
**通俗类比**：
想象你在开车。
*   **非线性控制**：像是赛车手在漂移过弯，需要极其复杂的直觉和技巧。
*   **LQR**：像是老司机在高速公路上保持车道。车稍微偏左，你就往右打一点点方向；偏得越多，打得越多。这种“温和的、线性的、基于误差的修正”，就是 LQR 的精髓。
---
## 2. 基础推导：无限视界 LQR
我们要解决的问题是：给定一个线性系统 $\dot{x} = Ax + Bu$，如何设计控制 $u$，让长期的代价 $J = \int (x^T Q x + u^T R u) dt$ 最小？
### 2.1 核心直觉：猜测答案的形式
我们在上一章学过 HJB 方程。对于这个问题，我们不需要死算，而是可以“猜”答案。
*   因为系统是线性的（$\dot{x}$ 是 $x$ 和 $u$ 的一次方）。
*   因为代价是二次的（$x^2, u^2$）。
*   所以，**未来的总代价（最优价值函数）也应该是二次型**的。
我们假设最优的代价函数长这样：$J^*(x) = x^T S x$。
这里的 $S$ 是一个对称矩阵。你可以把它想象成一张**“地形图”**：$x$ 是你的位置，$J^*$ 是那个位置的海拔高度。我们的目标就是“下山”。
### 2.2 最优策略：最陡峭的下降
根据 HJB 方程，最优控制 $u^*$ 应该让“当下的付出 + 未来的代价”最小。
通过求导（寻找函数的最低点），我们得到了那个著名的公式：
$$ u^* = -R^{-1} B^T S x = -Kx $$
**这是什么意思？**
*   $Sx$：这是代价函数 $J$ 关于 $x$ 的梯度，也就是地形最陡峭的方向。
*   $B^T$：这是投影。因为我们的控制输入 $u$ 可能只能影响状态的一部分（比如推力只能改变速度，不能直接改变位置），我们需要把梯度投影到“我们能控制”的方向上。
*   $R^{-1}$：这是缩放。如果 $R$ 很大（说明动作很贵，我们不想太用力），就会把控制量缩小。
**结论**：最优控制就是**状态的一个线性反馈**。只要知道状态 $x$，乘以一个常数矩阵 $K$，就能得到最优动作。
### 2.3 黎卡提方程（Riccati Equation）
那矩阵 $S$ 怎么求呢？把上面的 $u^*$ 代回 HJB 方程，经过整理，我们会得到一个关于 $S$ 的方程：
$$ 0 = SA + A^T S - S B R^{-1} B^T S + Q $$
这就是**代数黎卡提方程（ARE）**。它看起来很吓人，但在数学上，只要系统是“可稳定”的，它就有唯一的正定解。计算机解这个方程非常快。
**代码实践（Example 8.1）**：
在 Drake 中，这只有两行代码：
```python
(K, S) = LinearQuadraticRegulator(A, B, Q, R)
```
*   **K**：就是你的控制器增益。你用 $u = -Kx$ 就能控制机器人。
*   **S**：就是那张“地形图”。它可以告诉你从当前状态到达目标大概需要多少“代价”。

## 3. 局部稳定非线性系统：把曲线拉直
我们的机器人通常是非线性的（比如大角度摆动的 Acrobot）。LQR 还能用吗？
**能！** 这就是**线性化**的威力。
### 3.1 原理
想象一个崎岖的山路（非线性系统）。如果你只盯着脚下的一小块地方看，那块地其实几乎是平的（线性的）。
*   我们在平衡点（比如单摆倒立的位置）附近。
*   定义误差 $\bar{x} = x - x_{target}$。
*   把非线性方程 $f(x, u)$ 在目标点做泰勒展开，只保留一次项，得到线性方程 $\dot{\bar{x}} = A\bar{x} + B\bar{u}$。
*   对这个线性系统用 LQR，得到 $u$。
*   实际控制时，用 $u = u_{equilibrium} - K(x - x_{target})$。
**代码实践（Example 8.2）**：
Drake 极其强大，它甚至不需要你手动算 $A$ 和 $B$ 矩阵。你直接把非线性系统丢进去：
```python
controller = LinearQuadraticRegulator(nonlinear_system, context, Q, R)
```
Drake 会自动使用“自动微分”技术帮你算出 $A$ 和 $B$。这意味着同一套代码，既可以控制双积分器，也可以控制四旋翼，完全不需要改推导过程！

## 4. 有限视界 LQR：有“截止日期”的任务
之前的 LQR 假设时间无穷长。但很多时候，我们只关心未来 10 秒，或者特别强调“最后那一刻”要停在准地方。
### 4.1 时间依赖的代价函数
现在我们的代价函数 $S$ 不再是常数，而是随时间变化的 $S(t)$。
*   **终端代价 $Q_f$**：这代表你在最后时刻 $t_f$ 对误差的容忍度。如果你设得非常大，意味着“死也要死在终点上”。
*   **微分黎卡提方程（DRE）**：$S(t)$ 需要通过解一个微分方程来得到。我们要从终点 $t_f$ 倒着往回算。
### 4.2 直观理解
*   在任务刚开始时（$t=0$），$S(0)$ 的值通常比较平缓。
*   随着时间接近终点（$t \to t_f$），$S(t)$ 会迅速变大，变得越来越陡峭。
*   这意味着：**离终点越近，控制器的反应越激烈，因为时间不多了！**
### 4.3 轨迹跟踪
LQR 不仅能控制到 0，还能跟踪一条随时间变化的轨迹 $x_d(t)$。
比如让机械臂画一个圆。我们把“圆上的点”当作瞬时的目标 0。LQR 算出的力会试图把机械臂拉回到圆周上。

## 5. 变体与扩展：LQR 的七十二变
### 5.1 离散时间 LQR
计算机是数字的，控制是按周期采样的（比如每 0.01 秒一次）。
离散版的 LQR 有一个对应的**差分黎卡提方程**。
**与强化学习的联系**：文档中 Example 8.4 提到了“拟合价值迭代”。
*   这其实就是用强化学习的方法来解 LQR。
*   我们不知道 $S$ 矩阵是多少，我们猜一个，然后通过采样的数据来修正它。
*   **关键点**：如果系统不稳定，这种“猜”的方法可能会发散（猜得越来越离谱）。只有当系统是稳定的时候，它才会收敛到真正的 $S$。
### 5.2 带约束的 LQR
标准的 LQR 不允许你说“力不能超过 10 牛顿”。
一旦加上这种约束，问题就没有解析解了。这直接引出了**MPC（模型预测控制）**：每一步都解一个优化问题，算出未来一段时间的最优控制，只执行第一步，下一步再重新算。
### 5.3 流形上的 LQR（Segway 例子）
这是一个非常经典的机器人学难点。
**场景**：平衡一个 Segway（两轮自平衡车）。轮子在地面滚动，这是一个**非完整约束**（不能侧向滑移）。
如果直接线性化整个系统，你会发现有些状态（比如侧向位置）是不可控的，LQR 会报错。
**解法**：投影法。
*   找到约束矩阵 $F$，把状态空间分成“允许的方向”和“禁止的方向”。
*   只在“允许的方向”（零空间）里设计控制器。
*   **代码实践（Example 8.5）**：在代码中，我们不直接控制球的位置 $x$ 和角度 $\theta$，而是构建一个投影矩阵 $P$，把模型投影到只包含滚动自由度的空间里，然后在这个降维的空间里解 LQR。
### 5.4 隐式形式
有些系统的状态 $x$ 之间不是独立的（比如多体动力学中的广义坐标）。我们用 $E \dot{x} = Ax + Bu$ 来描述。这需要用到“广义黎卡提方程”。
### 5.5 系统级综合
这是一个比较高级的视角。
通常我们求 $u = Kx$，这在数学上是非凸的（$K$ 和 $x$ 乘在一起）。
**技巧**：如果我们把控制量重新写成初始状态 $x_0$ 的函数：$u[n] = \tilde{K}_n x_0$。这时候，优化问题就变成了凸优化（二次规划）。
**意义**：这使得我们可以同时优化很多控制器，或者在控制器上加上稀疏性约束（比如“这个电机绝对不要动”）。

## 6. 深度实践与代码解析
为了让你真正掌握，我们对文档中的关键代码和概念进行深度剖析。
### 实践一：双积分器的 LQR（Example 8.1）
这是最基础的实验。
*   **系统**：$A = [[0, 1], [0, 0]]$。这意味着状态是 $[位置, 速度]$。位置的导数是速度，速度的导数是加速度（由控制 $u$ 决定）。
*   **代码**：
    ```python
    Q = np.eye(2) # 位置和速度的误差都很重要
    R = np.eye(1) # 不太介意用力大一点
    (K, S) = LinearQuadraticRegulator(A, B, Q, R)
    ```
*   **结果**：你会得到 $K = [1, \sqrt{3}]$。这意味着控制律是 $u = -1 \cdot x - 1.732 \cdot \dot{x}$。
*   **物理意义**：这其实就是一个完美的 PD 控制器！LQR 告诉了我们 P 和 D 应该选多少才是数学上最优的。
### 实践二：处理数值稳定性
文档中提到了“平方根形式”。
*   **问题**：在计算机里，由于浮点数精度误差，解微分方程时，矩阵 $S(t)$ 可能会失去对称性或正定性（比如变成 -0.0000001），导致控制器崩溃。
*   **解法**：不解 $S$，而是解 $P$，其中 $S = P P^T$。就像开平方根一样，这保证了 $S$ 永远是正的。
### 实践三：Segway 平衡（Example 8.5）
这是文档中最复杂的代码示例之一。
*   **物理模型**：球在地面滚。这里有 $x = -r \theta$ 的约束。
*   **难点**：直接对 $[x, z, \theta_{ball}, \theta_{body}]$ 求导，会发现矩阵是奇异的（不可逆）。
*   **操作**：
    1.  构造约束矩阵 $F = [[1, r, 0, 0], ...]$。这代表 $x + r\theta = 0$。
    2.  计算 $P$ 矩阵（零空间基）。$P$ 的每一列都是一个“合法的动作方向”。
    3.  把系统矩阵 $A, B$ 投影：$A_{proj} = P A P^T$, $B_{proj} = P B$。
    4.  对投影后的矩阵求 LQR。
*   **实验提示**：如果你自己在写代码，一定要检查 $F$ 矩阵是否正确。如果约束写错了，投影出来的空间就是错的，车就会乱跑。
