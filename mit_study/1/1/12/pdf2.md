## 0. 开篇：从"算一条路"到"搜一条路"

### 0.1 一句话概括

> **当障碍复杂、代价非凸、维度又高时，别用优化"算"路径，也别用网格"铺"空间——改用"随机撒点 + 连边"把连续空间变成图，再用图搜索（A\* 那一套）在图上找路。这就是基于采样的运动规划。**

### 0.2 作者开场白的逐句翻译

**第一层：motion planning 是个大词，本章只补"搜索"这一块。**
> "motion planning"是个**相当通用**的词，**几乎肯定涵盖**我们已经讲过的动态规划、反馈设计、轨迹优化。**但是**，还有一批我们**没讲过**的算法和思想，它们**从"把运动规划表述成一个搜索问题"这个想法里长出来**——比如在**一张大到内存装不下的图**里，搜一条从起点到目标的路。

**类比（全章总纲，请刻进脑子）**：
- **轨迹优化（第10章）** = 你站在迷宫入口，**闭眼用微积分"算"出一条光滑曲线**穿过去——迷宫简单时算得又快又漂亮，**但迷宫一复杂，你的"算"会卡在某个死胡同的局部最优里**。
- **基于采样的规划（本章）** = 你**不闭眼算**，你**往迷宫里随机撒一把荧光粉（采样点）**，**把挨得近、中间没墙的粉点用线连起来**，连成一张"**荧光地铁图**"，然后**用导航软件（图搜索）在图上找路**。**迷宫越怪，这招越稳**——因为它不依赖"地形光滑"，只依赖"能不能连边"。

**第二层：为什么需要随机采样？因为机器人活在连续空间。**
> 为了处理机器人里**常见的连续域**，这些算法**常常依赖随机采样**。

**第三层：本章算法在什么时候最值钱？**
> 对机器人来说，当**规划问题几何上复杂**（如机器人在 3D 里绕障碍移动），或**优化景观非常非凸**时，它们会**特别有价值**——**因为这些正是我们之前学的非线性轨迹优化会因局部极小而"惨败"的问题**。

**第四层：本章的真正主题 = 让"老算法"适配"动力学"。**
> 这些算法**很多最初是为离散或纯运动学规划问题开发的**；**本章的一大主题**，将是**让它们能用于带动力学约束的系统（包括欠驱动系统）的"改造"**。

**人话**：原始的 PRM/RRT 只管"**位置能不能连一条无碰撞的线**"（运动学），**不管"以这个速度、这个加速度能不能真的开过去"**（动力学）。**让采样规划"懂物理"，是本章的硬核部分**（12.3.1 的 kinodynamic-RRT、LQR-RRT 等）。

**第五层：参考书。**
> [1]（LaValle 的《Planning Algorithms》）是关于规划算法（尤其运动规划算法）**非常好**的一本书。

## 1. 大规模增量搜索（12.1）—— 在"装不下的图"里找路

### 1.1 一段 AI 史：从"背知识"到"会搜索"

> 几十年来，许多 AI 研究者相信，造智能机器的路 = **收集庞大的知识本体（ontologies）**，然后**做极高效的搜索**。这段"传奇历史"里的著名例子包括：**Samuel 的跳棋程序、自动定理证明、Cyc、下国际象棋的 Deep Blue**。

**类比**：早期的 AI 思路 = "**把人类所有知识编成一本超厚词典，再写个超快的查词典程序**"。后来大家发现，**光有词典不够，"会查、会搜、会推"才是智能的核心**。

> 确实，**得益于几十年的研究**，AI 里的规划算法也**扩展到了令人印象深刻的高度**，**高效利用启发式（heuristics）和分解（factorizations）** 去解**规模惊人**的规划实例。**自 1998 年起**，**国际自动规划与调度会议（ICAPS）** 一直举办**常规规划竞赛**，**帮助固化了问题规格格式、并对最前沿水平做了基准测试**。

### 1.2 这些算法是"离散/逻辑"的——和我们第7章的图搜索是亲戚

> 这些算法**主要聚焦逻辑/离散规划**（虽然它们**支持"objects（物体）"**，所以**能有某种"开放词汇"**）。**在本笔记的语境里**，这些方法和我们**为引入"作为图搜索的动态规划"而讨论过的"离散状态、离散动作、离散时间"规划问题**最密切相关。

**人话**：ICAPS 那一派处理的是"**把箱子从 A 搬到 B、先开门再拿钥匙**"这种**逻辑步骤**的规划；它的"图"是**状态=世界的一种摆法，边=一个动作**。**这和我们第7章 Grid World 的图搜索，骨子里是一回事**——只是 ICAPS 的图**大到离谱**。

### 1.3 关键转折：DP 算"全图"太亏，增量搜索只算"需要的部分"

> **动态规划是"解出每个状态的 cost-to-go"的高效算法**；**但如果我们只需要找一条从单个起点到目标的最优路径，我们也许能做得更好。**

**类比（这是理解"增量搜索"的钥匙，必懂）**：
- **DP / 值迭代** = 导航软件**事先把全城每个路口到公司的时间全算好存起来**——**信息最全，但城市一大，这张表内存装不下**。
- **增量搜索（A\*）** = 导航软件**不背全城**，它**从你家出发，一边查一边往公司方向"探"**，**只算它真正需要的那几个路口**——**图再大，它也不用把整张图塞进内存**。

> **尤其，为了扩展到超大规模规划实例，一个本质思想 = "增量"搜索（incremental search）**，它**能避免把整张（常常指数大、有时甚至无限的）图放进内存**。

### 1.4 可容许启发式（admissible heuristic）—— "乐观的直线距离"

> **不访问每个节点，也能保证找到最优路径吗？能！** 确实，**驱动这些增量算法的一个关键洞察 = 用"可容许启发式"引导搜索**——**一个保证"绝不高估 cost-to-go"的近似 cost-to-go**。

**绝佳的例子**：在**道路地图**上搜方向——**从起点到目标的欧氏距离（"直线飞过去的距离"，as the crow flies）**，**保证绝不高估真实的"走道路"的 cost-to-go**（因为你**走弯路一定比直线远**）。

**类比（"乐观估计"，必懂）**：
- 可容许启发式 $h̃(v)$ = **一个"永远乐观"的预估**："从 $v$ 到目标**至少**还要花这么多"。
- **直线距离**就是这种乐观预估：**真实路程只会更长，不会更短**。
- **为什么"乐观"这么重要**？因为**只要预估不夸大，A\* 就敢保证"我找到的第一条到目标的路，就是最优的"**——**它不会被一个"看起来近、其实是被高估骗了"的路带偏**。（后面会严格看到。）

> **也许利用这些启发式最著名的搜索算法 = A\*。** 在机器人里，我们**常用它的在线规划扩展**，如 **D\*** 和 **D\*-Lite**（**边跑边发现新障碍时，能"局部修补"之前的搜索，不用从头来**——像导航软件遇到封路时实时重算）。

### 1.5 Algorithm 12.1：离散 A\* —— 逐行翻译成人话

> A\* 算法解一张图上的最短路问题。图由**顶点 $V$**、**源顶点 $v_s$**、**目标顶点 $v_t$** 定义，**（带权）边**由一个函数 `GetSuccessors()` **隐式**定义——它返回**从 $v$ 可达的顶点集合**（**"隐式"= 边不预先存好，要用的时候现算**，这正是"不把整张图塞内存"的关键）。

**先定义一堆记号**：

| 记号 | 人话 |
|---|---|
| $g(v)$ | 从源 $v_s$ 到 $v$ 的**最优"已走代价"（cost-to-come）** |
| $h(v)$ | 从 $v$ 到目标 $v_t$ 的**最优"剩余代价"（cost-to-go）** |
| $f(v)=g(v)+h(v)$ | **经过 $v$ 的、受约束最优路径的代价**（已走 + 真剩余） |
| 路径 $p$ | 一串顶点（由图的边相连），**从 $v_s$ 开始** |
| $\tilde g(p)$ | **遍历路径 $p$ 的实际代价**（已走代价的"当前估计"） |
| $\tilde h(v)$ | **启发式近似的 cost-to-go**，$v$ 是 $p$ 的**最后一个顶点** |
| $\tilde f(p)=\tilde g(p)+\tilde h(v)$ | **"已走 + 乐观估剩余" = A\* 用来排优先级的分数** |

**可容许（admissible）的定义**：

$$\tilde h(v) \le h(v),\quad \forall v\in V$$

**人话**：**乐观估计 $\tilde h$ 处处不超过真剩余 $h$**——**"我估的剩余时间，永远 ≤ 真实剩余时间"**。

**算法本体（逐行翻译）**：

```
current path        p = [v_s]                 # 当前正在探的路，从源开始
"visited" dict      S = {v_s : p}             # 字典：记"到每个点，目前最好的路是哪条"
priority queue      Q.insert(p)  按最低 f̃ 排   # 优先队列：谁的 f̃ 小，谁先被探
while not Q.empty():
    p = Q.pop()                               # 取出 f̃ 最小的那条路
    u = p.last()                              # 看这条路走到哪了（末端节点 u）
    if u == v_t:  return p                    # 到目标了！返回这条路（保证最优，见下）
    for all v in GetSuccessors(u) where v ∉ p:   # 看 u 能去哪些"没在这条路上"的邻居（防绕圈）
        p' = Path(p, u, v)                    # 把 v 接上去，得到新路径 p'
        if v ∉ S  or  g̃(p') < g̃(S[v]):        # 若 v 没访问过，或这条新路比"记在册的到 v 的路"更便宜
            S[v] = p'                         #   更新"到 v 的最好路"
            Q.insert(p')                      #   把新路塞进队列，等以后探
return failure                                # 队列空了还没到目标 = 无路可走
```

**人话串起来**：A\* 维护一个"**待探路径的优先队列**"，**永远先探"已走 + 乐观估剩余"最小的那条**。每探到一个节点，**看它能不能到目标**；不能，就**把它的所有没绕圈的邻居接成新路，塞回队列**。同时用字典 $S$ 记"**到每个点，目前最便宜的路**"，**只有更便宜的新路才值得再探**（**剪掉那些"绕远到同一点"的烂路**）。

### 1.6 A\* 的"魔法性质"—— 为什么它既对又省

> **A\* 有一个非凡的性质**：**若 $\tilde h$ 可容许，则 A\* 永不扩展满足 $\tilde f(p) > f(v_s)$ 的路径。** 停下来品一品这句话！**若启发式恰好就是最优 cost-to-go，则 A\* 只访问那些"在最优路径上"的顶点！**

**人话（这是 A\* 最漂亮的地方，必懂）**：
- $f(v_s)$ = **最优路径的总代价**（因为 $g(v_s)=0$，$h(v_s)$=最优总代价）。
- A\* 保证：**任何"已走 + 乐观估剩余"超过最优总代价的路，它碰都不碰**——**因为它知道"这条路就算走完，也一定比最优差"**。
- **极端情况**：若你的启发式**准到等于真剩余**（$\tilde h=h$），那 A\* **一路直奔最优路径，一个废节点都不探**——**像开了天眼的导航**。

> **不幸的是，硬币的另一面**：**A\* 会扩展图里所有满足 $\tilde f(p) < f(v_s)$ 的路径。** **越强的启发式 → 越 performant / 越 scalable 的搜索。**

**人话**：**启发式越"准"（越接近真剩余、但仍不高估），被 $\tilde f < f(v_s)$ 这条线"漏进来"的废路就越少**——**所以"想个更好的乐观估计"是 A\* 提速的命门**。**直线距离**是个及格估计；**若你能算出"忽略某些障碍的最短路"当启发式，就更准、更快**。

### 1.7 两个该懂的性质：完备性 + 最优性

> 除了经验性能，关于增量规划算法，还有几个性质值得理解。

- **完备性（completeness）**：**若从起点到目标存在可行路径，算法保证能找到一条**。**人话**：**"有路就一定能找到"，不会漏**。
- **最优性（optimality，指返回解的最优性）**：**算法保证找到最优路径**。**人话**：**"找到的还是最好的那条"**。

> **A\* 算法两者兼具（既完备又最优）。**

### 1.8 另一种启发式：分解（factorization）

> 除了近似 cost-to-go，**还有大量其他启发式驱动着最前沿的大规模逻辑搜索算法**。**另一个重要的 = 分解（factorization）**。

**机器人例子**：考虑一个**要操作许多可能物体的机器人**——**先假设"操作物体 A"和"操作物体 B"互相独立**，**各自独立规划**，**然后只有当最优计划"碰巧让两个物体的路径相交"时，才回头修正计划**，**这是合理的**。

**类比（"先各管各，撞了再协调"，必懂）**：
- 你给一家人**规划周末行程**：**先假设爸爸、妈妈、孩子各玩各的**，分别排时间表（**分解成三个小问题，每个都好解**）。
- **排完一看**：**爸爸和妈妈"撞车"了**（同一时间要用同一辆车）→ **这时才回头协调这一个冲突**，**而不是从一开始就把"三人所有可能的组合"一起算**（那会爆炸）。
- **这就是 factorization**：**把大问题拆成独立小问题，只在"耦合真的发生"的地方付协调的代价**。

> **许多这类启发式在 Fast Downward 论文 [2] 里总结得很好**；**Fast Downward 多年来一直处于 ICAPS 规划竞赛的最前沿**。

### 1.9 深度学习也在用规划：MCTS、LLM

> **当今深度学习一些最瞩目的成功故事，仍然在用规划。** 例如：**DeepMind 的 AlphaGo 和 AlphaZero**，**把多年来在离散博弈里发展的规划算法——尤其是蒙特卡洛树搜索（MCTS）——与"以策略和价值函数形式存在的、学出来的启发式"结合起来**。

**人话**：AlphaGo **不是纯靠神经网络"直觉"下棋**，而是**神经网络给"哪步值得想"打分（学出来的启发式 $\tilde h$）+ MCTS 真的去"想几步"（搜索）**——**"直觉 + 搜索"双剑合璧**。**这正呼应了 1.6 的洞察**：**搜索快不快，全看启发式准不准；AlphaGo 用深度学习把启发式练得极准，于是搜索如虎添翼**。

> **如何把大语言模型（LLM）与规划连接起来、以支持更长程的推理，是一个极其活跃的研究领域。**

**人话**：LLM 擅长"一步接一步地说话"，但**容易在长链条推理上"说着说着就忘了初衷"**；**给它接一个规划器（像 A\*/搜索那样"先想好整条计划再执行"）**，有望补上这块短板——**这是当下 AI 的热门方向**。

## 2. 概率路线图 PRM（12.2）—— 离线撒点建"地铁图"，在线连起终点查 A\*

### 2.1 动机：怎么把 A\* 推广到连续空间？

> **我们怎么把 A\* 这种强大的增量算法，推广到连续域的运动规划？**

**老规矩：先从运动学问题入手。**
> **按这领域的惯例**，我们**先考虑运动学规划问题**；在这类问题里**我们只考虑位置（如构型 $q$），不考虑速度或加速度**。**最简单版本的问题**：**构型 $q_1$ 和 $q_2$ 之间任何无碰撞的路径，都算可行**。

**类比**：运动学规划 = "**只问'能不能画一条不撞墙的线连两点'，不管'以多快的速度、多大的加速度画'**"。**先解决这个简单版，再加物理**。

### 2.2 固定网格为什么不行？—— 引出"分辨率完备"

> **若我们选构型空间的一个固定离散化**（像我引入动态规划时用的那种网格），**那我们就会牺牲完备性（从而也牺牲最优性）**。例如：**构型空间里障碍之间可能有一条窄走廊**——**路径明明存在，却很容易"被固定网格漏掉"**（网格点没落在走廊里）。

**类比（网格漏走廊，必懂）**：
- 你用**粗渔网**捞鱼，**窄缝里的小鱼全漏了**——**鱼明明在，你的网眼太大没捞着**。
- 固定网格 = 粗渔网；**窄走廊 = 缝里的小鱼**。

> **所以很自然地，必须把离散化当成一个迭代过程**，**先分析"无限迭代极限下"规划器的完备性**。我们用**分辨率完备（resolution complete）** 这个词，描述**当分辨率任意细时完备**的算法。** invoking 一些小假设**（如**可行路径不是无限窄的**），**可以论证"一个不断增加分辨率、直到找到解（若存在）的算法，会在有限次迭代内终止"**。

**人话**：**分辨率完备 = "只要我把网眼织得足够细，就一定能捞到那条鱼"**——**前提是鱼不是"无限细"的（路径有一定宽度）**。**网格越细越能保证找到，但细到一定程度计算就爆炸**——**所以固定网格"理论上能完备，实际上不划算"**。

### 2.3 PRM：随机撒点 + 连边，出奇有效

> **更流行的是一个变体**：**实现起来更简单，实践中出奇有效**。**不用固定离散化**，而是**从构型空间上的均匀随机分布采样点**，**拒绝落在碰撞里的样本**。**我们可以给"任何'到它的直线无碰撞'的邻居"加边**。**这让我们能离线在构型空间上建一张"概率路线图（probabilistic roadmap）"** [3]。**在线**，**当给定一个新起点和一个新目标时**，我们**简单地把这两个点连到路线图上**，**然后在图上用 A\* 规划**。**这个算法在无限样本的极限下完备**；我们用**概率完备（probabilistically complete）** 这个词。

**类比（PRM 的两阶段 = "先建地铁图，再查路线"，必懂）**：
- **离线建图（BuildRoadmap）** = 城市规划局**往城里随机撒一万个候选地铁站**，**删掉落在河里/山里的**，**把"两站之间能直线修隧道（无碰撞）的"用轨道连起来**——**得到一张"地铁图"**。**这活儿只干一次，慢慢干没关系**。
- **在线查询（FindPath）** = 你**临时告诉它"我要从家到公司"**，它**把"家"和"公司"各连到最近的几个地铁站**，**然后在地铁图上跑 A\***——**秒出路线**。
- **概率完备** = "**撒的点越多，'漏掉可行路'的概率越低，趋于零**"——**不像分辨率完备那样"细到一定必找到"，而是"点越多越几乎一定找到"**。

### 2.4 Algorithm 12.2：PRM —— 逐行翻译

**离线阶段 `BuildRoadmap()`**：

```
V = {}, E = {}                                  # 顶点集、边集，先空
for k = 1 to K:                                 # 撒 K 个点
    do { q = UniformRandom() } until q 无碰撞     # 随机撒一个构型，撞墙就重撒，直到落在自由空间
    V.insert(q)                                 # 加入顶点集
    for all q in V:                             # 对每个顶点
        for all qn in NearestNeighbors(q, V):   #   看它的"近邻"们
            if {q, qn} 无碰撞:                    #   若两点间直线无碰撞
                E.insert({q, qn})               #     连一条边
return V, E
```

**在线阶段 `FindPath(V, E, q_s, q_t)`**：

```
V.insert(q_s)                                   # 把起点加进图
E.insert(q_s 到 V 的最短无碰撞路径)               # 把起点连到图（连边=一段无碰撞短路径）
V.insert(q_t)                                   # 把目标加进图
E.insert(V 到 q_t 的最短无碰撞路径)               # 把图连到目标
return DiscreteGraphSearch(V, E, q_s, q_t)      # 在图上跑离散图搜索（如 A*）
```

**人话**：**离线"撒点 + 连无碰撞的边"建图**；**在线"把起终点接进图 + 跑 A\*"**。**注意一个细节**：在线连起终点时，"连边"不是连一条直线，而是连"**到图里某个点的、最短的无碰撞路径**"——**因为起终点是临时的，得现算它到图的连接**。

### 2.5 PRM 的能力边界与工程细节

> **PRM 是个简单的想法，但实践中出奇有效——至少到，比方说，10 维。**

**人话**：**10 维构型空间**（如一个 7 自由度机械臂 + 几个关节）用网格根本没法铺（$k^{10}$ 爆炸），**但 PRM 撒点照样能玩**——**这就是采样相对网格的杀手锏**。

> **算法最贵的步骤 = 最近邻查询 + 碰撞检测查询**——**它们不仅在采样的顶点上调用，也在边上调用**。**候选边通常通过"沿边密集采样、做许多点碰撞检测"来查碰撞**，**但存在带更强保证的算法**（参 [4]）。

**类比**：建地铁图时，**最费时间的不是"画站"，而是"勘测两站之间能不能修隧道"**（碰撞检测）+ "**找出每个站最近的几个站**"（最近邻查询）。**这两件事被调用海量次**（每个点、每条候选边都要查），**是 PRM 的速度瓶颈**。

> **高效的 PRM 实现会优化这些查询，并在 CPU 或 GPU 上并行化它们。**

> **在 TRI（Toyota Research Institute），我们有优化的实现，打算在 Drake 里开源**——**但说实话，这个 issue 已经开了很久了！**（**作者自嘲：开源这事拖了很久**。）

### 2.6 Example 12.1：PRM 能把单摆 swing-up 起来吗？

> **Example 12.1 (How well would a PRM swing up a pendulum?)**

**人话（这是个"灵魂拷问"，必懂）**：单摆 swing-up 是个**动力学**问题——**它需要"先往后甩、攒够劲、再翻上去"**，**路径在"位置-速度"的相空间里**，**而且"能不能从 A 到 B"取决于速度/力矩，不只是位置**。**纯运动学 PRM 只看"位置能不能连直线"，根本不懂"甩"这回事**——**所以拿原始 PRM 去 swing-up 单摆，会失败或很别扭**。**这正是 12.3 要解决的："让采样规划懂动力学"**。**这个例子是个"钩子"，把你引向 RRT 和 kinodynamic 规划**。

### 2.7 12.2.1 获得平滑轨迹 —— 给 PRM 的"折线"抛光

> **即使是运动学规划，我们可能也想施加动力学约束**，**要求路径连续可微（到某阶）**，**并也许尊重速度、加速度或其他限制**。

**人话**：PRM 给你的路是**一堆直线段拼成的"折线"**——**机器人走到拐点要"急转弯"，速度/加速度瞬间跳变，物理上做不到/很伤机器**。**所以要把折线"抛光"成光滑曲线**。

**两条路**：
- **后处理 PRM 输出（Post-processing PRM outputs）**：**先拿 PRM 的折线当"骨架"，再用轨迹优化/样条把它磨光滑**（**折线给了优化器一个"好初猜"，避开局部极小**——**这正是采样 + 优化"强强联合"的典型套路**）。
- **用 GCS 做运动学轨迹优化（用采样生成区域）**：**用采样在自由空间里"圈出一块块凸区域"，喂给第10章的 GCS**，**让 GCS 在凸区域上直接优化出光滑轨迹**（**采样负责"探地形"，GCS 负责"在凸块里光滑地走"**）。

**类比**：PRM 折线 = **用直尺在地图上画的"之字形"路线**；抛光 = **拿曲线板把之字形描成"平滑的公路"**。**采样给"拓扑"（该左拐还是右拐），优化给"几何"（怎么拐得平滑）**。

## 3. 快速扩展随机树 RRT（12.3）—— 不建全图，朝空旷处"长树"

### 3.1 动机：PRM 想兼容动力学，于是引出 RRT

> **思考"如何扩展 PRM 以容纳动力学约束"，会把我们引向一个稍有不同的、同样极流行的算法——RRT。**

**人话**：PRM 是"**先撒一堆点、两两连边、建一张全图**"——**但带动力学时，"两点能不能连"不再是"直线无碰撞"那么简单，而是要"真的能开过去"**，**两两连边的代价太高**。**RRT 换了个思路**：**不建全图，只从起点"长一棵树"，让树朝目标方向、朝空旷处蔓延，长到目标就停**——**省掉了"建全图"的浪费**。

### 3.2 Example 12.2：一棵"随机树"的朴素算法（稻草人版）

> 记**装着树的数据结构**为 $T$。**算法非常简单**：

```
用起点初始化树：       T ← x_0
每次迭代：
    从 T 选一个随机节点   x_rand          # 在"已有的树节点"里随机挑一个
    从可行动作分布选随机动作 u_rand         # 随机挑一个动作
    计算动力学：         x_new = f(x_rand, u_rand)   # 从挑中的节点，用挑中的动作，走一步
    若 x_new ∈ G：       终止，找到解！      # 落进目标区域 = 成功
    否则把新节点加进树：   T ← x_new         # 没到目标，就把新节点挂到树上
```

**人话**：**每次"在树上随机抓一个节点 + 随机做一个动作 + 走一步 + 把落点挂回树上"**——**像一棵树在随机地"抽枝"**。**抽到目标区域就停**。

> **可以证明，这个算法其实是概率完备的。** **但是**，**若没有强启发式引导"该扩展哪些节点"，它可能极不高效。**

### 3.3 稻草人算法为什么烂？—— 节点全堆在一起

> **看一个简单例子**：考虑系统 $x[n]=u[n]$，$x\in\mathbb{R}^2$，$u_i\in[-1,1]\ \forall i$，**目标区域** $15\le x_i\le 20$。**我们从原点出发**，**目标区域如上**（即 $[15,20]^2$ 那个远处的方块）。

> **虽然这个"稻草人"算法概率完备，但它肯定不高效。** **扩展 1000 个节点后，树基本是"一堆节点点全叠在一起的一团糟"**（Figure 12.3/12.4 动画）。**我们离目标还远着呢，而这还是个特别简单的问题实例。**

**人话（请在这里停顿，理解"为什么烂"，必懂）**：
- 每步动作 $u\in[-1,1]^2$，**最多让状态挪 $\sqrt2$ 那么远**。
- 目标在 $[15,20]^2$，**离原点 $(0,0)$ 有十几格远**。
- 稻草人算法"**在树上随机抓节点 + 随机做动作**"——**因为树还小，抓到的节点几乎都在原点附近**，**随机动作又朝四面八方**，**于是 1000 步全在原点周围"原地踏步、互相叠"**，**根本没人朝远处的目标"定向生长"**。
- **结果**：**树长成了一团挤在原点的"毛球"，远处的目标区一片空白**。

**类比（醉汉原地转圈，必懂）**：
- 稻草人算法 = **一个醉汉被蒙着眼，每次"随机抓自己之前踩过的一个脚印、再随机迈一步"**——**他永远在自己脚边打转，走不到十米外的家**。
- **问题根子**：**它没有"朝没去过的地方探"的机制**——**不知道哪里是"空旷的、该去的"**。

### 3.4 关键诊断：我们丢了"标记已探索区域"的能力

> **生成一棵可行点树的想法，有明显优势**；**但似乎我们丢掉了"把某块空间区域标记为'已被充分探索'"的能力**。**看来，要让随机算法有效，我们至少需要某种启发式，去鼓励节点散开、探索空间。**

**人话（这是引出"标准 RRT"的临门一脚，必懂）**：
- 稻草人算法的病灶 = **它"在树上随机抓节点"**，**导致"已经被节点挤满的区域，还被反复抓、反复扩展"，而"空旷区域没人理"**。
- **解药** = **别在树上随机抓，而是"在空间里随机撒一个目标点 $q_{rand}$，然后让树里'离它最近的那个节点'朝它长一步"**。
- **为什么这能"鼓励散开"**？因为**空旷区域面积大**，**随机撒点"撒到空旷区附近"的概率高**，**而空旷区附近"树节点稀疏"，最近邻往往就是"边界上那个节点"**——**于是树被"拽着朝空旷处长"**。**这个机制有个漂亮的名字 = Voronoi 偏向（Voronoi bias）**：**树天然偏向"自己还没覆盖的区域"生长**——**这正是稻草人算法缺的那味药**。（**PDF 正文没点名 Voronoi，但"need heuristic to encourage spread"指的就是它**；我在增补里把它讲透，并在代码里实现标准 RRT。）

**类比（朝"空地"长树，必懂）**：
- 标准 RRT = **你蒙着眼，但每次"朝随机方向扔一块石头，听见石头落地的声音，就让离石头最近的那个同伴朝石头走一步"**——**石头常落在空地上，于是同伴们被"均匀地拽向四周的空地"，队伍迅速铺开**，**而不是挤成一团**。

> **Figure 12.3 / 12.4**：动画（PDF 为点击观看的动画占位）。**人话**：动画会给你看"稻草人树挤成一团" vs "标准 RRT 迅速铺满空间"的对比——**亲手跑一遍增补里的代码，比看动画更直观**。

### 3.5 12.3.1 带动力学的机器人的 RRT（占位标题 + 概念补充）

> **正文留白（占位标题）。**

**补充概念（kinodynamic RRT，必懂）**：
- **运动学 RRT** 的"连边/steer" = "**两点间画直线**"。
- **带动力学的 RRT（kinodynamic-RRT）** 的"steer" = "**从 $x_{near}$ 出发，真的用动力学 $f$ 积分（仿真）一步或一段，看能到哪**"——**因为"能不能从 A 到 B"现在取决于速度/力矩，不能画直线**。
- **具体做法**：在 $x_{near}$ 处，**要么用随机动作 $u$ 积分一步**（像稻草人但加了"朝 $q_{rand}$ 选最近邻"的引导），**要么解一个局部小优化/用 LQR 把 $x_{near}$ 朝 $q_{rand}$  steer 一段**（后者 = **LQR-RRT**，下面讲）。
- **这就是 12.0 说的"让采样规划懂物理"的核心改造**。

### 3.6 12.3.2 变体与扩展（占位标题 + 概念补充）

> **正文只列了名字（占位）。** 逐个补充：

- **RRT\***：**RRT + "重连（rewire）"**——**每加一个新节点 $x_{new}$，不仅把它挂到最近邻上，还"检查它附近的节点：若改认 $x_{new}$ 当爹更省钱，就改爹"**；**反过来也让 $x_{new}$ 挑一个"最省钱的爹"**。**结果**：**树随着采样增多，逐渐"自我优化"，收敛到最优路径**——**RRT 只概率完备，RRT\* 还渐近最优**。
- **RRT-sharp / RRTx**：**RRT\* 的改进版**——**RRTx 能在"环境变化/发现新障碍"时增量地修补树**（像 D\* 之于 A\*），**适合在线/动态环境**。
- **Kinodynamic-RRT\***：**把 RRT\* 的 rewire 搬到带动力学的设定**——**rewire 时"改爹"要真的能用动力学走通**，**更难但更强**。
- **LQR-RRT(\*)**：**steer 和 rewire 都用"局部 LQR 控制器"**——**用第8章的 LQR 把 $x_{near}$ 朝 $q_{rand}$ 稳稳地开一段**，**既懂动力学、又比"随机动作" steer 得更准更远**——**这是"采样规划 + 最优控制"的精华联姻**（呼应第10章的"漏斗/LQR-Trees"思想）。
- **Complexity bounds and dispersion limits（复杂度界与分散度极限）**：**理论分析**——**"撒 $N$ 个点，树离'铺满空间'还差多少（dispersion）？收敛到最优有多快？"**——**给 RRT/RRT\* 的"概率完备/渐近最优"配上"速率保证"**。

**类比**：
- **RRT** = "**先连通再说**"（找到一条路就满足）。
- **RRT\*** = "**连通后还不断优化**"（路越走越短，趋于最优）。
- **RRTx** = "**路修好后，遇到塌方还能局部抢修**"。
- **LQR-RRT** = "**不让新手司机乱 steer，派一个 LQR 老司机去开每一段**"。

## 4. 分解方法（12.4）—— 把自由空间切成"凸块"，喂给 GCS

### 4.1 单元分解（Cell decomposition，占位 + 补充）

> **正文留白（占位）。**

**补充概念**：**单元分解 = 把整个自由空间切成一块块"单元（cell）"**，**每个单元内部"怎么走都行"（如都是凸的）**，**然后只在"单元之间"建图搜索**——**把连续空间"粗粒化"成一张小图**。**精确单元分解**（如梯形分解）在 2D 多边形障碍下能精确切；**高维/复杂障碍下精确切太难**，于是用**近似分解**。

**类比**：**把一座城市切成一个个"街区"**，**街区内部随便走**，**规划时只考虑"从哪个街区到哪个街区"**——**问题规模瞬间缩小**。

### 4.2 复杂环境的近似分解：IRIS（占位 + 补充）

> **正文留白，只点名 IRIS。**

**补充概念（IRIS = Iterative Regional Inflation by Semidefinite programming，迭代半正定区域膨胀）**：
- **目标**：在**复杂（非凸、带障碍）的自由空间里**，**自动找出一块块"尽量大的凸多面体"**，**且这些凸块覆盖大部分自由空间**。
- **怎么做**：**从一个种子点出发，迭代地"膨胀"一个凸多面体**——**一边往外扩，一边用"到最近障碍的距离"当约束，保证凸块不碰障碍**——**用 SDP/凸优化反复扩，直到扩不动**。
- **为什么值钱**：**这些凸块正好能喂给第10章的 GCS**——**GCS 在"凸集图"上搜最短路**，**IRIS 负责"把非凸自由空间变成 GCS 能吃的一堆凸集"**。**这就是"采样/分解探地形 + GCS 凸优化走路"的完整流水线**（呼应 12.2.1 的"用采样生成区域 + GCS 轨迹优化"）。

**类比**：**IRIS = 在布满礁石的海里，用一个个"尽量大的圆形安全泳池"去覆盖所有能游泳的水域**；**GCS = 在这些泳池之间规划"从这池游到那池"的路线**。**礁石（障碍）把海切成非凸，但每个泳池是凸的——GCS 最爱凸**。

## 5. 习题 12.1：RRT 与 RRT\* 规划（逐题讲透 + 实现要点）

> **在这道练习里，我们为 RRT 写代码**。**在这个实现的基础上，我们还要实现 RRT\*——RRT 的一个"收敛到最优解"的变体**。**全部在 notebook 里完成**。

### (a) 实现 RRT

**实现要点（标准 RRT，含"朝随机样本找最近邻"的探索偏向）**：

```
T ← {x_0}                                  # 树从起点开始
for k = 1 to K:
    q_rand  ← UniformRandom(自由空间)        # ① 在空间里随机撒一个目标点（不是"在树上随机抓"！）
    x_near  ← NearestNeighbor(q_rand, T)     # ② 找树里离 q_rand 最近的节点（Voronoi 偏向的来源）
    x_new   ← Steer(x_near, q_rand)          # ③ 从 x_near 朝 q_rand 走一步（运动学=直线截断；动力学=积分/局部控制）
    if  Path(x_near, x_new) 无碰撞:           # ④ 这一段无碰撞才接受
        T.add_node(x_new); T.add_edge(x_near, x_new)
        if x_new ∈ 目标区域: return 回溯路径    # ⑤ 到目标，沿父指针回溯出路径
return failure
```

**人话**：**和稻草人算法的唯一、但致命的区别 = 第①②步**：**稻草人是"在树上随机抓节点"，标准 RRT 是"在空间随机撒点 + 找树里最近邻"**——**就这一步，把"挤成一团"变成了"迅速铺满"**。**Steer 在运动学下 = "朝 $q_{rand}$ 走，最多走一步长 $\epsilon$"**；**在动力学下 = "用 $f$ 积分/局部 LQR 朝 $q_{rand}$ 开一段"**。

### (b) 实现 RRT\*

**在 (a) 的基础上，加两件事（rewire）**：

```
... 得到 x_new 并挂到树上之后 ...
X_near ← Near(x_new, T, 半径 r)              # 找 x_new 附近的一圈节点
# ① 给 x_new 挑一个"最省钱的爹"
x_parent ← argmin_{x∈X_near} [ cost(x) + dist(x, x_new) ]   # 选"到 x_new 累计代价最小"的邻居当爹
重新把 x_new 的父边接到 x_parent
# ② 看 x_new 能不能当别人"更省的爹"（rewire）
for x in X_near:
    if cost(x_new) + dist(x_new, x) < cost(x):   # 若"经 x_new 到 x"比 x 现在的路更省
        把 x 的父边改接到 x_new                    # 改爹！
```

**人话**：**RRT 是"新节点随便认个最近的爹"；RRT\* 是"新节点在一圈邻居里挑最省的爹，并且反过来帮邻居们'优化爹'"**——**这一来一回的 rewire，让整棵树"越采样越省"，最终收敛到最优路径**。**$r$（near 半径）要随节点数慢慢缩小**（按 $\sqrt{\log n / n}$ 那一类公式），**才能保证渐近最优又不连太多边**。

**类比**：
- **RRT** = "**新搬来的住户，随便认最近的邻居当介绍人**"。
- **RRT\*** = "**新住户在一圈邻居里挑'人脉最通的'当介绍人，并且主动告诉其他邻居'以后找我办事更近'**"——**整个社区的人脉网越住越优化**。

## 增补一：把"还不够通俗"的 6 个概念，各加一个类比 / 澄清

1. **稻草人 RRT vs 标准 RRT 的本质区别（Voronoi 偏向，全章最该补的直觉）**：稻草人"**在树上均匀随机抓节点**" → 已密集的区域被抓的概率高 → **正反馈地更密集** → 挤成一团。标准 RRT "**在空间均匀随机撒 $q_{rand}$ + 找树中最近邻**" → **空旷区域面积大、撒中概率高、而那里树节点稀疏、最近邻就是边界节点** → 树被拽向空旷处 → **自动铺满**。这个"朝空旷长"的偏向，数学上等于"**每个树节点'吸引'它的 Voronoi  cell 里的随机样本**"，**cell 越大（越空旷）被抽中越频繁** → 故称 **Voronoi bias**。**这就是 PDF 那句"need a heuristic to encourage spread"的真正答案**。**代码里 `NearestNeighbor(q_rand, T)` 这一行，就是这味药**。
2. **resolution complete vs probabilistically complete**：前者 = "**网眼细到 $\epsilon$ 必捞到宽于 $\epsilon$ 的鱼**"（**确定性保证，靠"加细"**）；后者 = "**撒 $N$ 个点，漏鱼的概率 $\to 0$**"（**概率保证，靠"加多"**）。**PRM/RRT 是后者**——**理论上"极小概率还是漏"，但实践中 $N$ 一大就几乎不漏，且比"加细网格"省得多**。
3. **admissible heuristic 为什么保证 A\* 最优（一句话证明直觉）**：设最优代价 $C^*=f(v_s)$。A\* 弹出目标时，**该路径的 $\tilde f \le C^*$**（否则它不会先于最优路被弹出，因为最优路在队列里的 $\tilde f = C^*$）；又因 $\tilde f = \tilde g + \tilde h \ge \tilde g$（$\tilde h\ge0$）且到目标 $\tilde h=0$ 故 $\tilde f=\tilde g$=该路真代价；同时 $\tilde h\le h$ 保证**没被弹出的路"真实代价 $\ge \tilde f \ge$ 已弹目标的代价"** → **已弹目标的路不可能比任何未探的路差** → **最优**。**核心就是"$\tilde h$ 不高估 → 不会过早放弃真最优路"**。
4. **PRM 的"边碰撞检测"为什么贵 + 怎么省**：一条边要"**沿线撒几十个点查碰撞**"，$K$ 个点、每个连 $k$ 个邻居 → **$O(Kk\times$每边几十次)** 次碰撞查询。**省法**：**用 BVH/OBB 包围盒层次加速碰撞**、**用 GPU 批量查**、**用"lazy PRM"先假设边都通、只在最后最短路上查碰撞、不通再重搜**（**先乐观后验证，省掉大量无用边检测**）。
5. **RRT\* 的 near 半径 $r(n)$ 为什么要随 $n$ 缩**：$r$ 太大 → 每步 rewire 查太多邻居 → 慢；$r$ 太小 → 错过"能优化"的爹 → 不收敛到最优。**理论要求 $r(n)\propto(\log n/n)^{1/d}$**（$d$=维度）→ **保证"渐近最优"又"边数可控"**。**这是 RRT\* 论文 [Karaman & Frazzoli] 的核心结论之一**。
6. **IRIS + GCS 的"为什么凸这么重要"**：GCS 在图上搜最短路，**每个节点是一个凸集、每条边的约束是凸的** → **整个搜索的"凸松弛"是个凸优化，常常紧到直接出全局最优**（第10章 10.8.3 讲过）。**IRIS 的价值 = 把"非凸自由空间"预先切成"凸块"**，**让 GCS 有凸块可用**。**所以"采样/分解"和"凸优化"不是竞争关系，而是"前者给后者备料"**。

### 实验 1：A\* 在网格上（可跑，对照 Algorithm 12.1，验证"可容许启发式"）

**8×8 网格 + 几堵墙，直线距离当 $\tilde h$，跑 A\*，并对比"用 $\tilde h=0$（退化成 Dijkstra）"扩展了多少节点**——**亲眼见"启发式越准，废节点越少"**。

```python
import numpy as np, heapq
H, W = 8, 8
wall = {(2,2),(2,3),(2,4),(5,5),(5,6)}          # 几堵墙
start, goal = (0,0), (7,7)
def succ(p):
    h,w = p
    for dh,dw in [(-1,0),(1,0),(0,-1),(0,1)]:
        nh,nw = h+dh, w+dw
        if 0<=nh<H and 0<=nw<W and (nh,nw) not in wall: yield (nh,nw)
def heur(p, admissible=True):                    # 直线(曼哈顿)距离，可容许
    return (abs(p[0]-goal[0])+abs(p[1]-goal[1])) if admissible else 0  # 0 = 退化成 Dijkstra
def astar(admissible=True):
    g = {start:0}; came={}
    pq = [(heur(start,admissible), 0, start)]    # (f, g, node)
    expanded = 0
    while pq:
        f,gc,u = heapq.heappop(pq)
        if u in g and gc > g[u]: continue
        expanded += 1
        if u==goal: break
        for v in succ(u):
            ng = gc+1
            if v not in g or ng < g[v]:
                g[v]=ng; came[v]=u
                heapq.heappush(pq, (ng+heur(v,admissible), ng, v))
    # 回溯路径
    p, path = goal, []
    while p in came: path.append(p); p=came[p]
    return list(reversed(path)), expanded
pathA, eA = astar(True);  pathD, eD = astar(False)
print("A*(直线启发) 扩展节点 =", eA, " 路径长 =", len(pathA)+1)
print("Dijkstra(h=0) 扩展节点 =", eD, " 路径长 =", len(pathD)+1)
print("-> 启发式让 A* 少探了", eD-eA, "个废节点，路径一样最优")
```

**你会看到**：**两条路径一样长（都最优，验证 A\* 最优性）**，**但 A\* 扩展的节点明显少于 Dijkstra**——**亲手验证"可容许启发式 = 既最优又省"**。**把 `heur` 换成"故意高估"的值（如曼哈顿×3）**，**会看到路径变短但不再最优**——**亲眼见"不可容许 → 失去最优性"**。

### 实验 2：PRM 在 2D 带圆障碍（可跑，对照 Algorithm 12.2，含离线建图 + 在线 A\*）

**平面 $[0,1]^2$ 里放几个圆障碍，离线撒点建 PRM，在线连起终点跑 A\***——**把 Algorithm 12.2 的两阶段写活**。

```python
import numpy as np, heapq, math
rng = np.random.default_rng(0)
obstacles = [(0.3,0.4,0.12),(0.6,0.6,0.15),(0.5,0.2,0.10)]   # (cx,cy,r)
def in_collision(p, margin=0.0):
    return any(math.hypot(p[0]-cx,p[1]-cy) < r+margin for cx,cy,r in obstacles)
def seg_free(a, b, n=30):                          # 边碰撞检测：沿线撒 n 点
    for t in np.linspace(0,1,n):
        if in_collision((a[0]+t*(b[0]-a[0]), a[1]+t*(b[1]-a[1]))): return False
    return True
# ---- 离线 BuildRoadmap ----
K, k_near = 400, 6
V = []
while len(V) < K:
    q = rng.uniform(0,1,2)
    if not in_collision(q): V.append(q)
V = np.array(V)
E = []
for i,q in enumerate(V):
    d = np.linalg.norm(V-q, axis=1); d[i]=1e9
    for j in np.argsort(d)[:k_near]:
        if seg_free(q, V[j]): E.append((i,j))
# ---- 在线 FindPath：连起终点 + A* ----
start, goal = np.array([0.05,0.05]), np.array([0.95,0.95])
def connect(q):                                    # 把 q 连到图，返回 (节点idx列表, 边列表, 新顶点idx)
    idx = len(V); V2 = np.vstack([V, q]); e2 = []
    d = np.linalg.norm(V-q, axis=1)
    for j in np.argsort(d)[:k_near]:
        if seg_free(q, V[j]): e2.append((idx,j))
    return V2, e2, idx
V, e_s, si = connect(start);  E += [(a+0,b+0) for a,b in []]   # 占位对齐
E += [(si, b) for (_,b) in e_s]
V, e_g, gi = connect(goal);   E += [(a, gi) for (a,_) in e_g]
# A* on graph
adj = {}
for a,b in E: adj.setdefault(a,[]).append((b,np.linalg.norm(V[a]-V[b]))); adj.setdefault(b,[]).append((a,np.linalg.norm(V[a]-V[b])))
g={si:0}; pq=[(np.linalg.norm(V[si]-V[gi]),0,si)]; came={}
while pq:
    f,gc,u=heapq.heappop(pq)
    if u==gi: break
    if gc>g.get(u,1e9): continue
    for v,w in adj.get(u,[]):
        ng=gc+w
        if ng<g.get(v,1e9): g[v]=ng; came[v]=u; heapq.heappush(pq,(ng+np.linalg.norm(V[v]-V[gi]),ng,v))
path=[gi]
while path[-1] in came: path.append(came[path[-1]])
path=list(reversed(path))
print("PRM 顶点数 =", len(V), " 边数 =", len(E), " 路径节点数 =", len(path),
      " 路径长 ≈", round(g.get(gi,math.nan),3))
print("路径(起→终) 前3点后3点坐标:\n", np.round(V[path[:3]],2), "\n ... \n", np.round(V[path[-3:]],2))
# 可视化：plt.scatter(V[:,0],V[:,1],s=2); 画边; 画障碍圆; 画 path 折线 —— 即 Figure 风格的 PRM 图
```

**你会看到**：**400 个随机点 + 近邻连边，在线 A\* 在障碍间绕出一条路**——**亲手复现"离线建地铁图 + 在线查路线"**。**把 `K` 调小（如 30）**，**可能"连不通"起终点（return 空路径）**——**亲眼见"概率完备 = 点越多越几乎一定连通"**。**把障碍摆成"窄缝"**，**看 PRM 需要更多点才能"撒进缝里"连通**——**体会 2.2 的"窄走廊"问题**。

### 实验 3：RRT vs 稻草人 RRT（可跑，本章最有教学价值，对照 Example 12.2 + §3.4）

**同一套动力学 $x_{new}=x+u$（即 PDF 的 $x[n]=u[n]$ 的连续类比），同一起点/目标，对比"稻草人（树上随机抓+随机动作）" vs "标准 RRT（空间撒点+最近邻+steer）"**——**亲眼见"一团糟" vs "迅速铺满"**。

```python
import numpy as np, math
rng = np.random.default_rng(1)
bounds = np.array([0.,20.]); goal_box = (15.,20.)             # 目标 [15,20]（PDF 的 15<=xi<=20）
def in_goal(x): return goal_box[0]<=x[0]<=goal_box[1] and goal_box[0]<=x[1]<=goal_box[1]
def clip(x): return np.clip(x, bounds[0], bounds[1])
STEP = 1.0
# ---------- 稻草人 RRT（PDF Example 12.2 原文：树上随机节点 + 随机动作）----------
def strawman(K=1000):
    T = [np.array([0.,0.])]; par = {-1:None}
    for _ in range(K):
        i = rng.randint(0,len(T))                            # 树上随机抓节点
        u = rng.uniform(-STEP,STEP,2)                        # 随机动作
        xnew = clip(T[i]+u)
        T.append(xnew); par[len(T)-1]=i
        if in_goal(xnew): return T,par,len(T)-1
    return T,par,None
# ---------- 标准 RRT（空间撒点 + 最近邻 + 朝样本 steer）----------
def rrt(K=1000):
    T = [np.array([0.,0.])]; par = {0:None}
    for _ in range(K):
        q = rng.uniform(bounds[0],bounds[1],2)               # 空间随机撒点
        i = int(np.argmin([np.linalg.norm(q-x) for x in T])) # 树中最近邻（Voronoi 偏向！）
        d = q-T[i]; n = np.linalg.norm(d)
        xnew = T[i] + (d/n)*min(STEP,n) if n>1e-9 else T[i]  # 朝 q 走一步(steer)
        xnew = clip(xnew)
        T.append(xnew); par[len(T)-1]=i
        if in_goal(xnew): return T,par,len(T)-1
    return T,par,None
Ts,_,gs = strawman(1000); Tr,_,gr = rrt(1000)
print("稻草人 1000 步: 到目标?", gs is not None, " 树覆盖x范围 =",
      round(np.ptp([x[0] for x in Ts]),2))
print("标准RRT 1000 步: 到目标?", gr is not None, " 树覆盖x范围 =",
      round(np.ptp([x[0] for x in Tr]),2))
# 可视化：scatter 两棵树的节点 —— 稻草人挤在 [0,~3] 一团，标准 RRT 铺到 20
```

**你会看到**：**稻草人 1000 步"到目标=False"，x 范围只到 2~3（挤在原点）**；**标准 RRT "到目标=True"，x 范围铺到 20**——**亲手复现 Figure 12.3/12.4 的"一团糟 vs 铺满"，并验证 §3.4 的诊断：差别全在"最近邻到空间样本"那一行（Voronoi 偏向）**。**这就是"为什么 PDF 的稻草人算法要引出标准 RRT"的代码铁证**。

### 实验 4：RRT\* —— 加 rewire，看路径"越采样越短"（可跑，对照 Exercise 12.1b）

**在实验 3 的标准 RRT 上，加"挑最省的爹 + rewire 邻居"**，**记录"到目标的路径代价随采样数下降"**——**亲眼见 RRT\* 渐近最优**。

```python
import numpy as np, math
rng = np.random.default_rng(2)
obs = [(5,5,1.5),(10,12,2.0),(14,6,1.5)]
def coll(p): return any(math.hypot(p[0]-cx,p[1]-cy)<r for cx,cy,r in obs)
def seg_free(a,b,n=40):
    for t in np.linspace(0,1,n):
        if coll(a+t*(b-a)): return False
    return True
start, goal = np.array([0.,0.]), np.array([18.,18.]); STEP=1.5
def near_radius(n): return 6.0*math.sqrt(math.log(max(n,2)+1)/(n+1))   # 渐近最优的 r(n)
def rrtstar(K=1500):
    T=[start.copy()]; par={0:None}; cost={0:0.}
    for _ in range(K):
        q = rng.uniform(0,20,2)
        i = int(np.argmin([np.linalg.norm(q-x) for x in T]))
        d=q-T[i]; n=np.linalg.norm(d); xnew=T[i]+(d/n)*min(STEP,n) if n>1e-9 else T[i]
        if coll(xnew) or not seg_free(T[i],xnew): continue
        # ① 在 near 里挑最省的爹
        near=[j for j in range(len(T)) if np.linalg.norm(T[j]-xnew)<near_radius(len(T)) and seg_free(T[j],xnew)]
        best,bc = i, cost[i]+np.linalg.norm(T[i]-xnew)
        for j in near:
            c=cost[j]+np.linalg.norm(T[j]-xnew)
            if c<bc: bc,best=c,j
        idx=len(T); T.append(xnew); par[idx]=best; cost[idx]=bc
        # ② rewire：xnew 能否当邻居更省的爹
        for j in near:
            c=cost[idx]+np.linalg.norm(xnew-T[j])
            if c<cost[j]: par[j]=idx; cost[j]=c
        if np.linalg.norm(xnew-goal)<STEP and seg_free(xnew,goal):
            T.append(goal); par[len(T)-1]=idx; cost[len(T)-1]=cost[idx]+np.linalg.norm(xnew-goal)
            return T,par,cost,len(T)-1
    return T,par,cost,None
T,par,cost,g = rrtstar(1500)
def pathlen(g):
    L,p=0.,g
    while par[p] is not None: L+=np.linalg.norm(T[p]-T[par[p]]); p=par[p]
    return L
print("RRT* 到目标?", g is not None, " 路径代价 ≈", round(pathlen(g),2) if g else "NA",
      " (随 K 增大而下降 -> 渐近最优)")
```

**你会看到**：**RRT\* 找到的路径"会绕着障碍走平滑的捷径"**；**把 `K` 从 300 加到 3000，路径代价单调下降、趋于一个稳定值**——**亲手验证 rewire 带来的"渐近最优"**。**对比不加 rewire 的纯 RRT（把①②去掉）**，**路径明显更"锯齿/绕远"**——**体会"RRT 只完备、RRT\* 才最优"**。

### 实验 5：带动力学的 RRT（kinodynamic，可跑，对照 12.3.1 + Example 12.1 的"动力学钩子"）

**双积分器 $\dot q=v,\ \dot v=u$，steer = "用随机/朝样本的 $u$ 积分一段"**——**让 RRT "懂物理"，去解一个"运动学 RRT 解不了"的带惯性问题**。

```python
import numpy as np
rng = np.random.default_rng(3)
# 状态 x=[q0,q1,v0,v1]，控制 u=[u0,u1]，|u|<=1
def step(x,u,dt=0.2):                              # 简单欧拉积分一段
    q=x[:2]+x[2:]*dt; v=x[2:]+u*dt; return np.concatenate([q,np.clip(v,-5,5)])
start=np.zeros(4); goal_q=np.array([8.,8.])
def in_goal(x): return np.linalg.norm(x[:2]-goal_q)<1.0 and np.linalg.norm(x[2:])<1.0
T=[start.copy()]; par={0:None}
for _ in range(3000):
    q=rng.uniform(-2,10,4)                         # 在状态空间撒点(含速度维)
    i=int(np.argmin([np.linalg.norm(q-x) for x in T]))
    # steer：朝 q 的方向选 u（简单版：u 指向 q 的速度/位置误差，截断到|u|<=1）
    err=q-T[i]; u=np.clip(err[[2,3,0,1]]*0.5,-1,1) # 把位置误差当"想要的速度"，速度误差当"想要的加速度"
    xnew=step(T[i],u)
    T.append(xnew); par[len(T)-1]=i
    if in_goal(xnew):
        print("kinodynamic RRT 到目标! 用了", len(T), "节点 (位置,速度)=", np.round(xnew,2)); break
else:
    print("3000 步未到，最近位置距离 =", round(min(np.linalg.norm(x[:2]-goal_q) for x in T),2))
# 关键：steer 用 f 积分而非画直线 -> 树在 (q,v) 空间里"按物理"生长，能处理惯性
```

**人话**：**运动学 RRT 在 $(q,v)$ 空间"画直线"是作弊**（你不可能瞬间改变速度）；**kinodynamic RRT 用 $f$ 积分 steer**，**树在相空间里"按惯性长"**——**这才真的能开过去**。**把 steer 换成"局部 LQR 把 $x_{near}$ 朝 $q_{rand}$ 开一段" = LQR-RRT**（更准、更远，但每步要解一次 Riccati）。**这就是 12.3.1 + 12.0"让采样懂动力学"的代码落地**，也回应了 Example 12.1"PRM 能否 swing-up 单摆"——**答案：运动学 PRM 不行，kinodynamic/LQR-RRT 才行**。

## 给初学者的"本章通关三句话"

1. **别算路，去搜路；别撒网格，去随机撒点**：当障碍怪、代价非凸、维度高时，**轨迹优化会卡局部极小、网格会维度爆炸**——**基于采样的规划用"随机撒点 + 连边"把连续空间变成图，再用图搜索找路**，**10 维照样玩**。
2. **A\* 靠"乐观启发式"既对又省，PRM/RRT 靠"随机"换"完备"**：**A\* 用"绝不高估的 $\tilde h$"保证最优且不探废路**；**PRM "离线建地铁图、在线查 A\*"，RRT "从起点长树、朝空旷处蔓延"**——**两者都是"概率完备"（点越多越几乎一定找到）**，**而 RRT 的"朝空旷长"靠的是"空间撒点 + 找最近邻"带来的 Voronoi 偏向**（**PDF 的稻草人算法正因缺这味药而挤成一团**）。
3. **采样给"拓扑"，优化给"光滑/保证"，两者联姻才是王道**：**原始 PRM/RRT 只懂运动学**；**让 steer 用动力学积分/LQR（kinodynamic-RRT、LQR-RRT）就"懂物理"**，**加 rewire（RRT\*）就"渐近最优"**，**用 IRIS 把自由空间切成凸块喂给 GCS、或对 PRM 折线后处理**，就**把"采样的鲁棒"和"凸优化/轨迹优化的光滑最优"焊成一条流水线**——**这正是"采样规划 + 最优控制 + 凸优化"三方合流的前沿**。
