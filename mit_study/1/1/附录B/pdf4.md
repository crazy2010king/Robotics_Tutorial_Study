# 第一部分：通俗易懂的全面讲解

## 0. 什么是“采样运动规划”？（引言）

* **原理直白讲**：在之前的章节中，我们学习了动态规划（DP）和轨迹优化（Trajectory Optimization）。但在真实的机器人世界里（比如在装满家具的房间里移动的机械臂，或者在复杂地形中穿行的无人机），空间极其庞大，障碍物形状千奇百怪，优化问题充满了“局部最小值”——就像你在迷宫里走，稍微不注意就会撞墙或死胡同。


* **形象类比**：
* **轨迹优化** 像是在山顶放一颗滑雪球，希望它顺着山坡滑到终点；但如果山上全是坑洼（障碍物），球就会卡在半山腰的坑里（局部最优）。
* **采样运动规划** 就像是在山里随机撒下几千个小侦察兵（随机采样），让他们互相打探路线并连成一张路线网，从而帮你绕过所有大坑和悬崖，找到一条通往终点的路。

## 12.1 大规模增量搜索（Large-Scale Incremental Search）

### (1) 为什么需要增量搜索？

* **核心思想**：传统的动态规划（DP）非常厉害，它能算出**从地图上每一个点到终点**的最优路线，但缺点是太吃内存了！如果我们只想找**从特定的起点到终点**的一条路，完全不需要把整个地图都装进内存里，而是边走边探索，这就是“增量搜索”。


* **形象类比**：
* **动态规划** 就像是印制一本涵盖全国每一条乡村小道的《全国地图导航全书》，极其耗费纸张和大脑内存。


* **增量搜索** 就像是手机实时导航，只有当你走到某个路口时，才查一下这个路口通向哪里，没去的地方根本不上锁进内存。





### (2) 启发式函数与 $A^*$ 算法

* **可采纳启发式（Admissible Heuristic, $\tilde{h}(v)$）**：
* **直白解释**：启发式就是对“还剩多少路程”的估算。“可采纳”的意思是：**估算出来的剩余路程，绝对不能超过实际所需的最短路程（即绝不高估）**。


* **生活类比**：两点之间的“直线距离”（大雁飞行的距离）。你开车从北京到上海，直线距离是 1000 公里，实际开车的道路距离肯定大于等于 1000 公里。因此，“直线距离”就是一个完美的“可采纳启发式”，因为它永远不会高估实际车程。




* **$A^*$ 算法评估公式**：
* $f(v) = g(v) + \tilde{h}(v)$

* $g(v)$：从**起点**走到当前位置 $v$ 已经花的实际代价。


* $\tilde{h}(v)$：从当前位置 $v$ 预估走到**终点**还需要花的代价。


* $f(v)$：经过当前位置 $v$ 走到终点的预估总代价。





### (3) $A^*$ 算法代码实践逻辑拆解（Algorithm 12.1）

在代码中，$A^*$ 的工作流程如下：

1. **定义队列**：使用优先队列 $Q$，优先级最高的（排在最前面）是总预估代价 $f(v)$ 最小的路径。


2. **记录字典**：用字典 $S$ 记录每个访问过的节点以及到达它的最佳路径。


3. **循环探索**：
* 每次从优先队列 $Q$ 中弹出当前预估代价最小的路径。


* 检查路径末端的节点 $u$ 是否是终点 $v_t$。如果是，直接返回路径（成功找到最短路）！


* 如果不是，查找 $u$ 的所有邻居节点（通过 `GetSuccessors(u)`）。


* 对每个邻居 $v$，计算新的路径代价 $g(p')$。如果这个邻居还没被探索过，或者新路径比之前记录的更近，就更新字典 $S[v]$ 并加入优先队列 $Q$。





### (4) 理论性质与高级扩展

* **完备性（Completeness）**：如果问题存在可行解，算法保证能找到解。$A^*$ 是完备的。


* **最优性（Optimality）**：算法保证找到的解是代价最小的（最好的）。$A^*$ 在使用可采纳启发式时保证最优。


* **分解（Factorization）与 AI 前沿**：
* 像 Fast Downward 这种经典逻辑规划器利用独立性分解简化了搜索。


* DeepMind 的 AlphaGo 和 AlphaZero 将蒙特卡洛树搜索（MCTS）与深度学习组合。现在，大语言模型（LLM）与规划算法的结合也是前沿热点。

## 12.2 概率路图法（Probabilistic Roadmaps, PRM）

### (1) 如何把搜索扩展到连续的机器人世界？

* **背景**：棋盘的格子是离散的，但机器人的角度、位置是连续无限的。如果直接把空间切成固定网格（固定网格离散化），遇到狭窄通道（如窄门）时就很容易漏掉可行路径。


* **分辨率完备（Resolution Complete） vs 概率完备（Probabilistically Complete）**：
* **分辨率完备**：网格划分得越来越细，当网格无限细时，只要有路就一定能找到。


* **概率完备**：随着采样点数量增加到无穷多，找到可行路径的概率无限接近 100%。





### (2) PRM 的核心机制（Algorithm 12.2）

PRM 算法分为**离线建图**和**在线查询**两个阶段：

* **形象类比**：
* **离线建图** 就像是在一个新城市里修建地铁网络。城市规划师随机选很多平地（碰撞检测通过的采样点），然后在相近的站台之间修直达铁轨（直线的无碰撞路径），建好一张大地铁网。


* **在线查询** 就像是你从家到公司。你先从家走到最近的地铁站（起点连入路图），坐地铁穿越城市，到了离公司最近的地铁站再出来（终点连入路图），中间在地铁网里的规划直接用 $A^*$ 求解。





### (3) 代码/实验实践重点与瓶颈

* **伪代码逻辑**：
1. `BuildRoadmap()`：在构型空间中均匀随机采样 $q$，剔除撞到障碍物的点。对每个安全点 $q$，寻找其邻近节点 $q_n$，若直线路径无碰撞，添加边到集合 $E$ 中。


2. `FindPath()`：将起点 $q_s$ 和终点 $q_t$ 连接到路图中，调用图搜索算法（如 $A^*$）求出路径。




* **实践性能瓶颈**：
* **90% 以上的计算时间都耗费在“碰撞检测”（Collision Detection）上**！不仅要检测点，还要沿着连接边进行密集的离散采样检测。


* PRM 在 10 维以下的运动规划中表现极佳，通常需要借助 CPU/GPU 并行化进行加速（如 Drake 仿真平台中的优化）。

## 12.3 快速探索随机树（Rapidly-exploring Random Trees, RRT）

### (1) 为什么有了 PRM 还需要 RRT？（引入动态约束）

PRM 假定任意两点之间可以通过直线连接，但这只适用于**运动学规划**（没有速度、加速度限制）。如果是**动力学规划**（例如一辆高速行驶的汽车，不能原地 90 度转弯；或者单 took 摆 swing-up），你就不能随便把两个点用直线连起来。

### (2) “稻草人”算法（Straw-man Random Tree）为什么会失败？

* **实验设计**：如果我们随意建一棵树——随机从树上挑一个已有节点 $x_{rand}$，随机给一个合法的控制输入 $u_{rand}$，根据物理方程 $x_{new} = f(x_{rand}, u_{rand})$ 推出新节点，这能成功吗？


* **结果分析**：虽然理论上它是概率完备的，但在实验中极其低效！展开 1000 个节点后，所有节点全都死死地挤在起点附近，像一团乱麻，根本无法向外拓展。



### (3) RRT 的魔法：Voronoi 偏置（Voronoi Bias）

RRT 解决树不扩散问题的核心技巧在于：**不要先选树上的节点，而是先在空间中随机撒一个目标点！**

* **标准 RRT 步骤**：
1. 在全空间中随机采样一个点 $q_{rand}$。


2. 在已有的树上找到距离 $q_{rand}$ 最近的节点 $q_{near}$。


3. 从 $q_{near}$ 朝着 $q_{rand}$ 的方向扩展一小步，生成新节点 $q_{new}$。




* **形象类比（Voronoi 偏置）**：
* 假设树上的各个节点是分布在荒野上的村庄，空间中未被探索的大片空白区域就像是未开垦的土地。
* 在空白区域最大、周围村庄最稀少的地方，其对应的“领地面积”（Voronoi Cell）极其庞大！
* 当你随机往地图上投掷飞镖时，飞镖掉进这片庞大空白领地的概率极高。于是，距离这片空白最近的边缘村庄就会被频繁选中向外扩展。**RRT 就像是有磁铁在吸引树枝向着最大的未探索空间生长！**




### (4) 变体与扩展（RRT*, Kinodynamic-RRT* 等）

* **RRT***：标准 RRT 找到的路通常是歪歪扭扭的折线，很不优。RRT* 在加入新节点后，会检查周围邻居，如果通过新节点重新连接（Rewire）能让路径更短，就“修改树的连接”，从而收敛到最优路径。


* **其他变体**：RRT-sharp、RRTx（动态环境）、Kinodynamic-RRT*（带动力学约束的最优树）、LQR-RRT*（结合局部反馈控制）。

## 12.4 分解方法（Decomposition Methods）

* **单元分解（Cell Decomposition）**：将复杂的无障碍空间切割成一个个简单的几何体（如凸多边形）。


* **近似分解（如 IRIS 算法）**：针对极其复杂的环境，通过算法（如 IRIS）自动在无碰撞空间中拟合出尽可能大的凸区域（Convex Regions），方便后续进行高效规划。

# 终极全景教程：第12章 采样运动规划（Sampling-based Motion Planning）

## 章节全景导图与核心矛盾

在之前的机器人学课程中，我们学过**动态规划（DP）**和**轨迹优化**。

* **为什么还需要采样规划？**
* 轨迹优化依赖梯度下降，如果在三维复杂空间中（比如机械臂在充满障碍物的管道里穿行），优化地形极其复杂且高度非凸（Nonconvex），算法会像无头苍蝇一样**卡在局部最小值（死胡同）**。


* 采样规划通过“在空间中随机掷骰子”的方式，避开了复杂的连续导数计算，特别擅长解决**几何形状复杂**或**存在物理动力学限制**的避障难题。

## 一、 大规模增量搜索（Large-Scale Incremental Search）

### 1.1 历史演进与“增量”的智慧

人工智能的历史上， Samuel 的跳棋程序、Deep Blue 国际象棋、Cyc 知识库等都依赖高效搜索。

* **动态规划（DP）的局限**：DP 试图算出全图**每一个状态到终点的最优代价（Cost-to-go）**。这就像为了从家去超市，却把全省所有的地图细节全部塞进脑子里，内存一下子就爆了。


* **增量搜索（Incremental Search）**：只从起点开始，边走边在内存中建图，绝不把庞大的（甚至是无限的）完整图结构一次性塞进内存。



### 1.2 启发式与 $A^*$ 算法的本质

#### 什么是可采纳启发式（Admissible Heuristic）？

* **定义**：记估算的剩余代价为 $\tilde{h}(v)$，真实的最优剩余代价为 $h(v)$。可采纳性要求：$\tilde{h}(v) \le h(v), \forall v$。


* **生活类比**：你在山脚下爬山，问路人还有多久到山顶。如果路人总是“往小了估计”（比如明明要走2小时，他说“最多1小时”），这就是“可采纳估算”。只要他不虚报大数，你就不会因为盲目放弃而错过了最短路径。两点之间的欧式直线距离（“像乌鸦飞行一样”）就是最经典的不高估启发式。



#### $A^*$ 算法评估函数与绝妙定理

* **评估公式**：$f(v) = g(v) + \tilde{h}(v)$

* $g(v)$：起点到 $v$ 的**已花费实际成本**。


* $\tilde{h}(v)$：$v$ 到终点的**预估剩余成本**。




* **神奇定理（PDF 遗漏点补充）**：


1. 如果 $\tilde{h}(v)$ 是可采纳的，**$A^*$ 绝对不会去扩展那些预估总成本 $\tilde{f}(p)$ 大于真正最优总代价 $f(v_s)$ 的路径**！


2. 如果你的启发估算完美等于真实剩余代价（$\tilde{h}(v) = h(v)$），$A^*$ 将展现“上帝视角”，**只访问恰好在最优路径上的节点，零弯路**！





#### $A^*$ 算法伪代码详解与代码实现逻辑 (Algorithm 12.1)

```python
# A* 算法逻辑拆解
p = [v_s]                  # 初始化路径，起点为 v_s
S = {v_s: p}               # Visited 字典：记录访问过的节点及其最佳路径
Q = PriorityQueue()        # 优先队列：按 f(v) 从小到大排序
Q.insert(p)

while not Q.empty():
    p = Q.pop()            # 弹出当前总预估代价 f(p) 最小的路径
    u = p.last()           # 获取该路径的最后一个节点
    
    if u == v_t: 
        return p           # 到达终点 v_t，成功返回路径！
        
    for v in GetSuccessors(u):  # 遍历 u 的所有邻居
        if v not in p:          # 避免简单环路
            p_new = Path(p, v)  # 拼接新路径
            # 如果邻居没被访问过，或者发现了更短的到达 v 的路径
            if v not in S or g(p_new) < g(S[v]):
                S[v] = p_new
                Q.insert(p_new)

```

* **性质总结**：$A^*$ 算法既是**完备的（Complete）**，也是**最优的（Optimal）**。


* **前沿扩展**：逻辑规划器 Fast Downward 利用问题分解（Factorization）简化搜索；DeepMind 的 AlphaGo / AlphaZero 则将蒙特卡洛树搜索（MCTS）与神经网络学的 Value/Policy 函数结合。

## 二、 概率路图法（Probabilistic Roadmaps, PRM）

### 2.1 从离散网格到连续空间的突破

* **固定网格离散化的致命缺点**：如果空间中有一条很窄的通道（如门缝），固定网格可能恰好没落进通道里，导致算法误判为无路可走（丧失完备性）。


* **概率完备性（Probabilistic Completeness）**：不采用固定网格，而是在空间里**随机撒点**。只要撒点数量无穷多，算法找到解的概率就会趋近于 100%。



### 2.2 PRM 算法双阶段详解 (Algorithm 12.2)

#### 阶段一：离线建图（Offline Roadmap Construction）

1. **随机采样**：在构型空间（Configuration Space）中均匀产生随机位置 $q$。


2. **碰撞检测**：检查 $q$ 是否撞到障碍物，剔除非法点。


3. **近邻连接**：对每个安全点 $q$，在已有节点集中找最近的 $K$ 个邻居 $q_n$。


4. **边碰撞检测**：如果 $q$ 与 $q_n$ 之间的**直线路径**完全无碰撞，则在路图中添加一条边 $\{q, q_n\}$。



#### 阶段二：在线查询（Online Query Phase）

当用户给出一个全新的起点 $q_s$ 和终点 $q_t$ 时：

1. 将 $q_s$ 和 $q_t$ 分别连接到离线建好的路图中最近的安全节点上。


2. 直接在路图网络上运行离散图搜索（如 $A^*$ 算法）。



```
【PRM 通俗比喻】：
离线阶段：在全城随机选点修“地铁站”，并在没有大楼遮挡的站与站之间修“地下铁轨”。
在线阶段：你想从 A 到 B。你只需从 A 走到最近的地铁站，乘坐地铁网穿过全城，到达离 B 最近的站出来即可。

```

### 2.3 实验实践瓶颈与轨迹平滑（补充细节）

* **计算瓶颈**：PRM 最耗时的步骤是**碰撞检测（Collision Detection）**。在检测边时，代码必须对线段进行非常密集的微细采样（Point Collision Detection），这占用了 90% 以上的 CPU 资源。现代框架（如 MIT 的 Drake）通常通过 CPU/GPU 并行化加速，或者使用最新的证书验证技术（如 Amice 等人在 2024 年提出的方法）。


* **轨迹平滑与动态约束（12.2.1 节补全）**：
PRM 规划出来的路通常是由折线组成的折角路径，机器人在折弯处速度必须降为 0。为了获得平滑轨迹，通常需要进行**后处理（Post-processing，如贝塞尔曲线拟合或拉直剪枝）**，或者结合 **GCS（凸集图轨迹优化，Graphs of Convex Sets）**，利用采样生成的无碰撞区域直接求解高阶连续的平滑轨迹。

## 三、 快速探索随机树（Rapidly-exploring Random Trees, RRT）

### 3.1 引入动力学约束：为什么 PRM 搞不定动效？

PRM 假设任意两点间可以用直线直接连通。但如果控制的是**欠驱动系统**（例如单摆 swing-up、无人机或者高速赛车），你不可能让赛车瞬间向侧面平移。系统运动受限于微分方程 $\dot{x} = f(x, u)$。

### 3.2 失败的尝试：“稻草人”纯随机树实验（Straw-man Algorithm）

为了解决动力学约束，有人提出了最简单的树状探索方法（稻草人算法）：

1. 树初始化：$T \leftarrow x_0$（起点）。


2. 循环：从树中**随机选一个已有节点 $x_{rand}$**，再**随机选一个合法控制量 $u_{rand}$**。


3. 物理推演：计算新状态 $x_{new} = f(x_{rand}, u_{rand})$。


4. 将 $x_{new}$ 加入树中。



#### 实验代码案例分析（PDF 12.3 深入剖析）

* **实验设置**：系统状态为二维平面的位置 $\mathbf{x} = [x_1, x_2]^T$，控制量 $u_i \in [-1, 1]$。起点在 $(0,0)$，目标区在 $[15, 20] \times [15, 20]$。


* **实验结果**：运行 1000 次迭代后，树的节点**全都堆积在起点 $(0,0)$ 附近**（形成一团乱麻，如图 12.2 所示），根本没有向目标区域蔓延！


* **失败原因**：先选节点再随机生长，使得树枝不断在内部自我重叠，**缺乏向未知空间拓展的驱动力**。



```
【稻草人算法崩溃图解】：
起点 (0,0) ---> 产生10个微小枝丫 
            ---> 随机选这10个枝丫再发芽 
            ---> 树枝全部死死缠绕在原点附近！

```

### 3.3 RRT 的灵魂：Voronoi 偏置（Voronoi Bias）

为了打破这一困局，LaValle 提出了 RRT。它的核心妙招是**反客为主**：

```
【RRT 核心算法三步走】：
1. q_rand = UniformRandom()  --> 先在全空间随机找一个“目标诱饵点”！
2. q_near = Nearest(T, q_rand) --> 在树上找到距离这个“诱饵”最近的节点！
3. q_new  = Extend(q_near, q_rand) --> 从 q_near 朝着 q_rand 前进一小步！

```

#### 几何直观解释：Voronoi 胞腔（Voronoi Cells, 图 12.3 & 12.4）

* **什么是 Voronoi 胞腔？** 空间中某个节点 $v$ 的 Voronoi 胞腔，指的是“全空间中所有离 $v$ 最近的点所组成的区域”。


* **偏置机制**：
* 在未探索的茫茫空白区域，其边缘节点的 Voronoi 胞腔**面积巨大无比**！


* 当你在全空间均匀撒点 $q_{rand}$ 时，点落入庞大空白胞腔的概率极高。


* 这就**强制吸引**树的边缘节点不断朝着未探索的巨大空白区域“爆芽”生长！这就是 **RRT（快速探索随机树）** 名称的由来。





```
【Voronoi 磁铁效应类比】：
假设已有的村庄都拥挤在南方，北方是一大片无人区。
我们在地图上随机扔一枚飞镖，飞镖掉在北方无人区的概率高达 90%。
按照“找最近村庄”的规则，北方无人区里所有的飞镖都会归属于最北边的那个村庄。
于是，最北边的村庄获得了 90% 的扩张机会，迅速向北方开拓！

```

### 3.4 算法扩展矩阵（PDF 12.3.2 补充）

* **RRT***：标准 RRT 只要找到一条通往终点的路就停止，路径往往极其崎岖。RRT* 引入了 **ChooseParent（寻找最佳父母）** 和 **Rewire（重连）** 操作，在生长过程中不断剪枝和优化重新连线，渐进收敛到最优路径。


* **Kinodynamic-RRT* / LQR-RRT***：引入微分方程与 LQR 局部控制器，使 RRT 能够在具有复杂力学约束（如欠驱动机器人 swing-up）的状态空间中高效寻优。


* **RRT-sharp & RRTx**：针对动态变化环境（障碍物会移动）的快速重新规划算法。

## 四、 空间分解方法（Decomposition Methods）

当环境过于复杂时，纯采样可能会在狭窄通道里卡住很久。

1. **单元分解（Cell Decomposition）**：将自由空间切分为相互连接的多边形格子。


2. **IRIS 算法（近似分解，如大范围凸区域拟合）**：自动在复杂三维障碍物之间，拟合出尽可能大的无碰撞凸多面体区域（Convex Regions），结合二次规划（QP）实现毫秒级轨迹生成。

## 五、 代码与实验实践指南（Exercise 12.1 手把手教）

在作业 Exercise 12.1 中，你需要动手编写 RRT 与 RRT*。以下是写代码时的核心逻辑对比拆解：

### 1. 标准 RRT 实现核心 Python 伪代码

```python
def plan_rrt(q_start, q_goal, max_iter):
    tree = Tree(q_start)
    for i in range(max_iter):
        q_rand = sample_random_config()                  # 1. 采样
        q_near = tree.get_nearest_neighbor(q_rand)       # 2. 找最近节点
        q_new  = step_towards(q_near, q_rand, step_size) # 3. 前进一小步
        
        if is_collision_free(q_near, q_new):
            tree.add_node(q_new, parent=q_near)          # 4. 加节点
            if distance(q_new, q_goal) < threshold:
                return tree.extract_path(q_new)          # 找到路径！
    return Failure

```

### 2. RRT* 代码核心改进：Rewire（重连）逻辑

RRT* 在 `tree.add_node` 之后，增加了两个极其关键的步骤：

```python
# --- RRT* 独有改进步骤 ---
# A. 找近邻圈子：寻找 q_new 周围半径 R 范围内的所有邻居节点 Q_near
Q_near = tree.get_neighbors_within_radius(q_new, radius)

# B. ChooseParent (择优认亲): 从 Q_near 中找一个能让到达 q_new 代价最小的节点作为 parent
best_parent = q_near
min_cost = get_cost(q_near) + distance(q_near, q_new)
for q_neighbor in Q_near:
    if is_collision_free(q_neighbor, q_new):
        cost = get_cost(q_neighbor) + distance(q_neighbor, q_new)
        if cost < min_cost:
            min_cost = cost
            best_parent = q_neighbor
tree.add_node(q_new, parent=best_parent)

# C. Rewire (改写家谱/重连): 检查 Q_near 中的邻居，如果“绕道 q_new 到达它们”路程更短，则修改它们的 parent 为 q_new！
for q_neighbor in Q_near:
    new_cost = get_cost(q_new) + distance(q_new, q_neighbor)
    if new_cost < get_cost(q_neighbor) and is_collision_free(q_new, q_neighbor):
        q_neighbor.parent = q_new  # 重新连线，更新树结构！

```
