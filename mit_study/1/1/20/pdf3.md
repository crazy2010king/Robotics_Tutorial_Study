# 机器人的“探路指南”：从 A* 到 RRT 的随机探索艺术
## 1. 引言：为什么要“采样”？
想象你要教一个机器人走迷宫。
*   **动态规划（DP）**：你把迷宫切成无数个小格子，算出从每个格子到终点的最佳路线。
    *   **缺点**：如果迷宫很大（状态空间维度高），格子数量是天文数字，计算机算不过来（维度灾难）。
*   **轨迹优化**：你用复杂的数学公式去推演一条路。
    *   **缺点**：如果迷宫里有陷阱（非凸），数学推演容易掉进坑里（局部最优），走不出来。
**基于采样的运动规划** 换了个思路：既然算不过来，那我就随机“扔”几个点进去试试！只要点扔得足够多，运气好就能连成一条路。这就是本章的核心思想。
---
## 2. 大规模搜索与 A* 算法：像 GPS 一样导航
在进入随机世界之前，我们先回顾一下经典的图搜索算法。这就像是在一张**地图**上找路。
### 2.1 离散 A* 算法
如果你在地图上找路，你肯定不会盲目地瞎走。你会看一眼终点在哪个方向，然后尽量往那边走。
*   **$g(n)$**：表示你已经走了多远（Cost to Come）。
*   **$h(n)$**：表示你**估计**离终点还有多远（Heuristic / Cost to Go）。
*   **$f(n) = g(n) + h(n)$**：这是 A* 算法的核心评分。我们要找的是 $f(n)$ 最小的路。
**关键概念：可采纳性**
为了保证 A* 算法能找到**最短**（最优）的路，你的估算 $h(n)$ 必须满足一个条件：**永远不要低估**实际距离（或者说，$h(n)$ 不能大于真实的 $h^*(n)$）。
*   **生活中的例子**：欧几里得距离（直线距离）。在走山路时，直线距离永远小于等于实际走路距离。所以直线距离是一个“可采纳”的启发式函数。
*   **威力**：如果估算得越准（越接近真实距离），A* 算法需要搜索的节点就越少。
### 2.2 增量式搜索与 AlphaGo
A* 算法是“完备”的（有路一定能找到）且“最优”的（路最短）。
现代人工智能（比如 AlphaGo）其实也是这个思路的延伸：它用**蒙特卡洛树搜索（MCTS）**在庞大的棋局图中搜索，只不过它用**神经网络**来充当那个 $h(n)$（估算函数），让它比人类估算得更准。

## 3. 概率路线图（PRM）：像修路网一样规划
如果环境是连续的（比如在一个空旷的大厅里走），A* 算法就不好用了，因为没有现成的“节点”和“边”。我们需要自己构建图。**概率路线图（PRM）** 就是一个经典的解法。
### 3.1 核心思想：离线建图，在线查询
这个过程分两步：
1.  **离线阶段（修路）**：在环境里随机撒一堆点（采样）。然后，把离得近的点连起来，如果能走通（没有障碍物），就连一条线。这样，整个环境就变成了一个网。
2.  **在线阶段（导航）**：当你要从 A 走到 B 时，只需要把 A 和 B 连到这个网上，然后用 A* 算法在网上找路。
**通俗比喻**：
*   这就像在一个新城市里搞开发。市政局先随机派人到处修路（离线采样建图），虽然有些路是死胡同，但最终形成了一张路网。
*   当市民（在线查询）想从家去公司时，他们只需要查地图，找到家到公司的路，而不需要自己重新去探路。
### 3.2 概率完备性
我们没法保证一次采样就能成功，但随着采样点越来越多，这张网越来越密，只要路存在，我们找到它的概率就趋近于 1。这叫**概率完备性**。
**代码实践补充**：
在实现 PRM 时，最耗时的部分通常是：
*   **碰撞检测**：连接两点时，需要检测中间有没有撞墙。通常需要在连线上密集采样检测。
*   **最近邻搜索**：找到一个点周围的邻居。通常用 **KD-Tree** 数据结构来加速，而不是遍历所有点。

## 4. 快速扩展随机树（RRT）：像树根一样生长
PRM 适合静态环境（环境不变）。但如果机器人是动的（动力学约束），或者环境变化很快，PRM 就不太灵了。这时候，**RRT** 登场了。
### 4.1 基本算法
想象一棵从起点长出来的树。
1.  **随机采样**：在空间里随机选一个点 $x_{rand}$。
2.  **寻找最近点**：在树上找到离这个随机点最近的那个节点 $x_{near}$。
3.  **生长**：从 $x_{near}$ 往 $x_{rand}$ 的方向走一步（步长固定），走到新点 $x_{new}$。
4.  **加入**：如果 $x_{new}$ 没撞墙，就把它加到树上。
就这样，树一点点长大，直到树枝碰到了终点。
### 4.2 陷阱：为什么“纯随机”很烂？
文档中举了一个非常生动的“稻草人”例子。
假设机器人的状态是 $(x, y)$，控制量是 $u$。
*   机器人的目标是 $(0,0)$。
*   但是控制量有限制，机器人的位置被限制在 $[15, 20]$ 这个框框里（比如像被墙挡住了）。
*   如果我们只是**纯随机**地选树上的节点，然后随机选动作，你会发现树虽然长得很大，但所有的节点都堆积在 $[15, 20]$ 这个边界上。
*   **结果**：树虽然很大，但根本没往目标方向探索，一直在原地打转。
**教训**：RRT 必须结合**启发式**（Heuristic），比如以一定的概率直接向目标采样，引导树向未探索区域生长，而不是像无头苍蝇一样乱撞。

## 5. 代码实践：如何动手写一个 RRT？
这是本章的重点。虽然文档中的伪代码很简洁，但在工程落地时有很多细节。
### 5.1 数据结构
你需要维护两个集合：
*   `V` (Vertices)：存储树上的所有节点（坐标）。
*   `E` (Edges)：存储树上的连线（谁连接谁）。
### 5.2 核心循环
```python
# 伪代码逻辑
tree = {start_node} # 初始化树
while True:
    # 1. 采样：以一定概率直接选终点，引导树生长
    if random.random() < 0.1:
        random_point = goal
    else:
        random_point = sample_random_point() # 在空间里随机撒点
    # 2. 找最近点：用 KD-Tree 快速查找
    nearest_node = find_nearest(tree, random_point)
    # 3. 扩展：从最近点往随机点走一步
    new_node = steer(nearest_node, random_point, step_size)
    # 4. 碰撞检测：检查这一步有没有撞墙
    if not is_collision(nearest_node, new_node):
        add_node_to_tree(tree, new_node)
        add_edge(tree, nearest_node, new_node)
    # 5. 检查是否到达终点
    if distance(new_node, goal) < threshold:
        return reconstruct_path(tree) # 回溯路径
```
### 5.3 进阶：RRT*（优化路径）
普通的 RRT 只要找到一条路就停了，但这路通常是弯弯曲曲的，很难看。
**RRT*** 的改进在于：
*   **重连**：每加一个新节点，都看看周围的节点，如果通过新节点走过去更近（代价更小），就把线剪断，重新连到新节点上。
*   **结果**：随着时间推移，树会不断自我修剪，路径变得越来越直，越来越短。
**代码难点**：RRT* 需要计算“代价”（Cost），通常是指路径的长度。在动力学 RRT 中，代价可能是时间或能量。
### 4.4 针对动力学系统的 RRT
文档最后提到了针对有动力学约束的机器人（如四旋翼、倒立摆），我们需要使用 **Kinodynamic RRT*** 或 **LQR-RRT***。
*   **区别**：不能简单地“走直线”。
*   **做法**：在“扩展”那一步，不是简单的几何移动，而是需要运行一个**局部轨迹优化**（比如简单的 LQR），算出从 $x_{near}$ 到 $x_{new}$ 的可行控制序列。这叫“局部规划”。

## 总结
这一章教会了我们：
*   当世界太复杂（连续、高维、非凸）时，不要试图穷举所有可能性。
*   **PRM** 适合静态环境，先建“路网”再导航。
*   **RRT** 适合动态或未知环境，像树根一样随机但带有方向性地探索。
*   工程实现中，**碰撞检测**和**最近邻搜索**是性能瓶颈，需要专门的数据结构优化。
掌握了这些，你就拥有了一套可以让机器人在杂乱无章的现实中自主探索和移动的通用工具箱。
