## 0. 开篇：这是一章"总装"，不是一章"新零件"

### 0.1 一句话概括

> **把"规划一条轨迹"升级成"规划一串带数学保证的反馈技能"。每个技能 = 一个局部控制器 + 它的吸引域（前置条件）+ 它的 Lyapunov 函数（后置条件）；只要"上一招的收招安全区"整个落在"下一招的起手区"里，就能安全地接成连招——而漏斗（不是轨迹）才是扛得住噪声的"管子"。**

### 0.2 作者引言的逐句翻译

**第一层：两条线终于汇合。**
> 整本笔记我们一直在发展**运动规划**（尤其轨迹优化、采样规划）和**反馈控制**（线性/非线性策略）的核心思想。**当然，这两条线是深度连接的。** 如果你的轨迹规划器**跑得够快**——快到**每个控制时步都能评估一次**（比如 MPC）——那么**规划器本身就成了一个策略（policy）**。反过来也对：**如果你有一个策略，前向仿真它就能生成一条轨迹规划。**

**类比（规划 ↔ 策略是一枚硬币的两面，必懂）**：
- **规划器** = **导航软件**：给你算一条"从 A 到 B 的路线"。
- **策略** = **老司机**：站在任何路口，告诉你"现在该往哪拐"。
- 如果导航软件**每秒钟重算一次**（MPC），它就**表现得像个老司机**（策略）；如果老司机的"驾驶习惯"是"沿着一条事先背好的路线开"，那**前向仿真他的习惯 = 还原出那条路线**（轨迹）。**所以"规划"和"控制"在极限情况下是同一件事**——本章要做的，是让这个"同一件事"**扛得住噪声**。

**第二层（本章真正的痛点）：噪声一来，老规划器就崩。**
> 上一章（13章）我们开始**显式地**考虑鲁棒性和不确定性。这让故事**复杂化了——但是以一种美丽的方式！** 反馈控制器**可以是鲁棒的，也可以不鲁棒**；但我们**之前建的那些规划器，开始挣扎了**。

> **"一条轨迹是鲁棒的"到底是什么意思？** 如果你用 $x(\cdot),u(\cdot)$ 表示一条轨迹规划，那么**噪声的存在会让这条规划变得不可行**（车被风吹偏，就偏离了你算的那条线，于是"沿着线开"的指令失效了）。**先不考虑噪声/不确定性去规划、然后再去稳定这条规划**，在简单情况下能 work；**但更丰富的连接是可能的**——这正是本章要探索的。

**类比（细线 vs 管子，全章最核心的图景，请刻进脑子）**：
- **轨迹** = 你在地图上画的**一根头发丝细的红线**。车只要被风吹偏一毫米，就**出了红线**——于是"沿着红线开"的指令**立刻失去意义**。**这就是"轨迹不能鲁棒"**。
- **漏斗（funnel）** = 你给这根红线**套了一根粗管子**。车在管子里**随便晃**（噪声、误差），**只要不出管壁，控制器就保证把它拽回管子中心**。**管子 = 轨迹 + 它周围的"安全余量"**。**这就是"漏斗能鲁棒"**。
- **本章的全部工作** = **不再规划"一根线"，而是规划"一串首尾相接的管子"**，并**用数学证明"车一旦进了第一根管，就一定能顺着管子流到终点，中途绝不出管壁"**。

## 1. 把反馈控制器当成"技能"（14.1）—— 从"控制论"跨到"AI 规划"

### 1.1 控制器的"适用范围"是有限的

> 我**最初**引入控制器概念时，给它的任务是"**稳定一个不动点**"或"**最小化长期代价**"，而且**对所有可能的初始条件**都要做到。

> 后来，受"**能用线性化 + 线性最优控制，为非线性系统找反馈控制器**"这件事的启发，我们开始**承认一个事实**：**有些控制器的适用范围是有限的**——它只在**某一块状态区域**里好使。于是我们发展了**估计这块区域的工具**：**吸引域（region of attraction）**，以及**轨迹周围的不变漏斗（invariant funnels）**。

**类比（招式有"起手范围"，必懂）**：
- 一个"过肩摔"的招式，**不是任何姿势都能使**——你得**先抓住对方的衣领、把重心压到某个范围**，这招才使得出来。
- **控制器 = 招式**；**它的吸引域 / 漏斗 = "使得出这招的起手姿势范围"**。
- 第9章我们学会了**用 Lyapunov 函数 / SOS 把这块"起手范围"精确地圈出来**——**这就是本章的"前置条件"的数学来源**。

### 1.2 STRIPS：AI 规划的老祖宗，给了"前置/后置条件"的语言

> AI 研究里**最早的规划方法之一**，是斯坦福研究院（SRI）的 **STRIPS 框架**。原始 STRIPS 针对**离散状态**（实际是**布尔命题**，比如"机器人在房间A"="真/假"）：**初始状态**由**一组命题**指定，**目标状态**由**另一组命题**指定。

> **对我们这里最重要的**是：STRIPS 里的"**动力学**"，是由**一组动作（或叫"技能"）** 给出的——**每个技能**由两部分定义：
> - **前置条件（preconditions）**：**执行这个技能之前，哪些命题必须为真**；
> - **后置条件（postconditions）**：**执行完之后，哪些命题会变成真**。

**类比（乐高说明书 / 菜谱，必懂）**：
- STRIPS 的"技能" = 菜谱里的一道工序，比如"**炒鸡蛋**"。
- **前置条件** = "**手里必须有打散的蛋液 + 热锅**"（不满足就不能做这步）。
- **后置条件** = "**做完后，锅里是熟鸡蛋**"。
- **规划** = **把一道道工序按"上一步的后置条件 = 下一步的前置条件"串起来**——**"熟鸡蛋"正好是"做蛋炒饭"的前置条件之一**，于是"炒鸡蛋 → 蛋炒饭"能接上。**这就是 STRIPS 的"组合"**。

> **STRIPS 处理的是"命题的真假"**（离散、逻辑）。**本章要做的，是把这套"前置/后置条件"的语言，搬到"连续状态 + 带保证的控制"上来**——**用吸引域当"前置条件"，用 Lyapunov 函数当"后置条件"**。

### 1.4 从 STRIPS 到 PDDL：任务级规划的进化

> 自 STRIPS 引入以来，**自动推理 / 任务级规划**这个领域**戏剧性地发展了**。**PDDL**（Planning Domain Definition Language，[2, 3]）**扩展了 STRIPS 的表示**，加入了**更具表达力的特性**：**类型化变量、条件效果、甚至时序逻辑量词**，并且**长期作为极具影响力的 ICAPS 规划竞赛系列的规范语言**。

**人话**：**STRIPS 是"只能写'真/假'命题"的简陋菜谱；PDDL 是"能写'如果…则…'、'在 t 时刻…'、'对所有物体…'"的高级菜谱语言**。**但骨子里，它们都是"前置条件 → 动作 → 后置条件"这一套**——**本章要做的，是给这套骨架填上"连续 + 带保证"的血肉**。

### 1.5 全章的"题眼"：用控制器当原语，而不是用轨迹

> **用"反馈控制器"作为原语（primitives）来规划，而不是用"轨迹"——这个想法可能非常强大。** 让我**强调一个关键点**：

> **轨迹不能鲁棒，但漏斗能。（Trajectories can't be robust, but funnels can.）**

**人话（这是整章的灵魂，再讲透一次）**：
- 用**轨迹**当规划原语 = 用**一根细线**当"招式"——**噪声一吹，线就废了**，你**没法保证**车还在线上。
- 用**漏斗**当规划原语 = 用**一根管子**当"招式"——**噪声在管里晃，但管子保证车不出壁**，**所以你能"打包票"**。
- **所以本章的范式转换 = 把规划的"原子单位"，从'轨迹'换成'带漏斗的控制器'**——**这样规划出来的"连招"，天生就扛噪声**。

## 2. 组合的规则（14.1.1）—— "上一招的收招圈，要落进下一招的起手圈"

### 2.1 设定：两个带漏斗的技能

> 假设我有**两个控制器** $\pi_1(x)$ 和 $\pi_2(x)$，**各配一个 Lyapunov 函数** $V_1(x)$、$V_2(x)$，**已经证明**它们在**各自的子水平集** $V_1(x)\le\rho_1$、$V_2(x)\le\rho_2$ 上**满足 Lyapunov 条件**。

**人话**：**招式1 的"起手蓝圈" = $V_1\le\rho_1$；招式2 的"起手蓝圈" = $V_2\le\rho_2$。** 我们的目标：**证明"先使招式1、再使招式2"是安全的**。

### 2.2 一个微妙点：$\dot V\preceq 0$ 只保证"不变"，不保证"收敛"

> **记住一个微妙点。** 如果 $\dot V\prec 0$，我**保证**沿 Lyapunov 函数**下降**（车往圈中心走）；**但如果** $\dot V\preceq 0$，Lyapunov 函数**只保证不变性**（车不出圈，但**不一定往中心走**，可能在圈里某个地方"卡着晃"）。

> **对于鲁棒稳定性**（有**未知扰动或建模误差**时），**我们很可能根本实现不了真正的渐近稳定**（车永远被噪声踢，停不到一个点）。**但是**——上面那张"带漏斗的卡通图"**仍然可能非常合理**。

**类比（"圈"分两层：外圈"不出"，内圈"必到"，必懂）**：
- 在有噪声的真实世界，**外圈 $V\le\rho$** 你只能保证"**车不出这个圈**"（不变性，$\dot V\preceq 0$）——**因为噪声一直踢，你没法保证它精确停到中心**。
- 但你**可以**保证：**从外圈往里，车会收敛到一个"更小的内圈" $V\le\bar\rho$**（在这个"外→内"的环带里 $\dot V\prec 0$，车被往里拽）。
- **这个内圈 $\bar\rho$ = 招式1 真正的"收招安全区"**——**车使完招式1，最终会落进这个内圈，并在里面待着**。

> 它要求**存在** $0\le\bar\rho_i\le\rho_i$，使得：

$$\bar\rho_i \le V_i(x) \le \rho_i \quad\Rightarrow\quad \dot V_i(x) \prec 0$$

**人话**：**在"内圈和外圈之间的环带"里，$\dot V$ 严格负 → 车一定从外圈被拽进内圈。** 这就是"**启动集（外圈 $\rho_i$）→ 收招集（内圈 $\bar\rho_i$）的收敛**"。

### 2.3 组合条件：内圈 ⊆ 下一招的外圈

> **然后我们就能保证**：一个**高层规划器 / 控制器**，能**从"执行技能 $i$"转换到"执行技能 $j$"**——**只要**：

$$V_i(x) \le \bar\rho_i \quad\Rightarrow\quad V_j(x) \le \rho_j$$

**人话（组合的精髓，请在这里停顿 10 秒）**：
- **招式 $i$ 的"收招安全区"（内圈 $\bar\rho_i$）**，**整个落在招式 $j$ 的"起手区"（外圈 $\rho_j$）里**。
- 于是：**车使完招式 $i$，落进内圈 $\bar\rho_i$ → 因为内圈在 $\rho_j$ 里，所以此刻车正好处于招式 $j$ 的起手范围 → 可以安全地切换到招式 $j$！**
- **这就是"连招"的数学保证**：**上一招的"收招姿势"，恰好是下一招"使得出来"的姿势**。

**类比（接力赛的交接区，必懂）**：
- 接力赛里，**上一棒必须在"交接区"内把棒交给下一棒**。
- **招式 $i$ 的内圈 $\bar\rho_i$** = **上一棒"交棒时所在的区域"**。
- **招式 $j$ 的外圈 $\rho_j$** = **下一棒"允许接棒的区域"**。
- **组合条件 $\bar\rho_i \subseteq \rho_j$** = **"交棒区整个落在接棒区内"** → **交接一定成功**。
- **只要每一棒的"交棒区 ⊆ 下一棒的接棒区"，整支接力队就能跑完全程**——**这就是"漏斗的顺序组合"**。

### 2.4 怎么验证这个"包含"？SOS 或椭球

> **对于多项式 Lyapunov 函数**，可以用 **SOS 优化 + S-procedure** 来**证明这些包含条件**（第9章 9.2.3 的工具：把"$V_i\le\bar\rho_i \Rightarrow V_j\le\rho_j$"写成一个带乘子的 SOS 蕴含）。

> **对于二次 Lyapunov 函数**，这**漂亮地简化为"椭球包含（ellipsoidal containment）"**——**因为二次函数的子水平集就是椭球，"一个椭球在另一个椭球里"有简洁的矩阵判据**（增补里给可跑的解析版）。

**类比**：**多项式漏斗 = 不规则的"安全泡泡"，验证"泡泡A在泡泡B里"要用 SOS 这把"精确尺"；二次漏斗 = 椭球"安全蛋"，验证"蛋A在蛋B里"只要比两个矩阵的大小（一个 LMI / 特征值检查），快得多。**

### 2.5 时变漏斗的组合（轨迹周围的管子）

> 我们研究过的**另一类 Lyapunov 函数**，是**和"稳定一条轨迹"挂钩的时变 Lyapunov 函数**（第9章 9.3 / 第10章 10.5 的"漏斗"）。**这种情况下**，如果 Lyapunov 条件

$$\dot V(t,x) \le \dot\rho_i(t)\quad \text{对所有 } \{t,x \mid V_i(t,x)=\rho_i(t),\ t_0\le t\le t_f\}$$

> 满足，**并且底层动力学是时不变的**，那么**只要对任何有效的 $t_i,t_j$** 满足包含条件

$$V_i(t_i,x) \le \rho_i(t_i) \quad\Rightarrow\quad V_j(t_j,x) \le \rho_j(t_j)$$

> **就足够了。**

**人话**：**轨迹周围的管子是"随时间变粗细"的**（$\rho_i(t)$ 是时间的函数）。**组合时不必"同一时刻对接"**——**只要"招式 $i$ 在它某个时刻 $t_i$ 的管口截面，落在招式 $j$ 在它某个时刻 $t_j$ 的管口截面里"，就能在 $t_i$ 切到 $j$**。**因为动力学时不变，"时间标签"可以对齐**——**你不在乎是"第3秒切"还是"第5秒切"，只在乎"切的那一刻，车在 $i$ 的管内、且这个位置在 $j$ 的管内"**。

**类比（两班地铁的换乘，必懂）**：
- 时变漏斗 = **一班"按时刻表跑的地铁"**，它的"安全车厢"随时间移动。
- 组合 = **换乘**：你**不必在"同一秒"换乘**，**只要"你在 $i$ 号线某一站下车时，正好站在 $j$ 号线的站台上"**（$i$ 在 $t_i$ 的截面 $\subseteq$ $j$ 在 $t_j$ 的截面），**就能换乘成功**。

### 2.6 Example 14.1（单摆：从 swing-up 切换到 balance）

> **Example 14.1（Pendulum: transitioning from swing-up to balance）**

**人话（这正是第3章 3.6 的"两段式"控制，现在用本章的语言重新理解）**：
- **招式1 = 能量整形 swing-up 控制器**：它的"漏斗"把摆**泵到同宿轨道附近**（收招集 = 摆"擦着倒立点转"的那条窄带）。
- **招式2 = LQR 平衡控制器**：它的"起手区" = 倒立点附近的一个小椭球。
- **组合条件**：**swing-up 的收招窄带 $\subseteq$ LQR 的起手椭球** → **一旦摆被泵进这个窄带，就安全地切到 LQR，由 LQR 把它"钉死"在倒立点**。
- **这就是第3章"swing-up + balance"的'为什么能切换'的严格解释**——**以前我们靠"经验阈值"切换，现在我们知道"切换之所以安全，是因为漏斗包含条件成立"**。

## 3. 参数化的技能与漏斗（14.1.2）—— "一招学会，处处能用"

> **类似地**，我们可以**把"连续反馈技能"的概念，扩展到"参数化的技能 / 漏斗"**——**比如当技能是"目标条件化（goal-conditioned）"的时候**（同一个控制器，传不同的"目标"参数，就能去不同的地方）。

**类比（一个"走向目标"的通用招式，必懂）**：
- 非参数化技能 = "**走到厨房**"这一招（写死了目标）。
- 参数化 / 目标条件化技能 = "**走向 $\langle$目标$\rangle$**"这一招——**传"厨房"就走去厨房，传"卧室"就走去卧室**。**一个控制器，一族漏斗**（每个目标对应一个漏斗）。
- **这样规划时，"技能库"不用为每个目标存一份，而是存"一个带参数的招式 + 一族参数化的漏斗"**——**极大压缩了技能库**。

### 3.1 Example 14.2（Koditschek 的杂耍机器人）

> **Example 14.2（Koditschek's juggling robots）**

**人话**：**杂耍机器人要"把球颠到不同高度 / 不同节奏"**——**这正是"参数化技能"的天然场景**：**同一个"镜像律"控制器（第4章 4.5），传不同的"期望能量 $E_d$"参数，就颠出不同高度**；**每个 $E_d$ 对应一个"把球稳定在该高度的漏斗"**。**于是"杂耍"被表示成"一族参数化漏斗"，高层规划只需"选参数序列"**。

### 3.2 三个"特别好使"的特殊情况

> **多项式参数化 + SOS** 是通用路线。**但有几个特殊情况，能 work 得特别好**……

**① 等变性 / 循环坐标（Equivariance / cyclic coordinates）[4]**

**人话**：**如果系统有"对称性"**（比如地面是平移对称的——在 $x=0$ 走路和在 $x=5$ 走路，物理一模一样），那么**一个漏斗可以"沿对称方向平移复用"**——**学会"在原点走路"的漏斗，平移一下就得到"在 $x=5$ 走路"的漏斗**，**不用重新算**。**[4]（Majumdar 的博士论文《Funnel Libraries for Real-Time Robust Feedback Motion Planning》）的核心，就是建一个"漏斗库（funnel library）"，靠对称性让少量漏斗覆盖一大片状态空间**。

**类比**：**学会"在平地上迈一步"的招式，因为平地处处一样，这个招式在操场的任何位置都好使**——**你不用为操场的每个点单独学一招**。

**② 状态依赖 Riccati 方程（SDRE, State-Dependent Riccati Equation）[5]**

**人话**：**把非线性系统在每个状态 $x$ 处"冻结"成一个线性系统**（把非线性项当成"随状态变的系数"），**然后解一个"随 $x$ 变的 Riccati 方程"**，得到**随状态变的增益 $K(x)$ 和代价矩阵 $S(x)$**——**$S(x)$ 直接当 Lyapunov 候选 / 漏斗**。**[5] 用这套做"参数化运动规划库的代数验证"**。

**类比**：**LQR 给的是"一个固定的碗"；SDRE 给的是"在每个点现场捏一个局部碗，再把这些碗拼成一张随位置变化的'变碗地图'"**——**碗的形状跟着状态走**。

**③ 通过标称轨迹参数化（Parameterizing via a nominal trajectory）**

**人话**：**漏斗是"围绕一条标称轨迹"的管子**；**如果你把这条标称轨迹本身参数化**（比如"以不同速度 / 不同终点 / 不同曲率"的一族轨迹），**那么漏斗也跟着参数化**——**得到"一族围绕一族轨迹的管子"**。**规划时，先选一条参数化轨迹，再套上对应的漏斗**。

**类比**：**先画一族"候选路线"（参数化轨迹），再给每条路线"套上对应粗细的安全管"（参数化漏斗）**——**规划 = 在这一族"带管路线"里挑一条能连到目标的**。

## 4. 概率反馈覆盖（14.2）—— LQR-Trees：在状态空间"种一棵带安全网的树"

> **有一种很漂亮的方法，能把"采样运动规划"的思想，和"带保证的漏斗顺序组合"结合起来 [6]。**

**人话（这就是著名的 LQR-Trees，[6] = Tedrake, Manchester, Tobenkin, Roberts, 2010）**：
- **第12章的采样规划（RRT）** = **在状态空间随机撒点、连边，长成一棵"探索树"**——**但它连的边是"轨迹"，不扛噪声**。
- **LQR-Trees 的改造** = **每撒一个点 / 每连一条边，都"配一个 LQR 控制器 + 一个 SOS 验证的漏斗"**——**于是树的每条边不再是"一根细线"，而是"一根管子"**。
- **"连接"两个节点** = **验证"父节点的漏斗 ⊆ 子节点的漏斗"**（组合条件）——**保证"车一旦进了树，就能顺着管子流到根（目标）"**。
- **不断随机撒点、长漏斗、连边，直到"漏斗的并集"覆盖了"我们关心的整片初始状态区域"**——**这就是"概率反馈覆盖（probabilistic feedback coverage）"**：**像 RRT 一样"概率完备"，但每条边都带数学保证**。

**类比（在状态空间种一棵"带安全网的攀爬架"，必懂）**：
- 普通 RRT = **在墙上钉一排钉子、拉一根根细绳**——**看着能爬，但风一吹绳就晃，不保险**。
- LQR-Trees = **钉钉子的同时，给每根绳"套上一根粗钢管"**——**你抓着钢管爬，怎么晃都不掉**。
- **不断加钉子加钢管，直到"整面墙都被钢管网络覆盖"**——**于是从墙上任何一点出发，你都能"抓着钢管"安全爬到顶**。**"覆盖"是概率的（撒得越多覆盖越全），但"每根钢管的安全"是数学保证的**——**这就是"概率反馈覆盖"的精髓：用采样的'广度' + 漏斗的'保证'，二者兼得**。

## 5. 在线规划（14.3）—— 占位 + 概念补充

> **14.3 Online planning**：**PDF 只有标题，正文留白（占位）。**

**补充概念（把占位背后的"该懂的东西"补齐）**：

**类比**：**离线漏斗库 = 事先印好的"城市安全地铁图"，在线规划 = "遇到封路时，现场用无人机探一条新的安全通道并立刻验证它扛不扛得住风"**。

## 增补一：把"还不够通俗"的 4 个概念，各加一个类比 / 澄清

1. **为什么"先规划再稳定"不够，要"规划时就带漏斗"**？"先规划轨迹 + 再用 LQR 稳定"= **先画细线，再事后给线套管子**——**但管子可能"套不上"**（轨迹经过的地方，线性化太差 / 障碍太近，漏斗太细甚至不存在），**于是你规划完才发现"这条线根本护不住"**。**"规划时就带漏斗"** = **画线的同时就检查"这地方套得下多粗的管子"，套不下就换线**——**把"可鲁棒性"作为规划的约束，而不是事后补救**。
2. **$\bar\rho_i$（内层）和 $\rho_i$（外层）为什么不能合并成一个**？因为**有噪声时，外层 $\rho_i$ 上你只能保证"不出"（$\dot V\preceq 0$），保证不了"收敛"**——**车可能在外层边界"贴着晃"，永远不进内层**。如果你**只用一个圈**当"收招集"，你**没法保证车真的会落进去**，**切换就不安全**。**分两层 = 外层"兜底不出"，内层"保证必到"，用内层做交接**——**这是"鲁棒组合"必须的双层结构**。
3. **椭球包含的"形状矩阵"判据（代码1 的依据）**：椭球用**形状矩阵** $Q=P^{-1}$ 写成 $E(Q)=\{x\mid x^TQ^{-1}x\le 1\}$。**两个中心都在原点的椭球，$E(Q_1)\subseteq E(Q_2)\iff Q_1\preceq Q_2$**（即 $Q_2-Q_1\succeq 0$）。**直觉**：$Q$ 越大，椭球越"胖"；**$Q_1\preceq Q_2$ = "蛋1 在每个方向都不比蛋2 大" = 蛋1 在蛋2 里**。**这就是代码1 检查 `eigvalsh(Q2-Q1)>=0` 的数学依据**——**简洁、精确、可跑**。
4. **LQR-Trees 为什么"概率"完备而非"确定"完备**？因为它**靠随机采样撒点**——**和 RRT 一样，"撒得越多，漏斗并集覆盖目标初始区域的概率越趋于1"**，**但理论上"极小概率还有没覆盖到的缝"**。**"概率"来自采样的随机性，"保证"来自每个漏斗的 SOS 验证**——**二者正交，所以叫"概率反馈覆盖"**。

## 增补二：代码实践（重点！PDF 几乎无代码，全部翻译成可跑 / 骨架脚本）

> 说明：**(A) 纯 NumPy 版**真实可跑，验证"包含 / 组合 / 种树"的核心逻辑；**(B) Drake SOS 骨架版**展示"多项式漏斗严格验证"的标准写法，细节以你本地 Drake + 求解器为准，**重点看结构**。

### 实验 1：椭球包含 —— 二次漏斗的"包含"解析判据（可跑，对照 14.1.1 的"二次→椭球包含"）

**验证"招式1 的收招内圈 $\subseteq$ 招式2 的起手外圈"**，用形状矩阵判据 $Q_1\preceq Q_2$。

```python
import numpy as np
# 两个二次 Lyapunov: V1=xᵀP1 x (招式1), V2=xᵀP2 x (招式2)
P1 = np.array([[2.,0.],[0.,1.]])          # 招式1 的"碗"
P2 = np.array([[1.,0.],[0.,0.5]])         # 招式2 的"碗"
rho_bar = 1.0                              # 招式1 的收招内圈水平
rho     = 1.0                              # 招式2 的起手外圈水平
# 归一化成 {x | xᵀ(P/ρ)x ≤ 1}，形状矩阵 Q = ρ * P⁻¹
Q1 = rho_bar * np.linalg.inv(P1)          # 内圈椭球形状
Q2 = rho     * np.linalg.inv(P2)          # 外圈椭球形状
# 包含判据: E(Q1) ⊆ E(Q2)  <=>  Q1 ⪯ Q2  <=>  Q2-Q1 ⪰ 0
eigs = np.linalg.eigvalsh(Q2 - Q1)
print("Q2-Q1 特征值 =", np.round(eigs,4))
print("内圈 ⊆ 外圈 (可安全切换)?", bool(np.all(eigs >= -1e-9)))
# 调 P2 让它"更小"，会看到包含失败 -> 切换不安全
```

**你会看到**：**当 $Q_2-Q_1$ 半正定时打印 `True`**——**亲手验证"收招蛋在起手蛋里 = 可切换"**。**把 `P2` 调大（让招式2 的起手圈变小）**，**特征值变负 → `False`**——**亲眼见"交接区超出接棒区 = 连招失败"**。

### 实验 2：技能组合的图搜索 —— 把"连招"变成"图上找路"（可跑，对照 14.1 / 14.1.1 全章思想）

**每个技能 = 节点（带"起手椭球 $Q^{start}$"和"收招椭球 $Q^{end}$"）；边 $i\to j$ 存在 $\iff$ $Q^{end}_i \subseteq Q^{start}_j$（用实验1 的判据）。然后 BFS 找从"覆盖初始状态的技能"到"目标技能"的连招序列。**

```python
import numpy as np
from collections import deque
def contained(Q_end, Q_start):                     # Q_end ⊆ Q_start ?
    return np.all(np.linalg.eigvalsh(Q_start - Q_end) >= -1e-9)
# 5 个技能，每个给 (起手形状矩阵, 收招形状矩阵)（对角椭球，数值越小蛋越大）
skills = {
 'A':(np.diag([1,1]),   np.diag([2,2])),          # A 收招蛋较小
 'B':(np.diag([1.5,1.5]),np.diag([3,3])),
 'C':(np.diag([2.5,2.5]),np.diag([4,4])),
 'D':(np.diag([3.5,3.5]),np.diag([5,5])),
 'G':(np.diag([4.5,4.5]),np.diag([6,6])),          # G=目标技能
}
names=list(skills); n=len(names)
# 建边: i->j 若 i 的收招 ⊆ j 的起手
adj={i:[] for i in range(n)}
for i in range(n):
    for j in range(n):
        if i!=j and contained(skills[names[i]][1], skills[names[j]][0]):
            adj[i].append(j)
# BFS 从 A(0) 到 G(4)
start, goal = 0, 4; q=deque([(start,[start])]); seen={start}
while q:
    u,path=q.popleft()
    if u==goal: print("连招序列 =", " -> ".join(names[p] for p in path)); break
    for v in adj[u]:
        if v not in seen: seen.add(v); q.append((v,path+[v]))
else: print("无可行连招")
```

**你会看到**：**打印出一条 `A -> B -> ... -> G` 的连招**——**每一步都满足"上一招收招蛋 ⊆ 下一招起手蛋"**。**故意把某个技能的起手蛋调小**，**会看到连招断链 / 换一条路**——**亲手把 Figure 14.1 的"组合规则"跑成一个图搜索**。

### 实验 3：时变漏斗包含 —— 轨迹管子的"换乘"检查（Drake SOS 骨架 + numpy 采样近似）

**对应 14.1.1 的时变组合条件 $V_i(t_i)\le\rho_i(t_i)\Rightarrow V_j(t_j)\le\rho_j(t_j)$。** 严格版用 SOS 在 $\{V_i=\rho_i\}$ 上证蕴含；这里给**逐时刻采样近似**让你看"在哪些 $(t_i,t_j)$ 对能换乘"。

```python
import numpy as np
# 时变漏斗: 截面椭球形状随时间变 Q(t)（这里 toy: 管子先细后粗）
def Q_i(t): return np.diag([1+0.5*t, 1+0.3*t])     # 招式 i 的管截面
def Q_j(t): return np.diag([2+0.2*t, 2+0.4*t])     # 招式 j 的管截面
T = np.linspace(0,5,50)
# 找所有"可换乘"的 (ti,tj): Q_i(ti) ⊆ Q_j(tj)
pairs=[]
for ti in T:
    for tj in T:
        if np.all(np.linalg.eigvalsh(Q_j(tj)-Q_i(ti)) >= -1e-9):
            pairs.append((round(ti,1),round(tj,1)))
print("可换乘的 (ti,tj) 对数 =", len(pairs), " 例:", pairs[:3], "...")
# Drake SOS 严格版骨架（在 Vi=ρi 边界上证蕴含，用 S-procedure 乘子 λ）:
#   prog = MathematicalProgram(); V_i,V_j,ρ_i,ρ_j 为符号多项式
#   λ = prog.NewSosPolynomial(...)   # 乘子
#   prog.AddSosConstraint( (V_j-ρ_j) + λ*(V_i-ρ_i) 的"反向"蕴含形式 )  # 见第9章9.2.3
#   时变版把 t 也作为 indeterminate 加入
```

**你会看到**：**一批 $(t_i,t_j)$ 对满足换乘**——**印证"不必同一时刻对接，只要某个截面包含另一个截面"**。**SOS 骨架**展示"严格版怎么把时变包含写成带乘子的 SOS"。

### 实验 4：LQR-Trees 思想演示 —— 撒点 + LQR 漏斗 + 连接，长一棵"带管子的树"（可跑，对照 14.2 / [6]）

**简化版**：随机撒目标状态，每个用 LQR 得一个"局部漏斗"（用 LQR 的 $S$ 当 ROA 椭球近似——**不严格，严格版用 SOS 漏斗**），尝试把新漏斗"连到树上"（新漏斗的根落在某个已有漏斗内）。**看树怎么长大、漏斗并集怎么覆盖。**

```python
import numpy as np
from scipy.linalg import solve_continuous_are
A=np.array([[0,1],[0,0]]); B=np.array([[0],[1]])   # 双积分器 toy
Q=np.eye(2); R=np.eye(1)
S=solve_continuous_are(A,B,Q,R)                     # LQR 代价矩阵 ~ 局部"碗"
def lqr_ellipsoid(center, scale=1.0):               # 用 S 的逆当漏斗截面形状(近似ROA)
    return center, scale*np.linalg.inv(S)
rng=np.random.default_rng(0)
tree=[lqr_ellipsoid(np.array([0.,0.]), 1.0)]        # 根=目标
def in_any_egg(x):                                   # x 落在树里某个漏斗内?
    return any((x-c)@np.linalg.inv(Qi)@(x-c) <= 1.0 for c,Qi in tree)
for _ in range(60):                                 # 随机撒点长树
    x_new = rng.uniform(-3,3,2)
    if in_any_egg(x_new): continue                  # 已被覆盖，跳过
    # 尝试连接: 新漏斗的"收招"(=它自己中心附近) 能否连到树上某漏斗?
    c_new, Q_new = lqr_ellipsoid(x_new, 0.6)
    # 连接条件(简化): 新中心落在某已有漏斗内 -> 接上
    if any((x_new-c)@np.linalg.inv(Qi)@(x_new-c) <= 1.0 for c,Qi in tree):
        tree.append((c_new,Q_new))
print("LQR-Tree 漏斗数 =", len(tree),
      "-> 撒点越多漏斗越多，'反馈覆盖'越全（概率完备）；每个漏斗=带保证的管子")
# 可视化: 画每个椭球 -> 看到一棵"带安全管的树"逐渐铺满区域
```

**你会看到**：**漏斗数随撒点增长，椭球逐渐铺满区域**——**亲手复现 LQR-Trees 的"概率反馈覆盖"**。**注意**：这里用 $S^{-1}$ 近似 ROA 是"思想演示"；**[6] 的严格版用 SOS 算每个 LQR 控制器的真漏斗，并用实验1/2 的包含条件连边**——**把这段的 `in_any_egg` / 连接条件换成 SOS 验证，就是论文本尊**。

### 实验 5：SOS 漏斗包含的 Drake 骨架 —— 多项式技能的严格组合（对照 14.1.1 的"多项式用 SOS + S-procedure"）

**证明 $V_i(x)\le\bar\rho_i \Rightarrow V_j(x)\le\rho_j$**，用 S-procedure 乘子 $\lambda$。

```python
from pydrake.all import MathematicalProgram, Variables
from pydrake.symbolic import Variable
# 符号状态
x = Variables([Variable("x0"), Variable("x1")])
prog = MathematicalProgram()
# V_i, V_j 为给定的多项式 Lyapunov (这里占位: 用 SOS 搜出来的或 LQR 的二次型)
V_i = ... ; V_j = ... ; rho_bar = 1.0 ; rho = 1.0
# S-procedure: 要证 (V_i - rho_bar <= 0) => (V_j - rho <= 0)
# 充分条件: 存在 SOS 乘子 λ, 使  -(V_j - rho) - λ*(V_i - rho_bar)  is SOS  (注意符号方向)
lam, _ = prog.NewSosPolynomial(Variables(x), degree=2)
prog.AddSosConstraint( -(V_j - rho) - lam*(V_i - rho_bar) )
sol = Solve(prog)
print("漏斗包含 (V_i≤ρ̄ => V_j≤ρ) 可证?", sol.is_success())
# 时变/参数化版: 把 t 或参数 θ 也加入 Variables，乘子也对其多项式 -> 证一族漏斗的组合
```

**人话**：**这就是 14.1.1 "多项式 Lyapunov 用 SOS + S-procedure 证包含"的代码形态**——**和第9章 9.2.3 的 ROA 蕴含是同一个套路，只是把"动力学 $\dot V\le 0$"换成了"另一个 Lyapunov 的子水平集"**。**参数化技能（14.1.2）= 把参数也塞进 `Variables`，一次证"一族包含"**。

## 给初学者的"本章通关三句话"

1. **规划的原语，从"轨迹"换成"带漏斗的技能"**：轨迹是一根**细线**，噪声一吹就废（**trajectories can't be robust**）；漏斗是一根**管子**，车在管里晃但不出壁（**but funnels can**）。**每个技能 = 控制器 + 吸引域（前置/启动集）+ Lyapunov（后置）**——**这正是把 STRIPS 的"前置/后置条件"搬到了连续控制上**。
2. **连招靠"包含"，组合靠"双层圈"**：要使"招式 $i$ → 招式 $j$"安全，**必须"招式 $i$ 的收招内圈 $\bar\rho_i$ 整个落在招式 $j$ 的起手外圈 $\rho_j$ 里"**；而**有噪声时外圈只能保证"不出"、内圈才保证"必到"**，所以**必须分两层**——**多项式漏斗用 SOS + S-procedure 证包含，二次漏斗简化为椭球包含 $Q_1\preceq Q_2$，时变漏斗则"截面包含即可换乘"**。
3. **采样给广度，漏斗给保证，二者兼得 = LQR-Trees**：**像 RRT 一样随机撒点长树，但每条边配一个 SOS 验证的漏斗**，**不断长到"漏斗并集覆盖整片初始区域"**——**这就是"概率反馈覆盖"**；**而参数化技能（等变性漏斗库 / SDRE / 目标条件化）让"一招学会、处处能用"，把技能库压缩到能实时查**——**最终，离线漏斗库 + 在线 TubeMPC，构成了"从印好的安全地铁图，到现场探的安全通道"的完整鲁棒规划谱系**。
