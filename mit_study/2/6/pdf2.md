## 0. 开篇：为什么需要"自动导航"？

### 0.1 一句话概括

> **手写脚本和微分逆运动学能解决"简单已知环境"的抓取，但环境一乱、要避障、要提速就崩。这一章给你三类自动规划工具：① 把逆运动学当成"带约束的优化"；② 把整条轨迹当成优化对象（轨迹优化）；③ 当优化卡局部极小时，用"随机撒点长树"的采样方法全局探路；最后用"凸集图 GCS"把前两者的优点合二为一。**

### 0.2 引言逐句翻译 + 类比

作者先列了**三个"为什么需要自动规划"的理由**：

1. **环境变乱**：环境越杂乱，手写脚本越难写，还得担心**手臂撞环境**、**夹爪撞环境**。
2. **移动操作（mobile manipulation）**：手臂装在移动底盘上，每次到的环境都不同，即使几何不复杂，也每次都不一样，需要自动（哪怕简单）的规划。
3. **提速**：如果机器人在简单已知环境里干一整天，**优化它执行的轨迹能显著提速**。

> 作者还补了一句大实话：如果你跑过 clutter clearing demo，会发现**运动规划失败是那个方案最大的短板**——手或物体有时撞相机/箱子，或者微分逆运动学（它基本无视关节角）有时让机器人"自己把自己折起来"。这一章就是来治这个病的。

**类比（手写路线 vs 导航 App，全章总纲）**：
- 前面手写脚本 = **你背死一条固定路线**，环境一变就废。
- 自动规划 = **导航 App**：你只说"从 A 到 B"，它自己算路、避障、还能在堵车时重算。

### 0.3 作者对"无碰撞规划"问题表述的批评（很重要，别跳过）

> 作者坦白：尽管他自己也做过这个领域，但他**其实很讨厌"无碰撞运动规划"这个问题表述**。他认为**机器人整体上太怕撞东西了**（因为真撞了还是会出错）。他**不相信人类每次伸手都在解复杂几何问题**——哪怕在密集杂乱里伸手，他怀疑人类其实**很不会解**这些几何问题。他**更希望看到**这样的机器人：**即使只有很粗糙/近似的穿杂乱环境的计划，也不怕偶然接触，撞了也还能完成任务**。

**类比**：人类伸手拿杯子，**不会先在脑子里建个 3D 模型算无碰撞路径**，而是**大致伸过去，碰一下杯子边缘微调一下，照样拿到**。作者希望机器人也这样"**皮实**"，而不是"碰一下就报错停机"。**这个观点贯穿全章**——后面 GCS、TOPP 追求的是"带保证的规划"，但作者心里更想要"不怕撞的鲁棒机器人"。

## 1. 逆运动学 IK（6.1）—— "理解 IK，就掌握了规划的大部分"

> 作者一句关键论断：**"如果你真懂怎么解逆运动学，那规划轨迹需要的东西你大半就有了。"** 所以这一章从 IK 讲起。

### 1.1 IK 不是"求逆函数"，而是"带约束的优化"

我们知道前向运动学给一个**非线性映射**：末端位姿 $X_G = f_{kin}(q)$（关节角 $q$ → 末端位姿）。于是你自然以为 IK 就是求逆 $q = f_{kin}^{-1}(X_G)$。但作者说，**别这么想**——和微分逆运动学一样，**把 IK 想成"在丰富的代价和约束库里找关节角"的更一般问题**。

**为什么不能简单求逆？** 因为：
- **多解**：同一个末端位姿，关节角可能有**好几个甚至无穷多个**解（手臂可以"肘朝上"或"肘朝下"够到同一点）。
- **无解**：够不到的地方，逆根本不存在。
- **约束丰富**：我们几乎从不会"只有末端位姿约束"，**几乎总有**关节空间的代价/约束（如**关节限位**）和笛卡尔空间的约束（如**不穿透**）。

**类比（IK 像"找最舒服的姿势"，必懂）**：
- 简单求逆 = "解方程组"——可能无解、可能多解，僵死。
- IK 优化 = "**在所有能碰到目标的姿势里，挑一个最舒服的**"（比如离"自然站姿"最近）。**而且还能加一堆规矩**："肘别超过 120 度""别撞桌子"。

### 1.2 6.1.1 从末端位姿到关节角：代数几何与 IKFast

作者先讲了一个"硬核但完整"的背景：**前向运动学虽然非线性，但结构很特殊**——除了螺旋关节，**机器人有效笛卡尔位置的方程其实是多项式**！

> "等等，我的运动学方程里不全是 sin、cos 吗？" 作者解释：三角项出现在"关节角↔笛卡尔坐标"的关系里。但**同一刚体上两点 $A,B$ 的距离平方 $\|p^A-p^B\|^2$ 是常数**（多项式约束），**关节也只是"相邻刚体上两点重合"的多项式约束**。理解多项式方程的解 = **代数几何**的课题。对四杆机构、Stewart 平台这种复杂拓扑，我们能**数解的个数**、理解解的连续流形。

但代数几何算法**传统上面向离线全局分析**，**不适合控制环里要的实时 IK**。如今实时 IK 最流行的工具是 **IKFast**：它**不追求完备**，用一堆近似给"简单"IK 问题提供**快速、数值鲁棒**的解——利用"6DOF 机械臂的 6DOF 位姿约束有闭式解（有限个关节构型）"，对 7DOF 则在 6DOF 求解器上**对最后一个自由度采样**。

**类比**：代数几何 = "**用代数把机器人所有可能姿势的'解的地图'画全**"（精确但慢，离线用）；IKFast = "**只画常用区域的快速近似地图**"（快，实时用）。

### 1.3 6.1.2 IK 作为约束优化（核心）+ 代码 1

与其写 $q = f_{kin}^{-1}(X_G)$，不如解优化：

$$\min_q \|q - q_0\|^2 \quad \text{s.t.} \quad X_G = f_{kin}(q) \qquad (1)(2)$$

$q_0$ 是"舒服的名义姿势"。**这个表述更精确**：多个解时，挑离 $q_0$ 最近的。**但真正价值**是：换成优化视角，就能接上**丰富的额外代价和约束库**。

**Figure 6.2**：更丰富的 IK——解关节角 $q$ 让机器人伸进货架抓物体，同时避碰。

**和微分 IK 的关系**：微分 IK 我们用过伪逆、再升级到最小二乘，能加关节限/速度限/避碰约束。但那是**在名义构型附近找小变化**，所以非线性/非凸约束做线性/凸近似很合理。**现在考虑完整表述**：**直接解非线性/非凸优化，不限制"只做小变化"**——计算上难得多，但用 SNOPT 这种强非线性求解器，**常常能在交互速率下解出来**（下面例子很好玩）。**但没保证**：求解器返回"infeasible"时，解**可能其实存在**。

> 微分 IK 和完整 IK 紧密相关：**微分 IK 可以看成完整非线性问题的"一步投影梯度下降 / 一步 SQP"**。

Drake 提供 `InverseKinematics` 类，把标准运动学/多体约束装进 `MathematicalProgram`：两体相对位置/朝向约束、两体最小距离（不穿透）、最大距离等。

**Example 6.1（交互式 IK）**：notebook 里两个版本。第一版用滑块控制末端位姿（简单 IK，但仍用完整非线性优化引擎解，含关节限）。第二版**在机器人正前方加一根柱子**：微分 IK 和完整 IK 都能加避碰约束防你撞柱子；但**当你把目标从柱子一边移到另一边，完整 IK 能切换到"手臂绕到柱子另一侧"的新解，而微分 IK 永远跨不过去**（它会停在柱子第一侧，宁可不动也不允许碰撞）。

**Figure 6.3**：目标沿 $+y$ 移动时，IK 求解器找到手臂绕到柱子另一侧的新解。

**作者的两条 IK 建议（很重要）**：
1. **目标（代价）保持简单**：他通常**只用"关节居中（joint-centering）"二次代价**。把本该是约束的东西塞进代价当惩罚，会导致大量"调代价函数"的苦活。
2. **约束写最小化**：让可行构型集合**尽可能大**。比如不需要完全约束夹爪朝向，就别约束。

**Example 6.2（抓圆柱）**：用 IK 抓圆柱（想象成扶手）。**沿圆柱抓在哪、抓的朝向都无所谓**，那就**只写这些约束的最小版本**。notebook 里圆柱位姿放滑块上，你移动它，看 IK 怎么摆机器人——**特别地，沿 $\pm y$ 移圆柱，机器人不会跟着走……直到手到圆柱末端**。

作者的实现技巧：在夹爪坐标系定义**两个点** $^{B}p^Q=[0,.1,0]$ 和 $[0,.1,-0.02]$、$[0,.1,0.02]$（夹爪两垫之间的点），用 `AddPositionConstraint` 要求这两点**正好落在圆柱中心线段上**（$p_{AQ}$ 范围 $[0,0,-0.5]$ 到 $[0,0,0.5]$）。**这一招紧凑地留下了"绕圆柱轴的朝向自由"，又抓住了圆柱位置约束**。

**Example 6.3（可视化配置空间）**：回到 iiwa 伸货架。两个主约束：① 目标球心在夹爪中心；② 手臂避碰货架。为画约束，**冻结 iiwa 三个关节**，只剩平面内三个关节。在三个关节角的密网格上采样，每格标 1（满足）或 0，跑 **marching cubes** 提取约束在配置空间的近似 3D 几何。"抓球"约束产生右边漂亮的绿色几何（被关节限裁剪）；**避碰约束则复杂得多**——你得打开 3D 可视化自己转着看，"吓人！"

**Example 6.4（可视化 IK 优化景观）**：只看返回解附近一小块。绿色面 = 代价景观（简单二次关节居中代价）；约束**可行画蓝、不可行画红**：关节限是简单 bounding-box（只画红不可行区）；位置约束三元素（$x,y,z$），$y$ 平凡满足（全蓝，因机械臂只在平面动），另两个看着全红，关掉可视化能看到两条窄蓝条；**最震撼/吓人的是"最小距离"（不碰撞）约束**——把距离画成实值函数， reveals 给求解器的优化景观。所有蓝区的交 = 上例的配置空间。

**类比（配置空间 = "把机器人所有关节角当成一个点"，必懂）**：
- 机器人有 7 个关节角 → 配置空间是 7 维空间里的**一个点**。
- "撞货架"在笛卡尔空间是个复杂形状，但**映射到配置空间，变成一块"禁区"**。
- IK/规划 = **在这 7 维空间里，从起点走到终点，不碰禁区**。
- 配置空间障碍**形状极其扭曲**（Example 6.3/6.4 的"吓人"几何），这就是规划难的根源。

### 🧪 代码 1：IK 作为约束优化（scipy，可跑，2D 两连杆）

PDF 没内联代码，这段用 scipy 演示"IK = 带等式约束+关节限的优化"，对照 (1)(2)。

```python
import numpy as np
from scipy.optimize import minimize
L1, L2 = 1.0, 1.0
q0 = np.array([0.3, -0.3])                      # 舒服的名义姿势
def fk(q):                                       # 2D 两连杆前向运动学
    x = L1*np.sin(q[0]) + L2*np.sin(q[0]+q[1])
    y = -L1*np.cos(q[0]) - L2*np.cos(q[0]+q[1])
    return np.array([x, y])
target = np.array([0.6, -1.2])                   # 想要的末端位置
cons = [{'type':'eq','fun': lambda q: fk(q)-target}]   # 等式约束 XG=fkin(q)
bnds = [(-2,2),(-2,2)]                           # 关节限
res = minimize(lambda q: np.sum((q-q0)**2), q0, bounds=bnds, constraints=cons)
print("IK 解 q =", np.round(res.x,3), " 末端误差 =", round(np.linalg.norm(fk(res.x)-target),6))
# 改 target 到够不到的地方 -> res.success=False (解可能不存在, 求解器报 infeasible)
```

**你会看到**：求解器返回一个**离 $q_0$ 最近、且末端精确到 target** 的关节角；把 target 改到够不到的地方，`res.success=False`——**亲眼见"IK 优化在无解时报 infeasible，但解其实可能存在（局部极小陷阱）"**。

### 1.4 6.1.3 全局逆运动学

无约束 6DOF IK 有闭式解；带丰富代价约束的广义 IK 是非线性优化，**实践好用但受局部极小困扰**（解可能存在却找不到）。**放弃交互速率，能否鲁棒地解到全局最优？** 这非常相关：离线生成训练数据训神经网络学 IK、工作空间分析、某些规划策略的离线"建造"阶段，都需要全局 IK。

作者经验：通用全局非线性求解器（MINLP、SMT 区间算术）**通常 scale 不到完整机械臂**。但**稍微限制代价/约束类**，就能进展。Drake 实现了 [5] 的 `GlobalInverseKinematics`，用**混合整数凸优化**，解时间几秒，完整约束双臂问题不到一分钟。[6] 用**半正定规划松弛层级**解窄版问题（只末端位姿+关节限）。

### 1.5 6.1.4 IK vs 微分 IK：何时用哪个

**IK** 解更全局的问题，但**不保证成功**，也**不保证代价/约束小变化时 $q$ 只小变化**（可能给机器人发大指令）。**需要解全局问题、或下一节要产实际轨迹时用 IK**。**微分 IK** 对**增量运动**极好——比如你能在末端空间设计平滑指令、在关节空间跟踪它。

### 1.6 6.1.5 用 IK 做抓取规划

第一版抓取选择里，我们放了"奖励从上方抓"的目标——这其实是"我们真想解的问题"的**糟糕代理**：我们想要"给定机器人舒服姿势下能实现的抓取"。所以**自然扩展**：对抓取候选**解一个 IK**，**用关节居中代价直接当目标**（代替末端朝向代价），**IK 不可行就拒绝样本**。

**更漂亮的扩展**（优化视角下自然）：任务不仅要在杂乱里**抓起**，还要在杂乱里**小心放下**。这时**好抓取 = 同时优化 pick 和 place 配置的夹爪相对物体位姿**。可以写**决策变量含 $q_{pick}$ 和 $q_{place}$**、约束 $^{O}X_G^{pick}=\,^{O}X_G^{place}$ 的优化，仍加所有丰富代价约束。**TRI 的装盘项目里这招极重要**：从水槽抓杯子、放进洗碗机架都高度约束，需要同时优化才找到成功抓取。

## 2. 运动学轨迹优化（6.2）—— "把整条轨迹当优化对象"

> 懂了 IK 的优化视角，就离"运动学轨迹优化"不远了。**不再独立解多个 IK，而是在一个优化里同时解一系列关节角**。更好：定义**参数化关节轨迹** $q_\alpha(t)$，$\alpha$ 是参数向量。IK 的简单扩展：

$$\min_{\alpha,T}\ T \quad \text{s.t.}\quad X_G^{start}=f_{kin}(q_\alpha(0)),\quad X_G^{goal}=f_{kin}(q_\alpha(T)),\quad \forall t,\ \|\dot q_\alpha(t)\|\le v_{max} \qquad (3)(4)(5)(6)$$

读作："**找一条轨迹 $q_\alpha(t)$，$t\in[0,T]$，让夹爪从起点到终点，时间最短**"。最后一行 (6) 是**速度限**——**这是我们告诉优化器"机器人不能瞬间瞬移"的唯一方式**。除了这行看着不太标准，**几乎就是"联合解两个 IK"**，只是对 $\alpha$ 而非 $q$ 求梯度（用链式法则轻松搞定）。

### 2.1 6.2.1 轨迹参数化：B 样条的妙处

有趣问题：怎么用参数向量参数化轨迹？如今你可能想 $\alpha$ 是个神经网络（输入 $t$、输出 $q$、$\alpha$ 是权重偏置）。当然可以，但对**标量输入**，我们常取**更简单稀疏的多项式参数化**。

多项式参数化轨迹有很多方式：动态规划里 direct collocation 用分段三次多项式表状态轨迹，伪谱法用 Lagrange 多项式。每种基函数选择都是为了利用基的某个性质。动态规划里大量精力花在动力学方程的积分精度上以保证动力学约束可行。

**但规划全驱动机械臂运动时，我们通常不太担心动力学可行，而聚焦运动学**。对运动学轨迹优化，**B 样条参数化有几个特别好的性质**：

- **B 样条的导数仍是 B 样条**（次数降一），系数对原系数**线性**。
- **基本身非负且稀疏** → B 样条系数（称**控制点**）有强几何解释：**整条轨迹保证落在"活跃控制点的凸包"内**。
- **合起来**：我们能优化有限参数化轨迹，却**用凸包性质保证关节位置及其任意导数的限用线性约束满足**——这种保证用别的多项式基代价大得多。

> 注：B 样条和 Bézier 曲线密切相关。但 B 样条的"B"其实只代表"basis"（基，没开玩笑），Bézier 样条略有不同。

**类比（B 样条凸包 = "控制点围成的笼子"，必懂）**：
- 控制点 = 你钉在纸上的**几个钉子**。
- B 样条曲线 = **一根橡皮筋，保证跑不出"钉子围成的笼子（凸包）"**。
- 所以**只要钉子都在"安全区"，整条曲线就安全**——**限控制点 = 限整条曲线**，而且是**线性约束**（凸，好解）！这是 B 样条的杀手锏。

### 2.2 6.2.2 优化算法 + 代码 2

Drake 默认 `KinematicTrajectoryOptimization` 类优化**用 B 样条表路径 $r(s)$，$s\in[0,1]$**，加一个标量决策变量 = 轨迹时长 $T$。最终轨迹 $q(t)=r(t/T)$。**这是表"未知时长轨迹"的特别好的方式**，且凸包性质仍能用。**速度限仍线性**；加速度及更高导数约束变非线性，但满足则仍隐含严格界。

`KinematicTrajectoryOptimization` 用 Drake 的 `MathematicalProgram`，默认自动选求解器：只有凸代价约束→凸求解器；但通常加了运动学的非凸代价约束，**默认又是 SQP 求解器 SNOPT**。

**能加的最有趣约束之一**：`MinimumDistanceLowerBoundConstraint`——所有潜在碰撞对最小距离 > 0 则避碰。**但注意**：这些碰撞约束**只能在路径的离散采样点 $s_i$ 强制**，**不保证整条轨迹无碰撞**（只有导数约束的特殊性质才能用凸包性质，一般非线性约束没有）。常见策略：**优化时在适量采样点加约束，优化后在执行前对优化轨迹更密地查碰撞**。

**Example 6.5（货架间移动的运动学轨迹优化）**：热身：平面 iiwa 从顶层货架伸到中层。**仔细看代码**：作者**实际解了两次**才让 SNOPT 返回好解（不幸，因为是局部优化，这可能发生）。对这个特定问题，**奏效的策略是：先不带避碰约束解一次，再用那条轨迹当初猜，解带避碰约束的问题**。代码里还有个"**可视化回调**"：优化时画一条蓝线表轨迹——通过告诉求解器一个"依赖所有变量、总返回零代价"的代价函数实现，每次评估代价时调用。**这肯定会拖慢优化，但极适合直观感受求解器何时"挣扎"**。作者认为这领域求解器最快最鲁棒的人，**和"花时间可视化、按摩求解器数值"的人高度相关**。

**Example 6.6（clutter clearing 的运动学轨迹优化）**：也能用 `KinematicTrajectoryOptimization` 做 clutter clearing 规划。**这个优化更鲁棒，不需解两次**。作者只**种子了一条平凡初轨迹**，避免"机器人绕底座转 270 度而非走短路"的解。

**相关方法**：CHOMP [7]、STOMP [8]、KOMO [9]，差异在参数化或求解技术。**KOMO** 是用**增广拉格朗日**把约束优化转成无约束、再用简单快速梯度求解器的少数轨迹优化技术之一 [10]。**增广拉格朗日如今最流行成功**。**但比较求解器要小心**：SNOPT 在不能满足默认容差（约 1e-6）时会报失败，而增广拉格朗日**永不报失败、也很少追求这种精度**。

**运动学轨迹优化成功时**，是运动规划问题**极令人满意的解**：表达所需运动的自然表达语言，快到能在线规划。**唯一问题：不总成功**——基于非凸优化，**受局部极小困扰，即使解存在也可能找不到**。

**Example 6.7（无碰撞轨迹优化的局部极小）**：极简单例子：点机器人从起点（蓝圈）到终点（绿圈），避碰红盒子，找最短路。避开 B 样条复杂度，写优化：

$$\min_{q_0,\dots,q_N}\ \sum_{n=0}^{N-1}\|q_{n+1}-q_n\|_2^2 \quad \text{s.t.}\ q_0=q_{start},\ q_N=q_{goal},\ \|q_n\|_1\ge 1\ \forall n$$

最后一行是避碰约束：每个采样点在红盒子（$\ell_1$ 球）外。或写更高级约束保证每线段在障碍外。**Figure 6.7**：左 = 全局最小；右 = 明显局部极小。**一旦非线性求解器考虑"右绕"的路径，极不可能找到左绕解**，因为解得**先变糟（违反避碰约束）才能变好**。

**为对付这局限，无碰撞运动规划领域重度转向采样方法**。

### 🧪 代码 2：B 样条运动学轨迹优化概念（scipy，可跑，2D 点机器人绕障碍）

PDF 没内联代码。这段用 B 样条控制点参数化路径，对控制点加避障约束（用凸包性质的近似：控制点离障碍足够远），最小化路径长，对照 6.2。

```python
import numpy as np
from scipy.optimize import minimize
# 3 次 B 样条(均匀节点)的基, 控制点 P[0..M-1], 在 t∈[0,1] 求值
def bspline3(P, t):
    M = len(P); t = np.clip(t,0,1)
    u = t*(M-3)                                  # 映射到节点区间
    i = np.clip(np.floor(u).astype(int),0,M-4)
    s = u - i
    B0=(1-s)**3/6; B1=(3*s**3-6*s**2+4)/6
    B2=(-3*s**3+3*s**2+3*s+1)/6; B3=s**3/6
    pts = np.array([P[i+k] for k in range(4)]).T   # 4 x 2 x len(t) 简化逐点
    out=[]
    for k in range(len(t)):
        ik=np.clip(int(np.floor(u[k])),0,M-4); sk=u[k]-ik
        b=np.array([(1-sk)**3/6,(3*sk**3-6*sk**2+4)/6,(-3*sk**3+3*sk**2+3*sk+1)/6,sk**3/6])
        out.append(b@P[ik:ik+4])
    return np.array(out)
obs = np.array([0.5,0.5]); r_obs=0.2; margin=0.25     # 障碍圆+凸包margin
start, goal = np.array([0.,0.]), np.array([1.,1.])
M=6
def path(P): return bspline3(P.reshape(M,2), np.linspace(0,1,40))
def cost(P): P=P.reshape(M,2); pts=path(P); return np.sum(np.linalg.norm(np.diff(pts,axis=0),axis=1))
def cons(P):                                   # 控制点离障碍>margin (凸包近似保证段内安全)
    P=P.reshape(M,2); return np.linalg.norm(P-obs,axis=1)-(r_obs+margin)
P0 = np.linspace(start,goal,M) + 0.0          # 直线初猜
bnds=[(0,1)]*2*M
res = minimize(cost, P0.ravel(), bounds=bnds, constraints={'type':'ineq','fun':cons})
print("B样条轨迹优化 路径长 =", round(cost(res.x),3))
# 可视化: 画 path(res.x) 与障碍圆, 看曲线绕开障碍且落在控制点凸包内
```

**你会看到**：优化后的 B 样条**绕开障碍**，且**整条曲线落在控制点凸包内**——**亲眼见凸包性质**。**注意**：控制点避障只是"凸包近似"，**对全局非凸自由空间不能严格保证段内无碰撞**——这正是 PDF 强调"碰撞约束只能在采样点强制"的原因。

### 3.1 6.3.1 RRT（快速扩展随机树）+ 代码 3

**RRT 思想**：从起点长一棵树，每次**随机撒一个目标点 $q_{rand}$**，找树上**离它最近的节点 $q_{near}$**，朝 $q_{rand}$ 方向**延伸一步**得 $q_{new}$，加进树。**树天然朝"空白未探索区"长**（因为空白区离树远，被 $q_{rand}$ 命中后延伸概率高）。

**Example 6.8（基本 RRT）**、**Example 6.9（RRT "bug trap"）**：bug trap 是经典陷阱——起点在一个"U 形凹槽"里，RRT 要先在凹槽里填满、找到出口才能逃出，演示 RRT 在窄通道上的挣扎。

### 🧪 代码 3：RRT 纯 numpy 2D（可跑，画树）

```python
import numpy as np
import matplotlib.pyplot as plt
rng=np.random.default_rng(0)
obs=[(0.5,0.5,0.18)]                            # 障碍圆 (cx,cy,r)
def free(q): return all(np.hypot(q[0]-cx,q[1]-cy)>r for cx,cy,r in obs)
def seg_free(a,b,n=20):                         # 线段无碰撞?
    for t in np.linspace(0,1,n):
        if not free(a+t*(b-a)): return False
    return True
start,goal=np.array([0.1,0.1]),np.array([0.9,0.9]); step=0.15
tree=[start]; par={0:-1}
for _ in range(1500):
    qrand=rng.uniform(0,1,2)
    near=min(range(len(tree)),key=lambda i:np.linalg.norm(tree[i]-qrand))
    d=qrand-tree[near]; d=d/(np.linalg.norm(d)+1e-9)
    qnew=np.clip(tree[near]+step*d,0,1)
    if free(qnew) and seg_free(tree[near],qnew):
        tree.append(qnew); par[len(tree)-1]=near
        if np.linalg.norm(qnew-goal)<step and seg_free(qnew,goal):
            tree.append(goal); par[len(tree)-1]=len(tree)-2; break
tree=np.array(tree)
plt.figure(); 
for c,r in obs: plt.gca().add_patch(plt.Circle((c,r if False else c),r if False else r,color='r',alpha=.3))
for cx,cy,r in obs: plt.gca().add_patch(plt.Circle((cx,cy),r,color='r',alpha=.3))
for i,p in par.items():
    if p>=0: plt.plot([tree[i,0],tree[p,0]],[tree[i,1],tree[p,1]],'gray',lw=.5)
plt.scatter(tree[:,0],tree[:,1],s=2); plt.scatter(*start,c='b'); plt.scatter(*goal,c='g')
plt.xlim(0,1); plt.ylim(0,1); plt.title('RRT: 树朝空白处长, 找到绕障碍的路'); plt.show()
```

**你会看到**：树**朝空白区蔓延**，最终**绕开红圆连到绿终点**——**亲眼见 RRT 的全局探路能力**。

### 3.3 6.3.3 后处理：shortcutting + 代码 4/5

RRT 路径** jerky**（"RRT dance"是许多机器人学家的最爱舞步）。**shortcutting**：随机选路径上两个不相邻节点，**试着用直线连**，若更短就替换，重复。**anytime b-spline smoother**：用 B 样条平滑。

### 🧪 代码 4：shortcutting 后处理（可跑，接代码 3 的树路径）

```python
import numpy as np
# 假设 path 是从树里提取的节点序列(列表 of 2D 点), seg_free 同上
def shortcut(path, iters=200):
    rng=np.random.default_rng(1); path=list(map(np.array,path))
    for _ in range(iters):
        if len(path)<3: break
        i,j=sorted(rng.choice(len(path),2,replace=False))
        if j<=i+1: continue
        if seg_free(path[i],path[j]): path=path[:i+1]+path[j:]   # 抄近道, 跳过中间
    return path
# 用代码3的树回溯出 path 后调用: path=shortcut(path); 路径明显变短变直
```

**你会看到**：shortcutting 后路径**显著变短变直**——**亲眼见"抄近道"消除 RRT dance**。

### 🧪 代码 5：RRT\* 重连（可跑，对照 Exercise 6.3b）

**RRT\*** 在 RRT 加"**重连（rewire）**"：加 $q_{new}$ 时，**不只连最近邻，还检查附近节点"改认 $q_{new}$ 当爹是否更短"**，是则改父节点。**样本趋于无穷时 RRT\* 收敛到最优路径**（普通 RRT 证明次优，因它"trap 自己"找不到更好的路）。

```python
import numpy as np
# 在 RRT 加 qnew 后, 对其半径 r 内的邻居尝试 rewire
def rewire(tree,par,cost,new_idx,r=0.3):
    for i in range(len(tree)):
        if i==new_idx: continue
        if np.linalg.norm(tree[i]-tree[new_idx])<r and seg_free(tree[i],tree[new_idx]):
            new_cost=cost[new_idx]+np.linalg.norm(tree[i]-tree[new_idx])
            if new_cost<cost[i]: par[i]=new_idx; cost[i]=new_cost   # 改认更短的爹
# 这就是 Exercise 6.3b 的核心: qnew 的父节点应是"最短路径意义下"的, 而非仅最近邻
```

## 4. 用凸集图 GCS 做运动规划（6.4）—— "把两者优点合二为一"

> 轨迹优化：丰富代价约束（含连续曲线导数约束）、scale 到高维配置空间，但**基于局部梯度优化、受局部极小困扰**。采样规划：全局推理、概率完备，但**难容纳连续曲线导数约束、高维挣扎**。**有没有两全其美？** 作者和学生做的 **GCS（Graphs of Convex Sets，凸集图）** 就是想桥接这个 gap。

**动机**：为什么 PRM 难处理连续曲率约束？建图阶段花大量碰撞检测证"连两顶点的直线段无碰撞"（通常只到某采样分辨率）；在线查询阶段搜离散图找（不连续）分段线性最短路。**一旦平滑这条路径或用连续曲线近似，没保证仍无碰撞，也未必最短路**。因为离线建图只考虑直线段，**没给在线优化留余地**。带动力学后更糟。

**对 PRM 工作流的小改动**：每次采样，**不只把配置空间点加进图，而是把该点"膨胀"成配置空间里一个凸区域**。我们乐意付离线计算找"漂亮的大区域"，因为在线查询回报巨大：**图能稀疏得多**（少量区域覆盖配置空间大半）→ scale 到高维；更重要，**有灵活性在线优化连续曲线，只要留在凸区域内**。这需要一个**能联合优化"图上离散路径 + 连续曲线参数"的图搜索推广**——**正是 GCS 提供的**。

### 4.1 6.4.1 GCS 框架

GCS 框架 [13]，Drake 有成熟实现。**混合连续+组合优化的通用框架**，能给任何"网络流"优化做连续扩展，但运动规划里我们先关心**图上最短路**。

经典最短路：源 $s$ 到目标 $t$，顶点集、边集、边代价。

**GCS 的推广**：**每访问图上一个顶点，还允许从该顶点关联的凸集里挑一个元素**。**边长可以是相应集合里连续变量的凸函数**，边上还能写**凸约束**（任何解路径必须满足）。

GCS 最短路能编码 **NP-Hard** 问题，但能表成**混合整数凸优化（MICP）**。**框架之所以强**：这个 MICP 有**极强且高效的凸松弛**——**松弛二值变量为连续变量，几乎得原 MICP 的解**。**实践中只解凸松弛（加一点 rounding）几乎总足以恢复最优解**。**如今机器人应用里几乎从不解完整 MICP**。

**类比（GCS = "把迷宫切成凸房间，房间连门，找最短路同时优化房间内连续路径"，必懂）**：
- 普通图最短路 = **路口是点，边是路**。
- GCS = **路口是"凸房间"（你在房间里还能选站哪），边是"门"，过门时要求"上一房间出口 = 下一房间入口"**。
- **找最短路 = 同时决定"走哪几个房间（离散）+ 在每个房间站哪、走什么连续曲线（连续）"**。
- **魔法**：这个混合问题的**凸松弛极紧**，**解凸问题就几乎得全局最优**——**比以前的混合整数转录快几个数量级**。

### 4.2 6.4.2 GCS 运动学轨迹优化

假设**给定无碰撞空间的凸分解**（强假设，下面证明）。

**观察**：同一凸无碰撞区里两点，**连线保证无碰撞**。两点在两 C-space 区交集，则能连连续路径穿多区。**这就是转录的本质**。意味着**每次访问 GCS 顶点，要在 C-space 区里挑两点**，使路径在区内。**所以 GCS 的凸集不是 C-space 区本身，而是"$n$ 维配置空间的、首尾两点都在 C-space 区"的集合**——即**该集合与自身的笛卡尔积**。两集合**当且仅当 C-space 区相交**时连无向边，边上约束"第一集合的第二点 = 第二集合的第一点"。

**Example 6.10（简单 2D 配置空间 GcsTrajOpt）**：起点左下、终点右上。跑两次：最小距离目标、最小时间目标（+速度限）。**Figure 6.10**。

**能大幅推广**：不只每集合放线段，**用 Bézier 曲线凸包性质保证整条固定次数连续路径在集合内**。用 Bézier 导数性质加**速度凸约束**，并保证区域交点处曲线光滑。但定义速度需知"遍历路径的速率"，所以**引入时间缩放参数化**（每凸集一个时间缩放参数，类似运动学轨迹优化）。

**结果**：相当丰富的轨迹优化框架，把许多（承认不是全部）想要的代价约束编进 GCS 凸优化框架。目标含：**时间（轨迹时长）、路径长（用上界近似）、路径"能量"上界**（如 $\int\|\dot q(t)\|_2^2$）；约束含：**路径导数连续（任意阶）、速度约束（对所有 $t$ 严格强制，不只采样点）、额外凸位置/路径导数约束（如初末位置速度）**。自动加路径连续约束、区域约束（整条轨迹留在 C-space 区并集，**对所有 $t$ 保证，不只采样点**）。

**Example 6.11（简单 2D 续）**：几乎同样的最小时间优化，但**每段用五阶 Bézier + 时间缩放，要求到四阶导（snap）连续**。检查轨迹导数 reveals 速度光滑且全程在速度界内，**不只采样点**。

**非凸轨迹优化当然能吃更丰富代价约束，但没有 GCS 的全局优化和完备性**。我们不断往 GCS 加更多代价约束——**有些看似非凸的约束其实有精确凸重构，有些有好的凸近似**。这导致**两技术自然融合**：**GCS 凸松弛里用复杂代价约束的凸近似，但 rounding 步用非线性优化精确处理非凸**（一旦 GCS 选好图上离散路径，给强初猜）。Drake 里用 `GCS` 的 `AddCost`/`AddConstraint` 的 `use_in_transcription` 选项，非凸约束只加到 `Transcription::kRestriction`。

### 4.3 6.4.3 无碰撞配置空间的凸分解

怎么得无碰撞配置空间的凸分解？**认真类比 PRM**：采样无碰撞点，**怎么把点膨胀成凸区域**？

**凸几何时答案简单**：用凸形状近似机器人欧氏空间几何合理（即使 iiwa 非凸 mesh，常能近似成简单凸几何并集；或直接对 mesh 凸分解）。**但即使欧氏空间凸，配置空间一般也不能当凸**。

**例外**：配置空间只含平移、或机器人几何对旋转不变（点/球机器人），配置空间仍凸——这是"配置空间作为机器人核心数学对象"的最早关键观察之一 [18]。移动机器人（甚至球近似的四旋翼）能用。这时易算采样点任意凸体对的最小欧氏距离，**把点膨胀成合适半径的球** [19]。为找更大区域，**重度使用 IRIS 算法** [20]（Drake 实现）：**交替找分离超平面 + 找最大体积内含椭圆**，"膨胀"区域局部最大化（体积的高效近似）。

**能扩展 IRIS 到更一般（非凸）配置空间找大凸区域**，两种方式：

- **非线性规划（NP）**：**IRIS-NP** [21]（Drake 实现），把"找最近碰撞"的凸优化换成 SNOPT 等非线性求解器。**随机采样潜在碰撞**使算法概率可靠；实践较快但**不保证区域完全无碰撞**。**IRIS-NP2** [22] 大幅改进，**面更少、区域更大、快几个数量级**。
- **零阶优化（ZO）**：把 IRIS-NP 的非线性优化换成零阶优化（不要梯度，只用样本），**IRIS-ZO** 区域略小，但**能平凡并行** [22]。
- **代数运动学 + SOS**：利用"大多数机器人运动学能用（有理）多项式表达"，用多项式优化工具搜**无碰撞的严格证书** [23]（Drake 实现）。**较慢但结果可靠**。代价：在**原空间的立体投影坐标**里找凸区域，**实践上代表坐标系的轻微扭曲**（从而轨迹长也扭曲）。

**Example 6.12（IRIS in Configuration Space）**：在 iiwa 伸货架例上跑 `IrisInConfigurationSpace`（即 IRIS-NP），用全 7 自由度 + 原始碰撞几何。演示两件事：① 用 `IrisInConfigurationSpace` 的机制；② IRIS 区域**即使贴着复杂配置空间几何也能覆盖大量体积**。

`IrisInConfigurationSpace` 可用单种子点配置；算法从该点周围小区域开始"膨胀"最大化体积。用 `InverseKinematics` 找伸进顶层货架的种子配置。**但若只从那跑 IRIS，它找的区域不会填满货架内，而是爬出货架去覆盖货架外大得多的配置空间**。为避免，**跑两次 IRIS**：一次用机器人"home 配置"种子，长出货架外区域；再用货架内 IK 种子跑第二次，但**加约束用第一区域当障碍**（要求不重叠），**逼第二区域用货架内体积最大化体积**。

**作者现在更偏好的另一种得体积方法**：用逆运动学在感兴趣区域**收集大量配置空间样本**，算 **`MinimumVolumeCircumscribedEllipsoid`** 作 IRIS 的 `starting_ellipse`，**只跑一次 IRIS** 得体积对应覆盖该配置空间区域的漂亮区域。**避免"用先前区域当障碍"的假约束**（→更大区域）、更快（一次迭代）、更可并行。

**若继续类比 PRM**：可想象随机采样、拒绝碰撞或现有 IRIS 区内的样本、膨胀剩余样本做凸分解。**但能做得更好**——**同样区域数覆盖更大百分比配置空间，或类似体积用更少区域**。当前最佳算法：**算"可见性图"的"最小团覆盖"** [24]（Drake 实现）。

**Example 6.13（简单 2D 续）**：用最小团覆盖算法、覆盖阈值 96% 配置空间，得自动分解。

**实践上**：7DOF 机械臂、甚至约 10 自由度，**算配置空间相当密的覆盖似乎合理可行**。但更高维，**作者认为"覆盖配置空间每个角落"是假目标**。**他强烈偏好"用代表配置空间'重要区域'的样本点初始化团覆盖算法"**。有时手动种子（IK 调用），或**检查 teleop 演示、另一规划器（能生成计划但无同样保证）、甚至 RL 策略来的轨迹**。

## 5. 时间最优路径参数化 TOPP（6.5）—— "给定路线，求最快开法"

> 有了运动计划，自然问题：**受速度/加速度/力矩限，最快能多快执行这条计划？**

定义轨迹：路径参数化 $r(s)$ + 时间参数化 $s(t)$，$q(t)=r(s(t))$，$s(t)\in[0,1]$，$s(t_0)=0,s(t_f)=1$。约束 $\forall t,\ \dot s(t)>0$ 使 $s\to t$ 逆映射总存在。**这参数化的好处**：$r(s)$ 固定时，许多想加在 $q(t)$ 上的目标约束**对 $s$ 的导数其实凸**。用简写 $r'(s)=\partial r/\partial s$ 等，写：

$$\dot q=r'(s)\dot s,\quad \ddot q(t)=r''(s)\dot s^2+r'(s)\ddot s$$

**更关键**：代入机械臂方程得：

$$u(s)=m(s)\ddot s+c(s)\dot s^2+\bar\tau_g(s) \qquad (7)(8)(9)$$

$u(s)$ 是缩放时间 $s(t)$ 的命令力矩，$m(s)=M(r(s))r'(s)$，$c(s)=M(r(s))r''(s)+C(r(s),r'(s))r'(s)$，$\bar\tau_g(s)=\tau_g(r(s))$。

**下一步关键变量替换**：$b(s(t))=\dot s^2(t)$，注意 $\dot b(s)=b'(s)\dot s=2\dot s\ddot s$。

**用参数化轨迹表 $b(s)$ 在 $s\in[0,1]$**。看能在采样时间点 $s_i=s(t_i)$ 把一组极有用的代价约束写成 $b(s)$ 的凸函数：

- **单调性约束**：$b(s_i)\ge\epsilon \Rightarrow \dot s(t_i)>0$。
- **速度限 = bounding-box 约束**：$\dot q_{min}\le r'_j(s_i)^2 b(s_i)\le\dot q_{max,j}^2$。
- **加速度限 = 线性约束**：$\ddot q_{min}\le r''(s_i)b(s_i)+\tfrac12 r'(s_i)b'(s_i)\le\ddot q_{max}$。
- **力矩限 = 线性约束**：$u_{min}\le\tfrac12 m(s_i)b'(s_i)+c(s_i)b(s_i)+\bar\tau_g(s_i)\le u_{max}$。
- **最小化时长是凸目标**：$t_f-t_0=\int_{t_0}^{t_f}1\,dt=\int_0^1\tfrac{1}{\sqrt{b(s)}}\,ds$。**看着非凸，但能用……写成凸**（用辅助变量/锥约束）。

**虽然希望有限约束足以隐含整段时间区间约束成立，实践上只在足够多采样时间强制、放弃严格保证**。

**TOPP 历史**：1980 年代广泛研究 [30]，定制算法试图揭示 bang-bang 轨迹所有切换时间。[31,32,33] 建立与凸优化的连接。[34] 做了流行数值实现 **TOPPRA**（基于可达性分析的时间最优路径参数化）。Drake 有 `PathParameterizedTrajectory` 类。

**常见问题**：TOPP 能否写轨迹 jerk（或更高导数）的凸约束？因许多工业机械臂有必须遵守的 jerk 限。[32] 处理了这问题的一个版本。

### 🧪 代码 6：TOPP 简单版（scipy，可跑，给定路径求最快时间）

PDF 没内联代码。这段演示 TOPP 核心：给定一维路径离散点，变量 $b_i=\dot s_i^2$，受单调/速度限/加速度限（线性），最小化时长（凸，用 scipy）。

```python
import numpy as np
from scipy.optimize import minimize
N=40; ds=1.0/N
vmax, amax = 2.0, 3.0                       # 速度限, 加速度限 (在 s 空间)
bmax = vmax**2
def time_cost(b): return np.sum(ds/np.sqrt(np.maximum(b,1e-6)))   # 凸目标 ∑ ds/√b
def cons(b):
    c=[]
    c += [b[i]-1e-4 for i in range(N)]                          # 单调 b>=eps
    c += [bmax-b[i] for i in range(N)]                          # 速度限 b<=vmax^2
    for i in range(N-1):                                       # 加速度限 (b_{i+1}-b_i)/(2ds)<=amax
        c.append(amax - (b[i+1]-b[i])/(2*ds))
        c.append(amax + (b[i+1]-b[i])/(2*ds))
    return np.array(c)
b0=np.full(N,0.5)
res=minimize(time_cost,b0,bounds=[(1e-4,bmax)]*N,constraints={'type':'ineq','fun':cons})
print("TOPP 最短时间 ≈", round(time_cost(res.x),3))
# 可视化 b(s)=ṡ² 曲线: 典型"先加速后减速"的 bang-bang 味
plt.plot(np.linspace(0,1,N),res.x); plt.xlabel('s'); plt.ylabel('b=ṡ²'); plt.title('TOPP: 受速度/加速度限的最快时间参数化'); plt.grid(alpha=.3); plt.show()
```

**你会看到**：$b(s)$ 呈**先升后降的拱形**（先加速到速度限、再减速），**典型 bang-bang 味**——**亲眼见 TOPP 在受限下求最快执行**。

## 增补一：把"还不够通俗"的 6 个点再补类比

1. **配置空间障碍为什么"扭曲吓人"**：笛卡尔空间一个简单盒子，映到关节角空间，因正运动学的 sin/cos 非线性，**变成弯弯曲曲的"香蕉形"禁区**（Example 6.3/6.4）。**这就是为什么"在笛卡尔空间看着简单的避障，在配置空间是噩梦"**。
2. **RRT 的 bug trap 为什么难**：起点在 U 形凹槽里，**随机点大多落在凹槽外**，但凹槽外的点连不进凹槽内（被墙挡），**树在凹槽外疯长，凹槽内只有起点孤零零**，**很久才偶然撒到出口附近**。**演示 RRT 在窄通道的挣扎**。
3. **RRT-Connect 为什么快**：双向长树，**两棵树互相朝对方延伸**，**相遇即连通**——**搜索空间从"填满整个迷宫"变成"两棵树各填一半相遇"**，**快得多**。
4. **GCS 凸松弛为什么"紧得离谱"**：直觉上，**最优路径在凸房间里走直线/光滑曲线，离散选择（走哪几个房间）的"0/1"在松弛成"0到1的流量"后，最优解天然把流量集中到一条路径上**（因为绕路只会增加凸代价）——**所以松弛解几乎自动是整数**。这是 GCS 的"魔法"，但严格证明见 [13][15]。
5. **IRIS 为什么"膨胀"而非"采样覆盖"**：采样覆盖要"撒够多点才盖全"，**IRIS 从一个安全点"吹气球"，碰到障碍就停，一次吹出一大块凸安全区**——**用优化代替密集采样**，**区域大、数量少**。
6. **TOPP 的 $b=\dot s^2$ 替换为什么神**：速度限 $\dot q=r'\dot s$ 含 $\dot s$，**对 $\dot s$ 非凸**；但 $b=\dot s^2$ 后，速度限变 $r'^2 b$（**对 $b$ 线性**！），加速度限 $r''b+\tfrac12 r'b'$ 也**对 $b,b'$ 线性**，力矩限也线性——**一个替换把一堆非凸约束全变线性/凸**。**这是 TOPP 能用凸优化解的钥匙**。

**通关三句话**：
1. **逆运动学不是求逆函数，而是"带丰富代价约束的优化"**——多解时挑最舒服的，无解时报 infeasible，还能加关节限/避碰；理解 IK 就掌握了规划轨迹的大半，因为"同时优化一系列关节角"就是运动学轨迹优化。
2. **轨迹优化用 B 样条参数化整条轨迹**（凸包性质让"限控制点=限整条曲线+导数"成线性约束），但**基于局部梯度，受局部极小困扰**（点机器人绕盒子，左绕全局最优、右绕局部极小，求解器跨不过去）；**于是采样规划登场**——RRT 随机撒点让树朝空白长、PRM 离线建图在线搜，**全局探路、概率完备**，RRT\* 靠重连渐近最优，shortcutting 抄近道消除 jerky。
3. **GCS 把两者优点合二为一**——把无碰撞配置空间切成凸房间（IRIS 膨胀），房间连门成图，**找最短路同时优化房间内连续曲线，且凸松弛极紧，解凸问题就几乎得全局最优**；而 **TOPP 在"路径已定"后求最快执行**，靠 $b=\dot s^2$ 替换把速度/加速度/力矩限全变线性/凸。**贯穿全章的作者私心**：他其实更想要"不怕偶然接触的皮实机器人"，而非"碰一下就报错"的洁癖规划器。
