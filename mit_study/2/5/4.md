# 一、初版通俗讲解：第 5 章《Bin Picking》到底在讲什么？

这一章的标题是 **Bin Picking**，中文通常叫“料箱抓取”或“杂乱物体抓取”。

它的核心问题非常朴素：

> 一个料箱里堆满了随机物体，机器人要把它们从一个箱子搬到另一个箱子里。  
> 我们不关心物体是什么，也不关心它们放到另一个箱子里的精确位置，只要机器人能稳定、反复地把物体搬过去。

听起来像“抓娃娃机”，但其实是机器人学习、感知、控制、规划、接触力学、抓取几何的综合训练场。

---

## 5.0 本章任务：为什么 Bin Picking 很重要？

PDF 开头说：

- 这是 bin picking 的最简单版本。
- 机器人只需要把物体从一个 bin 搬到另一个 bin。
- 我们对物体类别不挑剔。
- 我们对放置位置也不挑剔。
- 但希望系统对很多物体都能工作。

为什么这很有用？

### 1. 工业价值大

物流、仓储、分拣、上料、装箱，都和 bin picking 有关。

### 2. 是机器人学习的训练场

你可以让机器人白天黑夜反复做：

```text
从 A 箱抓物体 → 放到 B 箱
从 B 箱抓物体 → 放回 A 箱
```

还可以不断加入新物体，增加多样性。

在仿真里更容易，因为你可以无限随机生成场景。

### 3. 更复杂版本也存在

比如：

- 只抓某一类物体；
- 放到指定位置；
- 装箱 packing；
- 避免损坏；
- 按订单分拣。

但本章先从最基础版本开始。

### 通俗类比

这就像让机器人当一个“仓库临时工”：

> 面前有一筐乱七八糟的零件，你的任务是把它一个一个扔到另一个筐里。  
> 不要求摆得漂亮，但不能一直失败、一直抓空、一直撞箱子。

# 5.1 生成随机杂乱场景

要训练或测试 bin picking，首先得有一个“乱七八糟但合理”的场景。

PDF 的问题是：

> 如何在仿真中生成一个装满随机物体的 bin？

以前我们做仿真时，会手动设置每个物体的位置。  
但现在物体很多，手动摆不现实。

---

## 5.1.1 Falling Things：让物体自己掉进去

现实中最简单的方法：

> 把物体倒进箱子里。

仿真里也可以这样做。

但是有一个关键限制：

> 物理引擎不能接受多个物体一开始就占据同一块空间。

如果两个物体初始化时互相穿透，仿真可能直接爆炸或行为异常。

因此最简单的方法是：

1. 随机生成若干物体；
2. 每个物体随机位姿；
3. 在竖直方向上错开高度；
4. 让它们在重力下自然落下；
5. 等它们静止后，作为 bin picking 的初始场景。

### 通俗类比

就像你往一个盒子里丢积木。  
你不会把所有积木瞬间塞在同一个位置，而是一个一个从不同高度丢下去。  
等它们都躺平了，再开始抓。

---

## Example 5.1：2D 泡沫砖堆

PDF 给了一个 2D 例子：

- 初始位置水平方向均匀随机；
- 初始旋转随机；
- 竖直方向每隔 0.1 m 错开；
- 仿真约 1 秒后，砖块静止。

这里有一个细节：

Drake 并没有专门写一个 2D 物理引擎，而是仍然用 3D 物理引擎，只是给每个砖块加了 planar joint，把它限制在平面内。

这就像你在玩 3D 游戏，但给所有物体加了“只能在桌面上滑动”的约束。

# 5.2 带摩擦接触的静态平衡

物体掉进 bin 后会静止。  
这时机器人要抓取它们，首先要理解：

> 为什么这些物体能稳稳地停在那里？  
> 接触力、重力、摩擦力之间如何平衡？

这就是本节的核心：**Static Equilibrium with Frictional Contact**。

---

## 多体动力学方程

PDF 给出了机器人和物体的动力学方程：

\[
M(q)\dot{v} + C(q,v)v = \tau_g(q) + \sum_i J_i^T(q) F_{c_i}
\]

其中：

- \(q\)：广义位置；
- \(v\)：广义速度；
- \(M(q)\)：质量矩阵；
- \(C(q,v)v\)：科氏项；
- \(\tau_g(q)\)：重力引起的广义力；
- \(F_{c_i}\)：第 \(i\) 个接触点施加的空间力；
- \(J_i(q)\)：第 \(i\) 个接触的接触雅可比。

当物体静止时：

\[
v = 0,\quad \dot{v}=0
\]

因此方程变成：

\[
\tau_g(q) = -\sum_i J_i^T(q)F_{c_i}
\]

意思是：

> 重力想把物体拉倒，接触力必须把物体撑住。

---

## 通俗类比

想象一个箱子放在地上。

- 重力向下拉；
- 地面向上顶；
- 如果有倾斜，摩擦力还要阻止它滑下去。

如果这些力加起来不平衡，物体就会动。

---

# 5.2.1 Spatial Force：空间力 / Wrench

机器人学中，力不只是 3D 力向量。  
我们常用 6D 空间力，也叫 wrench：

\[
F =
\begin{bmatrix}
\tau \\
f
\end{bmatrix}
\]

其中：

- \(f\)：普通 Cartesian force，平移力；
- \(\tau\)：torque，力矩。

Drake 的 monogram notation 写成：

\[
F_{Bp}^{name,C}
\]

意思是：

- 作用在 body \(B\) 上；
- 作用点是 \(Bp\)；
- 表达在坐标系 \(C\) 中；
- name 是可选名字。

代码里通常写成：

```python
F_Bp_C
```

或更完整的：

```python
F_name_Bp_C
```

---

## 为什么力会有力矩分量？

世界真正施加的接触力通常是作用在某些点上的 Cartesian force。  
但我们经常想把很多点上的力总结到一个共同坐标系里。

这时候，一个力等效成：

- 一个新作用点上的力；
- 加上一个力矩。

### 通俗类比

你用扳手拧螺丝。  
你手施加的是一个力，但对螺丝来说，效果是一个力矩。  
把力从一个点“搬”到另一个点，就要补上相应的力矩。

---

## 空间力代数

### 1. 同一个物体、同一个坐标系下的空间力可以相加

\[
F_{Bp}^{total,C} = \sum_i F_{Bp_i}^{C}
\]

### 2. 空间力可以从一个作用点移动到另一个作用点

平移力不变：

\[
f_{Bq}^C = f_{Bp}^C
\]

力矩改变：

\[
\tau_{Bq}^C =
\tau_{Bp}^C +
{}^{Bq}p^{Bp}_C \times f_{Bp}^C
\]

也就是加一个“杠杆效应”。

### 3. 旋转可以改变表达坐标系

\[
f_{Bp}^D = {}^D R_C f_{Bp}^C
\]

\[
\tau_{Bp}^D = {}^D R_C \tau_{Bp}^C
\]

# 5.2.2 Collision Geometry：碰撞几何

在 Drake 的 SceneGraph 中，几何体有不同角色：

碰撞几何通常比视觉几何简单很多，例如：

- 低面数 mesh。

这样物理引擎更快、更稳。

Drake 有 `ModelVisualizer` 工具，可以把：

发布到 MeshCat。


然后查看碰撞几何。

### 实践意义

很多新手以为机器人看到的是漂亮 mesh，其实物理引擎碰撞检测用的可能是简化的盒子、球、圆柱。

---

## Collision Filter：碰撞过滤

不是所有几何对都需要检测碰撞。

例如 iiwa 机械臂：

- link 5 不需要和 link 4 检测碰撞；
- link 5 也不需要和 link 6 检测碰撞；

因为它们在物理上通过关节连接，不会发生那种碰撞。

碰撞过滤的好处：

1. 加快计算；
2. 允许使用简化碰撞几何；
3. 避免相邻 link 的简化几何互相误碰撞。

PDF 说默认 collision filter 通常够用，但可以调整。

---

## 接触力从哪里来？

每一对没有被 collision filter 过滤掉的碰撞几何，都可能产生一对大小相等、方向相反的接触力。

Drake 的 SceneGraph 提供：

```text
GetCollisionCandidates
```

返回所有可能碰撞对。

通常把碰撞对称为：

- body A；
- body B。

# 5.2.3 接触力：从穿透到力

数学上，两个刚体不能占据同一空间。  
但在数值仿真中，轻微穿透几乎不可避免。

大多数仿真器把两个物体之间的接触总结为：

- 一个或多个接触点；
- 每个点上有 Cartesian force。

PDF 特别提醒：

> 这一步很容易低估，也非常容易出 bug。

---

## 单点接触的问题

如果两个物体深度穿透，只用一个点上的力来代表所有接触效果，很容易出问题：

- 力不连续；
- 物体突然跳动；
- 仿真“爆炸”。

### 通俗类比

两个人互相挤在一起，你却假设只有一个人的手指尖在用力。  
这显然不稳定，稍微动一下，力的方向和大小就可能突变。

---

## 多点接触也不简单

有些仿真器用多个接触点。  
但问题是：

> 如何在每个时间步稳定地选择一致的接触点？

如果这一帧选了这组点，下一帧突然换成另一组点，力会跳变。

---

## Drake 的 Hydroelastic Contact

Drake 的一个重要创新是：

> hydroelastic contact，水弹性接触模型。

它不是简单点接触，而是对两个穿透物体之间的“hydroelastic surface”做积分， generalize 了 contact patch 的概念。

### 通俗类比

点接触像用一根手指戳物体。  
hydroelastic 更像用一块有弹性的橡胶面压住物体，力分布更连续、更稳定。

PDF 说目前在 Drake 中 hydroelastic 仍然需要 opt-in，但作者正在把很多例子都迁移过去。

# 5.2.4 Contact Frame：接触坐标系

接触力需要方向和作用坐标系。

PDF 约定：

- 接触坐标系的 \(z\) 轴沿接触法向；
- 正方向抵抗穿透；
- \(x,y\) 轴是切平面上的任意正交基。

---

## 法向怎么定义？

对于盒子角点这种不光滑位置，法向不唯一。

一个可靠方法是：

> 使用两个物体 signed distance function 的 subgradient 作为法向。

这样也能推广到广义坐标。

---

## Example 5.5：砖块放在平面上

考虑一块砖放在地面上。

地面焊在世界里，没有自由度。  
我们只关心砖块上的力。

假设接触引擎给出两个接触点：

- \(C_1\)
- \(C_2\)

分别在砖块底部两个角附近。

砖块受到三个主要空间力：

1. 重力；
2. 接触力 1；
3. 接触力 2。

重力可以写成：

\[
F_{g}^{B,W}
=
[0,0,0,0,0,-mg]^T
\]

也就是：

- 力矩分量为 0；
- Cartesian force 向下，大小 \(mg\)。

接触力通常先在接触坐标系里表达。  
例如：

\[
f_{z}^{Bc_1,C_1} \ge 0
\]

表示接触只能推，不能拉。

为了做力平衡，需要把所有空间力转换到同一个坐标系、同一个作用点。

例如把接触力 1 转到 body frame：

\[
F_{Bc_1}^{1,B} = {}^B R_{C_1} F_{Bc_1}^{1,C_1}
\]

再改变作用点：

\[
f_1^{B,B} = f_{Bc_1}^{1,B}
\]

\[
\tau_1^{B,B}
=
\tau_{Bc_1}^{1,B}
+
{}^Bp^{C_1}_B \times f_{Bc_1}^{1,B}
\]

最后写平衡：

\[
F_1^{B,B} + F_2^{B,B} + F_g^{B,B} = 0
\]

3D 中是 6 个方程，2D 中是 3 个方程。

结论：

- 平移部分告诉我们两个接触力的竖直分量加起来要等于 \(mg\)；
- 力矩部分告诉我们如果砖块质心在两个接触点中间，两个竖直接触力应相等。

---

# 5.2.5 Coulomb Friction Cone：库仑摩擦锥

接触力必须满足几个规则。

---

## 规则 1：没有接触就没有力

如果两个物体之间的距离：

\[
\phi_i(q) > 0
\]

则：

\[
f_{c_i}=0
\]

---

## 规则 2：法向力只能推，不能拉

\[
f_{c_i,z} \ge 0
\]

接触不能把物体吸过来。

---

## 规则 3：切向力来自摩擦

Coulomb friction：

\[
\sqrt{f_x^2 + f_y^2} \le \mu f_z
\]

其中：

- \(f_z\)：法向力；
- \(f_x,f_y\)：切向摩擦力；
- \(\mu\)：摩擦系数。

通常有：

- \(\mu_{static}\)：静摩擦系数；
- \(\mu_{dynamic}\)：动摩擦系数。

---

## 摩擦锥的几何意义

所有合法接触力形成一个锥：

> friction cone，摩擦锥。

如果接触力在锥内，摩擦可以阻止滑动。  
如果所需切向力超过锥边界，就会滑动。

滑动时，摩擦方向通常与滑动速度方向相反，并取最大耗散。

---

## 通俗类比

摩擦锥就像一把“摩擦力保护伞”。

- 伞越大，摩擦越大；
- 如果外力方向在伞内，物体不滑；
- 如果外力超出伞范围，物体开始滑。

---

## Example 5.6：斜面上的砖块

把平面倾斜角度 \(\gamma\)。

此时切向力变得重要。

PDF 问：

> 两个角上的接触力大小还一样吗？  
> 还是低处的角受力更大？

答案是：

> 低处的角法向力更大。

---

## 摩擦锥判断是否滑动

如果摩擦系数太小，摩擦锥不包含能够抵消重力的方向，那么砖块会滑下去。

如果摩擦系数足够大，可以找到一组接触力实现静态平衡。

此外还有一个条件：

> 砖块质心在斜面上的垂直投影必须落在两个接触点之间，否则砖块会翻倒。

---

## 斜面砖块的方程

假设砖块长度 \(l\)，高度 \(h\)，质心在中心。

平衡方程：

\[
f_{1x} + f_{2x} = -mg\sin\gamma
\]

\[
f_{1z} + f_{2z} = mg\cos\gamma
\]

\[
-h f_{1x} + l f_{1z}
=
h f_{2x} + l f_{2z}
\]

法向力非负：

\[
f_{1z} \ge 0,\quad f_{2z} \ge 0
\]

摩擦锥：

\[
|f_{1x}| \le \mu f_{1z}
\]

\[
|f_{2x}| \le \mu f_{2z}
\]

代入后可得：

\[
f_{2z} = f_{1z} + mg\frac{h}{l}\sin\gamma
\]

所以低处接触点的法向力更大。

# 5.2.6 静态平衡作为优化问题

除了让物体从天上掉下来，也可以直接用优化找一个已经处于静态平衡的初始状态。

Drake 提供：

```text
StaticEquilibriumProblem
```

它把以下约束收集成一个优化问题：

\[
\text{find } q
\]

subject to:

\[
\tau_g(q) = -\sum_i J_i^T(q) f_{c_i}
\]

\[
f_{c_i,z} \ge 0
\]

\[
\|f_{c_i,xy}\|_2 \le \mu f_{c_i,z}
\]

\[
\phi_i(q) \ge 0
\]

\[
\phi_i(q) = 0 \quad \text{or} \quad f_{c_i,z}=0
\]

以及 joint limits。

---

## Complementarity Constraint：互补约束

这一条很关键：

\[
\phi_i(q)=0 \quad \text{or} \quad f_{c_i,z}=0
\]

意思是：

- 如果两个物体没有接触，距离 \(\phi>0\)，那么接触力为 0；
- 如果有接触力，那么距离应该为 0。

这类约束叫 complementarity constraint。

常见形式：

\[
x \ge 0,\quad y \ge 0,\quad x=0 \text{ or } y=0
\]

也常写成：

\[
x \ge 0,\quad y \ge 0,\quad xy=0
\]

---

## 数值上如何放松？

直接处理 “or” 很难。  
可以把约束放松为：

\[
0 \le \phi_i(q) f_{c_i,z} \le tol
\]

这样优化器有梯度可跟。

代价是：

> 可能允许一点点“远距离力”，但数值上更容易求解。

---

## 可以加额外目标

比如我们希望找到的静态位姿靠近某个初始采样位姿：

\[
\min \|q-q_0\|^2
\]

这能帮助优化器找到我们想要的那一类平衡状态。

## Example 5.7：Tall Towers

PDF 用“高塔”例子展示 StaticEquilibriumProblem 的效果。

思想是：

这类问题通常是非凸的，初始猜测很重要。

# 5.4 Model-Based Grasp Selection：基于模型的抓取选择

现在场景有了，下一个问题：

> 什么是好的抓取？

这个问题在机器人学中研究了几十年。

PDF 引用了 grasping survey，并给出一个核心定义：

> 如果抓取的目标是让物体稳定地在手中，那么一个好的抓取应该能抵抗外部扰动 wrench。

---

# 5.4.1 Contact Wrench Cone：接触 wrench 锥

前面我们讲摩擦锥：

> 摩擦能产生哪些接触力？

现在反过来：

> 哪些外部扰动力可以被接触力抵抗？

把摩擦锥中的力取 additive inverse，就得到可以抵抗的 adversarial wrench 集合。

如果有多个接触点，我们想把所有接触点能抵抗的 wrench 加在一起。

这就需要把空间力代数推广到“集合”。

---

## Wrench Cone 符号

PDF 用：

\[
K_{Bp}^{name,C}
\]

表示作用在 body \(B\) 的点 \(Bp\)、表达在坐标系 \(C\) 中的 6D wrench cone。

对于点接触、无 torsional friction 的 Coulomb 摩擦锥，在接触坐标系中可以写成：

\[
K_C^C =
\left\{
\begin{bmatrix}
0 \\ 0 \\ 0 \\ f_x \\ f_y \\ f_z
\end{bmatrix}
:
\sqrt{f_x^2+f_y^2} \le \mu f_z
\right\}
\]

前三个 0 表示点接触没有绕接触法向的纯力矩。

---

## Wrench Cone 的空间代数

### 1. 同一点、同一坐标系下的 wrench cone 可以相加

这里加法不是普通加法，而是 Minkowski sum：

\[
K_{Bp}^{total,C}
=
K_{Bp_0}^{C}
\oplus
K_{Bp_1}^{C}
\oplus
\cdots
\]

意思是：

> 从每个 cone 中各选一个 wrench，然后相加，所有可能结果组成新的 cone。

---

### 2. Wrench cone 可以从一个作用点移动到另一个作用点

这是线性操作：

\[
K_{Bq}^C
=
\begin{bmatrix}
I & [{}^{Bq}p^{Bp}_C]_\times \\
0 & I
\end{bmatrix}
K_{Bp}^C
\]

其中 \([p]_\times\) 是叉乘对应的 skew-symmetric matrix。

---

### 3. 旋转可以改变表达坐标系

\[
K_{Bp}^D
=
\begin{bmatrix}
{}^D R_C & 0 \\
0 & {}^D R_C
\end{bmatrix}
K_{Bp}^C
\]

---

## Example 5.8：Contact Wrench Cone 可视化

PDF 提供交互式可视化：

- 一个固定盒子；
- 只受接触力，无重力；
- 显示接触点摩擦锥；
- 显示 body frame 下的 wrench cone。

为了简化，这个例子关闭了 hydroelastic contact，只用单点接触。

---

## 可视化的重要提醒

Wrench cone 本来在 6D 空间：

\[
\mathbb{R}^6
\]

但我们只能画 3D。

所以 PDF 把 6D cone 投影成两个 3D cone：

- 平移力部分；
- 旋转力矩部分。

这可能产生误导：

> 你不能独立地从平移锥和旋转锥中随便选两个力，因为它们属于同一个 6D wrench。

---

## 单点接触的 wrench cone

单个接触点的旋转部分维度很低。

为什么？

因为力矩来自：

\[
\tau = p \times f
\]

所以力矩必须垂直于从 body frame 到接触点的向量。

---

## 两个相对接触点

如果两个接触点在物体两侧正对：

- 每个接触点的旋转 cone 维度都不高；
- 但它们 span 的方向不同；
- 合起来可以抵抗更多纯力矩。

不过有一个关键限制：

> 如果没有 torsional friction，两个点接触不能抵抗绕两接触点连线方向的力矩。

### 通俗类比

你用两根手指捏住一根笔。  
你可以抵抗很多方向的扰动，但如果想让笔绕两手指连线方向扭转，纯点接触很难抵抗。

---

## Hydroelastic 和 Torsional Friction

课程中的夹爪使用 hydroelastic contact，可以模拟 contact patch。  
因此可以产生 torsional friction，抵抗绕夹持轴的力矩。

抵抗能力与夹爪夹紧程度有关。

---

## Force Closure：力封闭

如果所有接触产生的 contact wrench cone 是整个：

\[
\mathbb{R}^6
\]

则称抓取达到：

> force closure，力封闭。

经典抓取质量指标认为：

> contact wrench cone 越大，抓取越好。

---

# 5.4.2 Colinear Antipodal Grasps：共线反向抓取

基于 wrench cone 分析，一个经典启发式是：

> 对双指夹爪来说，寻找共线 antipodal 抓取点。

---

## Antipodal 是什么意思？

两个接触点的法向方向相反：

\[
n_1 \approx -n_2
\]

---

## Colinear 是什么意思？

两个接触点在同一条线上，这条线就是两接触点连线。

---

## 为什么这是好启发式？

因为这样的两个接触点通常能形成较大的 contact wrench cone。

即使我们不知道物体模型，也可以从点云中找近似 antipodal 的区域。

# 5.5.2 估计法向和局部曲率

抓取选择依赖局部几何：

- 法向；
- 曲率。

---

## 平面拟合问题

给定一组点，拟合一个平面：

- 平面位置 \(p\)；
- 单位法向 \(n\)。

点 \(p_i\) 到平面距离：

\[
|(p_i-p)^Tn|
\]

最小二乘优化：

\[
\min_{p,n}
\sum_{i=1}^N
((p_i-p)^Tn)^2
\]

subject to:

\[
\|n\|=1
\]

---

## 先求平面位置

对 \(p\) 求梯度，得到：

\[
p^* = \frac{1}{N}\sum_i p_i
\]

也就是局部点的均值。

---

## 再求法向

代入后问题变成：

\[
\min_n n^T W n
\]

subject to:

\[
\|n\|=1
\]

其中：

\[
W =
\sum_i
(p_i-p^*)(p_i-p^*)^T
\]

最优 \(n\) 是 \(W\) 最小特征值对应的单位特征向量。

\(-n\) 也是最优，因此需要后处理统一方向，例如让法向指向相机原点。

---

## 第二、第三特征值也有用

因为 \(W\) 对称，所以有正交特征向量。

- 最小特征值方向：法向；
- 最大特征值方向：表面主方向，通常对应 least curvature 或最大展开方向；
- 中间特征值方向：另一个切向方向。

这些信息对生成抓取候选很有用。

---

## 局部曲率怎么算？

对每个点：

1. 用 nearest neighbor 找附近一小片点；
2. 对这些局部点做平面拟合；
3. 得到法向和局部曲率信息。

如果是深度图，可以直接用像素邻域近似局部点云，跳过显式 nearest neighbor。

---

# 5.5.3 评价候选抓取

有了点云、法向、曲率之后，就可以给候选抓取打分。

---

## 抓取要抵抗重力 wrench

夹爪闭合后，接触力必须至少能抵抗物体重力。

夹爪的夹紧方向通常是 gripper frame 的 \(x\) 轴。

如果我们要抓起物体而不滑落，摩擦锥内的力要能抵抗重力 wrench。

由于我们不知道物体的真实重力 wrench，一个合理启发式是：

> 寻找法向近似相反、并且与夹爪 \(x\) 轴对齐的点云区域。

---

## Patch Contact 比 Point Contact 更真实

真实手指有橡胶指尖，会变形。  
物体也会变形。  
所以接触通常是 patch contact，而不是单点接触。

因此我们寻找一小片法向合适的点，而不是一个孤立点。

---

## 抓取评分第一项：法向对齐

把场景点云转换到候选夹爪坐标系：

\[
X_G
\]

然后裁剪到两指之间的 bounding box。

PDF 的成本项：

\[
cost = -\sum_i (n_{i,x}^G)^2
\]

其中：

- \(n_{i,x}^G\) 是第 \(i\) 个点法向在 gripper frame \(x\) 轴上的分量。

如果很多点的法向都对齐夹爪 \(x\) 轴，cost 更负，表示更好。

---

## 抓取评分第二项：夹爪姿态

对于运动学受限的机械臂，某些夹爪姿态更容易执行。

PDF 加了一个成本，鼓励夹爪保持接近竖直：

\[
cost += -\alpha [0,0,-1]^T R^G [0,1,0]^T
\]

整理后：

\[
cost += \alpha R^G_{3,2}
\]

其中：

- \(\alpha\) 是权重；
- \(R^G_{3,2}\) 是旋转矩阵第三行第二列。

---

## 抓取评分第三项：碰撞

如果候选抓取与 bin 或点云碰撞，则返回无穷大 cost。

---

# 5.5.4 生成抓取候选

现在我们有成本函数：

\[
cost(X_G)
\]

理想上我们想求解：

\[
\min_{X_G} cost(X_G)
\]

subject to collision constraints。

但这个问题非常难：

- 目标高度非凸；
- 约束高度非凸；
- 大多数随机 \(X_G\) 根本没有点在两指之间，因此 antipodal cost 为 0。

所以通常不用标准数学规划，而是：

> randomized sampling-based algorithm，随机采样算法。

---

## 启发式 1：基于局部曲率

一些方法，例如 ten Pas et al.，使用局部曲率：

- 让点云法向指向掌心；
- 让手指沿最大曲率方向对齐；
- 沿法向移动夹爪直到无碰撞；
- 在附近采样。

PDF 说这个方法不错，但对 YCB 中很多盒子物体不一定最好，因为盒子局部曲率信息不多。

---

## 启发式 2：寻找 antipodal point pairs

另一种方法：

1. 随机选一个点；
2. 沿该点法向反方向 ray cast；
3. 如果打到一个点，且该点法向足够反向；
4. 且两点距离小于夹爪宽度；
5. 则认为找到 antipodal pair。

---

## Example 5.12：生成抓取候选

PDF 作者用了更简单的策略：

1. 随机选一个点；
2. 从接近竖直的姿态开始采样；
3. 让夹爪 \(x\) 轴对齐该点法向；
4. 依赖 antipodal cost 找好的抓取；
5. 如果两指之间有点，就把夹爪沿 \(x\) 轴向外移动，让这些点在 gripper frame 中居中。

这样能减少闭合夹爪时撞翻物体。

最后：

- 采样若干候选；
- 选 cost 最低的几个；
- 可视化。

PDF 说这个策略很简单，但效果相当不错。

# 5.6 Corner Cases：抓取系统的边界情况

如果你玩一下上面的抓取评分，会发现不少缺陷。

---

## 缺陷 1：没有检查 pre-grasp 碰撞

当前 cost 可能只检查抓取瞬间碰撞，没有检查预抓取姿态是否安全。  
可以很容易加一个 pre-grasp collision check。

---

## 缺陷 2：物体在箱子角落

如果物体卡在 bin 角落：

- 夹爪可能无法同时放到物体两侧；
- 强行抓会撞 bin 或撞物体；
- 当前策略可能永远不会选择抓盒子角落。

对于较大的夹爪尤其明显。

---

## TRI 的 pushing heuristic

PDF 提到在 TRI 的系统中，如果：

- bin 中有点云；
- 但找不到可行抓取；

就使用简单推动策略：

> 把手伸下去，把那一堆点云朝 bin 中间推一推。

这经常非常有效。

### 通俗类比

就像你抓不到角落里的东西时，先把它拨到中间再说。

---

## 缺陷 3：没有物体概念

纯几何点云方法不知道什么是“一个物体”。

因此会出现：

### Double picks

两个物体靠得很近时，夹爪可能一次抓两个。

### 重物抓取位置不佳

对于重物，最好靠近质心抓。  
但纯几何策略可能会抓住锤子末端手柄。

---

## 学习方法可能改善

PDF 认为这不一定只是点云信息不足。  
即使给你同样的点云，人类也不会犯同样错误。

因此可以学习 grasp metric：

> 从成功和失败经验中学习哪些抓取更好。

不需要通用人工智能，只需要：

> 以前这样抓失败了，以后少这样抓。

---

# 5.7 Programming the Task Level：任务级编程

前面我们有了感知和抓取选择。  
但机器人还需要一个高层控制系统：

> 什么时候感知？  
> 什么时候规划？  
> 什么时候抓？  
> 抓失败怎么办？  
> 什么时候结束？

这就是 task-level programming。

---

## 传统程序式编程的问题

很多人会想写：

```text
while bin 里还有物体:
    找到物体
    规划抓取
    抓起
    移动到目标 bin
    放下
```

这不是错的。  
但问题是：

> 高层程序必须和运行在 100 Hz 或 1 kHz 的低层控制器通信。

所以我们需要更好的编程范式。

---

## 三类任务级编程范式

PDF 总结为三类。

---

### 范式 1：过程式代码 + 消息传递

高层代码运行在单独线程，通过消息/事件和主机器人线程通信。

常见于 ROS 生态。

---

### 范式 2：任务级策略

直接用：

- finite state machine，FSM；
- behavior tree，行为树；

在主机器人/仿真循环中执行。

---

### 范式 3：任务级规划器

规划器根据规则把行为串起来，实现长期目标。

可能形式：

1. 输出 plan，然后执行；
2. online replanning；
3. 把 plan 编译成 policy，例如 FSM。

---

## Rod Brooks 与 planning 之争

PDF 提到 Rod Brooks 的著名文章：

> Elephants Don't Play Chess

他主张 behavior-based robotics，反对高层 symbolic planning。

他的 subsumption architecture 属于 task-level policies，可视为 behavior trees 的前身，并在早期 Roomba 上取得成功。

Planning 社区则认为：

> 对复杂任务，人类不可能手写所有情况；规划才真正 scalable。

后来发展出：

- belief space planning；
- task-and-motion planning，TAMP。

# 5.7.4 一个简单状态机：Clutter Clearing

## Example 5.13：Clutter Clearing 状态机

状态包括：

```text
Wait For Objects To Settle
Picking from X Bin
Picking from Y Bin
Go Home
DONE
```

还有一些中间/转移逻辑：

```text
Done with behavior; found a viable grasp in X
No viable grasps in X; found grasp in Y
Detected failed grasp; Replan
```

### 直观理解

流程大致是：

1. 等物体静止；
2. 在 X bin 找可行抓取；

```python
# 伪代码
for i in range(num_bricks):
    instance = parser.AddModelFromFile("foam_brick.sdf")

    x = rng.uniform(x_min, x_max)
```

# 3. 带摩擦接触的静态平衡

物体落下静止后，我们需要理解接触力如何平衡重力。

---

## 3.1 多体动力学方程

\[
M(q)\dot{v} + C(q,v)v =
\tau_g(q) +
\sum_i J_i^T(q)F_{c_i}
\]

### 类比

- \(M(q)\dot{v}\)：物体有多难加速；
- \(C(q,v)v\)：运动中产生的耦合效应；
- \(\tau_g(q)\)：重力想把系统拉成什么样；
- \(J_i^T F_{c_i}\)：接触力通过接触点对系统产生的广义效果。

---

## 3.2 静态平衡

静止时：

\[
v=0,\quad \dot{v}=0
\]

所以：

\[
\tau_g(q) =
-\sum_i J_i^T(q)F_{c_i}
\]

意思：

> 重力产生的广义力必须被接触力完全抵消。

---

# 4. Spatial Force / Wrench

空间力是 6D 向量：

\[
F =
\begin{bmatrix}
\tau \\
f
\end{bmatrix}
\]

其中：

- \(\tau\)：力矩；
- \(f\)：平移力。

---

## 4.1 Monogram Notation

\[
F_{Bp}^{name,C}
\]

表示：

- body：\(B\)；
- application point：\(Bp\)；
- expressed in frame：\(C\)；
- name：可选名字。

代码中常写：

```python
F_Bp_C
```

或：

```python
F_name_Bp_C
```

---

## 4.2 空间力代数

### 相加

同一 body、同一 expressed frame：

\[
F_{Bp}^{total,C}
=
\sum_i F_{Bp_i}^{C}
\]

### 换作用点

从 \(Bp\) 换到 \(Bq\)：

\[
f_{Bq}^C = f_{Bp}^C
\]

\[
\tau_{Bq}^C
=
\tau_{Bp}^C
+
{}^{Bq}p^{Bp}_C \times f_{Bp}^C
\]

### 换表达坐标系

\[
f_{Bp}^D = {}^D R_C f_{Bp}^C
\]

\[
\tau_{Bp}^D = {}^D R_C \tau_{Bp}^C
\]

---

## 4.3 实践提醒

写代码时常见错误：

- 力在 A frame，力矩在 B frame；
- 作用点不一致；
- 忘记把接触力从 contact frame 转到 body frame；
- 忘记叉乘项。

---

# 7. Contact Frame 与砖块平衡

## 7.1 Contact Frame 定义

接触坐标系：

- \(z\)：接触法向；
- \(x,y\)：切平面基。

正法向力抵抗穿透。

---

## 7.2 法向来自 signed distance

对于角点或不光滑几何，使用 signed distance function 的 subgradient 是可靠方式。

---

## 7.3 Example 5.5：砖块在地面

假设两个接触点 \(C_1,C_2\)。

重力：

\[
F_g^{B,W}
=
[0,0,0,0,0,-mg]^T
\]

接触力必须满足：

\[
f_{z} \ge 0
\]

平衡：

\[
F_1^{B,B}+F_2^{B,B}+F_g^{B,B}=0
\]

如果质心在两个接触点中间，两个竖直接触力相等。

---

## 7.4 小 sphere 角点的技巧

在点接触模型中，face-on-face 接触不唯一。  
有时会在盒子八个角添加小 sphere collision geometry，帮助接触引擎稳定选择接触点。

Hydroelastic 通常不需要这个技巧。

# 8. Coulomb Friction Cone

## 8.1 三条基本规则

### 无接触无力

\[
\phi_i(q)>0 \Rightarrow f_{c_i}=0
\]

### 法向只能推

\[
f_{c_i,z}\ge 0
\]

### 切向摩擦限制

\[
\sqrt{f_x^2+f_y^2} \le \mu f_z
\]

---

## 8.2 Rigid vs Soft Contact

### Rigid contact

求最小法向力以满足非穿透。  
这叫 principle of least constraint。

### Soft contact

力是穿透深度和穿透速度的函数。

---

## 8.3 摩擦锥的物理意义

摩擦锥表示：

> 摩擦能够提供的合法接触力集合。

# 9. 斜面砖块 Example 5.6

斜面角度 \(\gamma\)。

平衡方程：

\[
f_{1x}+f_{2x}=-mg\sin\gamma
\]

\[
f_{1z}+f_{2z}=mg\cos\gamma
\]

\[
-hf_{1x}+lf_{1z}
=
hf_{2x}+lf_{2z}
\]

摩擦约束：

\[
|f_{1x}|\le \mu f_{1z}
\]

\[
|f_{2x}|\le \mu f_{2z}
\]

结果：

\[
f_{2z}=f_{1z}+mg\frac{h}{l}\sin\gamma
\]

所以低处接触点法向力更大。

# 18. 法向与局部曲率估计

## 18.1 局部平面拟合

给定点集 \(p_i\)：

\[
\min_{p,n}
\sum_i
((p_i-p)^Tn)^2
\]

subject to:

\[
\|n\|=1
\]

最优位置：

\[
p^* = \frac{1}{N}\sum_i p_i
\]

协方差矩阵：

\[
W =
\sum_i
(p_i-p^*)(p_i-p^*)^T
\]

法向：

\[
n =
\text{eigenvector of smallest eigenvalue of } W
\]

---

## 18.2 Python 伪代码

```python
def estimate_normal(points, query_idx, k=12, camera_origin=None):
    idx = nearest_neighbors(points, query_idx, k)
    P = points[idx]

    p_bar = P.mean(axis=0)
    P_centered = P - p_bar

    W = P_centered.T @ P_centered

    eigvals, eigvecs = np.linalg.eigh(W)

    n = eigvecs[:, 0]

    # 让法向指向相机
    if camera_origin is not None:
        if np.dot(n, camera_origin - points[query_idx]) < 0:
            n = -n

    return n, eigvals, eigvecs
```

---

## 18.3 特征值含义

假设特征值排序：

\[
\lambda_0 \le \lambda_1 \le \lambda_2
\]

则：

- \(\lambda_0\) 对应法向；
- \(\lambda_1,\lambda_2\) 对应切向主方向；
- 特征值比例可以描述局部曲率/平面度/边缘程度。

# 19. Grasp Cost Function

候选抓取位姿：

\[
X_G
\]

---

## 19.1 法向对齐项

把点云转换到 gripper frame：

\[
P^G = X_G^{-1} P^W
\]

裁剪到两指之间。

成本：

\[
cost_{align}
=
-\sum_i
(n_{i,x}^G)^2
\]

越多点法向对齐夹爪 \(x\) 轴，cost 越负。

---

## 19.2 竖直姿态项

PDF：

\[
cost += -\alpha [0,0,-1]^T R^G [0,1,0]^T
\]

等价：

\[
cost += \alpha R^G_{3,2}
\]

其中：

- \(R^G_{3,2}\) 是第三行第二列；
- \(\alpha\) 是权重。

---

## 19.3 碰撞项

如果夹爪与 bin 或点云碰撞：

\[
cost = \infty
\]

---

## 19.4 Grasp Cost 伪代码

```python
def grasp_cost(X_G, points_W, normals_W, environment, alpha=0.1):
    if in_collision(X_G, environment, points_W):
        return np.inf

    X_G_inv = X_G.inverse()
    points_G = X_G_inv.TransformPointCloud(points_W)
    normals_G = X_G_inv.rotation().multiply(normals_W.T).T

    mask = inside_finger_box(points_G)

    if np.sum(mask) == 0:
        return 0.0

    align_cost = -np.sum(normals_G[mask, 0]**2)

    R_G = X_G.rotation().matrix()
    orientation_cost = alpha * R_G[2, 1]

    return align_cost + orientation_cost
```

注意：实际 Drake 中 transform normals 的 API 可能不同。

```python
def sample_grasps(points_W, normals_W, N=100):
```

## Exercise 5.1：Assessing Static Equilibrium

### 5.1a：斜面上的盒子

盒子质量 \(m\)，斜面角度 \(\theta\)，摩擦系数 \(\mu\)。

不滑条件：

\[
mg\sin\theta \le \mu mg\cos\theta
\]

所以：

\[
\mu_{min} = \tan\theta
\]

---

### 5.1b：三个球垂直叠放

如果三个球完全同轴叠放：

- 所有接触力沿竖直方向；
- 不需要切向摩擦力；
- 力矩也为零。

因此：

> 可以静态平衡，即使 \(\mu=0\)。

但它可能不稳定，轻微扰动会倒。

---

### 5.1c：一个球偏移地放在另一个球上

如果只是两个球，上面球偏移，且只有一个接触点：

- 上球重力和接触力很难同时满足力平衡和力矩平衡；
- 接触法向不通过竖直方向；
- 摩擦力会产生力矩，但没有其他力矩平衡。

因此通常：

> 理想点接触下不能静态平衡，除非有额外支撑、接触 patch、torsional friction 或其他接触。

---

### 5.1d：金字塔堆叠

如果是两个底球加一个顶球：

- 顶球由两个底球支撑；
- 底球会受到向外的水平分量；
- 需要足够摩擦、底球之间接触力、或几何支撑来防止外滑。

因此：

> 可能静态平衡，但需要足够摩擦或合适的几何约束。

---

### 5.1e：金字塔但底球之间有距离 \(d\)

当底球间距增加：

- 顶球接触法向更倾斜；
- 水平分量更大；
- 需要更大的摩擦或更复杂支撑。

因此：

> 可能存在静态平衡，但所需摩擦系数随 \(d\) 增大而增大；超过某个几何范围则不可能。

---

### 5.1f：为什么初始猜测重要？

因为 StaticEquilibriumProblem 是非凸优化，并包含 complementarity constraints。

不同初始猜测可能导致：

- 不同平衡状态；
- 优化失败；
- 找到不稳定平衡；
- 找到不可行解附近。

---

### 5.1g：自由体Diagram能回答哪两个约束？

自由体图最直接回答：

1. 力/力矩平衡；
2. 接触力是否合法：法向非负、切向力在摩擦锥内。

也可以说它能帮助判断接触/非穿透，但最核心的是平衡与摩擦锥约束。

## Exercise 5.2：Normal Estimation from Depth

### 目标

利用深度图像本身的空间结构估计法向，不做 nearest neighbor。

---

### a. 数学分析

对每个像素，取局部 patch，例如 3x3 或 5x5。

把 patch 中的像素通过相机内参转换成 3D 点：

\[
x = \frac{u-c_x}{f_x}z
\]

\[
y = \frac{v-c_y}{f_y}z
\]

然后对这些点做局部 PCA：

\[
W =
\sum_i
(p_i-\bar{p})(p_i-\bar{p})^T
\]

最小特征值对应法向。

---

### b. 实现伪代码

```python
def normals_from_depth(depth, camera_info):
    fx, fy, cx, cy = camera_info

    H, W = depth.shape
    normals = np.zeros((H, W, 3))

    for v in range(1, H-1):
        for u in range(1, W-1):
            patch_points = []

            for dv in [-1, 0, 1]:
                for du in [-1, 0, 1]:
                    z = depth[v+dv, u+du]

                    if z <= 0:
                        continue

                    x = (u+du-cx) * z / fx
                    y = (v+dv-cy) * z / fy

                    patch_points.append([x, y, z])

            if len(patch_points) < 3:
                continue

            P = np.array(patch_points)
            p_bar = P.mean(axis=0)
            C = (P - p_bar).T @ (P - p_bar)

            eigvals, eigvecs = np.linalg.eigh(C)

            n = eigvecs[:, 0]

            # 让法向指向相机原点
            if n @ (-p_bar) < 0:
                n = -n

            normals[v, u] = n

    return normals
```

### c. 什么时候深度图法不如 nearest neighbor？

在以下情况：

- 深度边缘；
- 物体边界；
- 遮挡边界；
- patch 内包含前景和背景；
- 深度缺失；
- 非均匀投影导致像素邻域不等于空间邻域。

这时 nearest neighbor 在 3D 空间中找邻居更可靠。

## Exercise 5.3：Analytic Antipodal Grasping

### 目标

如果知道物体形状方程，能否解析找 antipodal points？

---

### a. Antipodal points 是能量函数临界点

定义两点距离平方：

\[
E(x,y)=\|x-y\|^2
\]

约束：

\[
x \in S,\quad y \in S
\]

其中 \(S\) 是物体表面。

在临界点，梯度必须垂直于表面切平面。  
因此：

\[
x-y \parallel n(x)
\]

\[
y-x \parallel n(y)
\]

这说明两点连线与法向对齐，法向相反，正是 antipodal grasp 的条件。

---

### b. 反命题不成立

不是所有临界点都是好的 antipodal grasp。

原因：

- 可能是局部最大距离；
- 可能是 saddle point；
- 可能碰撞不可行；
- 可能法向对齐但夹爪无法到达；
- 可能 Hessian 不定。

---

### c. MathematicalProgram 实现思路

```python
prog = MathematicalProgram()

x = prog.NewContinuousVariables(3)
y = prog.NewContinuousVariables(3)

# 表面约束
prog.AddConstraint(lambda x: surface_signed_distance(x), ...)
prog.AddConstraint(lambda y: surface_signed_distance(y), ...)

# antipodal energy
def antipodal_cost(vars):
    x = vars[0:3]
    y = vars[3:6]

    nx = surface_normal(x)
    ny = surface_normal(y)

    line_dir = (x - y)
    line_dir = line_dir / np.linalg.norm(line_dir)

    cost = np.sum((nx + ny)**2)
    cost += np.linalg.norm(np.cross(line_dir, nx))**2
    return cost

prog.AddCost(antipodal_cost, np.concatenate([x, y]))

result = Solve(prog)
```

### d. Hessian 与抓取类型

能量函数的 Hessian 可以判断临界点类型：

- positive definite：局部最小，稳定抓取；
- negative definite：局部最大，不稳定；
- indefinite：saddle point；
- 接近奇异：对称或退化抓取。

### 5.5a：球被打掉后发生什么？

场景：

- 机器人正在执行任务；
- 球从手中被打掉；
- 球滚到可见但较远的地方。

通常会：

1. `Ball Grasped?` 条件失败；
2. 树从根重新评估；
3. `Ball Close?` 也失败；
4. 因此执行 `Approach Ball`。

所以答案是：

> `Ball Grasped?` 失败；随后由于 `Ball Close?` 也为 false，行为树会重新执行 `Approach Ball`。

### 5.5b：补充 FSM

虽然 PDF 没有给出完整图，但逻辑通常是：

```text
Search Ball
  ↓ if ball seen but not close
Approach Ball
  ↓ if ball close
Grasp Ball
  ↓ if ball grasped
Transport / Place Ball
  ↓ if placed
Done
```

需要补的四个值通常对应：

1. ball not close → Approach Ball；
2. ball close → Grasp Ball；
3. ball not grasped → Grasp Ball；
4. ball grasped → Place/Transport。

### 5.5c：Bin Picking Behavior Tree

目标行为：

```text
while Bin1 not empty:
    if feasible grasp exists:
        select grasp
        grasp object
        transport to above Bin2
        drop
    else:
        randomize bin
```

一个可用的树结构如下：

```text
Root: Fallback
├── Sequence: TaskDone
│   └── Condition: Bin 1 empty?
│
└── Sequence: PickOneObject
    ├── Fallback: GetFeasibleGrasp
    │   ├── Sequence: TrySelectGrasp
    │   │   ├── Condition: Feasible Grasp Exists?
    │   │   ├── Action: Select Grasp
    │   │   └── Condition: Grasp selected?
    │   │
    │   └── Action: Randomize Bin
    │
    ├── Action: Grasp Object(s)
    ├── Condition: Object Grasped?
    ├── Action: Transport grasped object(s) to above Bin 2
    ├── Condition: Grasped Object(s) above Bin 2?
    ├── Action: Drop grasped object(s) into Bin 2
    └── Condition: Object(s) in Bin 2?
```

说明：

- 如果 `Bin 1 empty?` 成功，任务完成；
- 如果 bin 不空，进入 `PickOneObject`；
- 如果没有 feasible grasp，`GetFeasibleGrasp` fallback 会执行 `Randomize Bin`；
- 如果有 feasible grasp，则选择、抓取、运输、放下；
- 若需要持续清空整个 bin，外层可加 Repeat/Loop decorator，或由系统反复 tick root 直到 `Bin 1 empty?` 成功。

常见错误包括：

- 用 Sequence 处理“如果没有 grasp 就 randomize”，应该用 Fallback；
- `Randomize Bin` 放在错误位置；
- 缺少 `Object Grasped?` 检查；
- 先 Drop 后 Transport；
- 缺少 `Bin 1 empty?` 完成条件；
- 缺少循环机制。

### b. Filter antipodal pairs

常见过滤条件：

```python
def valid_pair(p, q, n, m):
    distance = np.linalg.norm(p - q)

    if distance > gripper_width:
        return False

    if np.dot(n, m) > -np.cos(max_angle):
        return False

    if collision_along_grasp(p, q):
        return False

    if not reachable(p, q):
        return False

    return True
```

```python
midpoint = 0.5 * (p + q)

z_axis = np.cross(x_axis, y_axis)

R = RotationMatrix(np.column_stack([x_axis, y_axis, z_axis]))

X_G = RigidTransform(R, midpoint)
```

# 29. 本章最重要的工程经验总结

---

## 经验 1：场景生成比想象重要

如果训练/测试场景不够多样，抓取系统会过拟合。

---

## 经验 2：静态平衡是接触物理的入口

理解摩擦锥、法向力、力矩平衡，才能理解为什么物体稳定或不稳定。

---

## 经验 3：抓取不是单点几何，而是 wrench 能力

好抓取不是“看起来夹住了”，而是：

> 能否抵抗重力、扰动、扭矩。

---

## 经验 4：点云抓取 pipeline 的顺序很重要

crop、normal estimation、merge、downsample 的顺序会影响结果。

---

## 经验 5：采样常常比硬优化更实用

抓取位姿优化高度非凸。  
随机采样 + cost scoring 是工程上常用且有效的方法。

---

## 经验 6：失败处理决定系统成功率

角落物体、double pick、抓空、碰撞、滑掉，都需要策略：

- replan；
- pushing；
- randomize；
- change grasp；
- ask for help。

---

## 经验 7：任务级控制必须与低层控制兼容

高层逻辑不能只是 Python 顺序脚本。  
它必须和实时控制器、传感器、状态机、规划器协同工作。
