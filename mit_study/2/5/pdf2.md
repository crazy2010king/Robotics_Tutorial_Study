## 0. 开篇：一箱乱玩具，机器人怎么搬？

### 0.1 一句话概括

> **料箱抓取 = 机器人面对一箱随机堆放的物体，要把它们从一个箱搬到另一个箱，至于物体是什么、搬到对面箱的哪个位置，都"无所谓"。本章教你：怎么造这样一箱乱东西来训练/测试机器人、物体静止后力怎么平衡、摩擦锥怎么限制抓取、怎么从点云里挑出一个捏得住的抓法、最后怎么用状态机/行为树把整个流程编排起来。**

### 0.2 作者开场白的逐句翻译

> 这章我们考虑料箱抓取问题的**最简单版本**：机器人有一个装满随机物体的箱，只需把那些物体从一个箱移到另一个箱。我们对那些物体是什么、它们在另一个箱最终落在哪**都无所谓（agnostic）**，但希望我们的解对**非常多样的物体**有合理性能。这恰好是创建机器人学习训练场的方便方式——我们可以让机器人**日夜不停地在箱间来回搬物体**，间歇地往箱里加/减物体以增加多样性。当然在仿真里更容易！料箱抓取在物流等行业有潜在非常重要的应用，而且这问题有**精细得多的版本**（例如我们可能只抓特定类的物体，和/或把物体放到已知位置做"packing 装箱"）。但先从基本版开始。

**类比（全章总纲，请刻进脑子）**：
- 想象你面前一个**玩具箱**，里面乱七八糟堆着积木、球、小车。你的任务是**把它们一个个捡起来，扔进旁边另一个空箱**——**至于捡哪个、扔对面箱的哪个角落，你不在乎，只要搬空就行**。
- 这就是料箱抓取。**它简单到能当"训练场"**（机器人可以 7×24 自己练），**又真实到物流仓库天天在干**。
- **更难的版本** = "只捡红色的""把积木按颜色码整齐"——那是"packing"，本章先不碰。

## 1. 对应 5.1：生成随机杂乱场景 —— "怎么造一箱乱东西"

### 1.1 为什么需要这步

> 如果我们的目标是测试多样料箱抓取情况，第一个任务是搞清楚**怎么生成多样仿真**。我们该怎么把箱装满物体？ finora 我们靠**仔细在 Context 里设每个物体的初始位置**来搭每个仿真，但那方法**不能 scale**（不能规模化）。

**类比**：以前你**亲手把每个玩具摆好**才能开始测试——摆 100 次累死。**我们需要"抓一把玩具往箱里一倒"的自动方法。**

### 1.2 对应 5.1.1：Falling things（掉落的东西）

> 真实世界里，我们大概就**把随机物体倒进箱里**。这对仿真也是不错的策略。只要初始条件（和时间步）合理，我们大致能期望仿真**忠实地实现多体物理**；但如果用**多个占据同一物理空间的物体**初始化 Context，物理就没定义好。最简单最常见的避免方法：**生成随机数量、随机位姿的物体，垂直位置错开（staggered）**，让它们 trivially 一开始不穿透。

**类比（错开高度往下倒，必懂）**：
- 你不能让两个玩具**一开始就叠在同一个位置**——物理引擎会"炸"（两个物体占同一空间，力算不出来）。
- 解决：**让每个玩具从不同高度开始往下掉**（垂直方向错开 0.1 米），它们各自掉下去、互相撞、最后堆成一堆。**就像你真的把玩具一把撒下去。**

> 如果你去找，能在大多数高级多体模拟器的 demo reel 里看到**大量物体掉落的动画**。（这些 demo 可能有点误导：从远处看大量物体掉落看起来相对不错，但 zoom in 仔细看常常发现很多 anomaly 异常。）对我们的目的，**掉落动力学本身不是焦点**。我们只想要**物体掉完后的状态**，作为操作系统的初始条件。

#### Example 5.1（2D 泡沫砖堆）

> 2D 情况。我加了很多我们最爱的红泡沫砖实例。注意可以写高度优化、利用物理被限制在 2D 的模拟器；我没那么做。而是给每个砖加一个**连接世界的 planar joint**，跑完整 3D 模拟器。planar joint 有 3 个自由度。我把它们定向成约束物体在 xz 平面。我把 Context 里每个物体初始位置设成**水平位置均匀分布、均匀旋转、垂直位置每 0.1m 错开**。我们只需模拟**一秒多一点**让砖静止，得到我们想要的"初始条件"。

**类比**：2D 里砖只能在"一面墙前的平面"里掉（planar joint 锁住另外 3 个自由度），**像看皮影戏**——简化了，但物理引擎还是跑完整的 3D 计算。

> 用任何随机物体做这个其实没区别——这是用 **YCB 数据集**里随机抽几个物体替换砖的样子。让我觉得有趣的是，即使物体有点荒谬，我们也能看到**中心极限定理在 hard at work**（一堆随机形状堆起来，统计上趋于某种规律分布）。

#### Example 5.2（用杂物填箱）

> 同样技术 3D 也行。3D 设均匀随机朝向需要多一点思考，但 Drake 提供 **`UniformlyRandomRotationMatrix`** 方法（也有四元数和 roll-pitch-yaw 的版本）帮我们做这活。

> 请 appreciate：**料箱是生成随机场景的特别简单的情况**。如果你想生成随机厨房环境，你不会满意于"从均匀随机 i.i.d. 位姿掉落冰箱、烤面包机、凳子"的方案。那些情况下，编写合理分布变得有趣得多 [2]；我们后面会回到**生成式场景模型**的话题。

**类比**：往玩具箱倒玩具，"随便撒"很自然；但往厨房"撒"冰箱和烤箱就荒谬了——**真实场景的物体摆放有结构**（冰箱靠墙、杯子在桌上），需要更聪明的"生成模型"。

## 2. 对应 5.2：带摩擦接触的静态平衡 —— "积木堆好为什么不倒"

> 虽然上面例子概念上很简单，物理引擎里其实发生很多事让这一切 work。为了欣赏一些细节，让我们探索最简单的情况——**所有物体静止后的（静态）力学**。

**类比（叠积木，全节总纲）**：一堆积木堆好不动，是因为**每块积木上所有力（重力 + 各接触点顶它的力）互相抵消、力矩也抵消**。本节就是把这件事写成方程。

### 2.1 力平衡方程

> 我不会深入完整讨论多体动力学/仿真（我有更多笔记在别处）。重要的是理解熟悉的 $f=ma$ 当我们用广义位置 $q$、速度 $v$ 写下来时取一个特定形式：

$$M(q)\dot v + C(q,v)v = \tau_g(q) + \sum_i J_i^T(q)\,F^{c_i}$$

> 我们已经理解广义位置 $q$、速度 $v$。方程左边只是"质量乘加速度"的推广：质量矩阵 $M$、科里奥利项 $C$。右边是（广义）力的和：$\tau_g$ 捕捉重力项，$F^{c_i}$ 是第 $i$ 个接触的**空间力**，$J_i(q)$ 是第 $i$ 个"接触 Jacobian"——从广义速度映射到第 $i$ 个接触帧空间速度的 Jacobian。

> 我们这里的兴趣是找这些微分方程的（稳定）**稳态解**，作为仿真的好初始条件。**稳态时 $v=\dot v=0$**，方便地方程左边所有项为零。这给我们只剩**力平衡方程**：

$$\tau_g(q) = -\sum_i J_i^T(q)\,F^{c_i}$$

**类比**：静止时"加速度=0"，所以"质量×加速度"那堆全没了，**只剩"重力 = 所有接触顶力的反作用"的平衡**。

### 2.2 对应 5.2.1：Spatial force（空间力）

> 继续之前，让我们对力记号更小心，定义它的**空间代数**。我们常把力想成施加在刚体某点的三元素向量（x,y,z 分量）。更一般地，我们定义**六分量向量的空间力**，用 monogram 记号：

$$F^{Bp_{name},C} = \begin{bmatrix} \tau^{Bp_{name},C} \\ f^{Bp_{name},C} \end{bmatrix}$$

> $\tau \in \mathbb{R}^3$ 是施加在 body B 的点 p、在帧 C 表达的**力矩**，$f \in \mathbb{R}^3$ 是**平移/笛卡尔力**。空间力也常被称为 **wrench**。如果你觉得把力想成有旋转分量奇怪，这么想：世界可能只在接触点施加笛卡尔力，但我们常想把施加在不同点的许多笛卡尔力的组合效果**总结到一个公共帧**。为此，我们把每个笛卡尔力在施加点的等效效果，表示成施加在 body 上不同点的力和力矩。

**类比（空间力 = "力 + 它产生的拧劲"打包，必懂）**：
- 你推门：手施加一个**力** $f$，但因为推的位置离门轴有距离，还产生一个**拧门的力矩** $\tau$。
- 空间力 = **把"力 + 拧劲"打包成一个 6 维向量**。
- **空间力相加**：施加在同一 body 同一帧的空间力直接加。
- **空间力换施加点**：力不变，力矩要加上"换点产生的额外拧劲"（叉积项 $\tau^{Bq} = \tau^{Bp} + ({}^{Bq}p^{Bp}\times f^{Bp})$）。
- **换 expressed-in 帧**：用旋转矩阵 $^DR^C$ 转力和力矩。

### 2.3 对应 5.2.2：Collision geometry（碰撞几何）

> 现在有了记号，我们接下来要理解**接触力从哪来**。机器人几何引擎（如 Drake 的 SceneGraph）区分几何在仿真中能扮演的几种角色。在机器人描述文件里，我们区分 **visual 几何**和 **collision 几何**。特别地，仿真里每个刚体可以有多个关联的 collision 几何（扮演"proximity 接近"角色）。碰撞几何常常比用于 illustration 和感知仿真的 visual 几何**简单得多**——有时只是 visual mesh 的低多边形版本，有时我们实际用更简单的几何（box、sphere、cylinder）。这些更简单的几何让物理引擎**更快更鲁棒**。

**类比（碰撞几何 = "简化版碰撞外壳"，必懂）**：
- **visual 几何** = 给人看的"漂亮外壳"（高多边形、有纹理）。
- **collision 几何** = 给物理引擎算碰撞的"简化外壳"（几个 box/sphere 拼起来）。
- **为什么分开**？算碰撞很贵，**用简单形状算快得多、也不容易出 bug**。

#### Example 5.3（Collision geometry inspector）

> Drake 有一个非常有用的 **ModelVisualizer** 工具，把 illustration 和 collision 几何角色 publish 到 Meshcat。在 meshcat controls 导航到 **Scene > drake > proximity**，勾选 box 启用可视化 proximity 角色的几何。

> SceneGraph 也实现 **collision filter** 概念。指定例如 iiwa link 5 的几何不能和 link 4 或 6 的几何碰撞可能很重要。指定某些碰撞应被忽略不仅加速计算，也促进对 link 用简化碰撞几何。如果我要确保那些 sphere 和 cylinder 在任何可行关节角都不 overlap，用它们准确近似 link 4 和 5 会极难。

**类比（collision filter = "自己人别互相撞"）**：机械臂相邻两节本来就连在一起，**不该算"碰撞"**——collision filter 就是告诉引擎"这俩是连着的，别报碰撞"。

> 那么接触力 $F^{c_i}$ 从哪来？每对没被 collision filter 过滤掉的碰撞几何，潜在地有一个相等相反的接触（空间）力。在 SceneGraph，**`GetCollisionCandidates`** 方法返回它们全部。我们称碰撞对里两个 body 为"body A"和"body B"。

### 2.4 对应 5.2.3：碰撞中 body 间的接触力

> 在我们的数学模型里，两个 body 绝不会占据同一空间区域，但用数值积分的仿真里这很少能完全避免。大多数模拟器把碰撞中两 body 间的接触力**总结成一个或多个接触点的笛卡尔力**。很容易低估这步！

> 首先，让我们 appreciate 我们代码里要搞对的 case 的纯粹数量；不幸地开源工具在这里有 bug 极常见。但我觉得我下面创建的简单 GUI 让"要求用施加在一点的单个笛卡尔力总结深穿透中两 body 间的力"充满 peril 相当明显。当你移动物体，你会发现很多不连续；这是为什么你有时看到刚体仿真"explode 爆炸"的常见原因。用多个接触点而非单接触点总结力可能看起来自然，有些模拟器这么做，但很难写一个只依赖几何当前构型、从一时间步到下一致地选接触点的算法。

> **Drake 的创新之一**使它特别擅长模拟复杂接触情况的是我们**移除了点接触模型**。当我们在 Drake 启用 **hydroelastic 接触**，穿透两 body 间的空间力通过对"hydroelastic surface"积分计算，推广了接触 patch 的概念 [3]。

**类比（点接触 vs hydroelastic，必懂）**：
- **点接触** = "两物体接触 = 一个点顶着一个点"——**简单，但深穿透时"用哪个点"很难定，容易跳变、爆炸**。
- **hydroelastic** = "两物体接触 = 一片'压扁的面'互相压"——**对这片面积分算力**，**更稳、更物理**。Drake 的杀手锏之一。

### 2.5 对应 5.2.4：The Contact Frame（接触帧）

> 我们仍需决定这些空间力的幅度和方向，为此我们需要指定空间力施加于其中的**接触帧**。例如，我们可能用 $C^B$ 表示 body B 上的接触帧，力施加在帧原点。

> 虽然我强烈主张在你的仿真里用 hydroelastic 接触模型，但为了 exposition，让我们在这里想点接触模型。如果碰撞引擎产生若干接触点位置，我们该怎么定义帧？**我们的约定是把正 z 轴对齐"接触法向"，正力抵抗穿透**。定义这法向也需要小心。例如，box 角上的法向是什么？取两 body 间 **signed-distance 函数的（子）梯度**作为法向提供可靠定义，能推广到广义坐标。接触帧的 x 和 y 轴是切向坐标的任何正交基。

**类比（接触帧 = "在接触点立一个小坐标架"，必懂）**：
- 在接触点立一个小坐标架：**z 轴垂直于接触面往外**（"顶"的方向），**x、y 轴躺在接触面上**（"滑"的方向）。
- **法向力**沿 z（只能顶，不能拉）；**摩擦力**在 x-y 面内（抵抗滑动）。

#### Example 5.5（Brick on a half-plane，砖在半平面上）

> 让我们在简单例子上过这些细节——我们泡沫砖坐在地上。地 welded 到世界，所以没自由度；我们可以忽略施加在地上的力，聚焦施加在砖上的力。

> 接触力和接触帧在哪？如果我们只用 box-on-box 几何，那么这"face-on-face"接触期间接触力位置选择不唯一；3D 里更甚（三个力就够）。让我们暂时假设我们的接触引擎决定两个接触点——box 每个角一个。我在下面草图标注了帧 $C_1$ 和 $C_2$。

> 为了达到静态平衡，我们要求砖上所有力和力矩平衡。我们有三个力要考虑：$F^g, F^1, F^2$，分别用 gravity、contact 1、contact 2 的简写命名。重力向量最自然在世界帧描述，施加在 body 质心：

$$F^{gB,W} = [\,0,\ 0,\ 0,\ 0,\ 0,\ -mg\,]^T$$

> 接触力最自然在接触帧描述；例如我们知道 $f^{1C_1,C_1,z}\ge 0$ 因为力不能拉地。为了写力平衡方程，我们需要用空间代数把所有空间力表达在同一帧、施加在同一点。例如，如果我们要变换接触力 1，我们可以先改变帧：$F^{1B,B}={}^BR^{C_1}F^{1C_1,C_1}$，然后改变它施加的点：$f^{1B,B}=f^{1B,B},\ \tau^{1B,B}=\tau^{1B,B}+({}^{B}p^{BC_1}\times f^{1B,B})_B$。

> 我们现在可以解力平衡：$F^{1B,B}+F^{2B,B}+F^{gB,B}=0$，这是 3D 里六个方程（或 2D 里只三个）。平移分量告诉我 $f^{1B,B}+f^{2B,B}=[0,0,mg]^T$，但是 y 里的力矩分量告诉我如果质心离两接触点等距，$f^{1,B,z}$ 和 $f^{2,B,z}$ 必须相等。我们还没说水平力的任何事，除了它们必须平衡。让我们接下来发展那个。

**类比（两脚站立的体重分配，必懂）**：砖坐在地上两角 = 你**两脚站立**。重力 $mg$ 往下，两脚各顶一部分（$f^{1z}+f^{2z}=mg$）。如果你**站得正**（质心在两脚正中），两脚各顶一半；**往前倾**，前脚顶得多、后脚顶得少。力矩平衡方程就是在算这个"体重分配"。

### 2.6 对应 5.2.5：The (Coulomb) Friction Cone（库仑摩擦锥）

> 现在支配接触力的规则开始成形。首先且最重要，我们要求**没有"力在距离上"（no force at a distance）**。用 $\phi_i(q)$ 表示构型 $q$ 中两 body 间距离，我们有

$$\phi(q)>0 \Rightarrow f^{c_i}=0$$

> 第二，我们要求**法向力只抵抗穿透**；body 绝不被拉进接触：$f^{c_i,Cz}\ge 0$。在刚接触模型里，我们解强制非穿透约束的**最小法向力**（这被称为**最小约束原理 principle of least constraint**）。在软接触模型里，我们定义力为穿透深度和速度的函数。

> 切向方向的力由摩擦引起。最常用的摩擦模型是**库仑摩擦**，它陈述

$$\sqrt{(f^{c_i,Cx})^2+(f^{c_i,Cy})^2} \le \mu\, f^{c_i,Cz}$$

> $\mu$ 是非负标量摩擦系数。典型地我们定义 $\mu_{static}$（切向速度为零时施加）和 $\mu_{dynamic}$（切向速度非零时施加）。在库仑摩擦模型里，切向接触力是这摩擦锥内**产生最大耗散**的力。

> 放在一起，这些约束的几何形成可容许接触力的锥。它著名地被称为"**摩擦锥**"，我们会常提到它。

**类比（摩擦锥 = "推箱子不滑的安全角度锥"，必懂）**：
- 你推地上的箱子：**垂直往下压**，箱子纹丝不动；**斜着推**，只要不太斜，摩擦够，也不滑；**斜到某个临界角**，箱子"嗖"地滑出去。
- 那个"临界斜度"围成的锥 = **摩擦锥**。**接触力必须落在这锥里**，否则就滑。
- **$\mu$ 越大，锥越"胖"**（冰面 $\mu$ 小锥瘦，砂纸 $\mu$ 大锥胖）。
- **"力在距离上=0"** = 两物体没碰着，就**没有任何接触力**（不能隔空使劲）。
- **法向力 $\ge 0$** = 地面只能"顶"你，不能"吸"你。

> 我们写力在某个集合里有点奇怪。当然世界会只挑一个力施加？它不能施加集合里所有力。摩擦锥指定**可能力的范围**；在库仑摩擦模型下我们说世界将施加的力是这集合内**能成功抵抗接触 x-y 帧相对运动**的力。如果摩擦锥内没有力能完全抵抗运动，那么我们有滑动，我们说世界将施加的力是摩擦锥内**最大耗散**的力（对锥形摩擦锥，指向滑动速度的反方向）。所以即使世界确实会"挑"摩擦锥里的一个力施加，推理可能施加的力的集合仍有意义，因为它们表示摩擦能完美抵抗的可能对抗力的集合。例如，重力下的砖如果我们可以用摩擦锥内的力精确对抗重力就不会动。

#### Example 5.6（Brick on an inclined half-plane，砖在斜面上）

> 如果我们取上个例子，但把桌子倾斜相对重力一个角 $\gamma$，那么水平力开始变得重要。过方程之前，让我们检查你的直觉。这构型里两角上的力的幅度会保持相同吗？还是下角会有更多接触力？

> 在上面 illustration 里，你会注意到接触帧旋转使 z 轴对齐接触法向。我画了两个可能摩擦锥（深绿和浅绿），对应两个不同摩擦系数。我们能立即通过 inspection 看出**较小的 $\mu$ 值（对应深绿）不能产生完全对抗重力的接触力**（摩擦锥不包含垂直线）。这情况下，box 会滑动，这构型不存在静态平衡。如果我们增加（静态）摩擦系数到对应浅绿的范围，那么我们能找到产生平衡的接触力。确实，对这问题，我们需要一些摩擦才有平衡（我们会在练习里探索这个）。我们也需要质心在 ramp 上的垂直投影落在两接触点之间，否则砖会翻过底边。我们可以通过写同样的力/力矩平衡方程看到这。我们可以写它们施加在 B、在 body 帧 B 表达，假设质心在砖中心、砖长 $l$ 高 $h$：

$$f^{1B,Bx}+f^{2B,Bx}=-mg\sin\gamma,\quad f^{1B,Bz}+f^{2B,Bz}=mg\cos\gamma$$
$$-h f^{1B,Bx}+l f^{1B,Bz}=h f^{2B,Bx}+l f^{2B,Bz}$$
$$f^{1B,Bz}\ge 0,\ f^{2B,Bz}\ge 0,\quad |f^{1B,Bx}|\le\mu f^{1B,Bz},\ |f^{2B,Bx}|\le\mu f^{2B,Bz}$$

> 那么接触力的幅度相同还是不同？把第一个方程代入第三个揭示

$$f^{2B,Bz}=f^{1B,Bz}+\frac{mgh}{l}\sin\gamma$$

**类比（斜面站立的体重前移，必懂）**：砖在斜面上，**重力把它往下拉**，需要摩擦顶住（$f^x$ 平衡 $mg\sin\gamma$）。而且**下角顶得更狠**（$f^{2z}$ 比 $f^{1z}$ 多 $\frac{mgh}{l}\sin\gamma$）——**就像你站在斜坡上，体重压在前脚掌**。如果斜面太陡或摩擦太小，摩擦锥装不下需要的力，砖就滑；如果质心投影跑出两接触点，砖就翻。

### 🧪 代码 2：斜面砖的力平衡 + 摩擦锥检查（纯 numpy，对应 Example 5.6 + 练习 5.1）

> PDF 没内联代码。这段解斜面砖的力平衡，检查"给定 $\gamma$，最小 $\mu$ 是多少才不滑"，并验证"下角顶得更狠"。

```python
import numpy as np
m, g, l, h = 1.0, 9.81, 0.2, 0.05     # 质量, 重力, 砖长, 砖高
def solve_incline(gamma, mu):
    s, c = np.sin(gamma), np.cos(gamma)
    # 力平衡(2D): fx和=-mg s, fz和=mg c; 力矩平衡 -> f2z - f1z = (mgh/l) s
    # 设 f1z, f2z; 水平力取最大静摩擦边界方向(沿斜面向上抵抗下滑): f_ix = -mu*f_iz (抵抗下滑)
    # 由 fx和: -mu*(f1z+f2z) = -mg s  => f1z+f2z = mg s/mu
    # 由力矩:    f2z - f1z = (mgh/l) s
    sum_fz = m*g*s/mu if mu>0 else np.inf
    diff_fz = (m*g*h/l)*s
    f2z = 0.5*(sum_fz + diff_fz); f1z = sum_fz - f2z
    return f1z, f2z
for gamma in [np.radians(10), np.radians(30)]:
    for mu in [0.2, 0.5, 0.8]:
        f1z, f2z = solve_incline(gamma, mu)
        ok = (f1z>=0 and f2z>=0)        # 法向力非负(不拉地)
        print(f"γ={np.degrees(gamma):.0f}° μ={mu}: f1z={f1z:.2f} f2z={f2z:.2f} 可行(不拉地)={ok}")
# 观察: 下角f2z总>上角f1z; mu太小或γ太大 -> f1z<0 不可行(需拉地=不可能->滑)
```

**你会看到**：**下角 $f^{2z}$ 总大于上角 $f^{1z}$**（验证 Example 5.6 的公式）；**$\mu$ 太小或 $\gamma$ 太大时 $f^{1z}<0$**——**意味着需要"拉地"，不可能，于是砖滑/翻**。这就是练习 5.1a 的"最小摩擦系数"的数值版。

### 2.7 对应 5.2.6：静态平衡作为优化问题

> 与其从随机高度掉落物体，也许我们可以用优化初始化我们的仿真，找**已经处于静态平衡**的初始条件。在 DRAKE，**`StaticEquilibriumProblem`** 收集我们上面列举的所有约束进一个优化问题：

$$\text{find } q \quad \text{subject to}\quad \tau_g(q)=-\sum_i J_i^T(q)f^{c_i},\quad f^{c_i,Cz}\ge 0\ \forall i$$
$$\|f^{Cc_i x,y}\|_2\le\mu f^{Cc_i z}\ \forall i,\quad \phi_i(q)\ge 0\ \forall i$$
$$\phi(q)=0 \text{ or } f^{c_i,Cz}=0\ \forall i,\quad \text{joint limits}$$

> 这是**非线性优化问题**：它包含我们上章讨论的**非凸非穿透约束**。倒数第二个约束（逻辑或）特别有趣；形式 $x\ge0,\ y\ge0,\ x=0\text{ or }y=0$ 的约束被称为**互补约束（complementarity constraints）**，常写成 $x\ge0,\ y\ge0,\ xy=0$。我们可以通过放松等式为 $0\le\phi(q)f^{c_i,Cz}\le tol$ 让问题对非线性优化求解器更容易，这给优化器一个合适的梯度跟随，代价是允许一些"力在距离上"。

> 很容易加额外代价和约束；对初始条件我们可能用一个**保持 $q$ 接近初始构型空间样本**的目标。

**类比（互补约束 = "要么没碰，要么碰了但力顶住"，必懂）**：
- $xy=0$ 且 $x,y\ge0$ = "**$x$ 和 $y$ 至少一个是 0**"。
- 这里 $x$="穿透深度 $\phi$"，$y$="接触力 $f$"：**要么没穿透（$\phi>0$）那力必须 0；要么碰了（$f>0$）那穿透必须 0**。**两者不能同时为正**——你不能"既穿透又没力顶"。
- 放松成 $0\le\phi f\le tol$ = "**允许一点点'隔空使劲'，换优化器好算**"。

## 4. 对应 5.4：基于模型的抓取选择 —— "已知物体形状时，怎么挑好抓法"

> 什么构成好抓取？这话题在机器人里被广泛研究了几十年，最初聚焦想（潜在灵巧的）手与已知物体交互。[4] 是那文献的极好 survey；我在这里只总结几个关键想法。如果抓取的目标是在手里稳定物体，那么"好抓取"的一个定义是**能够抵抗施加在 body 上的"对抗"（adversarial）wrench 描述的扰动**。

**类比（好抓法 = "捏得稳，别人推搡也不掉"，全节总纲）**：你捏一个杯子，**好抓法** = 别人从各个方向推杯子，你手指的摩擦都顶得住、杯子不滑不转。**"能抵抗哪些推搡"的能力，用一个叫"接触 wrench 锥"的东西量化。**

### 4.1 对应 5.4.1：The contact wrench cone（接触 wrench 锥）

> 上面我们引入摩擦锥作为摩擦能为抵抗运动产生的可能力的范围。对抓取规划目的，通过对摩擦锥里的力施加**加性逆**，我们可以获得在接触点能抵抗的所有"对抗"力。为了理解所有接触力（施加在多个接触点）抵抗 body 运动的总能力，我们想以某种方式把这些力加在一起。幸运地，空间力的空间代数能容易地从操作空间力向量推广到操作整个空间力集合。

> 因为我们这里的兴趣集合是凸锥，我会用相对标准的选择 $K^{Bp_{name},C}$ 表示六维 wrench 锥。特别地，我们有对接触帧 C 点接触模型（按我们定义的没有扭转摩擦）的锥：

$$K^{CC}=\left\{\begin{bmatrix}0\\0\\0\\f^{CCx}\\f^{CCy}\\f^{CCz}\end{bmatrix}:\sqrt{(f^{CCx})^2+(f^{CCy})^2}\le\mu f^{CCz}\right\}\quad(5)$$

> 空间力的空间代数能直接应用到 wrench 锥：对施加在同一点、表达在同一帧的 wrench 相加，我们寻求的解释是 wrench 锥的和形成的锥描述通过从每个个体锥选一个元素并加起来能获得的 wrench 集合。这集合算子是 **Minkowski 和**，我们用 $\oplus$ 表示，例如：

$$K^{Bp_{total},C}=K^{Bp_0,C}\oplus K^{Bp_1,C}\oplus\cdots\quad(6)$$

> 把 wrench 锥从一个施加帧 Bp 移到另一帧 Bq 是锥上的线性操作；为强调我会用矩阵形式写：

$$K^{Bq,C}=\begin{bmatrix}I_{3\times3}&[{}^{Bq}p^{Bp}]_\times\\0_{3\times3}&I_{3\times3}\end{bmatrix}K^{Bp,C}\quad(7)$$

> 旋转可以用来改变"expressed-in"帧：$K^{Bp,D}=\begin{bmatrix}{}^DR^C&0\\0&{}^DR^C\end{bmatrix}K^{Bp,C}\quad(8)$

**类比（wrench 锥 = "这个接触能抵抗哪些推+拧"，必懂）**：
- 摩擦锥只管"力"（3 维）；**wrench 锥管"力 + 拧劲"（6 维）**——**因为力施加在离质心有距离的地方，会产生拧劲**。
- **Minkowski 和 $\oplus$** = "把多个接触点能抵抗的 wrench **叠起来**"——**两指捏杯子，两指的抵抗能力合起来 = 总的抵抗能力**。
- **换施加点（公式 7）** = 把"在手指尖能抵抗的拧劲"换算成"在杯子质心处等效的拧劲"（叉积项 $[p]_\times$ 就是"力臂产生力矩"）。

#### Example 5.8（接触 wrench 锥可视化）

> 我做了简单交互可视化让你玩。我有一个固定在空间的 box，只受接触力（这里没 illustrate 重力）；我在接触点和 body 中心画了摩擦锥。注意我故意对这例子禁用 hydroelastic 接触——力只用每碰撞对单接触点计算——以简化解释。

> 接触点单接触点的接触 wrench 锥有一个主要 caveat：我只能画 $\mathbb{R}^3$ 的锥，但 wrench 锥在 $\mathbb{R}^6$。所以我做了（标准）选择把 6d 锥投影到 3d 空间，用两个锥：一个平移分量（接触点绿色、body 帧红色），另一个旋转分量（body 帧蓝色）。这可能有点误导，因为不能实际从两集合独立选。

> 这里是单接触点的接触 wrench 锥，对两个不同接触位置可视化：我希望你立即注意到 **wrench 锥的旋转分量是低维的**——由于叉积，那空间里所有向量必须正交于向量 ${}^{B}p^C$。

> 这里是那 body 上直接相对的两接触点的接触 wrench 锥：注意虽然每个旋转锥是低维的，它们 span 不同空间。一起（如这两集合的 Minkowski 和理解）它们能抵抗施加在 body 帧的所有纯力矩。这直觉大致正确，但这也是 6d 锥投影到两 3d 锥变得有点误导的地方。有些 wrench 不能被这抓取抵抗。特别地，如果我要可视化直接在两接触点间那点的 wrench 锥，我们会看到 wrench 锥**不包含直接沿那轴的力矩**。两接触点单独，没有扭转摩擦，不能抵抗关于那轴的力矩。实践中，我们仿真工作流用的 gripper 模型用 hydroelastic 接触，仿真接触 patch，能产生关于这轴的力矩——所以我们能抵抗关于这轴的力矩。得到的精确量将正比于 gripper 挤压物体的力度。

> 现在我们可以计算任何接触集合能施加在 body 上的可能 wrench 的锥——接触 wrench 锥——通过把所有个体接触 wrench 锥放进公共帧并加起来。抓取的经典度量会说**好抓取是接触 wrench 锥大的**（能抵抗许多对抗 wrench 扰动）。如果接触 wrench 锥是全 $\mathbb{R}^6$，那么我们说接触达到了 **force closure** [4]。

**类比（force closure = "捏得无懈可击"，必懂）**：
- 单接触点：只能抵抗"某些方向"的推搡（wrench 锥是"扁"的，旋转方向缺）。
- 两指对捏：合起来能抵抗更多，但**沿两指连线轴的拧劲还是抵抗不了**（没有扭转摩擦时）。
- **force closure** = wrench 锥 = **整个 6 维空间** = "**从任何方向推、任何方向拧，都顶得住**" = **完美抓法**。hydroelastic 因为有接触 patch（产生扭转摩擦），更容易达到 force closure。

### 🧪 代码 3：接触 wrench 锥 + Minkowski 和 + force closure 检查（numpy，对应 5.4.1 + Example 5.8）

> PDF 没内联代码。这段构造单接触摩擦锥、投影成 wrench 锥、两接触做 Minkowski 和、检查 force closure。

```python
import numpy as np
def friction_cone(mu, n_samples=40):
    """摩擦锥边界方向(切向单位圆 * mu * fz, 法向fz=1), 返回3D力方向"""
    a = np.linspace(0, 2*np.pi, n_samples)
    return np.stack([mu*np.cos(a), mu*np.sin(a), np.ones(n_samples)])  # 3 x n
def wrench_cone_at(F_dirs, p):
    """把3D力方向F_dirs(3xn)在接触点p(3,)换成body质心处的wrench(6xn): [p×f; f]"""
    px = np.array([[0,-p[2],p[1]],[p[2],0,-p[0]],[-p[1],p[0],0]])
    tau = px @ F_dirs
    return np.vstack([tau, F_dirs])                          # 6 x n
mu = 0.5
F = friction_cone(mu)
p1 = np.array([0.05,0,0]); p2 = np.array([-0.05,0,0])      # 对跖两接触点
W1 = wrench_cone_at(F, p1); W2 = wrench_cone_at(F, p2)
# Minkowski和: 两锥方向的所有两两和(近似锥)
W_sum = np.hstack([W1[:,i:i+1]+W2[:,j:j+1] for i in range(W1.shape[1]) for j in range(W2.shape[1])])
# force closure 检查: 6维wrench锥是否"包围原点"(凸锥含原点内点)
from scipy.spatial import ConvexHull
try:
    hull = ConvexHull(W_sum.T)
    fc = hull.equations[:, -1].max() < 0                   # 原点严格在凸包内
except Exception:
    fc = False
print("两指对捏 wrench锥 维度覆盖: 秩 =", np.linalg.matrix_rank(W_sum), "/6")
print("force closure(含扭转轴?)=", fc, " (点接触无扭转摩擦->沿连线轴拧劲抵抗不了->False)")
```

**你会看到**：**两指对捏的 wrench 锥秩可能 = 6 但 force closure = False**——**因为沿两指连线轴的拧劲抵抗不了**（验证 Example 5.8 的 caveat）。**换成 hydroelastic（加扭转摩擦）或加第三个接触点，才能 True**。

### 4.2 对应 5.4.2：Colinear antipodal grasps（共线对跖抓取）

> 这 wrench 分析的美最初启发非常基于模型的抓取分析，可以试图优化接触位置以最大化接触 wrench 锥。但我们对这章的目标是假设对我们抓的物体知道得很少，所以我们会（暂时）避免在物体模型表面优化最好抓取位置。尽管如此，我们基于模型的抓取分析给我们一些即使对未知物体抓取也非常好的启发式。

> 特别地，两指 gripper 有大接触 wrench 锥的一个好启发式是找**共线"对跖"（antipodal）抓取点**。这里 antipodal 意思是**接触法向（接触帧 z 轴）指向正好相反方向**。"共线"意思是它们在同一条线——两接触点间的线。如你能在上面两指接触 wrench 可视化看到，这是有大总接触 wrench 锥的相当强启发式。如我们接下来会看到，我们能即使对物体几乎什么都不知道也应用这启发式。

**类比（对跖抓取 = "用两指对捏物体相对的两面"，必懂）**：
- 你捏一个杯子：**拇指和食指捏在杯子相对的两面，两指朝向正好相反**——**这就是对跖**。
- 为什么好？因为**对捏时两指的摩擦锥"对着顶"**，合起来能抵抗很多推搡（wrench 锥大）。
- **"共线"** = 两接触点连线 = 两法向所在直线——**捏得正**。

## 5. 对应 5.5：从点云的抓取选择 —— "不知道物体是什么，只看一堆点怎么捏"

> 与其看物体箱、试图识别特定物体并估计其位姿，让我们考虑一种方法，我们简单直接在（未分割的）点云上找可抓取区域。这些非常几何的抓取选择方法在实践中能 work 很好，也能用于仿真训练能在真实世界 work 很好、甚至处理部分视角和遮挡的基于深度学习的抓取选择系统 [6,7,8]。

**类比（点云 = "物体表面撒的一层点"，全节总纲）**：深度相机拍物体，得到**物体表面的一堆 3D 点**（点云）。我们**不知道这是什么物体**，但**看这堆点的局部形状（朝向、弯曲），就能猜"哪两块能对捏"**。

### 5.1 对应 5.5.1：Point cloud pre-processing（点云预处理）

> 为了得到箱的好视图，我们要设多个 RGB-D 相机。我在这里所有例子每箱用三个。那些相机不仅看箱里物体；它们也看箱、其他相机、可视工作空间里任何其他东西。所以我们要做一点工作把多相机点云合并成只包含兴趣区域的单点云。

> 首先，我们可以 **crop 点云**丢弃兴趣区域外的任何点（我们定义成已知箱位置正上方的 axis-aligned bounding box）。如我们下面会详细讨论，我们许多抓取选择策略会从估计点云"法向"受益。**实际在个体点云上估计法向、利用生成那些点的相机位置，比点云合并后估计法向更好**。对真实世界安装的传感器，合并点云需要高质量相机标定，必须处理 messy 深度返回。上章所有工具都相关，因为合并点云任务是点云配准问题的另一实例。对仿真能得到的完美深度测量，给定已知相机位置，我们能跳过这步，简单把点云里的点列表 concatenate。

> 最后，得到的原始点云可能包含比我们抓取规划实际需要的多得多的点。下采样点云的标准方法之一是用 **voxel 网格**——3D 里规则大小的立方体平铺。然后我们用每 voxel 正好一点总结原始点云。因为点云典型地只占据 3D 空间 voxel 的小百分比，我们用稀疏数据结构存 voxel 网格。在噪声点云里，这 voxelization 步也是有用的过滤形式。

**类比（点云预处理三步，必懂）**：① **crop** = "只保留箱子上方那块，扔掉背景"；② **合并多相机** = "三个角度拍的照片拼成完整点云"；③ **voxel 下采样** = "点太密了，每个小格只留一个代表点，顺便滤掉噪声"。

### 5.2 对应 5.5.2：Estimating normals and local curvature（估计法向和局部曲率）

> 我们下面会开发的抓取选择策略将基于场景的局部几何（法向方向和曲率）。理解怎么从点云估计那些量是点云处理的极好练习，代表其他类似点云算法。

> 让我们想**拟合平面（最小二乘意义）到一组点**的问题 [9]。我们可以用位置 $p$ 和单位长度法向向量 $n$ 描述 3D 平面。点 $p_i$ 和平面间距离简单由内积幅度给出 $|(p_i-p)^Tn|$。所以我们的最小二乘优化变成

$$\min_{p,n}\sum_i |(p_i-p)^Tn|^2\quad\text{subject to}\ \|n\|=1$$

> 对拉格朗日关于 $p$ 取梯度并设零给我们 $p^*=\frac{1}{N}\sum_i p_i$。代回目标，我们可以写问题为

$$\min_n n^TWn\quad\text{subject to}\ \|n\|=1,\quad\text{其中}\ W=\left[\sum_i(p_i-p^*)(p_i-p^*)^T\right]$$

> 几何上，这目标是原点中心的二次碗，带单位圆约束。所以最优解由**数据矩阵 $W$ 最小特征值对应的（单位长度）特征向量**给出。对任何最优，"翻转"法向也最优。我们现在可以暂时任意挑，然后在后处理步翻转法向（确保所有法向指向相机原点）。

> 真正有趣的是**第二和第三特征值/特征向量也告诉我们局部几何的某些事**。因为 $W$ 对称，它有正交特征向量，这些特征向量形成点云的（局部）基。**最小特征值沿法向指，最大特征值对应最小曲率方向**（和这向量的平方点积最大）。这信息对找和规划抓取非常有用。[6] 和它们之前的其他用这作为生成候选抓取的主要启发式。

**类比（PCA 拟合法向 = "给点云局部贴一块最贴合的小平板"，必懂）**：
- 取一个点周围的邻居点，**拟合一块最贴合它们的小平板**——**平板的法向 = 表面法向**。
- 数学上 = **PCA**：邻居点协方差矩阵 $W$ 的**最小特征向量 = 法向**（点云在法向方向"最薄"）。
- **最大特征向量 = 表面"最平/最直"的方向**（曲率最小）——**告诉抓取"手指该沿哪个方向对齐"**。

### 🧪 代码 4：点云法向 + 曲率估计（PCA，纯 numpy，对应 5.5.2 + Example 5.10）

> PDF 没内联代码。这段对一个球面点云，用 PCA 估每个点的法向和曲率方向，验证"最小特征向量=法向"。

```python
import numpy as np
rng = np.random.default_rng(0)
# 球面点云 + 噪声
N = 500; pts = rng.normal(0,1,(N,3)); pts = pts/np.linalg.norm(pts,axis=1,keepdims=True)
pts += 0.02*rng.randn(N,3)
def normal_curvature(pts, i, k=15):
    d = np.linalg.norm(pts-pts[i], axis=1); idx = np.argsort(d)[:k]
    nb = pts[idx]; nb = nb - nb.mean(0)              # 邻居去均值
    W = nb.T @ nb                                    # 协方差矩阵
    w, V = np.linalg.eigh(W)                         # 升序特征值
    n = V[:,0]                                       # 最小特征向量 = 法向
    curv_dir = V[:,2]                                # 最大特征向量 = 最小曲率方向
    return n, w
n, w = normal_curvature(pts, 0)
true_n = pts[0]/np.linalg.norm(pts[0])              # 球面真法向≈径向
print("估法向·真法向 =", round(abs(n@true_n),3), " (应≈1)")
print("特征值(小->大) =", np.round(w,4), " 最小=法向, 最大=最平方向")
```

**你会看到**：**估计法向和真法向点积≈1**（验证 PCA 法向估计）；**三个特征值"小/中/大"对应"法向/中曲率/最平方向"**。这就是 Example 5.10 的核心算法。

### 5.3 对应 5.5.3：Evaluating a candidate grasp（评估候选抓取）

> 现在我们处理了点云，我们有开始规划抓取所需的一切。我要把那讨论分成两步。这节我们会想出给抓取候选打分的代价函数。

> 跟随我们上面"基于模型"抓取选择的讨论，一旦我们捡起物体——或无论我们 squeeze 时手指间发生什么——我们会期望我们手指间的接触力至少要抵抗物体的重力 wrench。我们 gripper 提供的闭合力在 gripper 的 x 轴，但如果我们想能捡起物体而不让它从手里滑，我们需要我们接触摩擦锥内的力能抵抗重力 wrench。因为我们不知道那 wrench 会是什么（且某种程度上受我们手指几何约束），合理策略是**看点云表面共线对跖点，也对齐 gripper 的 x 轴**。在真实点云里，我们不太可能找到完美对跖对，但找法向指向几乎相反方向的区域是抓取的好策略！

#### Example 5.11（Scoring grasp candidates）

> 实践中，我们手指和物体间接触用 patch 接触比点接触描述更好。所以找点云里法向 agreeable 的 patch 有意义。我在这里通过把场景处理点云变换到 gripper 候选帧、crop 掉除指尖间 bounding box 内点外的所有点（我在 MeshCat 用红色标它们）来做。我抓取代价函数第一项只是点云里所有点的奖励，基于它们法向和 gripper x 轴的对齐程度：

$$cost = -\sum_i (n^{iGx})^2$$

> $n^{iGx}$ 是 crop 点云里第 $i$ 点在 gripper 帧表达的 x 分量。

> 对什么构成好抓取还有其他考虑。对我们运动学受限伸进箱的机器人，我们可能偏好让手处于对臂有利朝向的抓取。我在代码实现的抓取度量里，加了手偏离垂直的代价。我可以用世界向量 $[0,0,-1]$ 和用旋转进世界帧的 gripper 帧 y 轴的 dot product 奖励：

$$cost\mathrel{+}= -\alpha\begin{bmatrix}0\\0\\-1\end{bmatrix}^TR^G = \alpha R^G_{3,2}$$

> $\alpha$ 是相对代价权重，$R^G_{3,2}$ 是旋转矩阵第三行第二列的标量元素。最后，我们需要考虑候选抓取和箱以及点云的碰撞。当 gripper 碰撞时我简单返回无限代价。

**类比（抓取打分三件套，必懂）**：
- **项 1（法向对齐 $-\sum(n^{Gx})^2$）** = "指尖间的点，法向越对着 gripper 的捏合方向，分越高"——**鼓励对跖捏**。
- **项 2（手垂直 $\alpha R^G_{3,2}$）** = "手尽量竖直往下伸，对机械臂友好"。
- **项 3（碰撞 = 无穷代价）** = "手别撞箱壁/别撞别的物体，否则直接判死刑"。
- **总分最低 = 最好的抓法**。

### 🧪 代码 5：抓取候选打分（对跖 + 法向对齐 + 垂直偏好，numpy，对应 Example 5.11）

> PDF 没内联代码。这段对一个简单点云，枚举若干抓取候选（位置+朝向），用三项代价打分，选最优。

```python
import numpy as np
rng = np.random.default_rng(0)
# 模拟指尖间的一小片点云(在gripper帧), 法向大致沿gripper x(对跖捏得好)
M = 30; n_pts = rng.randn(M,3)*0.02
n_pts[:,0] = np.sign(rng.randn(M))           # 法向x分量≈±1(对跖)
n_pts = n_pts/np.linalg.norm(n_pts,axis=1,keepdims=True)
def score(nGx, R32, collides, alpha=0.5):
    if collides: return np.inf
    return -np.sum(nGx**2) - alpha*R32        # 法向对齐 + 垂直偏好
# 枚举候选: 好候选(法向对齐, 垂直, 不碰) vs 坏候选
good = score(n_pts[:,0], R32=0.0, collides=False, alpha=0.5)
bad_align = score(n_pts[:,1], R32=0.0, collides=False, alpha=0.5)   # 法向没对齐x
bad_collide = score(n_pts[:,0], R32=0.0, collides=True, alpha=0.5)
print("好抓取代价=%.2f  法向没对齐=%.2f  碰撞=inf" % (good, bad_align))
print("-> 代价越低越好; 对跖对齐+不碰 胜出")
```

**你会看到**：**好抓取（法向对齐 gripper x、不碰撞）代价最低**；**法向没对齐的分高（差）**；**碰撞直接 inf**。**这就是 Example 5.11 的打分逻辑**。

### 5.4 对应 5.5.4：Generating grasp candidates（生成抓取候选）

> 我们定义了代价函数，给定场景点云和环境模型，能给候选抓取位姿 $X^G$ 打分。所以现在我们想解优化问题：找最小化代价、满足碰撞约束的 $X^G$。不幸地，这是极难的优化问题，高度非凸目标和约束。而且，对应对跖点的代价项对大多数 $X^G$ 为零——因为大多数随机 $X^G$ 手指间不会有任何点。结果，不用典型数学规划求解器，文献大多数方法诉诸**随机采样**算法。我们确实有挑合理样本的强启发式。

> 一个启发式，例如 [6] 用的，是用点云局部曲率提议抓取候选，让点云法向指向 palm，定向手使手指对齐最大曲率方向。可以沿法向移动手直到手指不碰撞，甚至采样附近点。我们写了一个练习让你探索这启发式。但对我们的 YCB 物体，我不确定它是最好启发式；我们有很多 box，box 在局部曲率里没多少信息给。

> 另一启发式是**找点云里对跖点对**，然后采样会对齐手指和那些对跖对的抓取候选。许多 3D 几何库支持至少对点云 voxel 表示的"ray casting"操作；所以找对跖对的合理方法是简单在点云随机选一点，然后沿法向反方向 ray cast 进点云。如果 ray casting 找到的 voxel 法向足够对跖，且到那 voxel 距离小于 gripper 宽度，那么我们找到了合理对跖点对。

#### Example 5.12（Generating grasp candidates）

> 作为 ray casting 的替代，我在代码例子实现了甚至更简单的启发式：我简单随机选一点，开始采样朝向（从垂直开始）对齐 gripper x 轴和那点法向。然后我主要只靠我打分函数里的对跖项让我找到好抓取。我确实实现一个更多启发式——一旦我找到指尖间点云里的点，然后我沿 gripper 轴移出手，使那些点在 gripper 帧居中。这帮我们防止闭手抓取时 knock over 物体。但就这些！非常简单的策略。我采样少数候选抓取，只画代价最低的几个。如果你跑它很多次，我想你会发现它实际相当合理。每次跑，它模拟物体从天掉落；实际抓取评估实际相当快。

**类比（生成候选 = "撒一堆捏法，挑最好的"，必懂）**：既然精确优化太难，就**随机撒一堆"捏法"候选**（随机选点 + 随机朝向 + 沿法向移出手居中），**用上面的代价函数打分，挑最低的几个**。**简单粗暴但有效**——尤其配合"对跖项"这个强启发式。

## 6. 对应 5.6：The Corner Cases（角落情况）

> 如果你玩我上面实现的抓取打分一点，你会发现缺陷。有些容易（虽然启发式地）通过加几项到代价解决。例如，我没检查 pre-grasp 构型的碰撞，但这能容易加。

> 有些情况抓取单独作为策略不够。想象你把物体正好放在箱的一个角。可能不可能让手绕物体两边而不和物体或边碰撞。上面策略绝不会选试抓 box 的非常角（因为它总试图对齐采样点法向和 gripper），也不清楚它该不该。这可能对我们相对大的 gripper 尤其真。在我们在 TRI 用的 setup，我们实现了一个额外简单"**pushing**"启发式，如果 sink 里有点云但找不到可行抓取候选就用。我们不抓取，而是驱动手向下，nudge 点云那部分朝箱中间。这实际能帮很多！

> 我们简单方法还有其他缺陷，纯几何方法很难解决。大多数归结于我们系统至今没有"物体"概念的事实。例如，看这策略导致"double picks"如果两物体在箱里靠近，并不罕见。对重物体，捡起物体靠近质心可能很重要，以提高我们抵抗重力 wrench 同时留在摩擦锥内的机会。但我们这里策略可能通过 squeeze just 手柄非常远端捡起重锤子。

> 有趣地，我不认为问题必然是点云信息不足，即使没有颜色信息。我可以给你看点云，你不会犯同样错误。这些是学习抓取度量可能帮的例子类型。我们不需要达到人工智能来解决这；只要知道我们之前在某处试抓失败就足以显著改进我们的抓取启发式。

**类比（角落情况的三个坑 + 三招，必懂）**：
- **坑 1：物体在角上**，手绕不过去 → **招：pushing 启发式**（手往下压，把物体往箱中间推，推出来再抓）。
- **坑 2：double pick**（两物体挨着，一捏捏俩）→ 因为系统**没有"物体"概念**，不知道那是两个东西。
- **坑 3：抓重锤抓手柄远端**（会滑/翻）→ 因为没考虑"抓靠近质心才稳"。
- **共同病根**：**纯几何方法不懂"物体"**。**解药** = 学习抓取度量（甚至只要"记住上次这抓法失败了"就能改进）。

## 7. 对应 5.7：Programming the Task Level（编程任务层）

> 我们大多数人习惯用过程式编程范式写代码；代码从程序顶部通过函数调用、分支（如 if/then 语句）、for/while 循环等执行。tempting 也那样写我们的高层机器人程序。对 clutter 任务，我可以写"while 第一个箱有物体要捡，捡起来移到第二个箱；..."。这当然没错！但作为机器人框架的组件，这高层程序必须在运行时以某种方式和系统其余部分通信，包括和以某常规频率（如 100Hz 甚至 1kHz）运行的低层控制器有接口。那么我们怎么编写任务层行为以和高速低层控制无缝集成？

> 编写任务层行为有几个重要编程范式。广义上，我会把它们分成三类：
> - **过程式代码**（在单独线程）传消息/事件给住在主机器人/仿真线程的模块。这在像 ROS 的多进程消息传递生态系统里相对常见。
> - **任务层"策略"**可以直接编写为例如**有限状态机（FSM）**或"**行为树**（behavior trees）"，直接在机器人/仿真循环评估。
> - **任务层"规划器"**可以取任务层行为怎么链起来达成长期目标的规则：最简单情况，规划器输出能在机器人/仿真循环执行的计划，就像我们用来规划 gripper 运动的轨迹。如果规划器能在线跑（如给定新传感器信息不断调整/重规划），那么它能直接用于机器人/仿真循环。或者，少数规划器能实际把它们的计划直接"编译"成策略（如 FSM 形式）。

> 每个范式都有它的位置，有些研究者强烈偏好一个而非另一个。我会永远记得 Rod Brooks 写像《Elephants Don't Play Chess》的论文反对任务层规划 [12,13,14]。Rod 的"subsumption architecture"明确在"任务层策略"类，可看作行为树的先驱；它通过早期 Roomba 吸尘器的成功确立可信度。规划社区可能反驳对真正复杂任务，人类程序员不可能为 AI 系统可能遇到的所有排列/情况编写策略；规划是真正 scale 的方法。他们用像 belief space 规划和 task-and-motion 规划的扩展解决了关于符号 grounding 和建模要求的一些最初批评，我们会在笔记后面部分覆盖。

**类比（三种"编排任务"的方式，必懂）**：
- **过程式** = 写一段 `while 箱没空: 抓(); 放()` 的脚本，跑在后台线程，跟主控制循环发消息。
- **状态机/行为树** = 画一张**流程图**："在'找抓取'状态，找到了→转'抓取'状态；没找到→转'摇箱'状态"，每个 tick 检查一次。
- **规划器** = "先想好一整串动作再执行"，甚至能"把计划编译成状态机"。
- **Rod Brooks 的反对** = "别搞那么复杂的规划，像蟑螂一样'感知-动作'直接反应就行"（subsumption，Roomba 的哲学）。**规划派反驳** = "复杂任务靠反应式写不全，得规划"。

### 7.2 对应 5.7.2：Task planning（任务规划）

> 任务层规划器主要基于搜索。AI 规划作为搜索有长历史。**STRIPS** [15] 也许是最早且最著名的用初始状态、目标状态、带前提和效果的动作集合描述规划问题的表示（和算法）。**时序逻辑**（如 linear temporal logic (LTL)、metric temporal logic (MTL)、signal temporal logic (STL)）使规格能包含随时间演化的复杂目标或约束，如"event A 应最终在 event B 后发生"。**规划域定义语言（PDDL）** [16,17] 扩展 STRIPS 表示包含更表达性特征如有类型变量、条件效果、（甚至时序逻辑）量词，作为长期且高度有影响的 ICAPS 规划竞赛系列的规格语言。这些规划竞赛产生许多高度有效的规划算法如 **GraphPlan** [18]、**HSP** [19]、**Fast-Forward** [20]、**FastDownward** [21]。这些规划器展示"启发式搜索"的力量，强烈利用规格的面向对象性质用 factorization 作为强启发式。

**类比（STRIPS = "动作的'前提-效果'卡片"，必懂）**：
- 每个动作是一张卡片：**前提**（执行前必须真，如"手空"）+ **效果**（执行后变真，如"手持有球"）。
- 规划 = **从初始状态卡片堆，搜一条卡片序列，使目标卡片全真**。
- **时序逻辑** = 还能说"先 A 后 B"这种**时间顺序要求**。

### 🧪 代码 6：clutter clearing 状态机（纯 python，对应 Example 5.13 / 5.14）

> PDF 没内联代码。这段实现一个极简 clutter-clearing 状态机，模拟"找抓取/抓/放/失败重规划"的循环。

```python
import random
random.seed(0)
def has_grasp(bin_contents): return len(bin_contents)>0 and random.random()>0.2  # 模拟"找抓取"80%成功
def pick(bin_contents): return bin_contents.pop() if bin_contents else None
state = "WAIT"; binX = [1,2,3]; binY = []; log=[]
def settle(): log.append("settle")
settle()
for step in range(20):
    if state=="WAIT":
        state = "PICK_X" if binX else ("PICK_Y" if binY else "DONE")
    elif state=="PICK_X":
        if has_grasp(binX):
            o = pick(binX); log.append(f"pick {o} from X")
            state = "PLACE_Y"
        elif binY: state = "PICK_Y"                 # X没抓取但Y有 -> 转Y
        else: log.append("replan(shake)"); settle(); state="PICK_X"  # 失败->摇箱重规划
    elif state=="PLACE_Y":
        binY.append(log[-1].split()[1]); log.append("place to Y"); state="WAIT"
    elif state=="PICK_Y":
        if has_grasp(binY):
            o=pick(binY); log.append(f"pick {o} from Y"); state="PLACE_X"
        else: state="WAIT"
    elif state=="PLACE_X":
        binX.append(log[-1].split()[1]); log.append("place to X"); state="WAIT"
    if state=="DONE": break
print("log:", log); print("binX=",binX,"binY=",binY)
```

**你会看到**：状态机在 X/Y 箱间来回搬，**找不到抓取时"replan(shake)"**，**最终 DONE**。**这就是 Example 5.13 的状态机逻辑**，也是 Example 5.14 完整 demo 的"大脑"。

### 练习 5.1（Assessing static equilibrium，评估静态平衡）

> 对这问题，我们用库仑摩擦模型，$\|f_t\|\le\mu f_n$。换言之，摩擦力大到能抵抗任何运动，直到所需力超过 $\mu f_n$，那种情况 $\|f_t\|=\mu f_n$。
> **a.** 考虑质量 $m$ 的 box 坐在角 $\gamma$ 的 ramp，box 和 ramp 间摩擦系数 $\mu$：对给定角，box 不滑下平面所需最小摩擦系数是什么？用 $g$ 表示重力加速度。现在考虑平地，三个实心（均匀密度）sphere 坐在上面，半径 $r$ 质量 $m$。假设它们彼此间和与地有相同摩擦系数 $\mu$。对每个下列构型：sphere 能否对某些 $\mu,r$ 处于静态平衡？解释为什么或为什么不。记住所有 body 平衡需要力矩和力都平衡。
> **b.** Sphere 叠在彼此上面。**c.** 一个 sphere 在另一个上面，偏移。**d.** Sphere 叠成金字塔。**e.** Sphere 叠成金字塔，但底两 sphere 间有距离 $d$。
> 最后，几个概念问题：**f.** 为什么我们指定系统初始猜测重要？（提示：这是什么类型优化问题？）**g.** 看 StaticEquilibriumProblem 的 Drake 文档。它列解平衡时用的约束。这些里哪两个自由体能回答？

**通俗讲解 + 答案**：
- **a（斜面最小 $\mu$）**：不滑需摩擦顶住下滑分量 $mg\sin\gamma$，法向 $=mg\cos\gamma$，故 $\mu_{min}=\tan\gamma$。**类比**：斜面越陡，需要的摩擦越大，$\mu_{min}=\tan\gamma$。
- **b（竖直叠两球）**：上球压在下球正上方，接触法向竖直，**无水平力需求**，**任何 $\mu\ge0$ 都行**（只要几何上球能稳住——竖直叠接触点法向竖直，平衡）。**能平衡**。
- **c（偏移叠）**：上球重心不在下球接触点正上方 → 产生力矩 → 需要切向摩擦抵抗 → **需要足够 $\mu$**，且偏移太大几何上无法平衡（重心投影出接触点）→ **对某些 $\mu,r$ 能，太大不能**。
- **d（金字塔，底两球挨着）**：顶球压在底两球接触点上，对称 → 力可平衡，**能**（需足够 $\mu$ 抵抗顶球把底球往外推的趋势）。
- **e（底两球有距离 $d$）**：顶球跨在底两球上，**底两球被往外推**，需要底球与地的摩擦抵抗 → **需足够 $\mu$**；$d$ 太大顶球掉下去 → **不能**。
- **f（为什么初始猜测重要）**：因为这是**非凸优化**（非穿透 + 互补约束非凸），**求解器从初猜出发找局部解，不同初猜可能找到不同平衡构型或找不到**。**类比**：非凸优化像"有很多山谷"，初猜决定你从哪个山坡下、落到哪个谷。
- **g（哪两个约束自由体能回答）**：**力平衡**（$\tau_g=-\sum J_i^TF^{c_i}$）和**摩擦锥**（$\|f^{xy}\|\le\mu f^z$）这两个**自由体图就能回答**（画每个球受力，看能否求和为零 + 力在锥内）；**非穿透 + 互补**则需几何/优化。

### 练习 5.5（Behavior Trees，行为树）

> 让我们重新引入行为树术语。行为树提供在模块化和反应式方式切换不同任务的结构。行为树是有向根树，内部节点管理控制流，叶节点是要执行的动作或要评估的条件。例如，动作可能是"pick ball"。这动作能成功或失败。条件可能是"Is my hand empty?"能真（条件成功）或假（条件失败）。更具体地，每个节点被周期检查。依次它检查它的孩子，根据孩子状态报告状态为 success、failure 或 running。有不同类控制流节点，但我们会考虑两类控制流节点：
> **Sequence Node (→)**：Sequence 节点从左到右执行每个孩子行为。如果任何孩子失败 sequence 返回 failure，如果任何孩子 running 返回 running。想这算子的一种方式是 sequence 节点对所有孩子行为取"and"。
> **Fallback Node (?)**：Fallback 节点也一个接一个执行每个孩子行为。但 fallback 如果任何孩子成功就成功。想这算子的一种方式是 fallback 节点对孩子行为取"or"。

- **a（球被 knock out）**：执行"Approach Bin"时球被拍飞 → 回到行为树根重新评估 → **"Ball Grasped?"失败**（手空了）→ 沿 pick 子树重新走 → **"Ball Close?"失败**（球远了）→ 执行 **"Approach ball"** 重新接近。**这就是反应式**：环境一变，行为树下一 tick 自动反应。
- **b（填 FSM 4 空）**：典型填法 = 状态 `{Idle, Approaching, Grasping, Transporting, Placing}` 间的转移，如 `Grasping --grasp_success--> Transporting`、`Transporting --above_bin--> Placing`、`Placing --dropped--> Idle`、`any --ball_lost--> Approaching`（具体 4 空依图，逻辑是"动作完成→转下一状态、球丢→回接近"）。
- **c（bin picking 行为树）**：根 = **Fallback**[ **Sequence**[条件"Bin1 not empty?", **Sequence**[动作"Select Grasp", 条件"Grasp selected?", 动作"Grasp Object(s)", 条件"Object Grasped?", 动作"Transport above Bin2", 条件"above Bin2?", 动作"Drop into Bin2"] , 动作"Randomize Bin"] ]。**broken 修复要点**：① 外层循环用 **Fallback** 包"正常抓取序列"和"Randomize"（抓不到才摇箱）；② "Select Grasp"和"Grasp"之间要有"Grasp selected?"条件门；③ "Transport"前要"Object Grasped?"门；④ 循环条件"Bin1 empty?"应放在最外层 Sequence 首位作为继续条件。**类比**：行为树 = "**先试正常流程（Sequence 一串），哪步失败就 Fallback 到补救动作（摇箱）**"。

### 🧪 代码 8：行为树最小实现（pick-ball 任务，纯 python，对应练习 5.5）

> PDF 没内联代码。这段实现 Sequence/Fallback/Condition/Action 四种节点，跑 pick-ball 行为树，模拟"球被 knock out"的反应式重规划。

```python
import random
class Cond:
    def __init__(self,f): self.f=f
    def tick(self,bb): return "SUCCESS" if self.f(bb) else "FAILURE"
class Act:
    def __init__(self,f): self.f=f
    def tick(self,bb): return self.f(bb)
class Seq:
    def __init__(self,cs): self.cs=cs
    def tick(self,bb):
        for c in self.cs:
            r=c.tick(bb)
            if r!="SUCCESS": return r
        return "SUCCESS"
class Fb:
    def __init__(self,cs): self.cs=cs
    def tick(self,bb):
        for c in self.cs:
            r=c.tick(bb)
            if r!="FAILURE": return r
        return "FAILURE"
# 黑板(世界状态)
bb = {"ball_close":False,"grasped":False,"knock":False}
def approach(bb): bb["ball_close"]=True; return "SUCCESS"
def grasp(bb):
    if bb["knock"]: bb["grasped"]=False; bb["ball_close"]=False; bb["knock"]=False; return "FAILURE"
    bb["grasped"]=True; return "SUCCESS"
# pick-ball 子树: Fallback? 不, pick = Seq[ Fb[Cond ball_close, Act approach], Fb[Cond grasped, Act grasp] ]
pick = Seq([ Fb([Cond(lambda b:b["ball_close"]), Act(approach)]),
             Fb([Cond(lambda b:b["grasped"]), Act(grasp)]) ])
# 模拟: 第2次tick时人类knock球
for tick in range(3):
    if tick==1: bb["knock"]=True      # 粗鲁人类拍飞球
    print(f"tick {tick}: pick -> {pick.tick(bb)}  状态={bb}")
```

**你会看到**：tick 1 时 `knock=True` → grasp 失败、ball_close 被重置 → 下一 tick 行为树**自动重新 approach**——**验证练习 5.5a 的反应式行为**。

## 增补一：把"还不够通俗"的 5 个点再补类比

1. **互补约束 $xy=0$ 为什么非凸**：可行集是"坐标轴的两条射线"（L 形），**L 形不是凸集**（两射线上各取一点，连线穿过原点外的非法区）。**类比**：像"只能站东墙或南墙"，两墙各站一人，连线穿中间空地（非法）。
2. **pull-architecture**：Drake 系统"下游不拉，上游不算"——**GraspSelector 的采样很贵，只有 Planner 真问'最佳抓法'时才触发**。**类比**：像"按需供电"，不浪费电。
3. **force closure 为什么 6 维**：3D 物体能被"推"3 个方向 + "拧"3 个方向 = 6 维 wrench。**force closure = 6 维全能抵抗**。2D 则是 3 维（2 推 + 1 拧）。
4. **行为树"每 tick 从根重评估"= 反应式**：和状态机"记状态"不同，行为树**每个控制周期从根重新检查所有条件**，所以环境突变（球被拍飞）下一 tick 立即反应——**这就是练习 5.5a 的"反应式"**。
5. **LLM 写 python 控制机器人（Code as Policies [22]）**：LLM 不直接输出关节角，而是**写一段调用机器人 API 的 python**（如 `robot.move_to(ball_pos)`），**代码可执行、可调试、可复用**——**比直接回归关节角更稳健**。

**通关三句话**：
1. **料箱抓取 = 从一箱乱东西里把物体搬到另一个箱**，第一步是"造乱箱"（错开高度掉落避免初始穿透），而物体静止后能不能稳住，取决于**力平衡 + 摩擦锥**（$\sqrt{f_x^2+f_y^2}\le\mu f_z$，不能拉地、不能隔空使劲）；把这些写成优化就是 `StaticEquilibriumProblem`，但互补约束 $\phi f=0$ 非凸，要放松换好算。
2. **挑抓法分两条路**：已知形状时用**接触 wrench 锥**（6 维，Minkowski 和叠加多接触，全 $\mathbb{R}^6$ = force closure = 无懈可击），其最强启发式是**共线对跖抓取**（两指对捏相对两面）；不知物体时直接看**点云**——PCA 估法向和曲率，用"对跖对齐 + 手垂直 + 不碰撞"三项打分，靠随机采样 + ray casting 生成候选，简单粗暴但有效。
3. **编排整个任务靠任务层编程**：过程式脚本、状态机/行为树（Sequence=与、Fallback=或、每 tick 重评估=反应式）、规划器、乃至 LLM 写 python（Code as Policies）各有位置；最终 `GraspSelector`（点云→抓法）+ `Planner`（状态机指挥官）+ Drake 的 pull-architecture 把"感知-挑抓法-抓-放-失败摇箱"串成完整 demo——**而角落情况（角上、double pick、抓远端）暴露了纯几何方法"不懂物体"的病根，解药是学习抓取度量，哪怕只记住"上次这抓法失败了"也足以改进**。
