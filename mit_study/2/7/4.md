# 一、初版通俗讲解：第 7 章《Mobile Manipulation》到底在讲什么？

## 7.0 本章定位：从桌面操作走向移动操作

PDF 开头说：

> 到目前为止，我们主要关注 table-top manipulation，也就是桌面操作。

桌面操作已经足够有趣：

- 机器人固定在桌子上；
- 你把物体拿到它面前；
- 它可以抓取、放置、移动物体。

但作者问：

> 如果机器人还有轮子，或者有腿，会发生什么？

这就是 mobile manipulation，移动操作。

---

## 移动操作的核心观点

PDF 强调：

1. 很多桌面操作中的技术挑战，在移动操作中仍然存在。
2. 但有些挑战在移动场景中是新的，或者更加紧迫。
3. 本章目标是描述这些挑战，并给出一些解决方案。
4. 最重要的是：

> 给机械臂加上移动能力，可以扩大机器人的野心。

现在我们可以考虑：

- 机器人在房子里移动；
- 完成各种不同任务；
- 让世界成为机器人的工作场所。

### 通俗类比

以前机器人像一个“坐在桌子前的工人”：

> 你把东西递给它，它帮你处理。

现在机器人像一个“可以在房间里走动的管家”：

> 它可以自己走到厨房、走到桌子旁、走到柜子前，然后完成任务。

# 7.1 A New Cast of Characters：新角色登场

PDF 中这一节标题是：

> A NEW CAST OF CHARACTERS

正文没有详细展开，但标题的意思很清楚：

> 移动操作引入了一批新的“角色”和新组件。

在桌面操作中，主要角色是：

- 机械臂；
- 夹爪；
- 桌上的物体；
- 固定相机；
- 已知的桌子或 bin。

在移动操作中，新角色包括：

- 移动底盘；
- 轮子或腿；
- 机器人本体上的相机；
- 更大、更未知的环境；
- 地图；
- 定位系统；
- 可行驶区域判断；
- 动态障碍物；
- 机器人自身状态估计。

### 通俗类比

桌面操作像一场“桌面木偶戏”：

> 角色少，舞台小，布景基本固定。

移动操作像一部“公路电影”：

> 机器人要走出小舞台，进入真实世界，遇到新环境、新障碍、新问题。

# 7.2 What’s Different About Perception?：感知有什么不同？

移动操作对感知提出了新的要求。

桌面操作中，我们通常可以假设：

- 环境里装了多个相机；
- 桌子位置已知；
- bin 位置已知；
- 相机外参可以离线标定；
- 机械臂关节编码器可以精确告诉我们末端在哪里。

但移动机器人通常不能这么奢侈。

---

## 7.2.1 Partial Views / Active Perception：局部视角与主动感知

PDF 说：

> 在几何感知章节，我们讨论过只能看到物体局部视角的问题。

在桌面操作中，我们通常可以从外部多个角度安装相机。  
但即便如此，杂乱场景仍然会遮挡物体。

移动机器人更麻烦：

> 通常不能假设环境被充分传感器覆盖。

移动机器人通常只带：

- 头部相机；
- 手腕相机；
- 机器人本体上的传感器。

这意味着：

> 你可能只看到物体的一个侧面。

---

## 只看一半，怎么抓？

PDF 举了芥末瓶的例子：

> 如果你只看到半个 mustard bottle，那么当前传感器读数根本不足以规划一个抓取。

你必须推断瓶子背面长什么样。

这叫：

> shape completion，形状补全。

但作者强调：

> 这不一定是显式完成的。

也就是说，机器人不一定真的先重建完整 3D 模型。  
它可能直接学习：

> 看到这样的局部，应该怎样抓。

---

## 为什么学习是根本，而不是可有可无？

PDF 说：

> 你能猜出芥末瓶背面长什么样，是因为你以前接触过芥末瓶。

是物体的统计规律提供了缺失信息。

所以对移动操作来说：

> learning isn't just a convenience here, it's fundamental.

学习不是锦上添花，而是基础能力。

### 通俗类比

你看到半个可乐罐，不会惊慌地想：

> 完了，我只看到一半，不知道另一半长什么样。

你会自动脑补另一半，因为你见过很多可乐罐。

机器人也需要这种“经验补全”。

---

## Active Perception：主动感知

移动机器人还有另一个优势：

> 相机和传感器是移动的。

所以机器人可以主动移动传感器：

- 转头；
- 移动底盘；
- 改变视角；
- 减少不确定性。

这叫：

> active perception，主动感知。

它和：

> planning under uncertainty，不确定性下的规划

密切相关。

PDF 这里说：

> More to come.

说明后续还会展开。

### 通俗类比

你看不清一个东西时，不会站在原地发呆。  
你会：

- 探头；
- 侧身；
- 走近；
- 换个角度。

移动机器人也应该这样。

---

## 7.2.2 Unknown, Potentially Dynamic Environments：未知且可能动态的环境

桌面操作中，我们通常假设：

- 桌子几何已知；
- bin 位置已知；
- 可以把打到桌子上的点云裁掉；
- 只保留物体相关的点。

PDF 说：

> 当机器人被固定在桌子上时，这很合理。  
> 但一旦机器人移动起来，就要放松这个假设。

移动机器人要面对：

- 更不同的环境；
- 更少预先建模的环境；
- 可能动态变化的环境。

---

## 能不能把所有环境都建模出来？

一种思路是：

> 检测桌子；
> 估计桌子位姿；
> 拟合参数化桌子模型。

但 PDF 说：

> 这在多样、广阔的真实场景中是一条艰难的路。

因此作者问：

> 对于环境，有没有类似 antipodal grasping 对物体那样的方法，可以减少我们对显式环境模型的依赖？

---

## 理想环境表示的要求

PDF 列出了理想环境表示应满足的要求：

1. 不需要显式物体模型；
2. 支持运动规划需要的查询，例如：
   - 快速碰撞检测；
   - 最小距离计算；
3. 可以高效地从原始传感器数据更新；
4. 可以扩展到大场景。

---

## 原始点云的问题

原始合并点云：

优点：

- 容易更新；
- 不需要物体模型。

缺点：

- 不适合快速规划查询。

### 通俗类比

原始点云像一把散落的沙子。  
你能看到它，但很难快速问：

> 从这里到那里会不会撞到东西？

你需要把沙子整理成更有结构的地图。

---

## Voxel Grid：体素网格

PDF 给出答案：

> Voxel grids，体素网格。

体素网格的思想：

1. 把某个有限 3D 空间离散成固定大小的小立方体；
2. 例如每个 voxel 边长 1 cm；
3. 每个 voxel 标记为：
   - occupied，被占据；
   - unoccupied，未被占据；
   - 或者更一般地，占据概率。

然后运动规划时：

> 把被占据的 voxel 当作需要避开的碰撞几何。

---

## Voxel Grid 的优点

PDF 指出：

### 1. 碰撞查询快

很多 voxel grid 上的碰撞查询可以很快，而且容易并行。

特别是：

> sphere-on-voxel collision query，球体对体素的碰撞查询，可以非常快。

这也是为什么 Drake 中很多碰撞几何会用很多小球近似。

### 2. 点云更新高效

用点云更新 voxel grid 很高效。

### 3. 可以扩展到大场景

为了同时支持：

- 精细分辨率；
- 大场景；

需要使用聪明的数据结构。

---

## Example 7.1：Octomap

PDF 提到：

> Octomap。

Octomap 是机器人中一种高效的大规模 voxel grid 实现。

它的核心思想是使用 octree，八叉树：

- 空旷区域用大格子；
- 复杂区域用小格子；
- 从而节省内存并支持高效查询。

### 通俗类比

普通 voxel grid 像把整个城市都画成等大的方格纸。  
Octomap 像智能地图：

- 郊区用大格子；
- 市中心用小格子；
- 复杂路口用更细格子。

这样既省空间，又保留关键细节。

## 7.2.3 Robot State Estimation：机器人状态估计

PDF 说：

> 移动操作感知中最大的不同是：  
> 不仅要估计环境状态，还要估计机器人自己的状态。

---

## 桌面操作中的隐含假设

之前点云处理中，我们默认知道：

\[
{}^W X^C
\]

也就是相机在世界中的位姿。

我们可以通过离线标定估计相机外参。

我们也默认知道机器人运动学：

- 机械臂固定在桌子上；
- 世界到末端的变换可以通过高精度编码器直接测量。

但移动 base 一来，这些假设就不成立了。

### 通俗类比

固定机械臂像一个坐在固定椅子上的人：

> 他知道自己头在哪里，因为椅子不动。

移动机器人像一个一边走一边看的人：

> 他不仅要知道物体在哪，还要知道自己现在站在哪。

---

## 移动机器人状态估计的历史

PDF 提到：

> 移动机器人状态估计有很强历史。  
> 经典参考是 Probabilistic Robotics。

常见算法基于：

- approximate recursive Bayesian filtering，近似递归贝叶斯滤波；
- 或相关的 smoothing algorithms，平滑算法。

---

## 传感器融合

移动 base 通常装有：

- wheel encoders，轮式编码器；
- IMUs，惯性测量单元；
- range sensors，测距传感器；
- cameras，相机。

状态估计管线把这些噪声测量融合成一致估计。

PDF 强调一个重要教训：

> wheel odometry alone is almost always insufficient.

仅靠轮式里程计几乎总是不够。

原因：

> 真实轮子会打滑。

视觉和测距测量提供了必要的、独立的测量。

### 通俗类比

轮式里程计像闭着眼睛数步子：

> 你以为自己走了 10 步，但如果地面滑，你可能只走了 8 步。

视觉和激光像睁眼看地标：

> 可以修正“我以为我在哪里”和“我实际在哪里”的差距。

---

## 近年变化

PDF 指出：

自经典教材以来，很多事情变了。

### 1. 测距传感器进步

lidar 和 depth cameras 在以下方面显著提升：

- 量程；
- 精度；
- 帧率。

这让相关方法更有效。

## 2. 从依赖深度到 RGB-only 估计

PDF 说：

> 最大的变化之一，是从重度依赖测距传感器/深度相机，转向越来越强大的仅 RGB 相机估计算法。

原因包括：

- visual-inertial odometry，视觉惯性里程计；
- monocular depth estimation，单目深度估计；
- dense 3D reconstruction / structure from motion，稠密 3D 重建 / 运动恢复结构。

### 通俗类比

以前机器人必须带着“测距仪”才敢走路。  
现在它越来越像人：

> 只用眼睛，也能大致判断自己在哪、周围东西在哪。

## Example 7.3：iiwa 放在 prismatic base 上

作者给了一个最简单的移动机械臂构造：

1. 使用 iiwa 模型；
2. 不再把 link 0 焊接到世界；
3. 插入三个 prismatic joints；
4. 这三个移动关节对应：
   - x 方向；
   - y 方向；
   - z 方向；
5. x 和 y 可以无界；
6. z 设置适度关节限位；
7. iiwa 第一个关节本来就绕 base z 轴旋转，去掉关节限位后可以连续旋转。

这样：

> 我们就有了移动机器人的本质。

---

## 需要改多少运动规划工具？

PDF 回答：

> not much，几乎不用改。

原因：

> 我们的运动规划工具很通用，可以处理几乎任何 kinematic robot configuration。

移动 base 只是在 kinematic tree 上多加了几个 joints。

### 通俗类比

原来机械臂有 7 个关节。  
现在底座又多了 3 个“滑动关节”。  
对规划器来说，它只是变成了一个更多关节的机器人。

---

## 自由度增加带来的考虑

原来 iiwa 有 7 个自由度。  
加上 x、y、z 三个 prismatic joints 后，变成 10 个自由度。

PDF 分析：

### Trajectory Optimization

轨迹优化算法由于是局部优化，通常容易扩展到高维问题。

所以：

> 10 维没有问题。

### Sampling-Based Planners

采样规划器对维度更敏感。

但：

- RRT 在 10 维应该还可以；
- PRM 在 10 维也能工作；
- 但可能需要高效实现；
- 并开始接近极限。

---

## Continuous Joint：连续关节

移动 base 还可能引入 continuous joint。

例如绕 z 轴旋转没有关节限位：

\[
0 \equiv 2\pi
\]

PDF 说：

> 这需要在规划栈中小心处理。

---

## 不同规划器如何处理连续关节？

### Sampling-Based Planner

通常需要让距离度量和 extend 操作适配 wrap-around。

也就是：

> 角度差不能简单算成 \(10^\circ\) 和 \(350^\circ\) 差 340°，而应知道它们其实只差 20°。

### Nonconvex Trajectory Optimization

非凸轨迹优化本身不一定需要算法修改，但可能有 local minima。

### Graphs of Convex Sets，GCS

对于 GCS 轨迹优化：

> IRIS regions 应该在 local coordinate system 中操作，并且在任何 wrapping joint 上的 domain 不能宽于 \(\pi\)。

如果不处理，可能出现荒谬结果：

> 机器人明明可以短路径过去，却绕了一大圈。

PDF 给了一个例子：

> kinematic trajectory optimization 在书架间找到了次优解。

### 通俗类比

角度像一个圆形跑道。  
如果你把圆形跑道剪成一条直线，就可能误以为从跑道一端到另一端很远。  
实际上它们只隔一条缝。

---

答案是：

- 某些轮式机器人和大多数腿式机器人可以直接提供 prismatic joints 抽象；
- 但其他轮式机器人会引入必须在运动规划中考虑的约束。

# 7.3.1 Wheeled Robots：轮式机器人

PDF 说：

## Holonomic Drives：全向驱动

Holonomic drive 的意思是：

> 机器人可以瞬时向任意方向移动。

例如：

- mecanum wheels；
- omni wheels。

### 通俗类比

普通汽车像只能前后开、靠转向改变方向的车。  
全向底盘像一个可以在地面上横向平移、纵向平移、旋转的“魔法盘子”。

---

## Example 7.4：Mecanum Drive Kinematics

PDF 标题：

> Mecanum drive kinematics。

Mecanum 轮子的特点是轮缘上有斜置小滚轮。  
通过四个轮子不同速度组合，可以实现：

- 前进；
- 后退；
- 横移；
- 旋转；
- 斜向移动。

虽然正文未展开，但标准 kinematics 通常是：

给定底盘速度：

\[
v_x, v_y, \omega
\]

可以计算四个轮子转速。

不同轮子布局公式略有不同，但思想是：

> 底盘速度线性映射到轮子角速度。

---

## Example 7.5：在 Drake 中仿真 Mecanum Wheels

PDF 标题：

> Simulating mecanum wheels in Drake。

这说明可以在 Drake 中建立轮子、滚轮和地面接触，验证 mecanum 底盘运动。

---

## Nonholonomic Drives：非完整驱动

PDF 列举：

- Differential drive，差速驱动；
- Dubins car；
- Reeds-Shepp car。

非完整机器人不能瞬时向任意方向移动。

例如普通汽车：

- 不能横向平移；
- 有最小转弯半径；
- 必须通过前进/后退和转向改变位置。

### 通俗类比

全向底盘像可以在冰面上任意滑动的冰壶。  
差速车像一辆小汽车：

> 想 sideways 移动是不可能的，只能靠转向和前后移动慢慢挪。

---

## Example 7.6：Differential Drive Kinematics

差速驱动有两个轮子。  
如果左右轮速度不同，机器人会转向。

经典 unicycle 模型：

\[
\dot{x}=v\cos\theta
\]

\[
\dot{y}=v\sin\theta
\]

\[
\dot{\theta}=\omega
\]

其中：

- \(v\)：前进速度；
- \(\omega\)：旋转角速度；
- \(\theta\)：朝向。

这就是非完整约束的典型例子。

## Example 7.7：Mobile Manipulation with Spot

PDF 标题：

### 通俗类比

你走路时会自然判断：

> 这里是路，那里是坑，不能踩。

移动机器人也要学会判断“哪里能走”。

# 1. 从桌面操作到移动操作

## 1.1 桌面操作的边界

之前章节中，我们主要做：

```text
固定机械臂
+ 固定桌子
+ 已知 bin
+ 外部相机
+ 抓取/放置任务
```

这种设定非常适合学习基础：

- spatial algebra；
- forward/inverse kinematics；
- differential IK；
- pose estimation；
- bin picking；
- motion planning。

但它有隐含假设：

1. 机器人知道自己在哪里；
2. 相机知道在哪里；
3. 桌子/bin 知道在哪里；
4. 环境基本不变；
5. 机器人不需要移动本体。

---

## 1.2 移动操作的新目标

PDF 说：

> adding mobility can increase the scope of our ambitions.

移动后，机器人可以做：

- 在房间之间移动；
- 操作不同家具；
- 完成多样任务；
- 在未知环境中工作。

### 类比

桌面机械臂是“工作站机器人”。  
移动操作机器人是“管家机器人”。

---

# 2. 移动操作中的新角色

PDF 的 7.1 节标题是：

> A New Cast of Characters。

虽然正文未展开，但可以理解为移动操作引入的新组件：

| 新角色 | 作用 |
|---|---|
| mobile base | 让机器人移动 |
| wheels/legs | 与地面交互 |
| onboard sensors | 机器人自带感知 |
| state estimation | 估计机器人在哪里 |
| map | 表示环境 |
| navigation | 决定去哪里 |
| traversability | 判断哪里能走 |
| dynamic obstacles | 处理会动的物体/人 |

# 3. 感知的差异

移动操作感知有三个核心新问题：

1. 局部视角；
2. 未知环境；
3. 机器人自身状态估计。

---

## 3.1 局部视角与主动感知

### 问题

桌面操作中，我们可以在桌子周围装多个相机。  
移动机器人通常只能靠自身传感器。

因此常见情况是：

> 只看到物体的一侧。

---

### 为什么 antipodal grasping 会失效？

在 bin picking 中，我们寻找法向近似相反的点。

但如果只看到物体正面：

- 看不到背面；
- 无法直接找到反向点；
- 无法直接判断夹爪能否夹住。

---

### Shape Completion：形状补全

PDF 说：

> 如果只看到半个 mustard bottle，当前传感器读数不足以规划抓取。

机器人必须推断背面。

这可以显式做：

```text
局部点云 → 完整 mesh 重建 → 抓取规划
```

也可以隐式做：

```text
局部观测 → 学习到的抓取策略
```

后者不一定要显式重建完整形状。

---

### 为什么学习是 fundamental？

因为缺失信息只能来自经验。

你见过很多瓶子，所以知道瓶子背面大概是什么形状。  
机器人也需要从大量物体经验中学习这种统计规律。

---

### Active Perception：主动移动传感器

移动机器人可以：

- 转头；
- 移动底盘；
- 改变视角；
- 收集更多信息；
- 降低不确定性。

这就是 active perception。

### 实验思想

```text
初始观测：只看到物体正面
策略：移动相机到侧面
再次观测：看到更多几何
更新抓取候选
```

代码上可以建模为：

```python
while uncertainty_too_high():
    next_view = plan_next_best_view(object_estimate)
    move_camera_or_base(next_view)
    new_points = get_point_cloud()
    update_object_estimate(new_points)
```

---

## 3.2 未知且可能动态的环境

### 桌面操作中的假设

在 bin picking 中，我们知道 bin 的位置。  
因此可以：

```text
crop 掉 bin 的点
保留物体点
```

但移动机器人进入厨房、卧室、办公室时，不能总是预先知道所有家具几何。

---

### 两种思路

#### 思路 A：显式建模所有物体

例如：

```text
检测桌子
估计桌子位姿
拟合桌子模型
检测椅子
估计椅子位姿
...
```

优点：

- 语义清楚；
- 可以推理物体功能。

缺点：

- 大场景复杂；
- 物体种类多；
- 模型可能不可用；
- 实时性难。

#### 思路 B：使用适合规划的环境表示

PDF 更强调这种方向：

> 不需要显式物体模型，但能支持快速规划查询。

---

## 3.3 Voxel Grid：体素地图

### 基本思想

把空间切成小立方体：

```text
voxel size = 1 cm
```

每个 voxel 有一个状态：

```text
occupied / unoccupied / probability
```

---

### 点云更新 voxel 的伪代码

```python
def world_to_voxel(p, origin, voxel_size):
    return ((p - origin) / voxel_size).astype(int)

def update_voxel_grid(voxel_grid, point_cloud, origin, voxel_size):
    for p in point_cloud:
        idx = world_to_voxel(p, origin, voxel_size)
        voxel_grid[idx] += 1
        # 或者使用概率/log-odds更新
```

更概率化的版本：

```python
log_odds[idx] += log(p_hit / (1 - p_hit))
occupied = log_odds > threshold
```

---

### Voxel Grid 用于碰撞查询

运动规划时：

```text
occupied voxel = obstacle
```

规划器查询：

```python
def collision_free(q):
    robot_points = forward_kinematics_robot_points(q)
    for p in robot_points:
        idx = world_to_voxel(p)
        if voxel_grid[idx].occupied:
            return False
    return True
```

---

### 为什么 sphere-on-voxel 很快？

如果用很多小球表示机器人碰撞几何：

```text
robot collision geometry ≈ many spheres
```

那么碰撞检查变成：

```text
每个球是否进入 occupied voxel？
```

这个查询可以非常快，而且容易并行。

这也是 Drake 中一些模型使用 densely packed spheres 的原因。

---

## 3.4 Octomap

### 普通 voxel grid 的问题

如果整个空间都用 1 cm voxel：

- 大场景会非常耗内存；
- 大部分空间是空的；
- 精细分辨率和大范围难以兼得。

### Octomap 的思想

Octomap 使用 octree：

- 空区域用大 voxel；
- 复杂区域细分成小 voxel；
- 概率化更新；
- 适合大规模 3D 地图。

### 类比

普通 voxel grid 像整张城市都用 1 cm 方格画。  
Octomap 像自适应地图：

- 空旷天空用大格子；
- 树木、家具、墙壁用小格子。

---

## 3.5 机器人状态估计

### 为什么移动机器人必须估计自身状态？

固定机械臂的 base 焊在世界中：

\[
{}^W X^B
\]

已知。

移动机器人的 base 会动：

\[
{}^W X^B(t)
\]

未知且变化。

如果不知道机器人在哪里，就无法正确使用：

- 相机点云；
- 运动规划；
- 抓取目标；
- 地图。

---

### 经典状态估计框架

PDF 提到：

# 4. 运动规划的差异

移动操作的运动规划有一个重要结论：

> 很多原有工具仍然可用，但需要注意自由度增加、连续关节和底盘约束。

---

## 4.1 Example 7.3：iiwa + Prismatic Base

PDF 给出一个极简移动机械臂：

```text
iiwa base 不再焊接到世界
↓
添加三个 prismatic joints
↓
分别对应 x, y, z 平移
↓
x, y 无界
↓
z 有限位
↓
iiwa 第一关节可连续旋转
```

---

## 4.2 规划工具需要大改吗？

答案：

> 几乎不用。

因为 Drake 的运动规划工具通常面向一般 kinematic tree。  
移动 base 只是增加几个关节。

---

## 4.3 自由度增加的影响

原本：

```text
iiwa: 7 DOF
```

加上移动 base：

```text
mobile iiwa: 10 DOF
```

### Trajectory Optimization

局部优化通常对高维较友好。

10 DOF 没问题。

### Sampling-Based Planning

采样规划受维度影响更大。

但：

- RRT 在 10 维通常可行；
- PRM 在 10 维可行，但需要高效实现；
- 更高维时会更困难。

---

## 4.4 Continuous Joints 与 Wrap-Around

如果某个关节是连续的，例如：

\[
\theta = 0 \equiv 2\pi
\]

那么规划器不能把它当普通有界实数处理。

### 距离度量

错误方式：

```python
angle_distance = abs(theta1 - theta2)
```

正确方式：

```python
angle_distance = abs((theta1 - theta2 + pi) % (2*pi) - pi)
```

### GCS/IRIS 注意事项

PDF 特别提到：

> 对 GCS 轨迹优化，IRIS regions 应在 local coordinate system 中操作，并且在任何 wrapping joint 上 domain 不超过 \(\pi\)。

否则可能得到绕远路的荒谬轨迹。

---

## 4.5 Drake 中构造移动 base 的实践思想

概念代码：

```python
# 伪代码：不再 weld iiwa base
# 而是添加 prismatic joints

plant.AddJoint(
    PrismaticJoint(
        name="base_x",
        frame_on_parent=world_frame,
        frame_on_child=base_frame,

        pos_lower_limit=-np.inf,
        pos_upper_limit=np.inf
    )
)

plant.AddJoint(
    PrismaticJoint(
        name="base_y",
        frame_on_parent=...,
        frame_on_child=...,
        axis=[0, 1, 0]
    )

    PrismaticJoint(
        name="base_z",

# 5. Wheeled Robots：轮式机器人

PDF 指出：

> 虽然真实轮子会打滑，但运动规划通常先用 no-slip assumption。  
> 然后用反馈控制跟踪路径。

---

## 5.1 Holonomic Drives：全向驱动

### 特点

全向底盘可以瞬时实现：

\[
v_x, v_y, \omega
\]

也就是：

- 前后；
- 横移；
- 旋转；
- 任意组合。

对规划器来说，它可以近似成一个 prismatic base。

---

## 5.2 Mecanum Drive Kinematics

Mecanum 轮子有斜置滚轮。  
四个轮子组合可以实现全向运动。

一个常见的底盘速度到轮速映射为：

设：

- \(v_x\)：前后速度；
- \(v_y\)：横向速度；
- \(\omega\)：旋转速度；
- \(L_x+L_y\)：轮距相关项；
- \(r\)：轮半径。

则四个轮子角速度可写为：

\[
\omega_1 = \frac{1}{r}(v_x - v_y - (L_x+L_y)\omega)
\]

\[
\omega_2 = \frac{1}{r}(v_x + v_y + (L_x+L_y)\omega)
\]

\[
\omega_3 = \frac{1}{r}(v_x + v_y - (L_x+L_y)\omega)
\]

\[
\omega_4 = \frac{1}{r}(v_x - v_y + (L_x+L_y)\omega)
\]

注意：具体符号取决于轮子安装方向和编号。  
但核心思想是：

> 底盘速度线性映射到四个轮子速度。

---

## 5.3 在 Drake 中仿真 Mecanum Wheels

Example 7.5 的思想是：

> 用 Drake 仿真 mecanum wheels 与地面接触，验证运动学。

实践建议：

1. 先实现简化 holonomic base；
2. 再尝试完整轮式接触仿真；
3. 检查：
   - 横移是否正确；
   - 旋转是否正确；
   - 轮子接触是否稳定；
   - 是否有明显滑移。

---

## 5.4 Nonholonomic Drives：非完整驱动

### 差速驱动机器人

两个主驱动轮，左右速度不同即可转向。

轮速到底盘速度：

\[
v = \frac{r}{2}(\omega_r + \omega_l)
\]

\[
\omega = \frac{r}{L}(\omega_r - \omega_l)
\]

其中：

- \(r\)：轮半径；
- \(L\)：两轮间距；
- \(\omega_r\)：右轮角速度；
- \(\omega_l\)：左轮角速度。

底盘运动学：

\[
\dot{x}=v\cos\theta
\]

\[
\dot{y}=v\sin\theta
\]

\[
\dot{\theta}=\omega
\]

---

### 非完整约束的含义

差速车不能直接横移。  
它必须通过朝向变化和前后运动改变位置。

因此规划时不能简单把它当成：

\[
(x,y,\theta)
\]

空间中的自由点。

需要考虑：

- 转向限制；
- 最小转弯半径；
- 前进/后退约束；
- Dubins path；
- Reeds-Shepp path。

---

### 类比

全向底盘像“可以横着走的螃蟹”。  
差速底盘像“普通小汽车”。

def is_traversable(point):

    return True
```

## Exercise 7.2：Mobile Base Inverse Kinematics

### 目标

比较固定 base 和移动 base 的 IK。

---

### 核心思想

固定 base：

```text
base pose 固定
IK 只调 arm joints
```

移动 base：

```text
base pose 也是 decision variables
IK 可以同时调 base 和 arm joints
```

因此：

> 移动 base 增加了冗余自由度，使 IK 更容易成功。

---

### Drake IK 概念代码

```python
ik = InverseKinematics(plant, context)

q = ik.q()
prog = ik.prog()

# q 包含 mobile base joints + arm joints
# 用一个 nominal posture 作为正则化目标
prog.AddQuadraticErrorCost(
    Q=np.eye(len(q_nominal)),
    q_desired=q_nominal,
    vars=q
)

# 末端抓取目标
ik.AddPositionConstraint(
    frameA=world_frame,
    p_AQ_lower=target_lower,
    p_AQ_upper=target_upper,
    frameB=gripper_frame,
    p_BQ=[0, 0.1, 0]
)

# 可选：避免碰撞
ik.AddMinimumDistanceConstraint(0.01)

result = Solve(prog, q_initial_guess)
```

---

### 为什么“移除 base position constraints”会让 IK 更容易？

固定 base 时：

```text
base 不能动
如果目标太远或角度不好，IK 可能 infeasible
```

移动 base 时：

```text
base 可以移动
机器人可以先把 base 开到合适位置
再用手臂抓取
```

### 类比

固定 base 像你坐在椅子上拿远处杯子。  
移动 base 像你站起来走到桌子边再拿杯子。

# 10. 本章最重要的工程经验

---

## 经验 1：移动不是简单加底盘

移动 base 会改变：

- 感知；
- 状态估计；
- 规划；
- 控制；
- 仿真；
- 任务设计。

---

## 经验 2：局部视角使学习变得必要

只看到一半物体时，几何本身不够。  
必须引入：

- 学习；
- 先验；
- 主动感知。

---

## 经验 3：环境表示要服务规划

移动机器人环境表示不能只为了可视化。  
它必须支持：

- 快速碰撞查询；
- 最小距离计算；
- 高效更新；
- 大场景扩展。

Voxel grid 和 Octomap 是典型方案。

---

## 经验 4：不要只信轮式里程计

轮子会滑。  
必须融合：

- 视觉；
- lidar；
- depth；
- IMU；
- wheel odometry。

---

## 经验 5：移动 base 增加自由度，但也增加规划细节

自由度增加通常对轨迹优化友好。  
但连续关节、wrap-around、底盘约束需要特别处理。

---

## 经验 6：轮子和腿的区别不只是“能不能走”

轮式：

- 平地高效；
- 模型可能非完整；
- 控制相对简单。

腿式：

- 适应复杂地形；
- 动态平衡复杂；
- 上层 API 常隐藏低层腿控制。

---

## 经验 7：仿真生态分两层

一层是引擎：

- Drake；
- MuJoCo；
- Isaac/Omniverse。

一层是内容平台：

- Sapien；
- Behavior 1K；
- Habitat 3.0。

做移动操作时，两者都很重要。
