## 0. 开篇：把机械臂"放出笼子"

### 0.1 一句话概括

> **桌面操作 = 机械臂被焊死在桌上，世界是已知、静止、被相机看光的。移动操作 = 把机械臂放到一个会跑的底盘上，让它闯进一个"没看全、会变化、自己也记不清自己在哪"的世界。于是感知、规划、仿真三件事全都变难了，本章逐一拆解这些新难题。**

### 0.2 引言逐句翻译 + 类比

> 之前我们主要聚焦桌面操作。你可以给钉在桌上的机器人带来很多有趣的物体/挑战，这够我们忙很多章。但在走太远之前，我想停下来问——**如果机器人还有轮子（或腿！）会怎样？**

> 移动操作里很多技术挑战和桌面操作一样。但有些挑战是**新的**，或至少**更紧迫**。描述这些挑战和部分解决方案，是本章首要目标。

> 最重要的是，给机械臂加 mobility 常常能**扩大我们对机器人的抱负范围**。现在我们能想象机器人在房子里移动、完成多样任务。**是时候让我们的造物出去探索（操作？）世界了！**

**类比（把机器人放出笼子，全章总纲）**：
- 桌面操作 = 把机械臂**关在一个灯光明亮、东西摆好、四面架满相机的玻璃房里**干活。世界是已知的、静止的、被看光的。
- 移动操作 = **把机械臂放出去，让它在别人家的厨房、仓库、客厅里干活**。灯可能暗、东西可能挪了、它自己走着走着还可能记不清自己在哪。
- 于是三件原本"省心"的事全变难了：**看不清（感知）、记不住自己在哪（状态估计）、路不熟还可能撞墙（规划）、连"模拟训练场"都得搭得更大（仿真）**。本章就围着这四件事转。

## 1. 对应 7.1：新角色登场（A NEW CAST OF CHARACTERS）

> PDF 此节仅给出标题，正文未展开。但它点出一个事实：**一旦机械臂能跑，舞台上就多出好几个"新演员"**。我把这些新角色补全，帮你建立全景。

桌面操作时，舞台上的演员很简单：**一只机械臂 + 一个夹爪 + 几台架死的相机 + 一张已知桌子**。一旦加上移动底盘，新演员登场：

- **移动底盘**（轮式或腿式）：它有自己的运动学（轮子怎么转、腿怎么迈），还可能打滑、要平衡。
- **车载/头戴相机**：相机跟着机器人动，**视角随时在变**，再也无法"架死看光"。
- **里程计 + IMU**：轮编码器数轮子转了几圈、IMU 测加速度，用来猜"我走到哪了"——但它们会**累积误差、会打滑**。
- **地图 / 体素网格**：机器人得**自己记一张环境地图**，因为没人提前告诉它墙在哪。
- **状态估计器**：把上面所有噪声测量**融合**成"我猜我在哪、世界长啥样"。

**类比**：桌面操作像**在自家厨房闭着眼都能摸到开关**；移动操作像**第一次去陌生朋友家、灯还关了一半，你得一边摸黑走、一边在脑子里画他家的地图、还得记清自己走到哪了**。新演员全是为此登场的。

## 2. 对应 7.2：感知有什么不同？（WHAT'S DIFFERENT ABOUT PERCEPTION?）

### 2.1 对应 7.2.1：部分视角与主动感知（Partial views / active perception）

> 在几何感知章我们讨论过"只看到物体一部分"的挑战。桌面操作时，我们通常能**从各个外部角度架相机看桌子**，但杂乱中仍会被遮挡。

> 当你是移动机器人时，我们通常**不能假设能把环境完全用仪器装备起来**。通常我们只用**机器人搭载的传感器**，比如头戴相机。如果我们**只看到物体的一面**，我们的对跖抓取（antipodal grasping，第 5 章那种"两指对捏相对两面"的策略）**不能直接用**。

> 主要解决方案是**用机器学习**。如果你只看到芥末瓶的一半，那么瞬时传感器读数**根本没有足够信息**去规划抓取；我们必须**以某种方式推断物体背面长什么样**（又叫 "shape completion" 形状补全，虽然不必显式做）。你之所以能猜芥末瓶背面长啥样，是因为**你以前和芥末瓶交互过**——是你交互过的物体的**统计**提供了缺失信息。所以**学习在这里不只是便利，而是根本性的**。我们很快会讨论 learning-based perception。

> 还有另一个缓解方法，移动机械臂常有：现在相机（和所有传感器）是**移动的**，我们可以**主动移动它们**以收集信息 / 减少不确定性。有丰富的 **"active perception"（主动感知）** 和 **"planning under uncertainty"（不确定下规划）** 文献。[More to come]

**类比（"绕过去看一眼"，必懂）**：
- 桌面操作 = 物体被**四台相机 360° 看光**，你早就知道它背面长啥样。
- 移动机器人 = 你**只有一只眼睛**，站在芥末瓶正面，**背面是盲区**。这时对跖抓取（要捏相对的两面）就抓瞎了——你根本不知道背面有没有把手、是不是凹的。
- **解法一：学习补全**。你以前摸过一百个芥末瓶，**脑子里有个"芥末瓶背面大概长这样"的先验**——这就是 shape completion，用学习把"看不见的部分"补出来。**作者强调：这里学习不是锦上添花，而是缺了它根本没法干**。
- **解法二：主动感知**。既然相机长在你头上，**你就走过去、绕到侧面、低头看一眼**——**用"动"去换"看得全"**。这就是 active perception：**规划的不只是"手怎么抓"，还包括"头/身体怎么动去把该看的看清楚"**。

**类比升级**：桌面操作像**法医对着摆好的证物拍照**；移动操作像**侦探进现场，得自己举着手电到处照，照到哪算哪，照不全还得挪位置补照**。

### 2.2 对应 7.2.2：未知的、可能动态的环境（Unknown, potentially dynamic environments）

> 桌面操作时，我们先假设物体已知，然后讨论能在未知物体上工作的方法（如对跖抓取）。但整个讨论中，我们**总假设知道桌子/箱子的几何和位置**！例如我们主动**裁掉**打到已知环境的点云，只留物体相关的点。机器人钉在桌子上时这很合理，但一旦移动、与更多样/更未知的环境交互，就得**放松这个假设**。

> 可以试着**建模环境里的一切**。可以做物体检测识别桌子，做位姿估计（可能形状估计）把参数化桌子模型拟合到观测。但这是条**难走的路**，尤其在多样广阔的场景。**有没有类似对跖抓取的类比，能类似地减少我们对环境显式建模的需求？**

> 我们想要一种环境表示：**不需要显式物体模型**，**支持运动规划所需的查询类型**（如快速碰撞检测、最小距离计算），**能从原始传感器数据高效更新**，**能扩展到大场景**。原始合并点云容易更新、不需要模型，但**不适合快速规划查询**。

**类比（"认每件家具" vs "记一张占用地图"，必懂）**：
- 笨办法 = **把房间里每件家具都识别出来、建个 3D 模型**（"这是桌子、那是沙发"）。在陌生、杂乱、还会变的家里，这太难。
- 聪明办法 = **不认家具，只记"哪里有空、哪里有东西挡着"**。规划时只问"我手臂伸过去会不会撞到'有东西'的格子"。
- 这就是作者想要的表示：**不建模物体，只记"占用"**，但要**查得快、更新得快、能装下大房子**。

#### Voxel grid（体素网格）—— 作者的答案

> **Voxel grids** 是满足（几乎所有）我们 desiderata 的几何表示——我们其实已经用它来高效下采样点云。在这种表示中，我们把 3D 空间某有限体积分成**固定大小立方体的网格**；比如 1 cm。我们把每个立方体标记为 **occupied（被占）** 或 **unoccupied（空）**（或更一般地，有被占据的概率）。然后对于无碰撞运动规划，我们把 occupied 立方体当作要避开的碰撞几何。voxel grid 的很多碰撞查询可以**很快**（且容易**并行化**）。特别地 **sphere-on-voxel 碰撞查询**可以非常快，这是为什么你看到 Drake 模型里很多碰撞几何用**密集打包的球**近似。用点云更新 voxel grid 也高效。为了让 voxel 表示**既有细分辨率又能表示很大场景**，我们可以用**巧妙的数据结构**。

**类比（Minecraft 世界，必懂）**：
- 体素网格 = **把世界切成一格一格的 Minecraft 方块**，每格标"有方块/没方块"。
- 碰撞查询 = "**我手臂要伸到的那个格子，有没有方块？**"——查表，极快。
- **sphere-on-voxel** = "**我手臂末端是个球，这个球压到哪些方块？**"——比"精确网格对网格"快得多，所以 Drake 喜欢把机器人几何也近似成**一堆小球**去查体素。
- **大场景怎么办**？用**八叉树**这类"按需细分"的数据结构——**空的大空间用一个大格子表示，只有有东西的地方才细分成小格子**，省内存。

#### Example 7.1（Octomap）

> 一个特别好且高效的、在 scale 上实现 voxel grid 的算法/软件包叫 **Octomap**……

**补充概念**：**Octomap = 八叉树版的体素地图**。它把空间递归地切成 8 块，**空的整块合并成一个大格，有东西的地方才细分**，于是**又省内存、又能表示大房子、还能高效更新**（新点云来了，只更新相关分支）。它是移动机器人建图的工业标准之一。

> 把视觉场景**分割成物体 vs 环境**，如今最好用**机器学习**做；我们很快会实现分割流水线。

**类比**：体素告诉你"哪有东西"，但**规划抓取时你还想知道"哪一团方块是同一个杯子"**——这就是**分割**，如今用神经网络做（把像素/点聚类成"物体实例"）。

### 2.3 对应 7.2.3：机器人状态估计（Robot state estimation）

> 移动机械臂感知中出现的**最大不同**是：需要估计的**不仅是环境状态，还有机器人自己的状态**。例如在我们之前的点云处理算法中，我们**默认知道相机在世界中的位姿**。我们可能投入繁琐的标定程序，用已知形状和模式，来（离线）估计这些相机外参。我们也认为**机器人运动学已知**——机器人钉在桌子上、世界到末端执行器的所有变换都用高精度编码器直接测量时，这是相当合理的假设。但**一旦机器人有移动基座，这些假设就失效了**。

> 移动机器人的状态估计有很强历史；**[2]（《Probabilistic Robotics》）是经典参考**。通常这些算法基于**（近似）递归贝叶斯滤波**，或密切相关的**平滑算法 [3]**。通常我们的移动基座除了**轮编码器和 IMU**，还装备**测距传感器和/或相机**。状态估计流水线把这些**噪声测量融合**成一致估计。确实，移动机器人**最大的教训之一**是：**仅靠轮里程计几乎总不足以做估计**；真实轮子会**打滑**，视觉/测距测量提供**基本且独立**的一组测量。

**类比（"数步子"为什么靠不住，必懂）**：
- 轮里程计 = **蒙着眼数自己走了几步**来猜位置。
- 但**轮子会打滑**（在冰上、地毯上、转弯时），**数 100 步可能实际只走了 95 步**，误差**一路累积**，走久了你猜的位置和真实位置差十万八千里。
- 所以必须**融合独立的"睁眼"测量**：相机看到"我离那面墙 2 米"、lidar 测到"左边 1.5 米有柱子"——**用这些"睁眼"的测量去不断纠正"数步子"的累积误差**。这就是**递归贝叶斯滤波**（如卡尔曼滤波/粒子滤波）干的事：**每一步用"我猜的"和"我看到的"做加权平均**。

> 自 [2] 写作以来很多东西变了。基于测距的传感器（lidar 和深度相机）在**测距、精度、帧率**上戏剧性改进，使方法戏剧性更有效。

#### Example 7.2（在 Drake 中仿真测距传感器）

> 也许**最大的变化**是从重度依赖基于测距的传感器/深度相机，转向**越来越强大的、只用 RGB 相机的估计算法**。这归功于**视觉惯性里程计 [4]**、**单目深度估计 [5]**、**密集 3D 重建 / structure from motion [6,7]** 等的进步。

**类比（从"激光尺"到"只用眼睛猜深度"，必懂）**：
- 老路线 = **扛一把激光尺（lidar/深度相机）**，直接量距离，准但贵、重。
- 新路线 = **只用普通摄像头**，靠**视觉惯性里程计**（相机画面 + IMU 一起猜自己怎么动）、**单目深度估计**（一张图猜深度）、**SfM / NeRF / 3D 高斯**（从很多张图重建 3D）来估计世界和自身位姿。
- **意义**：相机便宜、轻、信息丰富，**这条路让移动机器人能做得又轻又便宜**。

### 🧪 代码 1：体素化点云 + 占用查询 + 简单 EKF 融合里程计（numpy，可跑）

> PDF 没给内联代码。这段把 7.2 的两个核心——**体素占用表示**和**状态估计融合**——做成可跑的玩具，帮你建立手感。

```python
import numpy as np

# ---------- (A) 体素化点云 + 占用查询 ----------
res = 0.1                                  # 体素边长 10cm
def to_voxel(p, res): return tuple(np.floor(p/res).astype(int))
points = np.random.randn(2000,3)*0.3 + np.array([1.0,0.5,0.8])  # 一团"物体"点云
occ = set(to_voxel(p, res) for p in points)            # 占用体素集合
def is_occupied(p): return to_voxel(p, res) in occ
def sphere_voxel_collision(center, radius, res):       # sphere-on-voxel 碰撞
    for dx in (-1,0,1):
        for dy in (-1,0,1):
            for dz in (-1,0,1):
                if is_occupied(center + res*np.array([dx,dy,dz])):
                    if np.linalg.norm(center - np.array(to_voxel(center,res))*res - res*np.array([dx,dy,dz])) < radius:
                        return True
    return False
print("体素数 =", len(occ), " 查询(1,0.5,0.8)占用?", is_occupied([1,0.5,0.8]))
print("球(中心[1,0.5,0.8],r=0.15)碰撞?", sphere_voxel_collision(np.array([1.,0.5,0.8]),0.15,res))

# ---------- (B) 极简 EKF: 融合"数步子"(里程计) + "睁眼观测"(测距) ----------
# 1D 机器人位置 x; 里程计每步报"走了1"但有漂移; 观测偶尔给真实位置(带噪)
rng = np.random.default_rng(0)
x_true = 0.0; x_est = 0.0; P = 1.0          # 估计位置 + 不确定度
Q_proc, R_obs = 0.1, 0.5                     # 里程计漂移方差, 观测噪声方差
log = []
for step in range(50):
    x_true += 1.0                            # 真值每步走1
    # 预测(里程计, 带累积漂移)
    odo = 1.0 + rng.normal(0, np.sqrt(Q_proc))
    x_est += odo; P += Q_proc                # 预测: 不确定度增长
    # 每5步"睁眼"观测一次真实位置
    if step % 5 == 0:
        z = x_true + rng.normal(0, np.sqrt(R_obs))
        K = P/(P + R_obs)                    # 卡尔曼增益
        x_est += K*(z - x_est); P = (1-K)*P  # 更新: 不确定度下降
    log.append((x_true, x_est, P))
log = np.array(log)
print("50步后 真值=%.1f 纯里程计会漂, EKF估计=%.2f 不确定度P=%.2f" % (x_true, x_est, P))
```

**你会看到**：**纯靠"数步子"会一路漂**，但**每隔几步"睁眼"观测一次，EKF 就把估计拉回真值、不确定度 P 也被压下去**——**亲手见"融合独立观测纠正里程计累积误差"**，这正是 7.2.3 的核心教训。体素部分则让你见"**sphere-on-voxel 碰撞查询**"为何快。

## 3. 对应 7.3：运动规划有什么不同？（WHAT'S DIFFERENT ABOUT MOTION PLANNING?）

### 3.1 对应 Example 7.3：iiwa 装在棱柱基座上

> 让我们从一个也许最简单的（鉴于我们目前的工具箱）自己构建 mobile manipulator 的例子开始。

> **Example 7.3 (iiwa on a prismatic base)**：拿 iiwa 模型，给基座加几个自由度。与其把 link 0 焊到世界，不如**插入三个棱柱关节**（用不可见无质量连杆连接），对应 $x, y, z$ 中的运动。我让 $x$ 和 $y$ 无界，但对 $z$ 设适度关节限。iiwa 第一个关节已经绕基座 $z$ 轴转；我**去掉关节限**让它能连续转。简单改动，现在我有移动机器人的本质。

**类比（给机械臂装"滑板"，必懂）**：
- 桌面 iiwa = 7 个关节，**焊死在桌上**。
- 加 3 个棱柱关节 = **给桌子底下装个能前后左右上下滑的滑板**，于是基座能在空间平移。
- $x,y$ 无界 = 滑板能滑到任意远；$z$ 设限 = 滑板不能钻地也不能飞太高。
- 第一个关节去掉关节限 = **底座能原地转任意圈**（连续转，不被"拧到头"卡住）。
- 7（iiwa）+ 3（棱柱）= **10 个自由度**。

> 现在问：我得怎么改运动规划工具来用这个版本的 iiwa？**答案是：不多！** 我们的运动规划工具都相当通用，基本适用于任何运动学机器人构型。我们加的移动基座只是给运动学树多加几个关节，但其他直接契合框架。

> 一个可能的考虑是我们**增加了自由度数**（这里从 7 到 10）。**轨迹优化算法**，由于局部于轨迹，**容易扩展到高维问题**，所以这没问题。**基于采样的规划器**在维度上挣扎更多，但 **RRT 在 10 维应该没问题**。**PRM 肯定也能在 10 维工作**，但可能需要高效实现，且开始到极限。

**类比（维度 = 迷宫的维数，必懂）**：
- 自由度 = 迷宫的维数。维数越高，"撒点找路"的采样规划越吃力（**维度诅咒**：维数一高，撒的点填不满空间）。
- 但**轨迹优化**是"沿着一条候选轨迹局部修"，**它不太怕维数高**——所以加 3 个基座关节对它不是事。
- **RRT** 在 10 维还扛得住；**PRM**（要先撒一大张路网）在 10 维就开始喘。

#### 连续关节的 wrapping（绕圈）陷阱

> 另一个对移动基座可能新的考虑是**连续关节的存在**（绕 $z$ 轴的旋转没有关节限）。这些在规划栈中需要一些小心。在基于采样的规划器中，通常**距离度量和 extend 操作被适配以考虑能 wrap around 的边**。非凸轨迹优化本身不需要算法修改，但确实可能受局部极小之苦。对于用 **Graphs of Convex Sets** 的轨迹优化，只需小心让 **IRIS 区域在局部坐标系中操作，且在任何 wrapping 关节中域不超过 $2\pi$**（即一个完整圆周）。

> 不恰当处理这会导致**略微荒谬的计划，走远路**；这里有个例子，运动学轨迹优化找到在架子间导航的**次优解**，来自 [8]。

**类比（"绕圈关节"的坑，必懂）**：
- 关节角 $0$ 和 $2\pi$ 其实是**同一个姿势**（转一整圈回到原位）。但规划器若**傻乎乎地把 $0$ 和 $2\pi$ 当成差 $2\pi$ 的两个远点**，它就会让关节**傻转一整圈**去"走捷径"，而其实原地不动就行。
- 所以距离度量要懂"绕圈"：$0$ 和 $2\pi$ 的距离应算 $0$，不是 $2\pi$。这就是 **wrap around**。
- **IRIS 区域**（第 6 章那种"凸的安全区"）若**横跨 $0/2\pi$ 边界**，凸性就坏了，所以要让 IRIS 在**局部坐标**里、**域不超过 $2\pi$**。
- 不处理 → **规划器让手臂傻转 270° 而不是转 90°** 这种荒谬解（第 6 章也提过这个坑）。

> 如果用轮子或腿而非棱柱关节实现移动机械臂会怎样？我们会看到，一些轮式机器人（和大多数腿式机器人）能**直接提供我们的棱柱关节抽象**，但其他会加我们在运动规划中必须考虑的约束。

**类比**：棱柱基座 = "理想滑板，能瞬移到任意 $(x,y)$"。真实轮子/腿**不能瞬移**，它们有自己的运动约束（轮子不能横着滑、腿要迈），这些约束得加进规划。下面 7.3.1/7.3.2 就讲这些。

### 3.2 对应 7.3.1：轮式机器人（Wheeled robots）

> 即使真实轮子确实打滑，我们通常用**无滑假设**做运动规划，然后用**反馈控制**跟随规划路径 [9, Ch. 49]。

**类比（"先假设轮子不打滑来规划，跑起来再用控制纠偏"，必懂）**：
- 规划时**假装轮子抓地完美**（无滑），算出一条理想路径。
- 真跑时轮子难免打滑，**用反馈控制实时纠偏**，把真实轨迹拉回理想路径。
- 这是工程上的务实分工：**规划管"理想路"，控制管"纠偏"**。

#### 全向驱动（Holonomic drives）

> **Example 7.4 (Mecanum drive kinematics)** / **Example 7.5 (Simulating mecanum wheels in Drake)**

**补充概念（麦卡纳姆轮 = 能横着走的轮子，必懂）**：
- 普通轮子 = **只能前后滚，不能横着滑**（这是"非完整约束"，下面讲）。
- **麦卡纳姆轮** = 轮子上斜着装一圈小滚子，**四个轮子配合，能让车前后、左右、斜着、原地转任意组合地动**——**全向（holonomic）**，**想往哪平移就往哪平移**，**和棱柱基座一样自由**。
- 所以麦卡纳姆车**直接等价于我们的棱柱基座抽象**，规划时不用操心轮子的约束。

#### 非完整驱动（Nonholonomic drives）

> **Differential drive（差速）, Dubins car, Reeds-Shepp.**
> **Example 7.6 (Differential drive kinematics)**

**补充概念（差速 = 坦克式转向，必懂）**：
- **差速驱动** = 左右两个轮子各一个电机，**左轮快右轮慢就右转**。它**能前后、能转弯，但不能直接横着滑**——这就是**非完整约束**：**你能到的位置很多，但不能"任意姿势瞬移"**（不能像麦卡纳姆那样横移）。
- **Dubins car** = "**只能前进 + 转弯**"的车（不能倒车），规划出的最短路径是"直线 + 圆弧"的拼接。
- **Reeds-Shepp** = Dubins 但**允许倒车**，路径更灵活。
- **为什么非完整难规划**？因为**你不能"直线横移"**，规划器得规划出"先转、再走、再转"的曲线，**比全向车麻烦**。

### 🧪 代码 2：差速驱动 & 麦卡纳姆轮运动学（numpy，可跑）

> PDF 的 Example 7.4/7.6 只有标题。这段把两种轮式运动学做成可跑玩具，让你亲眼对比"全向 vs 非完整"。

```python
import numpy as np

# ---------- 差速驱动: 左右轮速 (vl,vr) -> 车身速度 (v, omega) ----------
L = 0.3   # 轮距
def diff_drive(vl, vr):
    v = 0.5*(vr+vl); omega = (vr-vl)/L
    return v, omega
# 积分一步: 状态 [x, y, theta]
def diff_step(state, vl, vr, dt):
    v, omega = diff_drive(vl, vr)
    x,y,th = state
    return np.array([x + v*np.cos(th)*dt, y + v*np.sin(th)*dt, th + omega*dt])

# ---------- 麦卡纳姆: 四轮速 -> 车身速度 (vx,vy,omega), 全向 ----------
def mecanum(w_fl, w_fr, w_rl, w_rr, r=0.05, lx=0.2, ly=0.15):
    vx = (w_fl+w_fr+w_rl+w_rr)*r/4
    vy = (-w_fl+w_fr-w_rl+w_rr)*r/4
    omega = (-w_fl+w_fr+w_rl-w_rr)*r/(4*(lx+ly))
    return vx, vy, omega

# 演示: 差速不能原地横移, 麦卡纳姆可以
s = np.array([0.,0.,0.])
s = diff_step(s, 1.0, -1.0, 0.5)   # 差速: 原地转
print("差速 原地转后 朝向=%.2f rad (能转, 但不能纯横移)" % s[2])
vx,vy,om = mecanum(1,-1,-1,1)      # 麦卡纳姆: 纯横移
print("麦卡纳姆 横向速度 vy=%.2f (能纯横移=全向)" % vy)
```

**你会看到**：**差速能原地转但无法纯横移**（非完整），**麦卡纳姆能纯横移**（全向）——**亲手见两种驱动的本质差别**，理解为什么麦卡纳姆"直接等价于棱柱基座"而差速要额外规划曲线。

### 3.3 对应 7.3.2：腿式机器人（Legged robots）

> 如果你的工作是做腿的规划和控制，那有丰富文献供你探索。但如果你用像 **Spot** 这样的腿式机器人做 mobile manipulation，且用 **Boston Dynamics 提供的 API**，那么（幸运或不幸地）你**不能深入腿的低层控制**。事实上，Spot 提供的 API **一阶上把腿式平台当作全向基座**。（有次要考虑，如机器人质心受动态约束限制，可能偏离你请求的轨迹以维持平衡）。

> 当然，当你在**粗糙或间歇地形**上做 mobile manipulation 时事情变得有趣得多；这是腿式平台真正闪光的地方！

**类比（"把 Spot 当成一个会自己保持平衡的全向滑板"，必懂）**：
- 用 Spot 的 API 时，你**不用管四条腿怎么迈**——你只下命令"基座移到 $(x,y)$、转 $\theta$"，**Boston Dynamics 的低层控制器自己搞定四条腿怎么迈、怎么平衡**。

## 5. 对应 7.5：导航（NAVIGATION）

> 我们这章迄今覆盖的大多数想法可被视为对我们现有 manipulation 工具箱的**相对适度扩展**。但有些与导航移动机器人相关的重要问题，**确实不在 table-top manipulation 中出现**。

### 5.1 对应 7.5.1：建图，除了定位（Mapping in addition to localization）

> PDF 此节仅标题。补充概念：

**类比（"边走边画地图" vs "在已知地图上找自己"，必懂）**：
- **定位（localization）** = **手里有地图，猜自己在地图哪**（"我看到左边有柱子，那我在地图的 A 点"）。
- **建图（mapping）** = **没地图，边走边画**（"我往前走 2 米看到墙，就在地图上画一面墙"）。
- **移动机器人通常两件事要同时做** = **SLAM（Simultaneous Localization And Mapping，同时定位与建图）**：**一边画地图、一边在新地图上猜自己在哪**——**鸡生蛋蛋生鸡，但有成熟算法（如 7.2.3 提到的 iSAM [3]）能解**。
- 桌面操作**不需要这俩**（地图已知、机器人钉死），所以这是移动操作**新冒出来的难题**。

### 5.2 对应 7.5.2：识别可通行地形（Identifying traversable terrain）

> PDF 此节仅标题。补充概念：

**类比（"哪里能走、哪里是坑"，必懂）**：
- 移动机器人导航前得知道**哪里能走**：平地能走、台阶要看腿能不能迈、悬崖不能去、水坑不能踩。
- **可通行地形识别** = 用相机/深度图/lidar **把地面分类成"可走/不可走/要小心"**，喂给规划器当"哪里能走"的地图。
- 这又和 7.2.2 的体素/分割接上：**体素记"哪有东西"，可通行图记"哪能走"**，两者一起喂给规划器。

# 第三部分：增补 —— 把"还不够通俗"的点 + 代码集中说明

### 通俗性增补（5 个再加类比）

1. **为什么"只看到一面"会让对跖抓取失效**？对跖抓取要**两指捏物体相对的两面**，且假设两面法向相反。只看到正面，**背面法向未知**，你不敢假设背面有个平整面让你捏——**可能背面是个圆把手，对捏会滑**。所以得先**补全背面**或**绕过去看**。
2. **为什么 voxel 比"原始点云"适合规划**？原始点云是**一堆散点**，查"手臂伸过去撞不撞"得对每个点算距离，**慢**。体素把空间**格子化**，查"这格有没有东西"是**查表**，**快且能并行**。代价是**分辨率固定**（格子大小），但用八叉树能缓解。
3. **为什么轮里程计"几乎总不够"**？因为它是**开环积分**——**误差只加不减**。轮子半径误差 1%、打滑 5%，走 100 米误差就米级。**视觉/测距是"绝对测量"**（"我离墙 2 米"），**误差不累积**，所以必须融合。这就是 EKF/粒子滤波的活（代码1）。
4. **非完整 vs 全向的"自由度"区别**：全向车**瞬时**能往任意方向平移（3 个瞬时自由度：$v_x,v_y,\omega$）。差速车**瞬时**只有 2 个自由度（$v,\omega$），**不能瞬时横移**——但**长时间**它仍能到任意位姿（**可控但非完整**）。规划时这个"瞬时不能横移"逼你规划曲线。
5. **为什么 Spot 的 API"一阶当全向"但有尾巴**？API 把"四条腿怎么迈"封装了，你下命令"基座去 $(x,y)$"，**一阶上它像全向滑板**。但**真实物理里**，迈腿时质心会晃、为不失衡控制器会**微调基座轨迹**，所以**你请求的轨迹和实际执行的有偏差**——规划时**留余量**即可。

**通关三句话**：

1. **移动操作 = 把机械臂放出"看光、静止、已知"的玻璃房，闯进"没看全、会变化、自己也记不清在哪"的真实世界**——于是感知、状态估计、规划、仿真四件事全变难，本章逐一拆解。感知上，只看到物体一面会让对跖抓取失效，解法是**用学习补全背面**或**主动移动去看**；环境不再已知，于是不建模物体、改记**体素占用地图**（Octomap 八叉树扛大场景）。

2. **机器人自己也记不清在哪，是移动操作最大的新难题**——轮里程计靠"数步子"会一路累积漂移，**必须融合相机/测距的独立测量**（递归贝叶斯滤波/EKF），而趋势是**只用便宜的 RGB 相机**靠视觉惯性里程计/单目深度/SfM 来估计。规划上，加移动基座让自由度变高但**轨迹优化不怕高维**，要小心**绕圈关节的 wrapping 坑**；轮式分**全向（麦卡纳姆，等价棱柱基座）** 和**非完整（差速/Dubins，不能瞬时横移，要规划曲线）**，腿式如 Spot 的 API 一阶当全向基座但留质心平衡的余量。

3. **仿真要搭得更大、导航要边走边画地图**——桌面只仿真桌上几物，移动操作要在广阔环境仿真，于是用建立在物理引擎上的**内容聚合器**（Sapien/Behavior 1K/Habitat）打包现成场景和任务；导航则新冒出**SLAM（边走边画地图+猜自己在哪）** 和**可通行地形识别**两件事。**贯穿全章的精髓是：移动操作的难，不在算法本身变复杂，而在"世界不再配合你"——看不清、记不住、路不熟、训练场也得自己搭；而应对之道，是用学习补全看不见的、用体素记不建模的、用滤波纠正记错的、用全向抽象简化轮腿的，最终让放出去的机器人，在陌生世界里也能稳稳地把活干完。**

> 最后送你一句收尾：这一章没有炫目的公式，它画的是一张"问题地图"——告诉你一旦把机械臂放出笼子，感知、估计、规划、仿真会各自冒出什么新坑，以及每个坑对应的工具。它最朴素的智慧是：**桌面操作之所以"简单"，是因为我们把世界关进了一个看光、静止、已知的玻璃房；而真实世界从不配合，它会遮你的眼、挪你的东西、让你记错自己在哪。移动操作的整门学问，就是学会在"看不清、记不住、路不熟"的世界里，依然稳稳地把活干完——用学习补全看不见的背面，用体素记住不建模的环境，用滤波纠正数错的步子，用全向抽象驯服轮与腿，最终让那个被放出笼子的机器人，在陌生厨房的灯光下，也能准确地把盘子放进洗碗机。** 🤖️
