# 第7章：移动操作——走出桌子的机器人
## 1. 引言：从“桌面”到“世界”
以前我们的 KUKA 机械臂是“钉死”在桌子上的。这种环境是**静态且已知**的。
现在，我们要给机器人装上移动底座。这意味着：
*   **环境未知**：机器人可能在一个陌生的厨房里，不知道桌子在哪，甚至不知道地面是不是平的。
*   **视角受限**：机器人不能再依赖架在周围的高清摄像头，只能靠自己头上的眼睛。
*   **自由度增加**：机器人不仅能动手，还能动脚，这让控制变得极其复杂。
---
## 2. 感知：睁大眼睛看不清的世界
移动机器人的感知比桌面机器人难多了。
### 2.1 局部视图与主动感知
*   **挑战**：如果机器人只看到半个物体，它能抓吗？
    *   **例子**：桌上的“反相对偶抓取”策略依赖于看到物体的两侧。如果机器人只看到半个 mustard bottle（芥末瓶），它根本不知道背面长什么样。
*   **解决方案 1：机器学习**。机器人必须根据过去见过的瓶子，**猜**出背面是什么（形状补全）。这不再是简单的几何计算，而是基于统计的学习。
*   **解决方案 2：主动感知**。既然眼长在头上，那就动动头！通过移动身体或摄像头，从不同角度看物体，消除盲区。这叫“主动感知”。
### 2.2 未知环境建模：体素网格
*   **问题**：在桌面任务里，我们假设桌子、箱子都是已知的，代码里直接把点云“切掉”来去除背景。
*   **现实**：在移动场景里，我们不知道环境长什么样。如果用**点云**直接表示环境，数据量太大，做碰撞检测太慢了。
*   **解决方案：体素网格**。
    *   **比喻**：这就像玩《我的世界》。把整个空间切成无数个小立方格（体素），比如 1 厘米见方。
    *   **标记**：如果扫描到有东西，就把那个格子标记为“占用”。空的标记为“空闲”。
    *   **优势**：
        1.  **查询快**：判断机器人撞没撞墙，只需要查几个格子的状态，瞬间完成。
        2.  **更新快**：有新的点云数据进来，直接更新对应的格子就行。
    *   **代码/实验补充**：Drake 支持从 `Octomap`（一种高效的八叉树体素地图）加载数据。`Sphere` 与 `Voxel` 的碰撞检测极其快速，这也是为什么很多机器人模型里其实是一堆紧密排列的球体。
### 2.3 机器人状态估计：我在哪？
*   **挑战**：以前我们假设编码器绝对准，所以机器人手在哪，我们算得准准的。但加上轮子后，轮子会打滑！光靠轮子转了多少圈算距离（里程计），误差会越来越大。
*   **解决方案：传感器融合 (SLAM/VIO)**。
    *   **思路**：结合轮子编码器、IMU（惯性测量单元）和摄像头。
    *   **视觉惯性里程计 (VIO)**：利用摄像头看到的画面特征变化，推算出机器人的移动轨迹。这比轮子里程计准多了，不怕打滑。

## 3. 运动规划：给机器人装上脚
现在我们要规划机器人“全身”的运动。不仅仅是手臂怎么动，还有底座怎么动。
### 3.1 简单的移动底座：滑块机器人
*   **建模技巧**：在 Drake 里，最简单的模拟移动机器人的方法，就是在机械臂基座下面加 3 个**移动关节**，分别对应 X, Y, Z 轴。
*   **变化**：机器人的自由度从 7 个变成了 10 个。
    *   **优化算法**：对于轨迹优化（如 GCS），多 3 个维度区别不大，很容易搞定。
    *   **采样算法 (RRT)**：维度越高，搜索越难。但在 10 维空间里，RRT 还是能工作的。
### 3.2 连续旋转关节：不要绕远路
*   **问题**：机器人底座的旋转（航向角）通常是 $0 \sim 360^\circ$ 连续的，没有极限。
*   **陷阱**：优化器可能会“犯傻”。比如要从 $350^\circ$ 转到 $10^\circ$（这其实只需转 $20^\circ$），但优化器可能会选择转 $340^\circ$ 绕远路。
*   **后果**：机器人会在原地转圈圈，看起来很滑稽。
### 3.3 轮式机器人：全向 vs. 非完整约束
*   **全向移动**：
    *   **代表**：麦克纳姆轮。
    *   **特点**：可以像螃蟹一样横着走，斜着走，原地转圈。
    *   **规划**：把它当普通的滑块机器人处理即可，很简单。
*   **非完整约束**：
    *   **代表**：差速驱动（像坦克、扫地机器人、普通汽车）。
    *   **限制**：不能横着走。如果要横移，必须先向前走，再转弯，再向后走（平行停车）。
    *   **规划策略**：通常假设轮子不打滑，规划出满足非完整约束的路径（如 Dubins 曲线或 Reeds-Shepp 曲线）。虽然实际会有打滑，但反馈控制器会修正这些误差。
### 3.4 足式机器人：比如 Spot 机器狗
*   **接口简化**：虽然足式机器人内部极其复杂，但对外提供的 API 通常把它当作一个**可以全向移动的底座**。
*   **隐形限制**：你不能让它瞬间加速到无穷大，也不能让它重心太偏导致摔倒。API 内部会有动力学限制保护。

## 4. 仿真：更大的沙盒
移动机器人需要在大场景里跑，这催生了新一代的仿真工具。
### 4.1 内容聚合器
以前我们用 Drake 写代码搭场景。现在有了专门的“地图编辑器”和“仿真平台”。
*   **Sapien**、**Behavior 1K**、**Habitat 3.0**：这些是基于游戏引擎（Unreal, Unity）的高级仿真器。它们提供了海量的物体模型、逼真的场景和复杂的任务（比如“打开微波炉”）。
*   **Drake 的角色**：这些工具负责“展示”，而 Drake 负责底层的物理计算。我们的目标是把这些平台生成的场景导入到 Drake 中，利用 Drake 强大的优化算法去解决它们。

## 6. 练习题与代码实战详解
PDF 里的练习主要关注搭建环境底座和 IK 的变化。
### 练习 7.1：搭建仿真场景
*   **任务**：加载物体，设置一个有用的操作场景。
*   **代码重点**：
    *   分析 SDF 文件中的**碰撞几何**。
    *   区分“视觉几何”和“碰撞几何”。在仿真中，碰撞几何越简单越好（比如用球体代替复杂的网格），这样算得快。
### 练习 7.2：移动底座逆运动学 (Mobile Base IK)
*   **任务**：为一个带移动底座的机械臂做 IK。
*   **技巧**：
    *   通常 IK 会约束“底座不动”（位置固定）。
    *   **移动 IK**：**去掉底座的位置约束**。优化器会自动算出底座该去哪，才能让手抓到目标。
    *   **结果**：你会发现，机器人为了抓到一个远处的物体，会自动走到那个位置。这就是移动操作的魅力！

### 给工程师的最后建议
*   **善用体素网格**：在开发移动机器人导航算法时，不要直接操作原始点云。先把点云转换为 Occupancy Grid（占用网格），这在计算代价场和碰撞检测时效率会有数量级的提升。
*   **理解非完整约束**：如果你想写一个差速机器人的规划器，不要试图让它横着走。这违反了物理定律。你需要学习 Dubins 曲线等路径模型，或者使用满足非完整约束的优化器。
*   **利用 API 简化**：如果你在使用像 Spot 这样的足式机器人，不要尝试去控制每一个关节。利用它提供的“全向底座”接口，把重点放在上层任务规划上，让它的低层控制器自己保持平衡。
