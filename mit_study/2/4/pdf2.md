## 0. 开篇：第 3 章的"作弊"该还了

### 0.1 一句话概括

> **第 3 章我们假装"知道砖在哪"。第 4 章用深度相机把这个假设去掉：从一堆带噪声、被遮挡、混着杂物的 3D 点里，认出并定位那个你认识的物体。整章就是一条流水线：拍照 → 变成点云 → 和"模型点云"对齐（配准）→ 处理遮挡和离群点 → 加上"不能穿模"的约束 → 跟踪 → 接回第 3 章去抓。**

### 0.2 作者开场白的逐句翻译

> 上一章我们开发了一个初始方案去移动物体，但**做了一个重大假设**：我们知道物体的初始位姿。本章要**第一次去掉这个假设**，开发用深度相机信息**估计位姿**的工具。本章工具在"操作**已知物体**（你有它的网格模型）、且环境**相对不杂乱**"时最有用，但它们也是后面更高级方法的**基线（baseline）**。

> 本章走的是**基于几何**的路线。**不是所有**感知系统都显式用几何——很多深度学习方法学的是"像素到动作"的直接映射。但**很多深度学习方法其实重度依赖几何**，而且近几年几何处理本身也革命了（稠密重建、text-to-3D 等）。所以我们**从几何开始**，因为它能给感知探索提供一个**扎实的地基**。

> **一个 caveat（作者亲口说的局限）**：我们用"位姿估计"当本章目标，因为它**具体、立刻有用**。但作者**在他最先进的操作系统里其实尽量不用显式位姿估计**——因为除了假设物体已知，**精确估计位姿本身很难**（部分视角、遮挡），而且**常常超出我们实现操作目标真正需要的**。

**类比（"认脸"vs"认动作"，全章总纲）**：
- **位姿估计** = 先**精确认出"这是哪个杯子、它转了多少度"**，再据此抓。
- **端到端** = 不认脸，**直接看画面就伸手**。
- 作者的态度：**本章教你"认脸"这套扎实功夫**（它是地基、是基线），但他**自己最先进的系统往往跳过这一步**——**因为"认脸"既难、又常常没必要**。但**地基必须先打**，所以本章必须讲。

## 1. 对应 4.1：相机与深度传感器 —— 机器人的"眼睛"

### 1.1 为什么先讲相机

> 就像选机械臂和手有很多选择，**给机器人/环境装传感器也有很多选择**。而且**比机械臂更甚**——近几年传感器**质量飞跃、成本尺寸骤降**，**主要拜手机产业所赐**，自动驾驶竞赛也推动了高端传感器。

> 硬件的变化**有时戏剧性地改变了算法路线**。比如**当传感器分辨率和帧率高到"两帧之间世界几乎没变"**，估计就**容易得多**——这无疑推动了过去十年 **SLAM（同时定位与建图）** 的革命。

**类比**：相机从"模糊低帧率"变"高清高帧率"，就像监控从"雪花屏一秒一帧"变"4K 六十帧"——**画面越清楚、越连贯，"看出物体在哪、怎么动"就越容易**。

> 有人可能觉得操作最重要的传感器是**触觉**（你也许是对的！）。但**实践中今天的重心是相机/测距**。至少我们该先讲相机，因为**如果不知道"该去摸世界的哪里"，触觉也帮不上忙**。

> 传统相机（输出彩色图像、某帧率）很重要。但机器人**重度使用"显式测距/测深度"的传感器**——有时和彩色一起，有时取代彩色。

### 1.2 对应 4.1.1：深度传感器的种类

> 主要是 **RGB-D 相机**（**ToF 飞行时间** vs **投影纹理立体 projected texture stereo** vs ……）和 **LiDAR**。本课程用的是 **Intel RealSense D415**。还有**单目深度（monocular depth）**、**学习型立体（learned stereo）[1]**。

**类比（四种"量距离"的办法）**：
- **ToF** = 相机**发一束光、计时它反射回来多久** → 算距离（像蝙蝠回声定位，但用光）。
- **投影纹理立体** = 相机**往物体上投一张已知的光点图案**，看图案被物体"扭曲"成啥样 → 三角算距离（像用两只眼睛看，但其中一只眼换成了"投影仪"）。
- **LiDAR** = 旋转激光，**扫一圈得到一圈距离**（自动驾驶车顶那个转的东西）。
- **单目深度 / 学习立体** = **只用一张/两张普通照片，靠神经网络"猜"深度**（[1]）。

### 1.3 对应 4.1.2：仿真相机

> 仿真一个 D415 有**好几个保真度层级**。本章先用**"理想" RGB-D 仿真**——深度图每个像素 = 该像素方向上的**真实几何深度**。在 Drake 里这是 **`RgbdSensor`** 系统，**直接连到 `SceneGraph`**。

端口（PDF 原文框图）：

```
geometry_query → RgbdSensor → color_image
                              → depth_image_32f
                              → depth_image_16u
                              → label_image
                              → X_WB
```

> 这个"信号与系统"抽象**封装了大量复杂度**：它内部是一个**完整渲染引擎**（和高端游戏里的一样）。Drake 支持多个渲染引擎；本课程主要用**基于 OpenGL（built on VTK）的实时渲染器**。Drake 也能接**基于光线追踪的高端 PBR 引擎**（如 Blender 的 **Cycles**，见 Drake-Blender 项目）——**适合渲染高质量图像去训练深度感知系统或做漂亮展示**。

**类比**：`RgbdSensor` = 在游戏世界里**架一台虚拟相机**，游戏引擎负责"画出"它看到的彩色图、深度图、语义标签图。**`X_WB`** = 这台相机**在世界里的位姿**（它装在哪、朝哪）。

### 1.5 对应 4.1.3：传感器噪声与深度丢失

> 真实深度传感器**远不理想**——深度误差**不是简单高斯噪声**，而是**依赖光照、物体表面法向、视觉材质**等。彩色通道也是近似。**即使高端渲染器，也得给场景加足够准确的几何、材质、光源**才能渲染好，而**真实环境的所有细节几乎不可能全捕捉**。我们会在理解一些基本操作后，再看真实传感器数据、以及"建模传感器 vs 真实传感器"的差距。

> **Figure 4.2**：真实深度传感器很乱。**最右图的红像素 = 丢失返回（missed returns）**——深度传感器返回了"最大深度"。**丢失返回，尤其在物体边缘（或反光物体上），是原始深度数据里的常见景象**（图复现自 [2]）。

**类比**：深度相机像"用激光尺量距离"，但**遇到反光玻璃、黑色吸光物、物体边缘**，尺子**量不到**，就**报一个"无穷远"（红像素）**——**这些"洞"是深度图的天生缺陷**。

### 1.6 对应 4.1.4：遮挡与部分视角

> 上面芥末瓶的例子**把相机的第一大挑战暴露得很清楚**：**相机看不到所有东西！它们只有视线（line of sight）**。想看瓶子背面，得**移动相机**；瓶子放在桌上，**想看瓶底就得把它拿起来**。在**杂乱场景**里更糟——瓶子被别的物体挡住。**即使不杂乱，头戴/桌装相机也常被机器人的手挡住**——**偏偏在你最希望传感器表现最好的时刻（伸手去抓时），它给的信息最少！**

> 把深度相机**装在机器人手腕上**能缓解部分视角，但**没完全解决**。所有深度传感器都有**最大和最小量程**。RealSense D415 返回**约 0.3m 到 1.5m** 的匹配。这意味着**接近物体的最后 30cm——又偏偏是你最希望相机表现最好的时刻——物体实际上"消失"了！**

> **Figure 4.3**：当条件允许，我们尽量往环境里**塞尽可能多的相机**。这是 TRI 的**装盘 testbed**，场景里**总共 8 个相机**（**仍然没解决遮挡问题**）。

**类比**：相机像"只能看直线的人"——**手一伸过去挡在眼前，就瞎了**；**而且太近（<30cm）也瞎**。所以**多装几台相机从不同角度看**，但**即便如此也堵不住所有死角**。

## 2. 对应 4.2：几何的表示 —— 同一物体，多种"画法"

> 3D 几何有**很多种表示**，各有适合的计算。常能互相转换，**但转换有时有损**。例子包括：**三角面片网格（triangulated surface meshes）**、**四面体体网格（tetrahedral volumetric meshes）**、**体素/占据栅格（voxel/occupancy grids）**、**隐式表示**（**符号距离函数 SDF**、**神经辐射场 NeRF [3, 4]**——最近作为深度学习 3D 视觉的表示又火起来）。但本章**从深度图和点云开始**。

> 深度相机返回的数据**形如一张图**，每个像素值 = 相机到该像素方向最近物体的**距离**。结合相机**内参（intrinsic，镜头参数，存在 Drake 的 `CameraInfo` 类）**，就能把深度图**变成一组 3D 点**。我用 $s_i$ 表示这些点，因为它们常被称为下面算法里的"**场景点（scene points）**"。这些点**表达在某个参考坐标系**（用刚体变换描述），**可选地附带彩色或其他信息**——这就是**点云表示**。在 Drake 的 `DepthImageToPointCloud` 系统里，**默认坐标系是相机坐标系 $C$**，但系统也接受一个（可选）输入端口，方便把它们变到别的坐标系（如世界坐标系）。

端口（PDF 原文框图）：

```
depth_image → DepthImageToPointCloud → point_cloud
color_image (optional) →
camera_pose (optional) →
```

> 深度传感器如此普及，领域已经攒了一堆**对点云做基本几何操作、并在表示间互转**的库。我们在 Drake 里直接实现了很多基本操作。也有开源工具如 **Open3D**。很多老项目用 **Point Cloud Library (PCL)**——现已停更，但文档仍有用。

> **重要**：深度图转点云**会丢信息**——具体说，丢了"**从相机到这个点的那条射线**"的信息。深度图 + 相机位姿除了说"这有个几何点"，还**隐含"相机到这个点之间的直线是空的（没有几何）"**。我们会在**某些算法**里用到这条信息，所以**别把深度图完全扔掉！** 更一般地，我们会发现**每种几何表示都有强弱**——**很常见的是同时保留多种表示、来回转换**。

**类比（五种"画物体"的方式）**：
- **三角网格** = 用**很多小三角形拼出物体表面**（像 3D 打印模型）。
- **四面体网格** = 把物体**内部也填满小四面体**（实心模型）。
- **体素/占据栅格** = 把空间切成**小立方格**，标记"这格有没有东西"（像 Minecraft）。
- **SDF / NeRF** = **隐式**：不直接画表面，而是给一个函数"空间每点离表面多远/带不带符号"或"每点发什么光"。
- **点云** = **一堆散点**，每个点 = "表面这有个点"。
- **深度图的"额外信息"** = 它不仅告诉你"这有点"，还告诉你"**相机到这点之间是空的**"——**这条'空射线'信息，点云里没有**，所以**别扔深度图**。

## 3. 对应 4.3：已知对应关系的点云配准 —— "拼图块上印了编号"

> 现在开始本章主目标——**我们有已知物体在机器人工作空间某处，从深度相机拿到点云，怎么估计物体位姿 $X_O$？**

> 一个**自然且研究透彻**的 formulation 来自**点云配准（point cloud registration，也叫 point set registration / scan matching）** 文献。给两个点云，配准要找**一个刚体变换，最优地把两个点云对齐**。对我们的目的，这暗示我们的"模型"也该是**点云**（至少暂时）。我们用**模型点列表** $O_{p_{mc_i}}$ 描述物体，其位姿表达在物体坐标系：$^O p_{mc_i}$。

> 第二个点云是**场景点** $s_i$，从深度相机来，经内参变到相机坐标 $^C p_{s_i}$。我用 $N_m, N_s$ 表示模型点和场景点个数。

> **暂时假设我们还知道对应关系（correspondence）**。这合理吗？对**手腕相机**，这相当于**解机械臂的正向运动学**。对环境相机，这相当于**知道相机在世界里的位姿**。**估计这些位姿的小误差，会在估计点云里造成大假象**。所以我们**非常小心地做相机外参标定**（标定代码见附录）。注意**移动操作平台**（臂装在移动底座上）这些讨论仍适用，但你**很可能在机器人坐标系而非世界坐标系里做所有配准**。

> **第二个大假设 = "已知对应"**。我说 correspondence 指：**对场景点云里每个点，能配一个模型点云里的特定点**；比如**每个点有唯一颜色、相机能可靠感知**。这**实践中不合理**，但**帮我们起步**。用对应向量 $c\in[1,N_m]^{N_s}$ 表示：$c_i=j$ 表示场景点 $s_i$ 对应模型点 $m_j$。**注意不假设一一对应**——**每个场景点都对应某个模型点，但反过来不成立**，**多个场景点可对应同一模型点**。

**类比（编号拼图 vs 没编号拼图）**：
- **已知对应** = 拼图块上**印了编号**，你知道"场景第 3 块 = 模型第 7 块"。
- **未知对应**（下一节 ICP）= 没编号，**只能靠"长得像/离得近"猜配对**。
- **不一一对应** = 场景里**好几块都对应模型的同一块**（比如模型上一个大平面，场景里采到它上面好几个点）。

> 于是配准**就成了一个（逆）运动学问题**。我们能把模型点和场景点**写在一个公共坐标系**（这里世界坐标系），**留下唯一未知变换 $X_O$** 去解。上一章我主张用**微分运动学**而非逆运动学；**为什么这里故事不同？** 微分运动学对感知**仍有用**（比如**获取初始位姿后跟踪位姿**）。但**和机器人情况不同**——机器人能读关节传感器拿到当前状态，**而感知里这个"硬问题"至少得解一次**。

> 解长什么样？每个模型点给**三个约束**，当 $N_s$ 远大于位姿决策变量数时，问题**严重过约束**。把每个对应当硬约束也**极易受测量噪声影响**。所以**用最小二乘找"描述数据的位姿"** 更好：

$$\min_{p,R}\ \sum_{i=1}^{N_s}\ \|\,p + R\,^O p_{mc_i} - {}^C p_{s_i}\,\|^2,\quad \text{s.t.}\ R R^T = R^{-1},\ \det(R)=+1 \qquad (1)$$

> 这里用**旋转矩阵**表示位姿；下面方法在**四元数**形式下也有等价 [5]。要把优化写成"用旋转矩阵系数 + 平移作决策变量"，需要这些约束，因为**不是每个 3×3 矩阵都是合法旋转矩阵**；满足这些约束保证 $R$ 合法。事实上 $\det(R)=\pm1$ 几乎够了；满足 $RR^T=I$ 但 $\det(R)=-1$ 的矩阵叫 **"improper rotation"（瑕旋转）** = 旋转 + 绕旋转轴的反射。

**类比（旋转矩阵的"身份证"**）：
- 一个 3×3 矩阵**长得像旋转**还不够，得验两件事：① 列互相垂直且单位长（$RR^T=I$）；② **不是"镜像"**（$\det=+1$ 而非 $-1$）。
- $\det=-1$ = **旋转里偷偷夹了一次"照镜子翻转"**——物理上做不到，要排除。

### 3.1 对应 Example 4.2（2D 仅旋转配准 = Wahba 问题）

> 我想让你对这个优化有**图形直觉**，但 9+3 个决策变量很难画目标函数。所以**砍到本质**：考虑**场景点和模型点只差一个旋转**（这就是著名的 **Wahba 问题**）。进一步简化，**在 2D 而非 3D**。

> 2D 里我们其实能**用两个变量线性参数化旋转矩阵**：

$$R=\begin{bmatrix}a & -b\\ b & a\end{bmatrix},\quad RR^T=I \Rightarrow a^2+b^2=1$$

> **Figure 4.4**：此图 $x,y$ 轴对应参数 $a,b$，定义 2D 旋转矩阵 $R$。**绿色二次碗** = 目标函数，**红色开圆柱** = 旋转矩阵约束。

> 这是你期望的吗？我**只用两个模型/场景点**生成此图，但**加更多点只会改变二次碗的形状，不改变它的最小值**。交互版里我加了滑块控制 ground-truth 旋转 $\theta$。

**类比**：2D 旋转 = 单位圆上的一个点 $(a,b)$（因为 $a^2+b^2=1$）。**目标函数是个碗**，**约束是"必须在圆上"**，所以**最优解 = 碗底投影到圆上的点**。点越多碗越"尖"，但最小值不变。

### 3.2 平移与旋转解耦 —— 用"质心"消掉平移

> 平移呢？有一个**超级重要的洞察**，让我们能**把旋转优化和平移优化解耦**：**点之间的相对位置受旋转影响，但不受平移影响**。所以**把点相对物体上某个"标准点"写**，就能**单独解旋转**。一旦有了旋转，**平移很容易反推**。对我们的最小二乘目标，甚至有个"**正确的**"标准点——**欧氏度量下的中心点（center of mass，若所有点等质量）**。

> 因此求解 (1)：**先定义中心模型点和中心场景点**：

$$^O p_{m\bar{}} = \frac{1}{N_s}\sum_{i=1}^{N_s}\,^O p_{mc_i},\qquad p_{s\bar{}} = \frac{1}{N_s}\sum_{i=1}^{N_s}\,p_{s_i}$$

> 用 SVD 算 $R^*$，再反推 $p^*$。

**类比（先各自"归零"再比旋转）**：
- 两堆点，一堆是模型、一堆是场景。**先把每堆各自平移到自己的中心**（减去质心），**这样"平移差异"就被消掉了**，**剩下的纯是旋转差异**——**先解旋转**。
- 旋转解出来后，**平移 = 场景中心 − 旋转后的模型中心**——**一步反推**。

### 3.3 SVD 解 —— 一步算出最佳旋转

> 为找 $R$，**组合数据矩阵**：

$$W = \sum_{i=1}^{N_s}\ (p_{s_i} - p_{s\bar{}})\,(^O p_{mc_i} - {}^O p_{m\bar{}})^T$$

> 用 SVD 算 $W = U\Sigma V^T$。最优解：

$$R^* = U D V^T,\quad p^* = p_{s\bar{}} - R^*\,^O p_{m\bar{}}$$

> 其中 $D$ 是对角矩阵，对角元 $[1,1,\det(UV^T)]$ [6]。这看起来像魔法，但**把 SVD 的奇异值换成 1，等于"最优投影回正交矩阵"**，而对角矩阵**保证我们不拿到瑕旋转**。

**类比（SVD = "找最佳对齐方向"**）：
- $W$ 编码了"场景点云和模型点云**怎么协变**"。
- SVD 把 $W$ 拆成"方向 × 拉伸 × 方向"。
- **把中间的"拉伸"全设成 1**（因为我们只要旋转、不要拉伸），**再补一个 $\det$ 修正防镜像** → 得到**最佳旋转**。
- 这"看起来像魔法"，本质是：**在所有正交矩阵里，找最接近 $W$ 的那个**——SVD 给闭式解。

> 文献里有很多推导，但**很多直接丢掉了行列式约束、没处理瑕旋转**。见 [7]（Haralick89，section 3）是我早期的最爱之一。

### 3.4 对应 Example 4.3（已知对应的点云配准）

> 例子里我**用随机点做了个随机物体**，用随机 2D 变换扰动它。**蓝点** = 模型坐标的模型点，**红点** = 场景点，**绿虚线** = （完美）对应。右边我**用估计位姿把两者都画到世界坐标系**。如预期，**算法完美恢复 ground-truth 变换**。

> **要理解的重点**：**一旦对应给定，我们就有一个高效、鲁棒的数值解去估计位姿**。

### 🧪 代码 1：SVD 配准（已知对应，2D/3D，可跑）

> 这段**纯 numpy**，复现 4.3 的 SVD 解，**验证完美恢复 ground-truth**。

```python
import numpy as np
rng = np.random.default_rng(0)
# 真变换: 旋转 R_gt + 平移 p_gt
ang = 0.7; R_gt = np.array([[np.cos(ang),-np.sin(ang)],[np.sin(ang),np.cos(ang)]])
p_gt = np.array([0.3, -0.2])
# 随机模型点 (2D), 加少量噪声生成场景点
M = rng.uniform(-1,1,(40,2))
S = (R_gt @ M.T).T + p_gt + 0.01*rng.randn(*M.shape)   # 已知对应: S[i] 对应 M[i]
# 中心点
Mc = M.mean(0); Sc = S.mean(0)
# 数据矩阵 W
W = (S - Sc).T @ (M - Mc)
U, s, Vt = np.linalg.svd(W)
D = np.diag([1, np.linalg.det(U @ Vt)])          # 防瑕旋转
R_est = U @ D @ Vt
p_est = Sc - R_est @ Mc
print("R 误差 Frobenius = %.2e" % np.linalg.norm(R_est-R_gt))
print("p 误差 = %.2e" % np.linalg.norm(p_est-p_gt))
# 3D 同理: D = diag([1,1,det(U@Vt)])
```

**你会看到**：$R,p$ 误差**接近机器精度**——**已知对应时 SVD 一步完美对齐**。这就是 4.3 的"高效鲁棒数值解"。

## 4. 对应 4.4：迭代最近点 ICP —— "没编号，反复找最近配对"

> 那**怎么得到对应**？事实上**如果给了物体位姿，求对应其实很容易**：模型上的对应点 = **变到公共坐标系后离场景点最近的点（最近邻 / closest point）**。

> 这暗示一个**自然迭代方案**：**从某个位姿初猜开始，用最近点算对应，再用这些对应更新估计位姿**。这就是**著名且常用（尽管有已知局限）的 ICP 算法**。

> 精确说，用 $\hat X_O$ 表示位姿估计，$\hat c$ 表示估计对应。"最近点"步：

$$\forall i,\quad \hat c_i = \arg\min_{j\in N_m}\ \|\,\hat X_O\,^O p_{m_j} - p_{s_i}\,\|^2$$

> 即找**变到公共坐标系后离变换后场景点欧氏最近的模型点**。这是著名的**最近邻问题**，我们有好的数值解（用优化数据结构），比如 Open3D 用 **FLANN [8]**。

> **联合求解位姿和对应很难**，但 ICP 利用"**分开解，两部分都有好解**"。这类迭代算法是优化里处理**双线性优化 / 期望最大化（EM）** 的常见套路。**要理解：这是非凸优化的局部解**，所以**会陷入局部极小**。

**类比（ICP = 反复"找最近 + 对齐"**）：
- 没编号的拼图，你**先随便摆个位置**，然后**给每块找"目前离它最近的"配对**，**按这些配对把拼图挪正一点**，**再重新找最近配对**，**再挪**……**反复迭代直到不动**。
- **缺陷**：一开始摆得太歪，**"最近配对"全配错**，于是**越挪越歪，卡在一个错的局部位置**——**局部极小**。

> 对这些局部极小的直觉**催生了一系列 ICP 变体**：**point-to-plane ICP、normal ICP、用颜色信息的 ICP、基于特征的 ICP** 等。一个**基于"点对特征（point-pair features）"** 的变体**在（几乎）年度物体位姿估计挑战里非常有效 [9, 10]**。

- **点到点 ICP** = "把对应点**点对点**拉近"。
- **点到面 ICP** = "把场景点**滑到模型表面上**"（不只拉到对应点，而是拉到对应点所在的**切平面**上）——**对平面/光滑表面更稳**。
- **加颜色/特征** = "配对时不只看位置，还看'颜色/局部形状像不像'"——**减少配错**。

### 5.2 对应 4.5.1：检测离群点

> 一旦有了**合理估计**，**检测离群点很直接**：每个场景点按"它和对应模型点的（平方）距离"对目标贡献一项。**距离大的场景点可标为离群点、从点云移除**，从而**没有这些干扰地精修位姿**。你会发现很多 ICP 实现（如 Open3D 这个）带 **"maximum correspondence distance"** 参数干这事。

> 这留下一个"**鸡生蛋**"问题——**需要合理位姿估计才能检测离群点，但点云很脏时可能很难在有离群点的情况下得到合理估计**。那从哪开始？一个**传统上配 ICP 用的常见方法** = **RANSAC（RANdom SAmple Consensus）[11]**。RANSAC 里我们**选若干随机（通常很小）的"种子"点子集**，**对每个算位姿估计**。**"内点（inliers）"最多**（低于最大对应距离的点数最多）的子集**被视为赢家**，**用来启动 ICP**。

**类比（RANSAC = 投票找共识）**：
- 拼图混进别家碎片（离群点）。你**随机抓 3 块试拼**，**看按这 3 块拼好后，剩下有多少块"也对得上"（内点）**。
- **重复很多次**，**哪次"对得上的"最多，就用那次的拼法当起点**，**再交给 ICP 精修**。
- **离群点永远不会"凑巧"凑出多数共识**，所以**赢家组大概率是真碎片**。

> 还有**另一个重要聪明的想法**。记住那个重要观察：**我们能解耦旋转和平移，靠的是"点间相对位置对旋转不变、对平移不变"**。可以**再进一步**：**点间相对距离对旋转和平移都不变**。这传统上用来**把尺度估计和旋转平移估计分开**（本章忽略尺度，因为它对我们的问题没直接意义）。在 [12] 他们提出**这也能用来在拿到初始位姿估计之前就剪掉离群点**。**如果场景里一对点的距离，和模型里任何一对点的距离都不像，那这两点里有一个是离群点**。用这个度量找**最大内点集** = 在图里找**最大团（maximum clique）**；可以对"最大团就是最佳匹配"做强假设，或承认这可能是个有用启发式。**如果大点云找最大团太贵，可用保守近似**。

### 5.3 对应 Example 4.6（对应图里的最大团）

> 这是 [12] 最大团想法的简单例子，我和作者 Hank 一起推过以确保我理解。

> **模型**（左）= 简单三角形，顶点标 $[A,B,C]$。**场景**（右）= 同一三角形，点标 $[a,b,c]$（恰好三对距离）。但它**还有一个金字塔**，会**额外产生六对距离匹配**（三个长 3、三个长 4）。**金字塔上的假对应会不会造成比 ground-truth 对应 $[A-a,B-b,C-c]$ 三角形更大的团？**

> 用**全对应**当初始猜测，**构造成对距离图**。图里**每个可能对应**有一个节点，如 $A-e$ 表示模型点 $A$ 可能对应场景点 $e$。然后在 $(A-e)$ 和 $(B-f)$ 之间连边 **当且仅当** $A,B$ 间距离 = $e,f$ 间距离。

> 现在检查团的价值就清楚了。**涉及金字塔对应的最大团只有大小 2**，但**场景三角形的最大团是大小 3**（我标红了）。所以**这个例子里最大团确实恢复了 ground-truth 对应**。

**类比（最大团 = "互相都吻合的最大一伙"**）：
- 图里每个节点 = "一个猜测配对"。两节点连边 = "这两个配对**互相不矛盾**"（距离对得上）。
- **团** = 一伙**两两都不矛盾**的配对。
- **最大团** = **最大的"互相吻合"团伙** = **最可能的真对应集合**。
- 金字塔的假配对**互相之间距离对不上模型**，所以**凑不成大团**——**最大团赢的是真三角形**。

> 这是"去除离群点的算法/启发式动物园"里的两个例子。再提一个 [9]：**用基于点对特征的优化投票/聚类方案**，他们做得**极高效**，**多年在在线位姿估计基准里表现很好**。

### 5.4 对应 4.5.2：点云分割

> 不是所有离群点都来自深度相机的坏返回，**很多时候来自场景里别的物体**。即使最基本的情况，**我们感兴趣的物体也放在桌上或箱子里**。如果**先验知道桌/箱的几何**，就能**减去那个区域的点**。或者**裁剪（crop）点云到感兴趣区域**。这对**非常简单或不杂乱的场景**够了，**对本章目标也刚好够**。

> 更一般地，**场景里多个物体**，我们可能仍想找感兴趣物体（芥末瓶？）。**如果真有鲁棒的点云配准算法**，可以想象**最优配准能让我们把模型点对应到场景点的子集**；**点云配准就能解物体检测问题！** 可惜**我们的算法还不够强**。

> **Figure 4.12**：来自 LabelFusion [13] 的多物体场景。

> 于是我们**几乎总用别的算法先"分割"场景成若干可能物体**，**再对每段独立配准**。有很多**几何分割方法 [14]**。但**如今我们倾向用神经网络做分割**，所以细节我不展开。

**类比（分割 = 先把桌上东西"一件件分开"**）：
- 配准假设"点云里就一个目标物体"。但桌上还有桌子、别的瓶子。
- **分割** = 先**用算法/神经网络把点云切成"这是桌子、这是瓶子 A、这是瓶子 B"**，**再对每块单独配准**。

### 5.5 对应 4.5.3：泛化对应

> 场景里的离群点或多物体**挑战了我们 finora 的对应方法**。 finora 我们用 $c_i$ 表示**每个场景点对应一个模型点**。但**注意算法的不对称**（场景 → 模型）。我选这个方向是因为**开篇芥末瓶的部分视角动机**。**一旦开始考虑桌上桌子等物体，也许我们本该做模型 → 场景？** 你该自己验证这对 ICP 只是小改动。**但如果有多个物体 + 部分视角呢？**

> **允许 $c_i$ 取一个特殊值"无对应（no correspondence）"** 就**够了**，确实有帮助。那种情况下我们**希望最优时**：对应感兴趣模型的场景点**映射到各自模型点**，**而来自离群点和其他物体的场景点**被标为"无对应"。**没被遮挡的物体部分的模型点**就**没有任何对应**关联。

> 还有**另一种稍更一般的记号**。用**对应矩阵** $C\in\{0,1\}^{N_s\times N_m}$，$C_{ij}=1$ 当且仅当场景点 $i$ 对应模型点 $j$。用这记号，**估计步（给定已知对应）** 写成：

$$\min_{X\in SE(3)}\ \sum_{i=1}^{N_s}\sum_{j=1}^{N_m}\ C_{ij}\,\|\,X\,^O p_{m_j} - p_{s_i}\,\|^2$$

> 这**包含**了我们之前的方法：若 $c_i=j$，则设 $C_{ij}=1$、该行其余为 0。若场景点 $i$ 是离群点，则**整行设 0**。之前的记号是"最近点"计算真正不对称性的更紧凑表示，**也清楚表明我们只需算距离**。但**这个更一般的记号会带我们到下一轮**。

### 5.6 对应 4.5.4：软对应（Coherent Point Drift / CPD）

> 如果**放松严格的二值对应**，把它们想成**对应权重**而非 $\{0,1\}$ 呢？这是 **"coherent point drift"（CPD）算法 [15]** 的主意。读 CPD 文献你会沉浸在一个**用高斯混合模型（GMM）作表示的概率论述**里。概率论述有用，但**别让它把你绕晕**；**相信我，它是一回事**。要最大化高斯的似然，**第一步几乎总是取 $\log$**（因为它是单调函数），**这把你直接带回我们的二次目标**。

> 概率论述确实给了一种**在算法每次迭代设对应权重的自然机制**，把它们想成"场景点给定模型点的概率"：

$$C_{ij} = \frac{1}{a_i}\exp\!\left(-\frac{\|\,X_O\,^O p_{m_j} - p_{s_i}\,\|^2}{2\sigma^2}\right) \qquad (4)$$

> 这是高斯的标准密度函数，$\sigma$ 是标准差，$a_i$ 是**让概率和为 1 的归一化常数**。把**离群点概率**编码进这个 formulation 也很自然（**它只修改归一化常数**）。

> CPD 算法现在**和 ICP 非常像**，**在"分配对应权重"和"更新位姿估计"之间交替**。**位姿估计步**和上面几乎一样，**"中心点"现在是**：

$$^O p_{m\bar{}} = \frac{1}{N_C}\sum_{i,j} C_{ij}\,^O p_{m_j},\quad p_{s\bar{}} = \frac{1}{N_C}\sum_{i,j} C_{ij}\,p_{s_i},\quad N_C=\sum_{i,j}C_{ij}$$

> 数据矩阵现在是：

$$W = \sum_{i,j} C_{ij}\,(p_{s_i}-p_{s\bar{}})\,(^O p_{m_j}-{}^O p_{m\bar{}})^T$$

> 其余更新（用 SVD 提 $R$、给定 $R$ 解 $p$）**相同**。代码里你看不到显式求和，因为**把点收进矩阵（每列一个点）后每步都有特别漂亮的矩阵形式**。

> 街上的说法是 **CPD 比"硬对应 + 二次目标"的 ICP 鲁棒得多**；**高斯模型通过把离群点对应权重设到近零来减轻离群点影响**。但**对大点云算所有成对距离也更贵**。在 [16] 我们指出**一个小 reformulation**（把场景点想成"在空间里经高斯分布"，而非"围绕模型点的高斯"）**能让我们回到只对场景点求和**。**它享受 CPD 的很多鲁棒性好处，也有 ICP 类算法的性能**。

**类比（硬对应 vs 软对应）**：
- **ICP 硬对应** = "每块拼图**只能配一块**，配错了就全错"。
- **CPD 软对应** = "每块拼图**对所有模型块都有一个'像不像'的权重**，越像权重越大"——**离群点对所有模型块都'不像'，权重自动近零**，**等于自动被忽略**。
- **代价** = 要算**所有成对距离**（$N_s\times N_m$），**大点云贵**。[16] FilterReg 的 trick = **换个角度看高斯**，**把求和从"成对"降回"只对场景点"**。

### 5.7 对应 4.5.5：非线性优化

> 我们 finora 讨论的所有算法**都利用"给定对应时用 SVD 解位姿估计"，并在"估计对应"和"估计位姿"之间交替**。还有**另一类重要算法**：**同时解两者**。这让优化**非凸**，暗示**仍会像迭代算法那样受局部极小之苦**。但**很多作者主张非线性求解器的求解时间能和迭代算法持平**（如 [17]）。

> **Figure 4.13**：鲁棒配准的多种目标函数。

> 用非线性优化的**另一大优势**：这些求解器能**容纳多种目标函数**，达到和 CPD 类似的**对离群点鲁棒性**。我画了几个流行目标函数。**这些函数的主要特征是它们 taper（渐平）**，所以**更大的距离最终不会带来更高的代价**。

> **重要**：和 CPD 一样，这意味着我们**能在目标里考虑所有成对距离**，因为**如果离群点给代价加一个常数（如 1），它们对决策变量就没有梯度、对最优解没有影响**。于是我们可以写，对我们喜欢的损失函数 $\ell$，目标形如：

$$\min\ \sum_{i,j}\ \left[\ell\!\left(\|\,X_O\,^O p_{m_j} - p_{s_i}\,\|\right)\right]$$

> 决策变量是什么？我们也能**利用求解器的额外灵活性用最小参数化**——如 2D 用 $\theta$，或 3D 用欧拉角。**目标函数更复杂，但能去掉约束**。

### 5.8 对应 Example 4.7（已知对应的非线性位姿估计）

> 为精确理解我们放弃了什么，考虑一个**热身问题**：用非线性优化 + 最小参数化做位姿估计。**只要不加任何约束，我们仍能分离旋转和平移的解**。所以考虑问题：

$$\min_\theta\ \sum_j\ \left[\ell\!\left(\left\|\begin{bmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{bmatrix}{}^O p_{mc_j} - (p_{s_j}-p_{s\bar{}})\right\|\right)\right]$$

> 我们现在有一个**复杂、非线性的目标函数**。**我们引入局部极小了吗？**

> 作为思想实验，考虑**所有模型点都在一个完美圆上**的问题。对任何一个场景点，在仅旋转优化里，**最坏情况是我们的估计 $\theta$ 离最优解 180 度**。该点代价 = $4r^2$，$r$ 是圆半径。事实上**用余弦定理**，我们能写出**任意误差 $\theta_{err}=\theta-\theta^*$ 下该点的平方距离**：

$$\text{distance}^2 = r^2 + r^2 - 2r^2\cos\theta_{err}$$

> 圆的情况下**每个其他模型点贡献相同代价**。**这不凸**，但**每个极小都是全局最优解**（只是被 $2\pi$ 包裹）。

> 事实上**即使更复杂、非圆几何，同样论证成立**。每个点绕圆转时都会产生误差，但**半径可能不同**。**所有模型点的误差随 $\cos\theta_{err}\to 1$ 而减小**。所以**每个极小都是全局最优解**。**我们其实还没引入局部极小（yet）！**

> **真正引入局部极小的是对应，以及我们可能加的其他约束**。

**预计算距离函数**

> 有一个**特别漂亮的 trick** 能加速这些非线性优化的计算，但**确实要求我们回到"想场景点到模型的最小距离"**（而非点对距离）。我觉得**现在这不算是大牺牲**，因为我们已经停止显式枚举对应。稍微修改上面的目标成：

$$\min\ \sum_i\ \left[\ell\!\left(\min_j\ \|\,X_O\,^O p_{m_j} - p_{s_i}\,\|\right)\right]$$

> 即**对每个场景点，取它到任何模型点的最小距离**，再套鲁棒损失。

> 嵌套函数从计算角度**看着有点吓人**。但这种形式 + **我们应用里模型点固定** 的事实，**实际上让我们能做一些预计算让在线步变快**。首先**把优化移到模型坐标系**，把内层项改成 $\min_j\|^O p_{m_j} - {}^O X_W\,p_{s_i}\|$。

> 现在意识到**对任何 3D 点，我们能预计算它到模型上任何点的最小距离**，记为 $\phi(x)$。上面的项**就是** $\phi(^O X_W\,p_{s_i})$。这个 3D 空间的函数，有时叫**距离场（distance field）**，密切相关的**符号距离函数（SDF）** 和 **level sets** 是几何建模里的常见表示。**它们正是我们快速算很多场景点代价所需要的**。

> **Figure 4.14**：我们矩形点表示的距离函数等高线（左），和我们"基于网格" 2D 矩形的 SDF（右）。**基于网格表示里更平滑的距离等高线能缓解上面观察到的一些局部极小问题**。

> **Figure 4.15**：3D 几何的 SDF 表示可视化（经 [3] 许可复现）。

> 如上图所示，我们能用**预计算距离函数表示到网格模型的最小距离**（而非只点云）。**小心一点**，我们能在 3D 空间定义**替代的"类距离"函数**，**带平滑次梯度**，**和非线性优化配合得更好**。这个课题文献丰富；见 [18] 是个好参考。

**类比（距离场 = "海拔地图带正负号"**）：
- **SDF** = 空间每点一个数：**外面正、表面零、里面负**，**绝对值 = 离表面多远**。
- **预计算** = **事先把整张"海拔地图"算好存起来**。
- 在线时，**每个场景点"查地图"就知道离模型多远**，**不用每次重新算最近点**——**快**。
- **基于网格的 SDF 等高线更平滑** → **优化器的"坡度"更顺** → **更少卡局部极小**。

### 5.9 对应 4.5.6：全局优化

> 有没有希望**利用我们在"已知对应配准"里发现的漂亮结构**，用**同时搜对应和位姿**的算法？

> 有些算法**声称对 ICP 目标全局最优**，**通常用 branch and bound 策略 [19, 20, 21]**，但**我们对它们在真实点云上的性能失望**。我们**提了另一个**：**用 branch and bound 显式枚举对应**，配**截断最小二乘目标** + **$SE(3)$ 约束的紧松弛 [22]**，但**这方法仍限于相对小的问题**。

> 近来工作 **TEASER [12]** 走**不同路线**，**用观察"截断最小二乘对尺度和平移能高效优化"**。对旋转，他们**解截断最小二乘目标的半定（SDP）松弛**。这松弛**不保证紧**，但（像本章所有凸松弛）**事后很容易验证最优解是否满足原约束**。而且**二次旋转矩阵约束的 SDP 松弛可以出奇地有效 [23]！**

**类比（全局优化的两种思路）**：
- **branch and bound** = "**系统地试所有可能，但用'下界'剪掉不可能最优的分支**"——**保证全局最优，但真实点云上太慢**。
- **TEASER** = "**先不管旋转，把尺度和平移精确解了；旋转用一个'凸近似'（SDP 松弛）解**"——**不保证紧，但事后能验证、且 SDP 松弛常常出奇地紧**。

## 6. 对应 4.6：非穿透与"自由空间"约束 —— "物体不能穿进桌子"

> 我们探索了位姿估计的两条主线——**一条基于漂亮 SVD 解，一条基于非线性优化**。下面会看到，**非穿透和自由空间约束在多数情况下是非凸约束**，所以**和非线性优化更配**。但**有些凸非穿透约束的例子**（如点不能穿透半平面），**能加进我们的凸优化方法**。两种版本我都用简单例子说明。

### 6.1 对应 Example 4.8（非线性优化的非穿透）

> 为简单，我**限制到 2D**，用参数化旋转矩阵：

$$R(\theta)=\begin{bmatrix}\cos\theta & -\sin\theta\\ \sin\theta & \cos\theta\end{bmatrix}$$

> **已知对应**求解。请记住**我们也能把对应搜索加进非线性优化框架**。

> 解以下优化：

$$\min_{p,\theta}\ \sum_i\ \|\,p + R(\theta)\,^O p_{mc_i} - p_{s_i}\,\|^2,\quad \text{s.t.}\ ^W p_{m_i} \ge 0,\ \forall i\in[1,N_m]$$

> 为加非线性代价和约束，我们**把一个 python 函数和要绑定的决策变量**传给 `MathematicalProgram` 的 `AddCost` 和 `AddConstraint` 方法。我在这个 notebook 提供了实现。

> **Figure 4.16**：带约束位姿估计问题的解。**我加了约束：估计位姿里所有点的 $x,y$ 在世界坐标系必须大于 0**（绿线所示）。**红场景点在穿透**，但**求解器返回蓝位姿，满足约束**。

**类比（非穿透 = "物体不能穿墙"**）：
- 配准时**模型点可能"穿进墙里"**（估计位姿让模型点坐标 < 0）。
- 加约束 $^W p_{m_i}\ge 0$ = "**每个模型点都必须在墙这边**"。
- 求解器**宁可让配准误差大一点，也不让物体穿墙**。

### 6.2 对应 Example 4.9（凸优化的非穿透）

> 对这个 2D 例子的**凸参数化旋转矩阵**，我们能利用旋转矩阵的方便形式：

$$R=\begin{bmatrix}a & -b\\ b & a\end{bmatrix},\quad a^2+b^2=1$$

> 这些是**非凸约束**，但**能松弛成** $a^2+b^2\le 1$。这**几乎正是**我们早前可视化的例子，**只是这里加了平移**。基于那张可视化，我们有理由**乐观单位圆盘松弛可能紧**。

> 解以下优化：

$$\min_{p,a,b}\ \sum_i\ \|\,p + R\,^O p_{mc_i} - p_{s_i}\,\|^2,\quad \text{s.t.}\ a^2+b^2\le 1,\quad ^W p_{m_i}\ge 0,\ \forall i\in[1,N_m]$$

> 其中 $R$ 依赖 $a,b$ 如上。正如上一章加约束**迫使**我们从伪逆解转到**基于数值优化的解**，**这问题的解也不再由 SVD 简单给出**。如 formulated，这优化属于 **二阶锥规划（SOCP）** 类，但**需用一个松弛变量放进"线性目标"的标准形式**。

> **请小心**。现在有了一个**依赖 $R$ 的约束**，**我们原来"独立解 $R$"的方法不再有效**（至少不修改不行）。我在 notebook 提供了简单实现。

> **Figure 4.17**：带约束位姿估计问题的凸近似。**我加了同样的 $x,y>0$ 约束**（绿线）。

> 这是**稍微夸张的情况**，场景点**真的把盒子往约束里拉**。我们能看到**这情况松弛不紧**；**盒子被稍微缩小以解释数据**。

> 这类约束优化**能做得相对高效**，**适合在 ICP 循环里用于中等大小点云**。但**主要局限**：我们**只能对凸非穿透约束（或约束的凸近似）这么做**，如这里用的"半平面"约束。**它大概不适合场景里两物体间的非穿透**。

**类比（凸松弛 = "把圆环放宽成圆盘"**）：
- 旋转约束 $a^2+b^2=1$ = "**必须在圆周上**"（非凸）。
- 松弛 $a^2+b^2\le 1$ = "**可以在圆盘里**"（凸）。
- **常常最优解仍在圆周上（紧）**，但**极端情况**（场景点把物体往约束里拽）**松弛不紧** → **求解器"作弊"把物体缩小一点**来满足约束。

### 6.3 对应 4.6.1：自由空间约束作为非穿透约束

> 还有**另一个漂亮想法**，我第一次在 [24] 看到……

> **Figure 4.18**：从相机到深度返回**投射的射线**定义了一个"**自由空间障碍**"，**其他物体不应穿透**。

**类比（自由空间 = "相机到物体之间的空气是空的"**）：
- 深度相机说"这方向 1 米处有个点"，**隐含"相机到 1 米之间是空的"**。
- 这条"空射线"扫出的区域 = **自由空间**。
- **别的物体（或估计位姿下的模型）不能占这块空**——**否则就和"相机看得到"矛盾**。
- 这又是一种**非穿透约束**，但**约束的是"自由空间"而非"桌子"**。

> 最终，**尽管我更偏爱带"更深理解（对我们）和更强保证（对算法）"潜力的凸 formulation**，**加非穿透和自由空间约束的能力实在太有价值，不能忽略**。**深度学习方法现在常能提供一个好初猜**，**能缓解一些对局部极小的担忧**。**我希望一两年后回来时，能报告我们对这些更复杂 formulation 有了强结果**。但**目前，多数应用里我会引导你用非线性优化方法、并利用这些约束**。

## 9. 对应 4.9：展望（LOOKING AHEAD）

> 尽管我**非常欣赏能严格思考这些几何方法的能力**，我们**需要批判地思考我们是否在解对的目标**。

> 即使**留在纯几何领域**，也**不清楚"等权重的最小二乘目标"是否正确**。想象**一本又高又瘦的书平放在桌上**——**我们可能只从书脊边缘得到很少返回**，但**这些返回包含的信息，按比例远多于我们从书封面得到的一大堆返回**。**把相对权重加进估计目标没问题**，但我们**还没有很成功的、基于几何的算法去一般地决定这些权重该是什么**。（这个方向有很多研究，但是个硬问题。）

**类比（信息密度不均）**：
- 书封面采到 1000 个点，但**它们几乎共面，信息量低**；书脊只采到 10 个点，但**它们决定了书的朝向，信息量高**。
- **等权重最小二乘** = "**1000 个低信息点压过 10 个高信息点**" → **朝向估不准**。
- **理想** = **给高信息点更大权重**——**但"一般地自动决定权重"还没解决好**。

> **但请意识到**，**尽管几何很美**，我们 finora **几乎完全忽略了最重要的信息：彩色值！** 虽然**能把彩色和其他特征放进 ICP 式流水线**，但**在彩色空间写一个简单距离度量很难**（**同一物体在不同光照下原始彩色值可能很不同，不同物体的彩色值可能看起来很像**）。**计算机视觉的进步，尤其近几年的深度学习，给这个问题注入了新生命**。**当我最近问学生"如果必须放弃一个通道，深度还是彩色，你放弃哪个？"答案是响亮的"我放弃深度；别拿走我的彩色！"** 这是**和几年前相比的大变化**。**就在 2019 年，在 6D 物体位姿估计基准（几乎年度竞赛）里，几何位姿估计仍胜过深度学习方法 [10]**。但**到 2020 版挑战，深度学习追平了**。

> **但深度学习和几何能（应该？）很好地配合**。**2020 版物体位姿估计挑战的赢家**用**深度学习做位姿初猜**，但**仍用几何感知（ICP 的一个变体）和深度通道精修估计 [10]**。**另一个例子**：**识别点云间对应**是本章一大主题——**我们还没完全解决它**。这是**彩色值和深度学习能提供很多的众多地方之一 [25]**。**我们很快会转向它们！**

**类比（几何 + 深度学习 = 初猜 + 精修）**：
- **深度学习** = "**一眼看出物体大概在哪、朝哪**"（快、对彩色鲁棒、给初猜）。
- **几何（ICP + 深度）** = "**在这个初猜上精细对齐**"（准、有几何保证）。
- **赢家 = 两者结合**。
- **学生"放弃深度保留彩色"** = 因为**彩色 + 深度学习现在太强**，**深度反而可由几何/学习补**——**风向变了**。

## 10. 对应 4.10：练习（EXERCISES）—— 逐题通俗讲解 + 可跑代码

### 练习 4.1（你需要多少个点？）

> 考虑**已知对应的点云配准**。点能直接映射到对应模型点以指定物体在场景里的位置和朝向。**多数情况我们的点远多于物体位姿的决策变量**。因此**把每个对应当等式约束会让问题过约束**。这引出一个自然问题：

> **a.** 在 **2D** 唯一指定物体位姿的**最少点数**？给简短理由。
> **b.** 在 **3D** 唯一指定物体位姿的**最少点数**？给简短理由。
> （提示：如果点对应未知，你的答案会怎么变？）

**通俗讲解 + 答案**：
- **2D 位姿** = 3 个自由度（$x,y,\theta$）。**每个对应点给 2 个方程**（$x,y$ 两个坐标约束）。所以**最少 $\lceil 3/2\rceil = 2$ 个点**（2 点给 4 方程 ≥ 3 未知，且一般不退化）。**但**要"唯一"且非退化，**2 点通常够**（两点定平移 + 旋转）。
- **3D 位姿** = 6 个自由度（3 平移 + 3 旋转）。**每个对应点给 3 个方程**。所以**最少 $\lceil 6/3\rceil = 3$ 个点**——**但 3 点共线会退化**，所以**一般要 3 个不共线点**（实践中常说 3 点，但为鲁棒唯一性常要更多/非共面）。
- **对应未知时**：点数要**多得多**，因为还要"猜对应"，且要排除对称/退化——**这就是为什么 ICP/RANSAC 需要一堆点**。

**类比**：**2D 拼图**，**2 块带编号的就够定位整张图**；**3D**，**3 块不共线的就够**。**没编号时**，**你得用很多块去"投票"猜对应**。

### 练习 4.2（旋转对称性）

> 我们对已知对应的点云配准有一个漂亮 formulation——**二次目标 +（松弛行列式约束后）二次等式约束**。有时物体**旋转对称**——想一个**完美立方体**的盒子。**二次目标怎么能捕捉"旋转 90 度同样好"的问题？**

**通俗讲解**：
- 立方体**转 90 度看起来一样**，所以**有 4 个（2D 投影）或 24 个（3D）同样好的位姿**。
- **二次目标** = 一个碗，但**对称物体让目标函数有"多个一样深的碗底"**（多个全局极小，旋转 90 度一个）。
- **优化器会收敛到其中一个**——**都对**。
- **这提醒**：**对称物体的位姿"不唯一"**，**配准/抓取时要意识到"转 90 度也行"**（第 3 章抓砖也提过旋转对称）。

### 练习 4.3（随机初始化的 ICP）

### 🧪 代码 2：ICP + 多随机旋转初猜（可跑，对应练习 4.3 + Example 4.4）

```python
import numpy as np
rng = np.random.default_rng(2)
ang_gt = 1.2; R_gt = np.array([[np.cos(ang_gt),-np.sin(ang_gt)],[np.sin(ang_gt),np.cos(ang_gt)]])
p_gt = np.array([0.2,-0.1])
M = rng.uniform(-1,1,(60,2))
S = (R_gt@M.T).T + p_gt + 0.005*rng.randn(*M.shape)
def icp(R0,p0,iters=30):
    R,p = R0.copy(), p0.copy()
    for _ in range(iters):
        # 最近邻对应
        Tm = (R@M.T).T + p
        d = S[:,None,:] - Tm[None,:,:]            # (Ns,Nm,2)
        c = np.argmin(np.sum(d**2,2),1)           # 每个场景点的最近模型点
        Mc = M[c]; 
        # SVD 解 R (已知对应子问题), 用中心化
        mcc=Mc.mean(0); sc=S.mean(0)
        W=(S-sc).T@(Mc-mcc); U,s,Vt=np.linalg.svd(W)
        R = U@np.diag([1,np.linalg.det(U@Vt)])@Vt
        p = sc - R@mcc
    err = np.mean(np.min(np.sum((S[:,None,:]-(R@M.T).T[None,:,:]-p)**2,2),1))
    return R,p,err
# 单次 vs 多初猜
R0s = [np.array([[np.cos(a),-np.sin(a)],[np.sin(a),np.cos(a)]]) for a in np.linspace(0,2*np.pi,24,endpoint=False)]
res = [icp(R0, np.zeros(2)) for R0 in R0s]
best = min(res, key=lambda r:r[2])
print("单次(单位初猜)误差 vs 24初猜最好误差:", round(icp(np.eye(2),np.zeros(2))[2],4), round(best[2],4))
print("最好 R 误差:", round(np.linalg.norm(best[0]-R_gt),3))
```

**你会看到**：**单次单位初猜常常误差大（卡局部极小）**，**24 个旋转初猜里最好的那个误差小得多**——**验证"多初猜 + 留最好"对 ICP 的提升**，且**旋转维度低、采样便宜**。

### 练习 4.5（平面两点 ICP）

> 我们看到 ICP 有很多局部极小。但**这些局部极小是什么**？能否说**初猜要错到什么程度才会掉进一个局部极小**？虽然一般几何分析会变复杂，**从简单例子开始**：平面两点 ICP。

> 模型点和场景点（在对应坐标系）给定（PDF 图：模型 $(1,0),(-1,0)$，场景 $(1,0),(-1,0)$，真对应按编号）。但**注意我们不知道真对应**——ICP 只按最近邻定。给定 vanilla-ICP 代价（成对距离平方和），用 $p_x,p_y,a,b$ 参数化 2D 位姿，优化写成：

$$\min_{p_x,p_y,a,b}\ \sum_i\ \left(\|\,R\,^Op_{mc_i}+p - {}^Wp_{s_i}\,\|^2\right),\quad \text{s.t.}\ a^2+b^2=1$$

> **a.** 当初猜导致**基于最近邻的正确对应**时，证明 ICP 代价在 $p_x=p_y=0,\ b=0,\ a=1$ 最小。
> **b.** 当初猜导致**翻转对应**时，证明 ICP 代价在 $p_x=p_y=0,\ b=0,\ a=-1$ 最小。描述收敛到这个错误解的初猜集合。
> **c.** 记住**对应不必一一对应**。事实上按最近邻算时常常不是。**通过构造数据矩阵 $W$**，证明**当两个场景点都对应同一个模型点时，ICP 卡住、达不到零代价**。**ICP 下一次迭代发生什么？**（提示：可假设对零矩阵做 SVD 得到 $U,V$ 为单位矩阵。）

**通俗讲解**：
- **a.** 正确对应时，**真位姿（单位变换）让距离全 0** → 全局最小。
- **b.** 翻转对应时，**最近邻把左右配反**，于是 ICP 收敛到 $a=-1$（旋转 180°，把模型翻过来"凑合"对上）——**一个错误局部极小**。**收敛到它的初猜集合** = **那些让"翻转配对"成为最近邻的初猜**（初猜旋转接近 180° 的区域）。
- **c.** 两场景点都配同一模型点 → **数据矩阵 $W$ 退化（秩不足/零）** → **SVD 给单位矩阵** → **$R=I$、平移解不出真值** → **卡住、代价非零**。**下一次迭代**：因为对应没变好，**ICP 在同一个退化对应上原地踏步**（或在小扰动下抖动）——**卡死**。

**类比**：**两块拼图都"觉得"自己配模型同一块** → **算法"困惑"，算不出旋转** → **卡住**。

### 🧪 代码 3：RANSAC 去平面（可跑，对应练习 4.7）

```python
import numpy as np
rng = np.random.default_rng(3)
# 造点云: 一个平面(z≈0) + 一个球(物体) + 噪声
plane = rng.uniform(-2,2,(300,3)); plane[:,2] = 0.02*rng.randn(300)
theta = rng.uniform(0,np.pi,200); phi = rng.uniform(0,2*np.pi,200)
ball = np.stack([0.5*np.sin(theta)*np.cos(phi),0.5*np.sin(theta)*np.sin(phi),0.5*np.cos(theta)+1.0],1)
pts = np.vstack([plane, ball])
def ransac_plane(pts, thr=0.05, iters=500, k=3):
    best_inl=[]; best_plane=None
    for _ in range(iters):
        idx = rng.choice(len(pts),k,replace=False)
        p = pts[idx]
        n = np.cross(p[1]-p[0], p[2]-p[0]); n = n/(np.linalg.norm(n)+1e-9)
        d = np.abs((pts-p[0])@n)
        inl = np.where(d<thr)[0]
        if len(inl)>len(best_inl): best_inl=inl; best_plane=n
    return best_inl, best_plane
inl, n = ransac_plane(pts)
mask = np.ones(len(pts),bool); mask[inl]=False
print("RANSAC 找到平面法向:", np.round(n,2), " 内点数(平面):", len(inl), " 剩余(物体):", mask.sum())
```

**你会看到**：**RANSAC 正确找出平面（法向≈[0,0,1]），剩下的是球**——**验证"RANSAC 去背景平面"**。

### 练习 4.8（ICP 里的离群点）

> 这题你将**探索 ICP 处理离群点的技术**，并**思考距离度量如何影响 ICP 对离群点的鲁棒性**。两部分，每部分三小问。

> **a.** 考虑下面可视化的设定。模型点黑色标 $U,V$，场景点红色标 $r_j$。考虑一个处理场景离群点的可能算法。
> 1. 先写下每个对应，即 $(b_i,r_j)$ 对。再算 ICP 误差（这些对应的成对平方距离和）。
> 2. 假设**告诉你场景点里有 1 个离群点**。用每个 $b_i,r_j$ 的成对距离，**你能检测出哪两个场景点最可能是离群点？**
> 3. **丢弃这两个提议的离群场景点**，算新 ICP 误差。**这就是 Trimmed ICP 的基本直觉！**

> **b.** ICP 的优化用**成对欧氏平方距离和**捕捉两集合距离。作为思想实验：**另一种可能的距离度量**（优化不那么友好）是**单向 Hausdorff 距离**。简单说，**对手在一形状上挑一个点，你被迫走到另一形状上最近的点**。考虑两种方案：
> - **方案 1**：对手挑**场景点**，于是你挑**离该场景点最近的模型点**。
> - **方案 2**：对手挑**模型点**，于是你挑**离该模型点最近的场景点**。
> **哪种对离群点更鲁棒？** 用 2D 例子探索。模型点黑标 $b_i$，场景点红标 $r_j$。
> 1. 考虑方案 1。我（对手）挑场景点 $r_5$。你能挑的最近模型点 $b_1$ 是什么？到这个模型点的距离？
> 2. 现在方案 2，我挑模型点 $b_1$。你能挑的最近场景点？距离？
> 3. 由此，**哪种方案对离群点更鲁棒？**

**通俗讲解**：
- **a（Trimmed ICP）**：**算每个对应的距离，距离最大的那几个 = 最可能的离群点，丢掉重算**——**"修剪"掉最差的对应**。
- **b（Hausdorff 两方案）**：
  - **方案 1**（对手挑场景点）：**离群场景点离所有模型点都远** → **对手一挑离群点，你就被迫走很远** → **代价被离群点主导** → **不鲁棒**。
  - **方案 2**（对手挑模型点）：**对手挑模型点，你找最近场景点**；**离群场景点"没人挑它"就不计入** → **离群点影响小** → **更鲁棒**。
- **结论**：**方案 2 更鲁棒**——**因为"从模型出发找场景"时，离群场景点不会被主动选中**。

**类比**：
- **方案 1** = "**让捣乱者先挑**" → 他挑离群点，你吃亏。
- **方案 2** = "**让好人（模型点）先挑**" → 捣乱的离群点没人理，影响小。

### 练习 4.10（组合符号距离函数 SDF）

> 这题我们**探索符号距离函数及其组合**！提醒：**集合的 SDF** 给一点 $p$ 到该集合边界的**最小距离**，**符号**取决于 $p$ 在边界**内还是外**。**边界内部的点为负，外部的点为正**。

> 2D 例子，考虑下面可视化的**绿盒子**。**盒子中心（原点）SDF = −1**（因为它离任何边距离 1 且在内部）。**盒子周界上的点 SDF = 0**。**盒子外的点 SDF = $+d$**，$d$ = 该点到周界的最小距离。

> 下图画两个物体：**阴影红物体**和**阴影蓝物体**（**紫色区域是两物体重叠**，物体应视为**无限半平面**）。设 $\phi_r(p)$ = 点 $p$ 到红物体边界的 SDF，$\phi_b(p)$ = 到蓝物体边界的 SDF。例如 $\phi_b(p_0)=-3,\ \phi_b(p_1)=+2$。

> **a.** 先考虑**红 ∪ 蓝的并集**定义的新区域。设 $\phi_{r\cup b}(p)$ = 点 $p$ 到这个新边界的 SDF。算 $\phi_{r\cup b}(p_0),\phi_{r\cup b}(p_1),\phi_{r\cup b}(p_2)$。
> **b.** 再考虑**红 ∩ 蓝的交集**（即紫物体）。设 $\phi_{r\cap b}(p)$ = 到这个新边界的 SDF。算 $\phi_{r\cap b}(p_0),\phi_{r\cap b}(p_1),\phi_{r\cap b}(p_2)$。
> **c.** 用 a 的经验，写**计算 2D 空间任意点 $p$ 到红蓝并集的 SDF 的表达式**，用 $\phi_r,\phi_b$ 表示。鼓励按 $p$ 所在区域分情况，再化简到 2 种情况的干净数学表达式。
> **d.** 用 b 的经验，写**到红蓝交集的 SDF 的类似表达式**，用 $\phi_r,\phi_b$，可只考虑 2 种情况。

> **一个错误的方法**：算两物体并集的 SDF 时**直接取每个物体 SDF 的最小值**。（值得花一分钟说服自己**为什么这方法错**！）虽然这方法**可能产生错误距离**，但它**会产出符号正确的值**（再说服自己这是真的！）。

> 因此**这个"错误但有用"的方法能告诉我们"对并集，我们在穿透还是没穿透"**。这让它**对计算非穿透约束有用**！我们称这方法生成的 SDF 为 **Penetration-Constraint-SDF**。

> **e.** 如课堂讨论，**对刚体，我们能预计算物体的 SDF**，**极大加速计算**。但**如果处理关节体（如机械臂），臂的构型依赖关节值，就不能再预计算"全局"SDF**。**每次臂构型变都重算"全局"SDF 很贵**。（全局 = 整个关节体的 SDF。）

> 相反，**DART（Dense Articulated Real-Time Tracking）算法 [24]** 考虑：**对关节体每个连杆，我们有一个"局部"SDF**。**局部 SDF 给"连杆坐标系里一点"的符号距离值**。**因为在连杆坐标系操作，我们能预计算这些局部 SDF**。考虑我们喜欢的**平面两连杆臂**（下图）。给定 $q_0,q_1$ 和**每个连杆的预计算局部 SDF**（连杆 AB、连杆 BC），**简述如何计算点 $(^Wx_p,^Wy_p)$ 的全局 Penetration-Constraint-SDF 值**。

**通俗讲解 + 答案**：
- **并集 SDF** = $\phi_{r\cup b}(p) = \min(\phi_r(p),\,\phi_b(p))$。**直觉**：并集 = "在红**或**蓝里"，**离并集边界 = 离"更近的那个"边界** = 取 min。
- **交集 SDF** = $\phi_{r\cap b}(p) = \max(\phi_r(p),\,\phi_b(p))$。**直觉**：交集 = "在红**且**蓝里"，**要同时在两者内**，**离交集边界 = 离"更紧的那个约束"** = 取 max。
- **c.** 并集 = $\min(\phi_r,\phi_b)$（分情况化简后）。
- **d.** 交集 = $\max(\phi_r,\phi_b)$。
- **"错误但有用" = min 对并集**：**距离值可能错**（并集边界在重叠区不是简单的 min），**但符号对**（**在并集内 = 负，外 = 正**）→ **能判断穿透与否** → **能当非穿透约束** = **Penetration-Constraint-SDF**。
- **e（DART）**：**全局 Penetration-Constraint-SDF** = **对每个连杆，把查询点 $(^Wx_p,^Wy_p)$ 用关节值 $q_0,q_1$ 的正向运动学**变到**该连杆的局部坐标系**，**查该连杆的预计算局部 SDF**，**再对所有连杆取 min**（Penetration-Constraint-SDF = min）。**因为局部 SDF 预计算了，在线只需做坐标变换 + 查表 + 取 min** → **快**。

**类比（SDF 组合 = 海拔地图的"并/交"**）：
- **并集** = "**两块地的合并**"，**离合并边界 = 离更近的那块边界** = min。
- **交集** = "**两块地的重叠**"，**离重叠边界 = 离更紧的约束** = max。
- **min 对并集"距离错但符号对"** = "**合并地的精确边界画不准，但'在不在合并地里'判断得对**" → **够用来判断"穿没穿透"**。
- **DART** = "**每个零件自带一张局部海拔图，查询时把点换算到零件坐标系查表，再取 min**" → **不用每次重算全局图**。

### 🧪 代码 4：SDF 组合（并/交/Penetration-Constraint-SDF）+ DART 思想（可跑，对应练习 4.10）

```python
import numpy as np
# 两个"无限半平面"物体: 红 = {x<=1}, 蓝 = {y<=1}  (SDF: 外正内负)
def phi_red(p):  return p[0]-1.0      # x>1 在外(正), x<1 在内(负)
def phi_blue(p): return p[1]-1.0
def union_sdf(p):        return min(phi_red(p), phi_blue(p))     # 并集 = min
def inter_sdf(p):        return max(phi_red(p), phi_blue(p))     # 交集 = max
def pen_constraint_sdf(p): return min(phi_red(p), phi_blue(p))   # "错但有用": 距离可能错, 符号对
pts = {'p0':np.array([0.,0.]), 'p1':np.array([2.,2.]), 'p2':np.array([0.,2.])}
for name,p in pts.items():
    print(name, "红=%.1f 蓝=%.1f | 并=%.1f 交=%.1f | PenConstraint=%.1f(符号对?%s)" % (
        phi_red(p), phi_blue(p), union_sdf(p), inter_sdf(p), pen_constraint_sdf(p),
        (pen_constraint_sdf(p)<0)==(union_sdf(p)<0)))
# DART 思想: 全局 Penetration-Constraint-SDF = 对每个连杆, 把世界点变到连杆局部坐标查局部SDF, 取 min
def local_sdf_link(p_local): return np.linalg.norm(p_local)-0.2   # 局部: 半径0.2的圆连杆
def world_to_link(p_world, q, anchor):   # 简化: 绕 anchor 转 -q
    c,s=np.cos(-q),np.sin(-q); R=np.array([[c,-s],[s,c]])
    return R@(p_world-anchor)
q0,q1 = 0.5,0.3; a0=np.array([0.,0.]); a1=np.array([0.5,0.3])
pw = np.array([0.3,0.2])
sdfs = [local_sdf_link(world_to_link(pw,q0,a0)), local_sdf_link(world_to_link(pw,q1,a1))]
print("DART 全局 Penetration-Constraint-SDF = min(局部SDF) =", round(min(sdfs),3))
```

**你会看到**：**并集 = min、交集 = max**，**Penetration-Constraint-SDF 与并集"符号一致"**（穿透判断对）；**DART 把世界点变到每个连杆局部坐标查局部 SDF 取 min**——**验证练习 4.10 的全部组合规则**。

## 增补一：把"还不够通俗"的 5 个点再补类比

1. **为什么"已知对应"用 SVD 而非迭代**：因为**对应已知时，配准是"一个凸最小二乘 + 正交约束"，SVD 给闭式全局解**——**一步到位，不用迭代**。ICP 的迭代**只在"对应未知、要交替猜"时才需要**。
2. **improper rotation 的物理**：$\det=-1$ = **旋转里夹了一次镜像** = **把右手系变左手系**——**物理世界做不到**（你不能把物体"翻成镜像"还叫刚体运动），所以**必须排除**。SVD 解里 $D=\text{diag}(1,1,\det(UV^T))$ 就是**自动把镜像情况修正成正旋转**。
3. **为什么 ICP 对平移好、对旋转差**：**平移误差在目标里"线性、凸"**，**最近邻配对对平移不敏感**；**旋转误差让"最近邻配对"整体错位**，**一旦配错就正反馈地更错** → **旋转更容易卡局部极小**。所以**多旋转初猜特别有用**。
4. **CPD 的 $\sigma$ 是什么**：**高斯的"宽度"** = "**多远的点还算'可能对应'**"。**$\sigma$ 大** = "**配对更宽松、更鲁棒但更模糊**"；**$\sigma$ 小** = "**配对更严格、更像硬 ICP**"。CPD 还能**每次迭代自适应调 $\sigma$**（从大到小，先粗后细）。
5. **Penetration-Constraint-SDF 为什么"距离错但够用"**：**非穿透约束只关心"穿没穿"（符号），不关心"穿多深"的精确值**。min 对并集**符号对**（在并集内=负、外=正）→ **穿透判断对** → **够当约束**。**精确距离错没关系**，**因为约束是 $\phi\ge 0$ 这种"符号/不等式"，不是"距离=某值"**。

# 给初学者的"本章通关三句话"

1. **本章补第 3 章的"作弊"**：第 3 章假装知道物体位姿，第 4 章用深度相机把它"看"出来——流水线是"拍照→深度图→点云→和模型点云对齐（配准）→处理遮挡离群点→加非穿透约束→跟踪→接回第 3 章抓"；而深度图比点云多一条"相机到点之间是空的"的信息，别扔。
2. **配准的两条路**：**已知对应**（拼图带编号）→ **SVD 一步算出最佳旋转**（用质心解耦平移、用 $\det$ 修正防镜像）；**未知对应** → **ICP 反复"找最近+对齐"**，但**会卡局部极小**，所以**多撒旋转初猜留最好**；点云脏了就**用 RANSAC/最大团/Trimmed ICP 找离群点、用分割先分开物体、用 CPD 软对应或鲁棒损失或预计算 SDF 抗噪**，要全局最优就上 **TEASER 的 SDP 松弛**。
3. **SDF 是非穿透约束的钥匙**：**SDF = 带正负号的海拔图**，**并集取 min、交集取 max**，**而"min 对并集"虽距离可能错但符号对，正好用来判断"穿没穿透"（Penetration-Constraint-SDF）**；**DART 则给每个连杆存局部 SDF、查询时换算坐标查表取 min，避免每次重算全局图**——**这套"非穿透+自由空间"约束，和第 17 章接触规划用的是同一类约束，只是这里用在"估位姿时别让模型穿墙"**。

> 最后送你一句动手箴言：这一章 PDF 一行内联代码都没有，但**所有"配准/ICP/离群点/SDF"的直觉都会在你跑通那 4 段代码后变成"显然"**。**尤其代码 1（看 SVD 一步完美对齐）、代码 2（看 ICP 卡局部极小、24 个旋转初猜救场）、代码 4（看并集=min、交集=max、Penetration-Constraint-SDF 符号对、DART 局部 SDF 取 min）这三段**——做完它们，"SVD 配准、ICP、RANSAC、CPD、SDF、非穿透、自由空间"这些最像黑话的词，就会像骑自行车一样长进你的肌肉记忆。**这一章的精髓不是某个公式，而是那个"从看见到抓住"的桥梁——第 3 章教会机器人"手怎么动"，第 4 章教会它"眼睛怎么看"；而配准的本质，不过是把"认出一个认识的物体并定位它"这件人一秒就能做的事，拆成"把两堆点对齐"的几何题，再用 SVD 的闭式解、ICP 的反复试探、SDF 的海拔地图，去对抗噪声、遮挡、离群点和"物体不能穿墙"的物理铁律。当你第一次在 MeshCat 里看到机器人靠 ICP 估出的位姿、稳稳抓起那块它"刚刚才看见"的芥末瓶时，你会明白：感知从来不是"拍张照就完事"，而是一场"在带噪声、被遮挡、混着杂物的 3D 点云里，固执地把模型和现实对齐"的几何苦功——而正是这份苦功，让机器人从"闭眼抓已知"走向"睁眼抓所见"。** 👁️🧩
