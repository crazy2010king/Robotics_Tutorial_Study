# 第4章：几何位姿估计——教机器人看世界
## 1. 机器人的眼睛：深度相机
在开始算数之前，我们得先拿到数据。
### 1.1 深度传感器：给世界拍“3D照片”
*   **传统相机（RGB）**：只能拍出颜色，不知道东西多远。一张照片里，近处的桌子和远处的山看起来是平的。
*   **深度相机**：除了颜色，还能告诉你每个像素点离镜头有多远。
*   **类比**：想象你手里有一个激光测距仪。你扫过房间，每扫到一个点，就记下“这个点的颜色是红的，距离是 1.5 米”。把这些点连起来，就形成了**点云**——就像用无数个小光点搭出来的 3D 模型。
### 1.2 仿真中的相机
在 Drake 仿真里，我们使用 `RgbdSensor` 系统。
*   **输入**：`geometry_query`（告诉渲染器有哪些东西）。
*   **输出**：彩色图像、深度图像、标签图像，以及相机自身的位姿 `X_WB`。
*   **仿真 vs 现实**：仿真里的深度图是“完美”的，就像上帝视角。但现实中的深度相机（比如我们用的 Intel RealSense D415）会有很多问题：
    *   **噪声**：距离数据会抖动。
    *   **盲区**：太远（超过 1.5 米）或太近（小于 0.3 米）都测不到。
    *   **反射/黑色物体**：像镜子或黑布，光线要么反射乱跑要么被吸走，导致深度失效。
**代码/实验补充**：
在代码中，使用 `DepthImageToPointCloud` 系统可以把 2D 的深度图转换成 3D 的点云。你可以指定输出的坐标系（比如从相机坐标系 `C` 转到世界坐标系 `W`）。
```python

point_cloud_system = DepthImageToPointCloud()
# 输入 depth_image 和 camera_pose (X_WC)
# 输出 point_cloud (在 World 坐标系下)
```
### 1.3 视觉的挑战：遮挡与视角
相机不是透视眼，它只能看到“视线”内的东西。
*   **遮挡**：如果砖头后面有个杯子，相机看不到杯子的背面。甚至，当机器人自己的手伸出去抓东西时，手会挡住视线！
*   **部分视图**：我们永远无法一次性看到物体的全貌。就像看人，你只能看到他面向你的那一面。
**解决方案**：
*   **多相机**：在房间里多装几个相机（比如 TRI 的测试台装了 8 个），像监控一样全方位无死角。
*   **手腕相机**：把相机装在机械臂手腕上。手往哪里，眼就往哪里。但要注意，太近了（小于 30 厘米）也看不清。

## 2. 数据的表示：点云与几何模型
深度相机直接吐出来的是**点云**，但我们的模型文件（比如砖头的 3D 网格）通常是**网格**。
*   **点云**：一堆散乱的点。优点是直接来自传感器，缺点是丢失了“点与点之间的连接关系”（比如不知道哪三个点构成一个面）。
*   **网格**：三角形面片组成的壳。优点是结构清晰，适合显示和碰撞检测。
*   **SDF (Signed Distance Function, 符号距离函数)**：这是一个高级表示。对于空间中任意一点，SDF 告诉你“离物体表面有多远，以及是在里面还是外面”。
    *   **类比**：想象一个带颜色的烟雾场。在物体内部是红色烟雾（负距离），外部是蓝色烟雾（正距离），表面是透明面（零距离）。这个“烟雾场”就是 SDF。
    *   **用途**：SDF 可以极快地计算“点到物体的最近距离”，这对于优化算法非常关键。

## 3. 核心问题：点云配准
现在，我们有一个“模型点云”（理想的砖头）和一个“场景点云”（相机拍到的、乱糟糟的砖头）。我们的目标是找到一个变换（旋转+平移），让这两个点云重合。
### 3.1 已知对应关系：SVD 神解法
如果我们有上帝视角，知道场景点云中的第 1 个点对应模型点云中的第 5 个点，第 2 个点对应第 10 个点……这叫**已知对应关系**。
在这种情况下，解法极其优雅，是基于**SVD（奇异值分解）** 的。
*   **思路**：
    1.  **去中心化**：先把点云的中心都移到原点。
    2.  **旋转分离**：旋转只影响点与点的相对位置，不影响整体中心。所以可以先只算旋转 $R$。
    3.  **SVD 分解**：构建一个矩阵 $W = \sum (s_i - \bar{s})(m_i - \bar{m})^T$。对 $W$ 做 SVD 分解得到 $U, \Sigma, V^T$。那么最优旋转就是 $R^* = U D V^T$，其中 $D$ 是一个处理镜像的特殊对角阵。
    4.  **计算平移**：有了 $R$，平移 $p^*$ 就是两个点云中心的差。
**代码/实验补充**：
Drake 中有现成的函数可以实现这个逻辑，但理解 SVD 原理对于调试很有帮助。
### 3.2 迭代最近点 (ICP)：猜测与修正
现实是残酷的，我们**不知道**对应关系。这就是 ICP 算法要解决的问题。
*   **核心思想（瞎子摸象升级版）**：
    1.  **猜测**：先瞎猜一个初始位姿。
    2.  **找对应**：根据这个位姿，把模型点云变换到场景里。对于场景里的每个点，在模型里找离它最近的那个点，认作“对应点”。
    3.  **修正**：用这些“对应点”和 SVD 方法，算出一个更准的位姿。
    4.  **迭代**：重复步骤 2 和 3，直到位姿不再怎么变化。
*   **致命弱点：局部最优解**
    *   **比喻**：想象你在爬山（寻找误差最低的山谷）。ICP 就像是一个只往下走的贪心算法。如果你一开始站在半山腰的一个小坑里（错误的初始猜测），你就会被困住，永远爬不到真正最深的那个山谷（真实位姿）。
    *   **实验现象**：你会看到点云在几个错误的姿态之间来回跳跃，最后卡在一个明显不对的地方。
**代码/实验补充**：
在练习中，你可以尝试用不同的初始猜测运行 ICP。你会深刻体会到它对初始值极其敏感。

## 4. 处理“脏”数据：异常值与分割
现实世界不仅不完美，还很混乱。场景点云里可能混入：
1.  **桌子的点**：我们只想要砖头，不想把桌子也配准了。
2.  **噪点**：传感器误差产生的孤立点。
3.  **离群点**：完全不相关的杂乱点。
### 4.1 检测并剔除异常值
*   **阈值法**：算完一次配准后，看看哪些对应点的距离特别远（比如超过 5 厘米）。这些点很可能是错误的对应，把它们踢出去，再重新算。
*   **RANSAC (随机采样一致性)**：
    *   **比喻**：民主投票。我们不一次性相信所有点。每次随机挑 3 个点算一个位姿，看看有多少其他的点“同意”这个位姿（即距离小于阈值）。支持者最多的那个位姿，就是赢家。
    *   **优点**：即使一半的点都是垃圾（离群点），RANSAC 也能找对。
### 4.2 点云分割
在配准之前，最好先把“砖头”从“桌子”上扣下来。
*   **几何方法**：比如我们知道桌子是个平面，可以用算法把所有平面上的点都删掉。
*   **深度学习方法**：现在更常用神经网络来“看图”，直接把图里的砖头轮廓抠出来。这在复杂场景中效果更好。

## 5. 进阶技巧：让配准更鲁棒
### 5.1 软对应关系 (CPD 算法)
ICP 是“硬”的：一个点要么对应 A，要么不对应，非黑即白。
CPD（相干点漂移）是“软”的：它认为场景点以一定的**概率**对应模型点。
*   **概率模型**：假设模型点周围有一团“概率云”。场景点落在云里的概率高，落在云外的概率低。
*   **效果**：这就像给离群点一个“软橡皮擦”，让它们对结果的影响逐渐消失，而不是生硬地切除。CPD 比 ICP 更抗干扰。
### 5.2 非线性优化：用代价函数说话
我们可以把整个位姿估计问题写成一个**优化问题**，而不是迭代猜测。
*   **目标**：最小化 $\sum \text{Loss}( \text{距离} )$。
*   **Loss 函数的选择**：
    *   **平方损失**：误差大的点会主导结果，对离群点敏感（这就是 ICP 的问题）。
    *   **鲁棒损失**：比如 Huber Loss 或 Tukey Loss。当误差大到一定程度后，Loss 不再增加。这就像说：“如果你误差太大，我就当你不存在，不让你破坏我的结果”。
*   **约束**：我们可以直接加“非穿透约束”，比如“估计出的砖头位姿不能穿进桌子”。
*   **求解**：使用非线性优化求解器（如 IPOPT）来解这个问题。它不会陷入简单的迭代陷阱，能综合考虑所有点。
**代码/实验补充**：
Drake 的 `MathematicalProgram` 非常适合做这个。你可以定义变量为位姿，添加鲁棒损失作为代价，甚至添加半平面约束作为“虚拟墙壁”。
```python
# 伪代码：添加非穿透约束
prog = MathematicalProgram()
X = prog.NewVariables(4, 4) # 姿态变量
# ... 添加代价函数 ...
# 约束：模型所有点的 z 坐标必须 > 0 (不能穿过地板)
for model_point in model_points:
    transformed_point = X @ model_point
    prog.AddConstraint(transformed_point[2] >= 0)
```
### 5.3 全局优化
ICP 和非线性优化都怕陷入局部最优。有没有办法直接找到**全局**最优解？
*   **TEASER 算法**：一种更现代的方法。它利用“截断最小二乘”和“半定规划（SDP）松弛”的数学技巧，能在一定条件下证明找到的是全局最优，并且速度很快。这是目前几何位姿估计的前沿方向之一。

## 6. 实战：把所有拼在一起
现在，我们有了全套武器：
1.  **相机**：拍出深度图。
2.  **预处理**：转点云、分割（去背景）、去噪。
3.  **位姿估计**：用 ICP 或优化算法算出物体位姿 $X_O$。
4.  **规划与控制**：像第 3 章一样，根据 $X_O$ 规划抓取轨迹，用逆运动学控制机械臂。
**练习 4.11 的代码实践重点**：
这个练习是本章的终极考核。你需要：
1.  **搭建场景**：在 Drake 里放机器人、桌子、你的名字字母（SDF 模型）、以及 3 个 RGB-D 相机。
2.  **获取点云**：从 3 个相机获取点云，并融合起来（或者选最好的一个）。
3.  **分割**：把字母点云从背景中分离出来。
4.  **ICP 配准**：用字母的模型点云和场景点云运行 ICP，得到字母的世界位姿。
5.  **抓取**：用估计出的位姿，调用你之前写的抓取代码，把字母放进另一个箱子里。

### 给工程师的最后建议
*   **不要迷信几何**：在 2019 年以前，纯几何方法（如 ICP）在位姿估计比赛里还领先。但到了 2020 年，深度学习方法已经反超了。最实用的方案往往是**混合的**：用深度学习给个粗略的初始猜测，再用几何方法（如 ICP 或优化）去精修。
*   **善用 SDF**：如果你需要做很多次碰撞检测或距离计算，一定要预计算物体的 SDF。这是性能优化的关键。
*   **视觉先于触觉**：这一章我们完全没用到触觉传感器。在抓取之前，视觉是我们获取环境信息的唯一途径，必须鲁棒可靠。
