# 第11章：强化学习——机器人通过“试错”进化
## 1. 引言：让机器人自己教自己
之前的章节主要关注“模型基”方法：我们需要知道物体多重、摩擦系数多少、动力学方程怎么写。这种方法很精确，但在面对极其复杂的接触（比如倒水、系鞋带）时，写模型太难了。
**强化学习 (RL)** 提供了另一种思路。它不依赖精确的物理模型，而是依赖于**大量的尝试**。
*   **为什么适合操作？**：机器人操作涉及复杂的接触力学、视觉感知。写规则太难，但让机器人自己在仿真器里试错，也许能学会一些人类难以描述的微妙技巧。
---
## 2. 工具箱：Gymnasium 与 Drake 的联姻
要搞强化学习，首先得有一个“游乐场”。
### 2.1 Gymnasium：通用的遥控器
Gymnasium（以前叫 OpenAI Gym）是强化学习领域的标准接口。
*   **核心思想**：它把所有环境（不管是机器人、Atari 游戏还是围棋）都包装成一样的接口。
*   **三大核心函数**：
    *   `reset()`：重置环境，开始新的一局。
    *   `step(action)`：执行一步动作，返回（观察结果, 奖励, 是否结束）。
    *   `render()`：画出画面。
### 2.2 DrakeGymEnv：把高保真物理引擎接入 Gym
虽然 Gym 很好，但它太“简陋”了，里面没有真正的物理。我们要用 Drake 里的刚体动力学引擎。
*   **连接器**：`from pydrake.gym import DrakeGymEnv`。
*   **做法**：这个类把 Drake 的 `Simulator`（仿真器）包装成一个 Gym 环境。你告诉它哪个端口是动作输入（比如电机力矩），哪个端口是观察输出（比如摄像头图像），它就能像玩游戏一样训练机器人了。
**代码/实验补充**：
```python
from pydrake.gym import DrakeGymEnv
# 我们需要一个 SimulatorFactory，因为每次重置环境时，物体的摆放可能不同
env = DrakeGymEnv(simulator_factory=my_factory, 
                     action_port_id=...,  # 关联动作端口
                     observation_port_id=...)  # 关联观察端口
```
### 2.3 为什么选 Drake？
有些 RL 研究者喜欢“黑盒”环境（完全不知道里面是什么）。但 Tedrake 教授认为，**模型化的优势不可替代**。
*   **理由**：虽然我们用 RL 训策略，但底层的物理（摩擦、重力）如果符合真实规律，训练出来的策略才更有用。而且，我们可以利用 Drake 的结构化特性，把 RL 和传统的控制算法结合。
**推荐的算法库**：
*   **Stable Baselines 3**：基于 PyTorch，实现了 PPO、SAC 等主流算法，文档好，用得人多。
*   **Nevergrad**：用于黑盒优化（不需要梯度）。

## 3. 核心算法：策略梯度方法
强化学习有很多流派，这里重点讲**策略梯度**，这是目前基于深度学习的 RL 的主流方法。
### 3.1 核心困境：我知道“我”怎么变，但我不知道“世界”怎么变
训练神经网络通常需要“梯度”（导数），告诉网络往哪个方向调参数。
*   **我们能算的**：策略梯度。如果我们把机器人的动作规则稍微变一点点（$\pi$），输出的动作概率会怎么变？这个我们知道。
*   **我们算不出来的**：环境梯度。如果我们稍微改变动作，环境的物理状态（比如物体滑没滑、倒了没倒）会怎么变？这个物理过程是个“黑盒”，没有明确的数学公式可以求导。
### 3.2 随机梯度下降：摸着石头过河
既然算不出环境的确切梯度，我们就用**随机采样**来近似它。
*   **比喻**：你在漆黑的屋子里想下山（最小化损失）。
    *   你往左迈一步，发现坡度变陡了（负反馈）。
    *   你往右迈一步，发现变平了（正反馈）。
    *   虽然你不知道地图的确切形状，但根据这些随机尝试的结果，你可以推断出大概往哪走好。
*   **REINFORCE, PPO, TRPO**：这些都是基于“策略梯度”的具体算法，它们区别在于怎么利用这些随机尝试的数据来更新策略。
### 3.3 PPO (Proximal Policy Optimization)：谨慎的更新
目前最流行的算法是 PPO。
*   **原理**：不要一次把策略改得面目全非。
*   **技巧**：它引入了“裁剪”。如果新算出的策略和旧策略差别太大，就强行限制更新幅度。
*   **好处**：防止“步子迈太大”导致训练崩溃，训练过程非常稳健。
*   **应用**：文中提到的 Example 11.3 就是利用 PPO 训练机器人翻箱子。
### 3.4 控制理论遇上 RL
Tedrake 教授指出，控制理论（LQR）其实很早就在用梯度下降了。虽然 LQR 的代价函数不是凸的，但往往没有局部最优解。这意味着我们现在的理论工具已经足够强大，可以处理复杂的 RL 优化问题。

## 4. 练习题深度解析与代码补充
这一章的练习题是理解 RL 数学原理的宝藏。
### 练习 11.1：随机优化与基线
这个练习揭示了 RL 中最基础的概念：**基线**。
*   **任务 a & b：SGD 与随机梯度**。
    *   SGD：使用精确的数学梯度 $\nabla J$。
    *   随机梯度：用噪声 $g \approx \nabla J$ 来代替。
*   **任务 c：基线的不变性**。
    *   **公式**：$\theta_{t+1} = \theta_t + \alpha (R_t - b) \nabla \ln \pi(a_t|s_t)$。
    *   **含义**：$R_t$ 是奖励，$b$ 是基线（比如平均奖励）。数学上可以证明，改变 $b$ 并不会改变梯度期望的方向，只改变方差。就像给全班考试加分，大家的排名（梯度方向）不会变，但分数的离散程度（方差）会变。
    *   **补充**：加基线是为了减少方差。想象你在网上买东西，如果你只知道“这件商品很好”（正奖励），你可能会盲目买。如果你还知道“同类商品平均质量一般”（基线），你就会更清楚这件商品到底有多好。
### 练习 11.2：REINFORCE 算法实现
这是最经典的策略梯度算法实现。
*   **任务 a：策略损失**。
    *   目标：让好动作（奖励高）出现的概率变大。
    *   **公式**：$Loss_{policy} = - \sum \log \pi(a_t|s_t) \cdot A_t$。
    *   **解读**：$A_t$ 是优势函数。如果 $A_t > 0$（这步比平均好），我们要减小负对数概率（即增加概率）。如果 $A_t < 0$（这步比平均差），我们要减小概率。
*   **任务 b：价值损失**。
    *   公式：$Loss_{value} = (V(s_t) - R_t)^2$。
    *   **解读**：训练一个“评论家”网络 $V(s)$，让它预测当前状态能得多少分。如果它预测不准，就惩罚它。
*   **任务 c：优势函数**。
    *   **公式**：$A_t = R_t - V(s_t)$。
    *   **解读**：这是“实际的”与“预期的”之差。如果实际比预期好，说明这步动作不错，要放大它的概率。
### 练习 11.3：分析 PPO 翻箱子
这个练习非常贴近实战。
*   **任务 a：奖励函数的设计**。
    *   PDF 提到：状态包含箱子角度 $\theta$，角速度 $\omega$，手指位置等。
    *   **推断奖励公式**：
        *   `angle_reward`: $-\cos(\theta)$ 或基于 $\theta$ 的某种函数。目标是 $\theta = \pi$（翻倒），所以 $\cos(\pi) = -1$ 最优。或者用模运算处理角度循环。
        *   `velocity_reward`: 正比于 $\omega$。我们希望箱子转动得越快越好，但可能也要考虑翻转到位后的速度惩罚（防止一直转）。
    *   **代码逻辑**：
        ```python
        # 假设 theta 是 0 是竖直，pi 是翻倒
        angle_reward = -math.cos(theta) 
        # 或者用模运算，鼓励它接近 pi
        angle_reward = -min(abs(theta - math.pi), abs(theta + math.pi))
        ```
*   **任务 b：PPO 的稳健性**。
    *   **问题**：如果 clipping 太小，更新极其缓慢（学习效率低）。如果 clipping 太大，就退化成了普通 REINFORCE，容易崩。
    *   **分析**：PPO 之所以比 REINFORCE 好，是因为它用了 Critic（价值网络）来减少方差，并且通过 Clipping 防止策略更新过头。
*   **任务 c：训练过程分析**。
    *   **初期**：机器人随机乱动，偶尔撞倒箱子，获得正反馈。
    *   **中期**：学会了把手指伸到箱子底部，开始有了“撬”的意识，但经常失败。
    *   **后期**：动作变得精细，能利用摩擦力快速翻转。
    *   **启示**：即使是 2D 翻箱子这种“简单”任务，也需要 300 万步的训练。这说明了基于稀疏奖励（只有成功才得分）的 RL 是极其困难的。

### 给工程师的最后建议
*   **不要忽视奖励函数的设计**：在 RL 中，Reward Function = Software Specification。如果奖励设计错了（比如只奖励手指移动速度，没奖励翻箱），机器人就会学会在桌子上疯狂摩擦手指。仔细检查练习 11.3 中的奖励设计逻辑。
*   **使用 Stable Baselines 3**：不要自己从头写 PPO。SB3 已经被无数人验证过，支持并行计算，能极大加速你的训练过程。
*   **利用预训练模型**：在做视觉输入的 RL 时，先用 ImageNet 预训练的卷积层（Backbone）冻结特征提取器，只训练最后几层策略。这能节省 90% 的训练时间。
