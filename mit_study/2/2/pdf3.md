# 第2章：装备你的机器人
## 1. 机器人的“身份证”：描述文件
想象你要玩一款 RPG 游戏，游戏里有很多角色。每个角色都有属性表（力量、敏捷、装备）。在机器人世界，这个属性表就是**机器人描述文件**。
*   **常见格式**：URDF（Unified Robot Description Format，统一机器人描述格式）和 SDF（Simulation Description Format，仿真描述格式）。它们就像是 XML 写的说明书，记录了机器人的连杆长度、关节位置、质量等。
*   **Drake 的魔法**：Drake 能读懂这些格式。为了方便，它还有一种 YAML 配置文件（`Drake Model Directives`），你可以像点菜一样，在一个文件里列出：“我要个 Kuka 机械臂，再要个桌子，再来个盘子”，Drake 就会自动把它们加载到一起。

## 2. 机械臂：选“自动挡”还是“手动挡”？
市面上的机械臂成百上千，我们为什么独独钟爱 **Kuka iiwa**？因为它有一个核心技能：**关节力矩控制**。
为了理解这个区别，我们看看市面上 90% 的机械臂是怎么工作的。
### 2.1 位置控制：工业界的“自动挡”
绝大多数工业机械臂（如 Universal Robots 的 UR 系列，ABB 的 Yumi）都是位置控制的。
*   **原理**：你告诉它“把关节转到 45 度”，它就死命转到 45 度。
*   **为什么不用电流直接控制力矩？** 因为机械臂里面有**减速器**。
    *   **减速器的作用**：就像自行车的变速器。电机转 100 圈，机械臂才转 1 圈。这能把小小的电机力量放大 100 倍。
    *   **代价**：齿轮之间的摩擦、间隙极其复杂。电机电流和最终输出的力矩不再是简单的正比关系了。
*   **怎么控制？** 既然力矩算不准，那我们就装个**编码器**在关节末端，直接看它转到了哪里。然后根据误差，用 **PID 控制器**不断调整电压，让它停在指定位置。
**深入浅出：反射惯量的秘密**
这是一个非常深刻的物理洞察，也是为什么简单的 PID 控制能管用复杂机械臂的原因。
*   **公式**：$I_{total} = I_{motor} + \frac{I_{arm}}{n^2}$。
    *   $I_{motor}$：电机自身的转动惯量（想象电机转子的重量）。
    *   $I_{arm}$：机械臂的惯量。
    *   $n$：减速比（比如 100）。
*   **现象**：当减速比 $n$ 很大时（比如 100），$\frac{I_{arm}}{10000}$ 变得非常小。
*   **结论**：机械臂感觉到的“重量”（惯量），其实主要是**电机自身的惯量**！机械臂本身的重量反而不重要了。
*   **结果**：因为电机惯量是恒定的，不管机械臂伸直还是缩回来，整个系统的惯量几乎没变。这意味着我们可以用**固定的 PID 参数**控制它，不需要随着姿态变化去调整参数。这就是工业机器人这么好用的物理基础。
### 2.2 力矩控制：科研界的“手动挡”
做接触研究（比如抓鸡蛋、推门），我们需要精确感知和控制力，而不仅仅是位置。这时候就需要**力矩控制**。
*   **Kuka iiwa**：它在关节里集成了**应变片**（贴在金属上测变形的传感器），直接测量输出端的力矩。为了传感器的灵敏度，它的减速器里有一个柔性部件（Flex Spline），像弹簧一样软一点。
*   **其他方案**：
    *   **直驱**：不用减速器，电机直接连手臂。力矩准，但电机要做得巨大、笨重。
    *   **串联弹性执行器 (SEA)**：在传动链里故意加一根弹簧。通过测量弹簧的压缩量来算力。 Baxter 机器人就是这样，很软，很安全。

## 3. 机器人的“手”：灵巧 vs. 实用
iiwa 手上只有个法兰盘，你需要自己选个“手”装上去。主要有三大流派：
### 3.1 灵巧手
*   **代表**：Shadow Hand, Allegro Hand。
*   **特点**：像人手一样，几十个关节。
*   **现状**：太贵、太脆弱、控制太难。OpenAI 让 Shadow 手玩魔方，但这背后是极其复杂的工程。
### 3.2 简单夹爪
*   **代表**：**Schunk WSG 050**（我们课程主要用的这个）。
*   **特点**：两个手指，一开一合。
*   **优势**：极其皮实，力控精度极高。虽然自由度少，但对于大多数“抓取-放置”任务完全够用。而且结构简单，让我们能更专注于算法本身。
### 3.3 欠驱动/软体手
*   **原理**：电机少，关节多。比如一根线拉三个关节，线一紧，手指自然包住物体。
*   ** Jamming Gripper (阻塞抓手)**：一个装满咖啡渣的气球。按下去时咖啡渣是流体，包住物体；抽气后咖啡渣变固体，死死抓住。
*   **优势**：利用机械结构的“聪明”，减轻控制算法的负担。

## 4. 仿真引擎：Drake 的双引擎
Drake 把“物理计算”和“画面渲染”分开了，这就像把“游戏逻辑”和“画面特效”分开一样重要。
### 4.1 MultibodyPlant（物理引擎）
这是 Drake 的心脏。
*   **作用**：计算力、加速度、碰撞。它知道 $F=ma$。
*   **为什么叫 Plant？** 在控制理论中，被控制的物理系统被称为“Plant”（工厂/装置）。
*   **代码实践**：你需要创建一个 `MultibodyPlant`，然后 `AddModelFromFile` 把机器人加进去。你可以调用它的接口算雅可比矩阵、质心位置等。
### 4.2 SceneGraph（场景图）
这是 Drake 的眼睛。
*   **作用**：管理 3D 几何形状、颜色、材质。它负责把世界画出来。
*   **为什么要分开？** 有时候我们要用复杂的 3D 场景（比如自动驾驶的真实城市模型），但想用简单的物理模型（比如把车当个质点）。分开后，我们可以让 `SceneGraph` 画漂亮的车，但 `MultibodyPlant` 只算简单的运动方程。
**代码/实验补充**：
在代码里，你需要把 `MultibodyPlant` 和 `SceneGraph` 连起来：
```python
builder = DiagramBuilder()
plant, scene_graph = AddMultibodyPlantSceneGraph(builder, time_step=0.001)
# 这里添加机器人...
Parser(plant).AddModelFromUrl("package://drake/manipulation/models/iiwa_description/iiwa7.sdf")
plant.Finalize()
```
### 4.3 低级控制器
在仿真里，如果你给 `MultibodyPlant` 发送 0 力矩，机器人会直接瘫倒在地。
*   **现实情况**：真实的 iiwa 有刹车，而且内部有重力补偿控制器。
*   **仿真处理**：为了模拟真实感，我们在 Drake 里也加了一个模拟 iiwa 内部控制器的模块。这样你发送“位置指令”，它会自动算出需要的力矩（包括抵消重力）。

## 5. 硬件站：Sim-to-Real 的秘密通道
这是 Drake 最强大的功能之一。它把复杂的仿真细节封装成了一个**“黑盒子”**。
### 5.1 HardwareStation（硬件站）
这是一个巨大的 `Diagram`（子系统）。
*   **输入**：你希望机器人去哪（位置指令），或者你希望施加多大的力（力矩指令）。
*   **输出**：机器人现在在哪（位置传感器），看到了什么（摄像头图像），感受到了什么（力传感器）。
*   **“作弊端口”**：在仿真模式下，这个盒子还会输出一些真实机器人没有的数据，比如“真实位置”、“真实接触力”。这方便我们调试算法。
**代码/实验补充**：
你不需要自己搭建物理引擎和渲染器，只需要写一个 YAML 文件：
```yaml
directives:
- add_model:
    name: iiwa
    file: package://drake/manipulation/models/iiwa_description/iiwa7.sdf
```
然后调用 `MakeHardwareStation(scenario_file="my_station.yaml")`，Drake 就自动把所有东西拼好了。
### 5.2 HardwareStationInterface（真实硬件接口）
这是 HardwareStation 的“双胞胎”。
*   当你把参数 `hardware=True` 传进去时，Drake 不再运行物理仿真，而是把你的指令通过网络（**LCM** 协议）发给真正的机器人驱动器，再把传感器的数据传回来。
*   **无缝切换**：这意味着你的控制算法**完全不需要修改**，就可以从仿真环境切换到真实机器人。这就是“Sim-to-Real”的魔力。
### 5.3 独立仿真器
为了测试网络延迟和真实环境的非确定性，Drake 还提供了一个独立的脚本 `hardware_sim.py`。它模拟了一个硬件服务器，通过网络与你通信，让你在开发阶段就能发现网络通信可能带来的 Bug。

## 6. 练习题详解与代码实践
### 练习 2.1：反射惯量的角色
*   **任务**：推导带齿轮箱的单摆动力学。
*   **代码重点**：你需要在 Drake 里搭建两个单摆，一个是直驱（无齿轮），一个是高减速比。你会发现，给它们同样的 PID 参数，直驱的可能根本停不下来（因为惯量小，太灵敏），而带齿轮的非常稳。
*   **数学直观**：体会 $I_{motor}$ 占主导地位时，系统动力学是如何被“简化”的。
### 练习 2.2：探索输入/输出端口
*   **任务**：查看 `HardwareStation` 有哪些接口。
*   **代码实践**：使用 `station.GetOutputPort("iiwa.position_measured").Eval(context)`。这就像在检查黑盒子背后的接线柱，看看哪根线输出的是位置，哪根线输出的是图像。
### 练习 2.3 & 2.4：直接关节控制与 PID
*   **任务**：自己写代码控制机器人，从“遥控”变成“写 PID 代码”。
*   **代码实践**：
    *   你需要创建一个 `LeafSystem`（自定义系统）。
    *   在 `DoCalcVectorOutput` 函数里，写 PID 公式：$u = K_p(q_d - q) + K_d(\dot{q}_d - \dot{q})$。
    *   将这个系统的输出连接到 `HardwareStation` 的输入端口。
    *   **调试**：你会遇到超调（震荡）或者稳态误差。通过调整 $K_p, K_d$ 参数，你会直观地理解控制理论。

### 给工程师的最后建议
*   **重视传感器噪声**：在仿真里，位置传感器是完美的。但在练习中，试着给传感器加一点噪声，看看你的 PID 控制器还能稳住吗？这能提前预防你在真机上遇到的问题。
*   **利用 YAML**：不要每次都手写 Python 代码加载模型。学会写 `scenario.yaml`，这是管理复杂机器人场景（比如双臂操作、多个摄像头）的最高效方法。
*   **理解反射惯量**：如果你以后自己做机器人设计，记得电机选型和减速比匹配。如果减速比太大，你会“感觉”不到负载的变化，虽然容易控制，但也失去了对外部世界的感知灵敏度。
